## 정확한 동작 — 둘은 다르게 동작

### Places New API (v1, 현재 메인)
```ts
getGoogleDetailPlaceByPlaceId(spot.googlePlaceId, LanguageType.KOREAN)
```
- 호출 시 `languageCode = ko` 명시
- Google API v1의 사양상 이는 **"한국어 원문 리뷰만 골라 달라"가 아니라 "응답 텍스트를 한국어로 통일해 달라"** 라는 의미
- 결과: 원문이 영어·일본어·중국어 리뷰여도 **Google이 자체 번역해서 한국어 텍스트로 응답**
- 즉 "한국어 원문 필터"가 아니라 "응답 한국어 통일" — 모든 리뷰가 후보가 됨

### Legacy API (fallback)
```ts
getLegacyGoogleDetailPlaceByPlaceId(spot.googlePlaceId)
```
- 언어 인자 없이 호출
- 모든 언어의 원문 그대로 응답을 받음
- 이후 `normalizeLegacyReviewToKorean`에서 각 리뷰의 `original_language`를 보고:
  - 한국어면 원문 사용
  - 그 외 언어(매핑된 14개)면 GPT로 번역
  - 매핑 외 언어면 **drop** (= "한국어가 아니어서 제외"되는 첫 지점)
