## 왜 "모른다"인지

- 발행 트리거(`sendSettlementInvoiceToPartner`)는 **fire-and-forget** — Lambda로 POST만 쏘고, 이 DB엔 아무것도 안 씀.
- 그 후 Lambda가 파일을 만들어 S3에 올리는데, **그때 어떤 키로 올리는지 / 발행 기록을 남기는지는 Lambda 코드에 있고 이 레포엔 없음.**

## 확인된 실제 저장 구조

발행 1회 = **랜덤 해시 zip 1개**:
```
creatrip.s3.ap-northeast-2.amazonaws.com/file-zipper/{랜덤}.zip
```
여러 달 예시: `y8vkgecd1xh.zip`(12월·2건), `cz59rgwfj1i.zip`(11월·5건), `bdnktrwnnt.zip`(06월·1건)… 전부 **랜덤 키**.

- **키가 랜덤** → 파트너·월로 **재구성 불가** (규칙 없음)
- 한 zip에 **그 배치의 여러 파트너 정산서가 함께** 들어감 (2건/5건/4건…) → 파트너 1명에게 zip째로 못 줌 (타 파트너 정산서 포함)
- 개별 파트너 파일의 S3 키는 **로그에 안 나옴** — zip URL만 노출

## 덤으로, 내부 조사 스레드(#bs-dev-tf)에서 정산서 로직도 드러났어

- 정산서는 **파트너 코드 단위**로 생성, 파일은 **XLSX + PDF** ("각 정산서의 파트너 코드를 기준으로... XLSX·PDF를 함께 변환")
- 반영 조건: 예약 상태가 **`PAID` 또는 `PARTIAL_REFUNDED`**만 포함
- **제외 파트너 목록**이 발송 로직에 있음 (예: 파트너십 코드 `64`가 과거 제외 목록에 있었음)
