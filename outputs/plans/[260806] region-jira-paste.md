# ▣ EPIC

**타입**: Epic · **우선순위**: Medium · **라벨**: TRAVEL · **컴포넌트**: 기획

### 제목
```
지역 도메인 개선
```

### 설명
> Phase 1(도메인 정리·표기 전환) 상위 에픽. 하위 태스크 T1~T7. Phase 2(신규 지역 유저페이지·테마·SEO)는 별도 에픽.

## 배경
- 크리에이트립의 '지역'은 목적이 다른 4개 체계(행정·운영분류·콘텐츠·마케팅)가 역할 없이 겹쳐 방치. region 514개 중 공개 13개
- 외부 여행 담론(r/koreatravel 10,001건)의 55.5%가 '지역' 관련인데, 지역 페이지는 스팟 리스트 트래픽의 3.8%만 수취·평균 체류 11초
- '도시×테마'(seoul restaurants)·'도시×구역'(seoul gangnam) 대형 SEO 키워드를 받을 페이지 구조 부재

## 개선 방향
- **역할 3분할**: 분류(CITY=시도 · DETAIL_LOCATION=시군구) / 콘텐츠(REGION) / 기하(LEGAL_LOCATION)
- **REGION 재정의**: 행정 폴리곤에 매인 단일 동네 → 여행객 인지 큐레이션 구역(구 연결 + 법정동 선택). 강남=강남구+서초구, 성수=성동구+{성수동1·2가}
- 스팟 `legal_location_legal_code` 보유 97.5%(위치 유효 99.7%)를 fine 해상도 자산으로 활용

## Phase 1 작업 목록 (하위 태스크)
- [ ] **T1. 도시·상세지역 법정동 정합 + 재오염 차단** — CITY=시도·DL=시군구 정합, 무연결 제거·재타입·시딩, /location 탭 정비, 카테고리 생성 재오염 차단
- [ ] **T2. REGION 어드민 '구 연결 + 법정동 선택' 기능** — 법정동 picker, 활성화 가드, region 순서 컬럼 *(선행 T1)*
- [ ] **T3. 관광지 REGION 생성·재배선 + REGION 정리** — 관광지 REGION 35개, 공개 13 재배선, 비공개 REGION 500개 삭제·스팟 직접연결 27링크 해제 *(선행 T1·T2)*
- [ ] **T4. 스팟 지역 표기·검색 REGION 격상 + 대표 region** — {도시}{region} 표기, 대표 region 지정, 검색 색인 *(선행 T3)*
- [ ] **T5. 스팟 CITY/DL 자동 파생 마이그레이션 + 상시 자동** — legal_code 파생 read-only, 단일 패스 재태깅 *(선행 T4)*
- [ ] **T6. 블로그·유저블로그·어학당 REGION 표기·셀렉터 + 자동승계** — 상세지역 드롭다운에 region 추가, 참조 컬럼, cutover 승계 *(선행 T4)*
- [ ] **T7. 관광지형 상세지역(DL) 삭제 (cutover 마무리)** — 관광지형 DL 삭제, 무중단 *(선행 T5·T6)*

## 실행 순서·의존성
`T1 정합 → T2 picker → T3 REGION 생성 → T4 표기 → (T5 재태깅 ∥ T6 블로그) → T7 DL 삭제`
- T1~T4 선형, T4 이후 T5·T6 병렬, T7 = T5 AND T6
- **유실 방지 불변식**: 관광지 스팟 재태깅(T5)은 표기 격상(T4) 이후 / 관광지 DL 삭제(T7)는 T5·T6 이후

> Phase 2(별도 에픽, 미생성): 신규 `/region/{city}/{zone}/{theme}` 4단 유저 페이지 · 테마 캐러셀·leaf · 구역 그리드 · SEO. Phase 1 데이터·표기 전환 완료가 선행.

# ① T1 — 도시·상세지역 법정동 정합 + 재오염 차단

**타입**: Task · **우선순위**: Medium · **라벨**: TRAVEL · **부모 Epic**: 지역 도메인 개선 · **선행**: 없음

### 제목
```
지역 도메인 개선 - '도시'·'상세지역' 법정동 정합 및 재오염 차단
```

### 설명
> **요약** — 뒤섞여 있는 도시·상세지역을 정부 법정동 체계(도시=시도, 상세지역=시군구)에 맞춰 정리하고, 상세지역이 다시 잡값으로 오염되는 생성 경로를 막는다. 지역 개편 전체가 딛고 설 데이터 토대.

## 배경
- 도시(CITY)에 시도급('서울')과 시/군급('강릉시')이 섞이고, 상세지역(DETAIL_LOCATION)에 행정구(강남구)와 관광지·동(홍대·성수동)이 혼재
- 상세지역 158개 중 105개(66%)가 상위 도시 없는 고아, 이름 중복(서면 3·성수동 2) 잔존
- 상세지역 생성 화면에 상위 도시 입력이 없어 만들 때마다 고아가 재생성
- → 개편 IA의 '구역 필터'가 이 분류 위에 서므로 정합 정비가 최우선 선행

## 구현

### 유저 플로우
- 관리자는 도시를 **시/도** 단위로, 상세지역을 **시/군/구** 단위로 관리
- 관리자는 지역 관리(/location) '시/도' 탭에서 '추가'로 도시 생성 — 법정동(시도)에서 선택하거나 법정동에 없는 값(한국·해외)은 자유 텍스트 입력
- 관리자는 시/군/구를 직접 만들지 않음(법정동 L2에서 전량 시딩되는 read-only), 시딩된 시/군/구의 **이름(15개 어권)만 편집**
- 관리자는 상세지역 상세 화면에서 그 구에 속한 법정동 목록을 읽기 전용으로 확인
- 관리자는 15개 어권 이름이 미입력된 시/군/구를 강조 표기로 즉시 식별(공개 스팟 보유 우선)

### 프론트엔드 요구사항
- /location 탭 라벨: **'도시' → '시/도'**, **'상세지역' → '시/군/구'**, **'법정지역' 탭 제거**(2탭 구성)
- ⚠️ 라벨은 표시층만 변경, 내부는 불변(`category.type` CITY/DETAIL_LOCATION·GraphQL 필드·링크 그대로)
- '시/도' 탭에 '추가' 버튼·생성 모달(법정동 시도 선택 또는 자유 텍스트)
- 시/군/구는 admin 생성·삭제 진입점 없음, 이름(다국어)만 편집
- 상세지역 상세 모달에 그 구의 법정동 목록 읽기 전용 노출(코드 자동 도출)
- 로케일 미입력 시/군/구 강조 표기(뱃지·색상 등 TBD), 공개 스팟 보유 우선 정렬

### 백엔드 요구사항
- **도시(CITY)만 admin 생성 대상** — 자유 텍스트 허용. **재오염 차단**: 카테고리 생성 시 상위 도시(parent) 입력을 강제하고 생성 가능한 종류(type)를 화이트리스트로 제한해, 상세지역 자유 생성·잡값 생성(고아 카테고리 재발생)을 막음
- **시/군/구는 법정동 L2에서 전량 시딩**(상위 도시·법정동 코드 자동 바인딩)
- 시/군/구에 시군구 단위 법정동 코드 1:1 저장(폴리곤용), 하위 법정동 pool은 구 코드 prefix로 조회 시 자동 도출(저장 안 함)
- **데이터 정비 순서**: ① 완전 무연결(스팟·블로그·어학당·유저블로그·region 전부 없음)만 제거 — '한국' 유지·'평양' 제거 ② 레벨 재타입(강릉시 CITY→DL, 코드 보존, 상위 도시 시도 재지정) ③ 법정동 기준으로 없는 값만 생성(있으면 재사용)

## 사람이 수행할 작업
- CITY 시도 승격 승인 — ✅ 완료(2026-07-08)
- 오분류 2건 재분류 확정(서울대입구·서면 = 관광지형)
- 동명 시군구 수동 매칭 6건(중·동·서·남·북구 상위 도시 판별, 강서구 서울 판별)
- 잡값 처리 확인(한국·해외 유지, 평양 제거)

## 수용 조건
- 모든 CITY = 시도, 모든 행정구 DL = 시군구
- 상세지역 admin 자유 생성 불가(재오염 경로 차단)
- 완전 무연결 잔재 0

# ② T2 — REGION 어드민: 구 연결 + 법정동 선택 기능

**타입**: Task · **우선순위**: Medium · **라벨**: TRAVEL · **부모 Epic**: 지역 도메인 개선 · **선행(blocked-by)**: T1

### 제목
```
지역 도메인 개선 - REGION 어드민 '구 연결 + 법정동 선택' 기능
```

### 설명
> **요약** — REGION 어드민에 '구(상세지역) 연결 + 그 구의 법정동 선택' UI를 추가해, 홍대·성수 같은 여행객 인지 구역을 데이터로 그릴 수 있게 한다. 관광지 REGION 생성의 도구.

## 배경
- REGION 어드민 편집 화면에 법정동을 고르는 UI가 없어 '홍대=마포구+{서교동·동교동…}' 같은 큐레이션 구역을 만들 수 없음
- 관광지 REGION 생성(T3)의 선행 도구

## 구현

### 유저 플로우 (관리자 — region 생성·편집)
- 상세지역(구)을 연결하면 상위 도시(시도)가 자동으로 정해지고, 그 구의 법정동(동)이 **전체 선택된 상태로** 표시
- 표시된 법정동 중 일부를 해제해 범위를 좁힘(성동구 → 성수동1·2가만). 미조정 시 그 구 전체가 범위
- 한 상세지역의 법정동을 전부 해제할 수는 없음(구를 빼려면 상세지역 연결 해제)
- 한 도시의 상세지역을 전부 선택할 수는 없음(도시 전체와 같은 범위 불가)
- 하나의 region은 오직 한 도시 아래에만 위치(타 도시 상세지역 혼합 불가)
- region 목록 순서 조정 가능 — 도시 페이지 구역 그리드 노출 순서로만 사용

### 프론트엔드 요구사항
- region 편집에 상세지역(구) 연결 + 그 구 법정동 목록 **전체 선택 → 체크 해제로 범위 조정** UI 신설
- 법정동 목록은 구 코드 prefix로 자동 도출한 결과를 읽기 전용 노출
- 상세지역 선택 시 상위 도시(시도) 자동 채움, 타 시/도 구 혼합 시 저장 차단·안내
- 한 구 법정동 전부 해제 저장 차단 / 한 도시 상세지역 전부 선택 차단
- 안내: **"도시 전체 범위의 지역은 만들 수 없어요. 상세지역을 하나 이상 제외해 주세요."**(문구 TBD)
- **활성화 가드**: REGION 활성화/게시하려면 부모 도시(CITY)가 활성(카드메타 image·tags·desc 충족)돼 있어야 함. 미충족 시 차단 + **CITY 편집 바로가기** + 인라인 **"이 도시 정보가 아직 없어요 → 입력"**
- 도시 탭(CITY 편집면) 유지(부산처럼 REGION 없이 활성화되는 도시용)
- region 순서 표시 + 재정렬 UI 신설(드래그·순서 번호)

### 백엔드 요구사항
- `region_has_detail_location` 재사용(REGION ↔ 구)
- `region.legal_location_legal_codes` **의미 전환·재사용**: 프리픽스 코드배열 → REGION이 선택한 법정동 집합
- 생성 제약: 도시 전체 선택 차단·타 도시 혼합 차단·상위 도시 자동(선택 상세지역 공통 상위)
- 활성화 가드(REGION 노출 ⟹ 부모 CITY 활성) — 미충족 시 게시 거부
- `region` **순서(priority) 컬럼 신설** — 도시 페이지 구역 그리드 순서 **전용**(대표 region 선정과 무관)

## 수용 조건
- 운영자가 '홍대 = 마포구 + {서교동·동교동·상수동}' 생성 가능
- 도시 전체 범위 저장 차단 / 부모 CITY 미활성 REGION 게시 차단

# ③ T3 — 관광지 REGION 생성·재배선 + REGION 정리

**타입**: Task · **우선순위**: Medium · **라벨**: TRAVEL · **부모 Epic**: 지역 도메인 개선 · **선행(blocked-by)**: T1, T2

### 제목
```
지역 도메인 개선 - 관광지 REGION 생성·재배선 및 방치 REGION 정리
```

### 설명
> **요약** — 관광지 이름(홍대·명동·서면 등)을 REGION으로 실제 생성·재배선하고(총 35개), 그동안 방치된 비공개 REGION과 잔재 연결을 청소한다.

## 배경
- 관광지 개념을 상세지역에서 빼내 REGION으로 이관해야 스팟 표기·검색을 region 기준으로 격상 가능
- 비공개·방치 REGION이 대량 잔존(514개 중 공개 13개, 2025-02-14 자동 벌크 500개)
- 스팟↔region 직접 연결(`region_spot_area_has_spot`, 27링크)이 새 모델과 어긋남

## 구현
### 관광지 REGION 확립 (총 35개 · 어드민 수동)
- **기존 공개 9개 재배선**(생성 불필요, 새 구조로 재배선만): 홍대·명동·경복궁·이태원·잠실·신사동·성수동·압구정·여의도
- **신규 생성 24개**: 남포동·서면·신촌·연남동·충무로·이대·인사동·대학로(혜화)·건대·인천공항·서울역·망원동·광안리·서촌·광화문·감천동·부산역·남산 등
- **DL 없는 신규 추가 2개**(용산·청담): 컨텐츠·어학당팀 확인 후 **개편 완료 시점 1회 일괄** 추가
- 각 REGION의 구·법정동은 **pre-run 초안**(관광지 DL 스팟의 legal_code 분포) 위에서 경계 가감·오배정 검수(빈 화면에서 시작 아님)
- 기존 공개 REGION 13개도 새 구조(구 연결 + 법정동 선택)로 재배선

### REGION 정리 (스크립트 일괄)

# ④ T4 — 스팟 지역 표기·검색 REGION 격상 + 대표 region

**타입**: Task · **우선순위**: Medium · **라벨**: TRAVEL · **부모 Epic**: 지역 도메인 개선 · **선행(blocked-by)**: T3

### 제목
```
지역 도메인 개선 - 스팟 지역 표기·검색 REGION 격상 및 대표 region 지정
```

### 설명
> **요약** — 스팟의 위치 표기·검색을 시군구에서 REGION 기준({도시}{region})으로 올리고, 한 스팟이 여러 REGION에 걸릴 때 대표로 보여줄 값을 정한다.

## 배경
- 스팟 표기가 아직 시군구 기준. 유저는 시군구보다 region(홍대·성수·신사) 이름으로 위치를 인지
- 하나의 스팟이 둘 이상의 region에 걸릴 수 있어('신사'·'강남') 대표로 표기할 값을 정하는 규칙 필요

## 구현
### 유저 플로우
- 스팟 상세: **{도시} {region}**(예: Seoul Sinsa). region 미소속 시 **{도시} {상세지역}**(예: 강원특별자치도 강릉시)
- region명 검색 시 검색어에 맞춰 표기(같은 스팟도 '홍대' 검색엔 홍대, '망원' 검색엔 망원)
- 관리자는 스팟 상세에서 대표 region 지정, 미지정 시 후보 중 먼저 생성된 region

### 프론트엔드 요구사항
- 스팟 상세·카드 표기 {도시}{대표 region} fallback {도시}{상세지역}. 표기 언어 = 유저 현재 로케일
- 어드민 스팟 상세에 대표 region 드롭다운 신설(옵션 = 스팟이 실제 소속된 region 동적)
- 링크: 스팟 상세 = 지역 페이지 링크 / 카드·검색 = 텍스트. 지역 페이지 없으면 링크 비활성(개방 시점 TBD)
- 검색 결과 카드는 검색어에 매칭된 region으로 표기, 매칭 없으면 대표 region(없으면 상세지역)

### 백엔드 요구사항
- `spot.representative_region_id`(nullable FK) 신설 — null = 자동(소속 region 중 생성순 첫), 값 있으면 override. 저장 검증(실제 소속인지)
- **대표 선정 규칙**: ① 검색어 매칭 우선 ② 매칭·질의 없으면 스팟 지정값, 없으면 생성순 첫 ③ 후보 비면 도시+상세지역
- REGION 스팟 조회 = 선택 법정동에 `spot.legal_code`가 속하는 스팟(소속은 저장값 아닌 파생)
- **검색 색인**: 스팟 소속 **전 region·전 언어**(도시·시군구·법정동 포함). 파생값이라 재색인(법정동 선택 변경·스팟 legal 변경·신규 등록 시)

## 수용 조건
- 홍대권 스팟이 'Seoul Hongdae'로 표기
- '신사'·'강남' 검색 시 각 검색어 REGION으로 표기
- 미소속 스팟은 '강원특별자치도 강릉시' fallback

# ⑤ T5 — 스팟 CITY/DL 자동 파생 마이그레이션 + 상시 자동

**타입**: Task · **우선순위**: Medium · **라벨**: TRAVEL · **부모 Epic**: 지역 도메인 개선 · **선행(blocked-by)**: T4

### 제목
```
지역 도메인 개선 - 스팟 도시·상세지역 legal_code 자동 파생(read-only) 마이그레이션
```

### 설명
> **요약** — 스팟의 도시·상세지역을 좌표에서 파생된 법정동 코드로 자동으로 채우고 직접 수정은 막으며(read-only), 기존 전 스팟도 같은 기준으로 일괄 재태깅한다.

## 배경
- 스팟의 도시·상세지역이 좌표에서 파생된 법정동 코드와 정합돼야 함
- 파생값을 직접 수정하면 원천(좌표)과 어긋나는 drift가 생기므로 read-only로 차단
- **선행 이유(T4 이후)**: 관광지 스팟 상세지역이 홍대→마포구로 바뀌어도, 표기가 이미 REGION(홍대)이면 '서울 홍대'가 유지됨. 표기 격상(T4) 이후 재태깅해야 유실 0

## 구현
### 유저 플로우
- 관리자는 스팟 등록·수정 시 좌표에서 파생된 도시·상세지역이 자동으로 채워지고 **read-only**임을 확인. 스팟 법정동도 읽기 전용 표시
- 유저는 **{시도} {시군구}** 표기, 해당 로케일 시군구 이름이 없으면 **{시도}만** 노출(연결은 유지)

### 프론트엔드 요구사항
- 스팟 도시·상세지역을 좌표 파생 법정동 코드로 자동 도출·**read-only 표시**(직접 수정 불가). 파생 순서: 좌표 → 법정동 → 시군구 → 시도
- 스팟 법정동(L3) 읽기 전용 표시
- 로케일명 누락 시 {시도}만 표기(빈칸·타언어 금지)
- 유효 `legal_code`가 없는 스팟(미코드)의 도시·상세지역 처리 = **TBD**(무효좌표 스팟 전수조사 후 확정)

### 백엔드 요구사항
- **상시 자동**: 등록·수정 시 좌표 → legal_code → CITY/DL 파생해 `spot_has_category` 저장(read-only). **좌표 변경 시 저장 시점 legal_code·CITY·DL 재파생(on-save resolve)** — 오배정 교정 경로
- **일회성 마이그레이션**: 전 스팟을 `spot.legal_location_legal_code`에서 CITY(시도)·DL(시군구) 파생해 **단일 패스로 일괄 재태깅**(일반·관광지 구분 없이 한 번에). 표기 유실 방지 위해 T4(표기 격상) 이후 실행
- 로케일 fallback은 서버가 완성 문자열(또는 표기 단위) 반환

## 사람이 수행할 작업
- 오배정 20건 좌표 교정(→ legal_code·CITY·DL 재파생)
- 미코드 159건 CITY/DL 처리 = TBD(전수조사 후)

## 수용 조건
- 전 스팟 CITY/DL이 legal_code와 정합
- 홍대권 스팟 재태깅 후에도 표기 'Seoul Hongdae' 유지
- 좌표 수정 시 CITY/DL 자동 갱신
