# ▣ EPIC — COM-2574 「지역 도메인 개선」

## 구조
- Phase 1 — CITY, DETAIL_LOCATION, REGION 재정비
- Phase 2 — /spot/region/* 유저페이지 UI 개선

## 배경
- 크리에이트립의 '지역'은 목적이 다른 4개 체계(행정·운영분류·콘텐츠·마케팅)가 역할 없이 겹쳐 방치 (region 514개 중 공개 13개)
- 외부 여행 담론(r/koreatravel 10,001건)의 55.5%가 '지역' 관련인데, 지역 페이지는 스팟 리스트 트래픽 3.8%만 수취·평균 체류 11초
- '도시×테마'(seoul restaurants)·'도시×구역'(seoul gangnam) 대형 SEO 키워드를 받을 페이지 구조 부재

## 개선 방향
- **REGION 재정의**: 행정 폴리곤에 매인 단일 동네 → 여행객 인지 큐레이션 구역(구 연결 + 법정동 선택). 동 단위까지 선택해 세밀 조정, 선택 범위 내 스팟 노출. e.g., 강남=강남구+서초구, 성수=성동구+{성수동1·2가}
- **지역(CITY·DL) 정리**: REGION 방향성에 맞춰 CITY·DL 성격 정리, 정리 과정에서 연관 도메인 영향 최소화
- 스팟 `legal_location_legal_code` 보유 97.5%(위치 유효 99.7%)를 fine 해상도 자산으로 활용

## 작업 순서 (Phase 1)

**1) CITY·DL 정합 및 스팟 좌표 갱신 — T1** (= legal_location 정합)
- 어떤 도메인과도 연결 없는 CITY·DL 제거 ('한국' 유지)
- 시/도(CITY) 생성/정합 — legal_location L1 17개: 이미 있음 8(서울·세종·대구·부산·울산·광주·인천·대전) / 신규 9도(경기·강원·충북·충남·전북·전남·경북·경남·제주)
- 시/군/구 재타입(CITY→DL) + 도시 도출 로직 전환(같은 배포): code 보존, 상위 지역명 = 동일 이름 legal 앞2자리 시/도(남양주 41360→경기도), 고성군 강원 처리·경남 고성 별도 DL, 도시=DL 상위 시도 도출
- 시군구(DL) 생성 — 없는 값만
- 스팟 좌표로 legal_code 백필
- legal 대응 안 되는 것 유지 → Region 경로: 관광지형(홍대·서면·광화문), 특례시(전주시 등 — legal엔 일반구만)

**2) REGION 정비 — T2·T3·T4**
- T2: REGION 어드민 '구 연결 + 법정동 선택' 관리 기능
- T3: 관리 안되는 REGION 제거 + 필요 REGION 생성 + 새 구조 마이그레이션
  - 관광지 Region: 제휴팀 판단('노출 가치 있는 지명') + 블로그·유저블로그 DL 중 비행정구역
  - 특례시 시-단위 Region: 전주시=완산구+덕진구 법정동 (시 전체 콘텐츠 수용)
  - 유지 Region은 이미 legal_code 연결·노출 로직 불변
  - 관광지형 중 'Region 대상 아닌 것'은 소속 구로 노출(의도)
  - 도시레벨 공개 REGION(부산·제주·춘천/가평/강릉) 해체: 도시 전체 REGION 생성 불가 → 스팟은 CITY로 노출, 필터는 CITY로 이동(T4)
- T4: 스팟 리스트 지역 필터 개선 — CITY + 하위 REGION 구조. REGION 있는 CITY=자기 섹션/없으면 OTHER CITY. CITY 노출=legal L1 `is_in_business` 스팟 ≥1(한국·해외 자동 제외) / REGION 노출=is_shown_map. 부산·제주 CITY 노출·구 필터 제거·피부과 칩 CITY

**3) 관련 도메인 영향 대응 — T5·T6·T7**
- T5: 스팟 표기 CITY+DL → CITY+Region(fallback CITY+DL) + 대표 region (선행 T3, sweep 먼저)
- T6: 스팟 CITY/DL 좌표 자동화 + legal_code 일괄 재태깅(sweep) (선행 T5) / 특례시→일반구 DL 자동
- T7: 블로그·유저블로그·어학당 셀렉터에 Region 옵션 + 기존 DL 재배선 (선행 T5) / 관광지형→대응Region / 특례시CITY→시-Region / 재타입(남양주) 재배선 불필요

**4) 데이터 정리 — T8**
- 무연결 CITY·DL 삭제 (선행 T6·T7): 관광지형 DL + 특례시 CITY + 순수 무연결. 재타입 CITY(남양주) 존속. 삭제는 참조 0인 것만

**Phase 2** — /spot/region/* 유저페이지 UI 개선 [TBD]

**실행 순서**: `T1 정합 → T2 picker → T3 REGION 생성 → T4 필터 → T5 표기 → (T6 재태깅 ∥ T7 블로그) → T8 삭제`
- 표기 먼저(T5 > T6) 홍대→마포구 유실 방지 / 입력 먼저(T6·T7 > sweep) 재오염 방지 / 삭제는 끝(T8, 참조 0만) / 노출 로직 Phase 1 불변

# ① T1 — COM-2575 「CITY·DL·스팟 좌표 legal_location 정합」

**요약** — CITY(시도)·DL(시군구)를 legal_location과 정합: 무연결 제거 → 시도 생성 → 시/군 CITY를 DL로 재타입(도시 도출 로직 전환 포함) → 시군구 생성 → 스팟 legal_code 백필. legal에 없는 관광지형·특례시는 유지(후속 Region). **선행: 없음**

## 배경
- 도시(CITY)에 시도급('서울')·시/군급('남양주시') 혼재, DL에 행정구(강남구)·관광지·동(홍대·성수동) 혼재
- 도 단위 시도(경기도 등 9개)가 카테고리에 없음 — CITY엔 광역시류 8개(서울·부산·대구·인천·대전·울산·광주·세종)만
- 스팟 legal_code 미보유 179개(좌표 정상권 129 포함)
- → 개편 IA(구역 필터·표기)가 이 정합 위에 서므로 최우선 선행

## 구현
### 유저 플로우
- 관리자는 도시=시/도·상세지역=시/군/구 단위 관리
- /location '시/도' 탭 '추가'로 도시 생성(법정동 시도 선택 또는 한국·해외 자유 텍스트)
- 시/군/구는 직접 못 만듦(read-only), 이름(15개 어권)만 편집 / 상세지역 화면에 법정동 목록 읽기 전용
- 스팟 좌표 저장 시 유효 범위면 법정동 자동 매핑, 좌표 안 바꿔도 미매핑이면 재시도
- 시/군(남양주) 물던 스팟·콘텐츠 도시는 상위 시도(경기도) 자동 노출

### 프론트엔드 [어드민 /location]
- 탭 라벨 '도시'→'시/도'·'상세지역'→'시/군/구'·'법정지역' 탭 제거(2탭, 표시층만·`category.type` 불변)
- '시/도' 탭 '추가' 버튼·생성 모달 — 추가 시 15개 어권 이름 입력 필수
- 시/군/구 admin 생성·삭제 진입점 없음, 이름(다국어)만 편집
- 상세지역 모달에 그 구 법정동 목록 읽기 전용(구 코드 prefix 자동 도출)

### 프론트엔드 [어드민 /spot/*]
- 스팟 상세에 매핑 법정동 노출, 미매핑 스팟 '지역 미매핑' 표기
- 도시 표기는 별도 CITY 링크가 아니라 상세지역(DL)의 상위 시도

### 백엔드 [데이터 정합 순서 (legal_location 기준)]
1. 어떤 도메인과도 연결 없는 CITY·DL 제거 ('한국' 유지)
2. **시도(CITY) 생성/정합** — legal L1 17개: 이미 있음 8(서울시·부산시·대구시·인천시·대전시·울산시·광주시·세종) / 신규 9도(경기도·강원도·충청북도·충청남도·전라북도·전라남도·경상북도·경상남도·제주도, 15개 어권) / 특수: '한국' 유지·'해외' 신규
3. **시/군 재타입(CITY→DL) + 도시 도출 로직 전환**: code 보존 + parent = 동일 이름 legal 앞2자리 시/도(남양주 41360→경기도 41). 동명 고성군: 강원도 처리·경남 고성 별도 DL. 제주시·서귀포시 재타입(상위=제주도). 도시=DL 상위 시도에서 도출(스팟 legal_code L1) → CITY 링크 비어도 도시 자동 확보
4. **시군구(DL) 생성** — 없는 값만(재타입 정상화값 재사용, 중복 없음). 15개 어권·시군구 법정동 코드 1:1
5. 스팟 좌표로 **legal_code 백필** — 대상 129개(경계 내부 119 + ±100m 버퍼 10), 이상치 5건 로그
   - 그 외 50건(이상치 5건 포함)은 T6에서 CITY '한국'/'해외' 배정

### 백엔드 [스팟 legal_code 매핑 (상시)]
- 상시 자동: 등록·수정 시 좌표→legal_code. 좌표 변경 시 재파생 + legal_code 비었고 좌표 유효 시 좌표 무변경 저장에도 재매핑(오배정·누락 교정)
- 매핑 자동화(재오염 차단): 미매핑(유효 좌표) 스팟 주기 탐지·매핑 스케줄러
- 매핑 실패 집계: 경계 밖 실패건 집계·노출로 좌표 이상치 식별
- 매핑 기준: 법정동 L3, 경계 내부→±100m 버퍼 순, 한국 범위 밖 제외 — 현행 유지

### 유지 (legal 밖 → 섹션② 이후)
- 관광지형 DL(홍대·서면·광화문), 특례시(전주시 등 — legal엔 일반구만)

## 수용 조건
- 모든 CITY=시도·행정구 DL=시군구 / 상세지역 admin 자유 생성 불가 / 완전 무연결 잔재 0 / 유효 좌표 스팟 legal_code 미보유 0(이상치·해외·물리위치 없는 상품 제외) / 스케줄러로 누락 재발 0

# ② T2 — COM-2576 「REGION 어드민: 구 연결 + 법정동 선택 기능 구현」

**요약** — REGION에 상위 구(시군구)를 연결하고 법정동을 선택하는 어드민 관리 기능(picker) + 순서 재정렬. region 법정동이 스크립트로만 세팅돼 편집 불가한 병목 해소. **선행: T1**

## 배경
- region 스팟 노출은 이미 `legal_location_legal_codes`(법정동) 매칭으로 동작(홍대 196개), /spot/region/* + /spot/list/* '지역' 필터 공유
- 법정동 코드에 어드민 입력 필드 없어(스크립트로만) 운영자가 못 고침 → region 13개만 공개된 근본 원인
- region이 상위 구+동으로 정확히 묶여야 스팟이 걸림 → 구역 필터가 이 구조 위에 섬

## 구현
### 유저 플로우
- 관리자는 region 생성 시 **상위 구(시군구) 필수 연결**, 그 구의 **법정동 선택**으로 범위 지정
- 구 연결 시 법정동은 **전부 미선택 상태로 노출**, 목록 맨 앞 **'전체 선택'** 으로 일괄 선택/해제 (개별 동 선택도 가능)
- **법정동 최소 1개 이상 선택해야 저장**
- 다중 구 선택 가능(강남=강남구+서초구)

### 프론트엔드
- region 편집: 구 연결 → 그 구 하위 법정동 목록 미선택 상태로 노출 (맨 앞 '전체 선택' 체크박스=체크 전체선택/해제 전체해제, 개별 체크/해제 / 구 미지정 시 저장 불가)
- 법정동 목록은 구 코드 prefix로 자동 도출(목록 구성 고정·수동 추가 없음), 그중 선택/해제
- 상세지역 선택 시 상위 시도 자동 채움, 타 시/도 구 혼합 시 저장 차단·안내
- **도시 전체 범위 region 방지**: 한 도시 상세지역 전부 선택 차단 (안내 "도시 전체 범위의 지역은 만들 수 없어요. 상세지역을 하나 이상 제외해 주세요.")
- 법정동 최소 1개 선택 필수
- region 순서 표시 + 재정렬 UI(드래그·순서 번호)

### 백엔드
- region에 상위 구(시군구) 바인딩 필수 — 생성·저장 검증
- 동 선택은 `legal_location_legal_codes`에 저장 — 항상 1개 이상(빈 값 저장 불가). '전체 선택' = 그 구 모든 법정동 코드 저장
- region 순서(priority) 컬럼 신설 — 도시 페이지 구역 그리드 순서 전용(대표 region 선정과 무관)
- 노출 로직(legal_code 매칭)은 현행 유지 — 편집 경로만 신설

## 수용 조건
- 관리자가 region 구·법정동 어드민 편집 가능, 다중 구 지원
- '전체 선택'한 region은 그 구 전체 법정동 스팟 노출 / 일부 선택 region은 선택 법정동만
- region 순서 재정렬 가능

# ③ T3 — COM-2577 「관광지·특례시 REGION 생성·재배선 + REGION 정리」

**요약** — 관광지(홍대 등)·특례시(전주 등)를 REGION으로 생성·재배선하고, 방치된 비공개 REGION·잔재 연결을 정리. **선행: T1·T2**

## 배경
- 관광지 개념을 상세지역에서 빼내 REGION 이관해야 스팟 표기·검색 격상 가능
- 특례시(전주 등)는 legal에 시가 없어(일반구만) 시 전체 DL 없음 → 시-단위 Region으로 복원
- 비공개·방치 REGION 대량(514 중 공개 13, 2025-02-14 벌크 500개 `id 25~531`)
- 스팟↔region 직접 연결(`region_spot_area_has_spot`, 6 area·27링크)이 새 모델과 어긋남

## 구현
### 관광지 REGION 확립 (총 35개 · 어드민 수동)

**요약** — 대응 REGION/시-Region/해외로 재연결 끝난 뒤, 무연결 CITY·DL(관광지형 DL + 특례시 CITY + 해외 CITY + 순수 무연결) 무중단 삭제. 재타입 CITY는 DL로 존속하므로 제외. **선행: T6, T7**

## 배경
- 관광지 상세지역(홍대·명동)이 카드·검색 노출 중 → 대응 REGION 표기·검색 살아나고 재연결 끝나기 전 지우면 끊김 → 무중단 필수
- T6(재태깅)·T7(블로그·유저블로그·어학당 재연결) 끝나야 표기 유실·dangling 없음

## 구현
- 관광지 상세지역 스팟이 소속 시군구로 재태깅됐는지 확인(T6)
- REGION 안 되는 ~68개 콘텐츠가 소속 구로 재지정됐는지, 되는 관광지형(재배선 10 + 신규, 수는 T3 확정)·특례시 CITY 콘텐츠가 대응 region/시-Region 승계됐는지 확인(T7)
- 해외(대만·타이난·타이페이) 콘텐츠 '해외' 재배선 확인
- **삭제 대상**: 관광지형 상세지역(관광지 82·동 16·중복 5) / 특례시 CITY(블로그 있는 특례시는 시-Region 승계 후 / 없는 특례시는 스팟 재태깅 후) / 해외 CITY 대만·타이난·타이페이 + 평양 / 순수 무연결 잡값. **재타입 CITY(남양주)·'한국'·'해외'는 존속 → 제외**
- 입력 개선으로 옛 값이 신규 선택에서 빠지므로 재배선 후 일괄 삭제로 충분
- 삭제는 삭제 시점 참조 0인 것만. 삭제 대상 목록 최종 승인(운영·기획)

## 수용 조건
- 관광지형 상세지역 0·특례시 CITY 0·해외 CITY 0·평양 0 / 스팟·블로그·유저블로그·어학당 dangling 0 / 유저 표기 유실 0(홍대·전주는 REGION 존속)
