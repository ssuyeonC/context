# 와이어프레임 수정 지시 — 지역 도메인 어드민 (`#region-domain-admin`)

작성일: 2026-09-03
대상 파일: `apps/wireframes/page/src/wireframes/region-domain-admin/index.tsx` (wireframes 레포)
정본: `outputs/plans/[260831] region-phase2-breakdown.md` §1-1 (AD-REGION-META) · §3-2 (카테고리 순서 변경) · §2-1 (CITY 2단 게이트)

> 배경: 현재 어드민 와이어프레임은 **CITY(도시) 메타 편집만 설계**돼 있고, REGION(지역) 쪽은 prod 현행 필드가 `콘텐츠 (삭제 후보)` 블록으로 남아 판단 보류 상태다. 유저페이지 시안 `#region-domain-renewal` 의 `/region/seoul/gangnam` 을 기준으로 필요한 입력을 역산해 확정했다. 아래대로 반영한다.

## 1. REGION 탭 — "지역 메타정보 입력" 섹션 신설

`RegionDetail` 안, `RegionBasicInfo`(지역 기본 정보) **아래 · `LegalRegionSection`(지역 범위) 위**에 배치한다. 구조·톤은 CITY 탭의 `CityDetail` "지역 메타정보 입력" 섹션과 **대칭**으로 맞춘다(같은 `Desc`/`DRow` 조합, 우상단 `🌐 자동번역` 버튼 포함).

| 필드 | 형태 | 비고 |
|---|---|---|
| 히어로 이미지 * | `ImageDrop` (풀폭) | 라벨에 `활성화 필수` 표기. 기존 `리스트 이미지 (228*128)` 를 **이 필드로 교체** |
| 태그 * | `TagSelect` | `활성화 필수`. 예시 태그: 쇼핑 · K-뷰티 · 코엑스 · 가로수길 |
| 한 줄 소개 | `input` | 유저페이지 h1 바로 밑 강조 문구 |
| 지역 설명 * | `textarea` | `활성화 필수`. **기존 '지역 설명 입력' 필드를 그대로 이동**(신규 아님) |
| slug | **읽기 전용 표시**(입력 필드 아님) | 영문 지역명에서 자동 생성 — §1-A |

- **활성화 필수 3종 = 히어로 이미지 · 태그 · 설명.** CITY 탭의 image·tags·desc 와 동일한 게이트 개념이며, 기존 `ActivationGuard`(부모 CITY 가드)는 **그대로 유지**한다(별개 가드).

### 1-A. slug 규칙 (확정 2026-09-03)

- **slug 입력 필드를 만들지 않는다.** 영문 지역명에서 자동 생성한 값을 **읽기 전용으로 표시**만 한다.
  ```
  slug   gangnam
         영문명 'Gangnam'에서 자동 생성 · 유저페이지 경로 /region/seoul/gangnam
  ```
- 생성 규칙 = slugify(소문자화 · 공백→하이픈 · 영숫자와 하이픈 외 제거).
- **REGION 이름은 생성 시에만 입력하고 생성 후에는 수정할 수 없다.** 상세 화면의 `지역명 입력` 은 **읽기 전용**으로 바꾼다(생성 모달에서만 입력). 이름이 불변이므로 slug도 불변이라 URL이 흔들리지 않는다. 리브랜딩은 고려 대상이 아니다.
- **생성 모달에서 이름 특수문자를 차단**한다(입력 검증 + 안내 문구). `압구정/신사` 같은 슬래시가 URL 경로를 깨뜨리는 것을 입력 단계에서 막는다.
- **`(city, slug)` 유니크 가드**(AD-SLUG): 3번째 칸은 zone 과 카테고리 leaf 가 **공유하는 네임스페이스**다(`/region/seoul/gangnam` ↔ `/region/seoul/restaurants`). 자동 생성이어도 충돌하면 저장을 막고 안내한다.
  > 안내 예: "'restaurants'는 이 도시에서 이미 카테고리 주소로 쓰고 있어요. 지역 영문명을 다르게 지어 주세요."
- 영문명이 비면 slug 가 없어 게시할 수 없다 — 별도 검증 없이 자연히 게이트가 된다. 노트로 남긴다.
- 3종 충족 여부를 목록에서 보이게 한다 — `RegionList` 공개 여부 칼럼 옆에 CITY 목록과 같은 `노출/숨김` 뱃지 또는 `MetaChip` 스타일 표기 추가.

## 2. REGION 탭 — 이동 정보 섹션

유저페이지 시안의 `이동` 모듈(주요 역 / 공항·패스 탭)에 대응한다.

- **주변 지하철역**: **기존 방식 그대로 — 운영자가 역을 검색해 수동 연결**한다(`TagSelect`, 저장은 기존 `region_has_subway`). 자동 추천·랭킹은 넣지 않는다. **신규 스키마 없음.**
  - 데이터: `MAIN_SUBWAY`(호선 11) → `MIDDLE_SUBWAY`(역 478), `parent_code` 연결. 역·호선 이름은 `category_translation` 으로 **이미 다국어**라 번역 입력 불필요.
  - **역별 한 줄 노트는 v1에서 제외**(시안의 `"강남 중심 환승"`). 짧은 텍스트지만 15개 언어 번역 테이블이 새로 필요해 비용이 크다. 역명·호선은 기존 다국어라 공짜. 노트는 후속.
  - ⚠️ **연결된 역이 0개면 유저페이지에서 '주요 역' 섹션 자체를 노출하지 않는다.** 호선 카탈로그가 **수도권 전용**(1~9호선·수인분당·공항철도)이라 부산·대구·광주·대전 지하철이 아예 없다 — 해당 지역 REGION은 수동으로도 역을 붙일 수 없다. 빈 섹션이 뜨지 않게 처리한다. (비수도권 호선·역 카탈로그 확충은 후속 별 트랙)
  - ⚠️ 표시 처리 2가지: ① **같은 역이 호선별로 다른 row** 이므로 역명 기준 머지해 `강남구청 · 7호선·수인분당선` 으로 묶어 보여준다 ② 호선 이름이 ko 로케일에도 영어(`Line 2`·`Suin·Bundang Line`)로 들어 있어 **번역 보정이 필요**하다는 노트를 남긴다.
- **공항 접근 정보**: 신규. `아이콘 · 라벨 · 설명` 반복 입력. 시안 값 예: `🚌 공항버스 6009 · "인천공항 → 강남역 약 70분"`.
  - 노트로 명시: **CITY 값 상속 + REGION override(선택)**. 미입력이면 부모 CITY 값 노출.
- **교통패스·유심 칩은 어드민 입력 대상이 아니다.** 전역 "여행 필수" 모듈이 카테고리 규칙으로 자동 노출한다(정본 `[260901]`). 노트로만 표기.

## 3. REGION 탭 — 추천 대상(persona) 섹션 신설

유저페이지 우측 "이런 여행자에게 추천" 카드에 대응. 카드 단위 반복 입력.

- 카드 1개 = `아이콘 · 라벨 · 설명 · 관련 스팟(다중)`. 시안은 3장.
- 추가/삭제/순서 변경 가능.
- 노트: **미입력 시 유저페이지에서 섹션 자체 미노출**(선택 항목).

## 4. REGION 탭 — 카테고리 순서 변경(AD-REORDER) 신설

2026-09-02 미팅 확정 사항인데 현재 와이어프레임에 없다. **도시 상세·지역 상세 양쪽 모두**에 추가한다.

- 구조: **대카테고리 순서**(드래그 재정렬) + 각 대카 펼치면 **그 대카 내 중카테고리 순서**(중첩 리스트).
- 기본값 = home-nav priority(대카) / category.priority(중카). 미설정이면 기본값 폴백.
- 도시 상세와 지역 상세는 **완전 독립**(상속 없음). 노트로 명시: 서울 상세에서 바꾼 순서가 강남 상세에 영향 없음.
- **묶기(grouping) 기능은 넣지 않는다** — 미팅에서 제외됨. 순서 재정렬만.
- 노트: 어드민은 중첩 리스트로 설정하지만 **유저 렌더는 캐러셀 + 더보기 → leaf 페이지 이동**이다(인페이지 확장 아님).

## 5. 삭제

`RegionContentFields`("콘텐츠 (삭제 후보)") 블록을 없애고, 살릴 항목은 위 1~2번 섹션으로 옮긴다.

| 항목 | 처리 |
|---|---|
| 지역 설명 | **살림** → §1 메타 섹션으로 이동 |
| 주변 지하철역 | **살림** → §2 이동 섹션으로 이동 + 노트 추가 |
| 지도 뷰 공개 여부 | **살림** → §2 또는 노출 제어 영역에 토글 유지. 폴리곤은 선택 법정동 union으로 자동 도출되므로 **입력 없이 on/off 토글만**. 라벨 의미 = "상세 지도 카드 노출" |
| 리스트 이미지 (228*128) | **삭제** → 히어로 이미지로 대체(§1). 이 규격을 쓰는 화면이 없음(구역 진입 = 지도 폴리곤 라벨, `/region` 인덱스 대표 이미지 = CITY 값) |
| 지역별 리뷰 공개 여부 | **삭제** (아래 노트 필수) |
| 지역 주소 입력 * | **삭제** — `RegionBasicInfo`에서 제거. 유저페이지에 주소 노출이 없고, 범위는 법정동 선택으로, 지도는 폴리곤으로 결정된다 |

**지역별 리뷰 삭제 시 노트로 남길 것** (오해 방지용):
> `region_review`(7,412행)는 유저가 지역에 직접 남기는 리뷰가 아니라 **스팟 후기가 그 스팟 위치의 법정동으로 복제 적재**되는 구조다. 2025-03 이후 `region_id`는 전량 null이고 `legal_location_legal_code`만 채워진다 — 즉 이 토글이 제어하던 region 연결은 1년 반째 신규 유입이 없다. **어드민 토글만 제거하고 테이블·적재 파이프라인은 유지**한다(스팟 리뷰 쪽이 깨짐).

## 6. 기존 노트 문구 교정 (CITY 2단 게이트 개정 미반영분)

두 곳이 2026-08-31 개정 전 서술로 남아 있다.

- **레이어 탭 주석** — 현재 `CITY 편집 탭은 유지(부산처럼 REGION 없이 스팟만으로 활성화되는 도시용)`.
  → 이 사유는 폐기됐다. **`콘텐츠 레이어 분리 때문에 유지`** 로 교정.
- **`CityList` 상단 노트** — 현재 `성립 ≠ 노출 — 스팟 있는 시/도면 페이지 성립(REGION 무관)`.
  → **2단 게이트**로 교체:
  > ① 어드민 도시 탭 등장 = **자식 REGION ≥ 1 보유** · ② 유저 그리드 선택 가능 = ① + 카드메타(대표이미지·태그·설명) 입력. 자식 REGION 없는 도시는 도시 탭·유저 그리드에 아예 뜨지 않는다.
- `CityList` 표에 **자식 REGION 수** 칼럼을 추가해 게이트 ①이 화면에 드러나게 한다.

## 7. CITY 탭 확인 사항

- `City` 데이터에 `slug` 값은 있으나 **편집 UI가 없다.** 라우팅(`/region/{city}`)에 필요하므로 `CityDetail` 메타 섹션에 slug 입력 필드를 추가한다.
