### 2-1. CITY ↔ REGION 포함관계 · 노출 규칙 (확정)

REGION이 상위 CITY를 부모 값으로 갖게 되면서(`region.city` FK) CITY⊃REGION 포함관계가 생긴다. 이 위에서 CITY 노출을 **2단 게이트**로 건다.

| 게이트 | 조건 | 결과 |
|---|---|---|
| ① 어드민 노출 | CITY가 **자식 REGION ≥1** 보유 | 어드민 `/region` **도시 탭에 등장**(초기 비활성) |
| ② 유저 노출 | 위 + **카드메타(대표이미지·태그·설명) 입력·저장** | CITY **활성화** → 유저 `/region` 지도 그리드에서 **선택 가능** |

- **한 방향 불변식 유지**: REGION 게시 ⟹ 부모 CITY 활성화(어드민 WF의 "REGION만 켜고 도시 메타 누락 고아 차단"). 여기에 **역방향 그리드 게이트 추가**: 자식 REGION 없는 CITY는 도시 탭·유저 그리드에 아예 안 뜸.
- **부산 라이프사이클(예시)** — ⚠️ 마스터 §3-3①의 "부산처럼 REGION 없이 활성화되는 CITY" 서술은 이 규칙으로 **개정**된다(REGION 전무 CITY는 그리드 비노출).
  1. T3: 부산 **도시 전체 REGION은 해체**(시도 전체 REGION 금지)하되, **서면·광안리·감천동·청사포 등 구역(zone) REGION을 신규 생성**(`[260730]` 초안: 서면=부산진구 부전동·전포동 / 감천동=사하구 감천동 …).
  2. 부산 CITY가 자식 REGION을 갖게 됨 → 어드민 도시 탭에 **비활성 상태로 등장**.
  3. 운영자가 부산 카드메타 입력·저장 → **활성화** → 유저 `/region` 그리드에서 부산 **선택 가능**, `/region/busan`에서 zone 그리드(서면·감천…) 노출.
- **결정 = 옵션 (A)**: CITY 그리드 노출 = 활성화 AND 자식 REGION ≥1. (이전 열린질문 "부산 그리드 노출 여부" 해소 — 부산은 zone REGION 보유라 자연히 노출 경로 확보.)

## 3. 축③ — 테마 · 스팟 그룹핑

### 3-1. 페이지별 그룹핑 구조 (확정 2026-08-31)

5개 페이지 타입이 **예약 카테고리 택소노미**로 한 단계씩 내려가며 그룹핑(기본). REGION 레벨은 CITY 규칙의 region-필터 미러:

| 페이지 | 스팟 범위 | 기본 그룹핑 축 |
|---|---|---|
| (a) `/region` | 없음(스팟 비노출) | — |
| (b) `/region/{city}` | 도시 스팟 | 예약 **대카테고리**(= home-nav 기본, 순서 변경 가능) |
| (c) `/region/{city}/{category}` | 도시 ∩ 대카 | 예약 **중카테고리** |
| (d) `/region/{city}/{region}` | 도시 ∩ region(선택 법정동) | 예약 **대카테고리** |
| (e) `/region/{city}/{region}/{category}` | 도시 ∩ 대카 ∩ region | 예약 **중카테고리** |

- **CITY 레벨(b·c)** = 예약 대카/중카 자동. 순서 = home-nav/category priority **기본 + 페이지별 순서 변경 가능**(§3-2).
- **REGION 레벨(d·e)** = 예약 택소노미 자동 그룹핑(스팟만 region 필터). 순서 변경만, **묶기 없음** → 기본 CMS 최소.

### 3-2. 큐레이션 = 페이지별 카테고리 순서 변경 (확정 2026-09-02, 미팅 반영)

큐레이션 장치 = **각 페이지에서 카테고리 섹션 순서를 운영자가 재정렬**. 묶기(grouping) 없이 **순서(order)만** override.

- **어드민 설정 = 도시 상세 / 지역 상세 페이지 각각에서 독립** — ① 대카 순서(그 페이지의 대카 섹션) + ② 각 대카 내 중카 순서(그 대카 leaf의 중카).
  - 예) **서울 상세**: `미식-체험-K뷰티…` + (미식 내)`한식-카페-오마카세…` / **강남 상세**: `체험-미식-K뷰티…` + (체험 내)`의상대여-한복스냅-운세…` → 서울·강남 **완전 독립**(D).
- **데이터 모델** `region_category_order(scope_type[city|zone], scope_id, parent_category, category_code, order)`
  - `parent_category` **NULL** → 그 페이지 **대카 순서** / **대카값** → 그 대카 leaf의 **중카 순서**.
  - 행 없음 = **기본값 폴백**(대카=home-nav priority, 중카=category.priority). **상속 없음(flat)** — 강남이 서울 순서 안 물려받음.
- **유저 렌더 = 캐러셀 + 더보기 → leaf 페이지**(§3-3, 인페이지 확장 아님). 어드민 설정(중첩 리스트)과 유저 렌더(페이지 이동)는 별개.
- CMS 부담 최소 — **드래그 재정렬만**, 새 엔티티·묶음·커스텀 slug 없음.

⚠️ **묶기(grouping) 기능 = 제거 (미팅 2026-09-02)** — 대카 여러 개를 하나로 묶는 "강남의 의료 = 메디컬+한의원" 식 큐레이션은 **도시·지역별로 일일이 관리하기 어렵다는 영업/제휴팀 의견**으로 v1에서 뺌. **추가 여지는 있음**(요청 시 재도입).
- 파급: `region_section`·대-레벨 묶음·중카 묶기·묶음 slug·nesting **전부 v1 제외.** leaf slug = 예약 카테고리 slug **고정**(커스텀 묶음 slug 없음) → SEO·라우팅 더 단순.
- ~~이전(하이브리드 C): zone별 대카 묶음 override(essential 예시)·중카 묶기 후속·스키마 nesting~~ → 미팅으로 폐기, 순서 변경으로 대체.

### 3-3. 노출·파생

- **노출 = 캐러셀 + leaf**: monthly best 상위 9 캐러셀 + 스팟 ≥10이면 "전체 보기" → leaf. ("캐러셀에 다 못 담으면 leaf" 단순 규칙, 비노출 구간 0)
- **`master_theme`·`region_section` 전부 불필요화** — 전역 테마 사전·묶음 CMS 없이, **"예약 카테고리 → 안정 slug 매핑 사전"** + **"(페이지, 카테고리) → 순서" 저장**만 필요. **BE-5 = 페이지별 카테고리 순서 저장**(묶기 제거로 최경량).
- **서울 CITY 테마**([260623]): home-nav 대카테고리 **개별 캐러셀**(체험·미식·명소&입장권…). 묶음(K-뷰티·웰니스 5코드)은 와이어프레임 컨셉일 뿐 — CITY는 단일 카테고리(§6 #3).
- **비-테마 모듈**(카테고리 섹션 아님): 도시간 이동·추천 렌즈·일정 동선(itinerary)·시즌 배지·거점 동네 칩([260623] §5).
  - **전역 "여행 필수" 모듈**(교통·유심·여행서비스) — 지역무관 고정 노출. 소스 = **744 대카째 + (743·745 ∖ 지역성 중카)**. 대카 통짜 금지(743·745는 근교셔틀·안경·식당 등 지역 스팟 혼재), **중카 블랙리스트 규칙**으로 순수 전역 ≈78개 자동 추출. `noindex` 링크 모듈. 데이터 조사·규칙 정본 = **`[260901] region-global-essentials-module.md`**.
- **BE**: leaf 쿼리(대카∩도시(∩region) → 중카 그룹) + 캐러셀 쿼리(monthly best 9) + 페이지별 순서 override 적용 = [260622] BE-4·BE-5(경량).

## 5. 순서·의존성

```
Phase 1 (T1~T8: 데이터·필터·표기)
   └─▶ 축① 어드민 CMS ─▶ 콘텐츠 입력(CITY 카드메타 · 페이지별 카테고리 순서는 선택)
          └─▶ BE(조회축·slug·leaf 쿼리·폴리곤) ─▶ 축② 유저페이지 + 축③ 테마 노출
                 └─▶ 축④ SEO 색인·측정(선행지표 → lagging, Q3말 물꼬·Q4 성숙)
```

- **어드민이 BE/FE보다 선행** — 데이터를 채워야 페이지가 성립(생성=어드민, 스크립트 아님).
- **유저 배포는 데이터 생성 완료 후** — Phase 1 T3(REGION)·서울 콘텐츠 입력 끝난 뒤 FE 공개.
- **리스트→region 유입 위젯**([260713] KR3)은 서울 페이지 라이브 후 소프트오픈(내부 트래픽으로 전환 먼저 튜닝).
