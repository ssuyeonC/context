## 1. 어쩌다 여기까지 (맥락)

1. 원래 방향(확정했던 것): DETAIL_LOCATION을 **구 55개로 정리**(관광지·동 삭제 → REGION 이관), REGION 스팟 노출은 **legal(법정동) 기반**으로 전환(= Idea 2 / T2 원복, 사인오프 완료).
2. 그러다 **CITY 레벨 비대칭**을 발견: `CITY → REGION → 구(DETAIL_LOCATION) → 동(LEGAL)` 4계층은 **광역시에만** 성립. 일반시(강릉시·구리시)는 시 아래 구가 없어 **DETAIL_LOCATION이 빈다**.
   - 광역시: 서울시 → 강남구 → 역삼동 ✅
   - 일반시: 구리시 → (구 없음) → 갈매동 ← DETAIL_LOCATION 자리 없음
3. → "그럴 거면 CITY·DETAIL_LOCATION 체계를 두지 말고 **legal_location만 쓰면?**" 아이디어 제기.

## 3. 갈림길

| | **Path 1 — 유지·정리** (기존 계획) | **Path 2 — DETAIL_LOCATION 폐지** (검토) |
|---|---|---|
| 구/동 | category(구 55)로 정리·유지 | **legal에서 도출** (구 category 없앰) |
| CITY | 시/군 그대로 | 큐레이션 레이어로 유지 (legal에 키잉) |
| REGION | 구 연결 + 법정동 선택 | **법정동 선택** (구는 legal 시군구 코드로 일괄) |
| 스팟 노출 | legal 기반 (이미 결정) | legal 기반 (동일) |
| 일반시 비대칭 | 잔존(3계층 예외) | **해소** (전국 동일 legal 계층) |
| 장점 | 점진적, 기존 FE/BE 유지 | 모델 깨끗, 유지 대상↓, 중복·고아·잡값 원천 차단 |
| 단점 | 구 category 계속 관리, 비대칭 잔존 | 구/동 읽는 FE/BE 전부 legal 도출로 이전 + i18n·잡값·no-legal 처리 |

## 4. Path 2 상세 (추천 후보)

**역할 3분할**
- **지리(동·구·시·도)** = 🤖 자동. 스팟의 `legal_code`에서 도출 → `LEGAL_LOCATION`.
- **여행 도시** = 🙋 사람. "서울·부산·강릉을 여행지로 노출" 큐레이션 → `CITY`.
- **인지 구역** = 🙋 사람. "명동·강남·홍대" 묶음 → `REGION`.
- **DETAIL_LOCATION(구) = 은퇴** (지리에서 자동 도출되므로).

**REGION 생성 흐름 (기존 설계와 호환)**
```
① CITY 선택            예: 서울시
② 구(시군구) 선택       예: 강남구+서초구  ← legal 시군구 코드, 그 구의 법정동 일괄 포함
③ (선택) 법정동 좁히기   예: 성수 = 성동구 → 성수동1·2가만
④ 테마 생성 + 예약 카테고리(MAIN_RESERVATION) 연결
```
- 유저 페이지: 테마별 스팟 = **REGION의 선택 법정동에 `spot.legal_code`가 속한 스팟** ∩ 테마 카테고리. (기존 "REGION의 DETAIL_LOCATION 스팟 ∩ 테마"와 결과 동일, 구 태그 대신 legal)
- ②의 "구"는 category가 아니라 legal 시군구 코드 → 구 카테고리 관리 불필요. 구 일괄 + 법정동 세부 모두 커버.
- 스팟 카드 라벨 "{도시} {구}"의 구는 legal에서 도출.
