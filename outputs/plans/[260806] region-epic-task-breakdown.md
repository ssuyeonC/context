> 🧭 **마스터 [260701] region-domain-improvement-master.md §6(로드맵)의 실행 구조 스포크** — Jira 티켓 구조(에픽 1 + 태스크 7)와 태스크 간 실행 순서·의존성을 소유한다. 각 태스크의 **상세 요구사항(FE/BE)은 기존 스포크가 정본**(한 사실 한 곳): CITY/DL 정합·스팟 재태깅=`[260701]`, REGION 트랙=`[260715]`, 데이터 초안·이관=`[260730]`, 블로그류=`[260730] blog-userblog-academy-region-label`.

## 왜 재편하나

기존 3 Epic은 **도메인별로 세로 분할**(CITY/DL·REGION·블로그)돼 있어, 실제 개발이 따라야 할 **가로 실행 순서**가 티켓 구조에 드러나지 않는다. 특히 유실 방지의 핵심 게이트 두 개 —
- 관광지 스팟 재태깅은 **REGION 표기 격상 이후**라야 '서울 홍대'가 유지됨
- 관광지 DL 삭제는 **스팟 재태깅 + 블로그류 재연결 이후**라야 표기가 안 깨짐

— 가 티켓 사이 **역방향 의존**으로 숨어(예: COM-2559의 마지막 DL 삭제가 다운스트림 COM-2567에 의존), 티켓만 보면 순서를 착각해 **표기 유실 버그**가 날 수 있다. → 하나의 순차 흐름을 **7개 태스크로 쪼개고 blocked-by 링크로 순서를 강제**한다.

## 실행 순서·의존성 (blocked-by 강제)

```
T1 ──▶ T2 ──▶ T3 ──▶ T4 ──┬─▶ T5 ──┐
(정합)  (picker) (REGION) (표기)  │        ├─▶ T7 (DL 삭제)
                                 └─▶ T6 ──┘
```
