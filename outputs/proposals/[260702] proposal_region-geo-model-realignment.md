# 지역 도메인 지리 체계 재정비 제안

작성일: 2026-07-02 · 갱신: 2026-07-08
상태: ✅ 승인 완료 — 2026-07-08 공유 후 이해관계자 전원 동의
관련 문서: `outputs/plans/[260701] region-geo-model-decision.md` (§0 확정 구조 · §2-4 실측) · `outputs/plans/[260701] region-domain-improvement-master.md`

### 왜 이게 문제인가?

- 스팟에 붙는 '도시'와 '상세지역'은 하나의 기준으로 정렬돼 있지 않음
    - **레벨이 뒤섞여있음**
        - 광역시는 '서울시'가 최상위인데, 일반 도(경기, 강원 등)에서는 '강릉시·의왕시' 같은 시가 최상위 도시로 들어가 있음
        - 같은 '도시' 칸에 시도급과 시급이 섞여 있어, "이 스팟이 어디에 있다"를 일관된 기준으로 말할 수 없음
    - **안 쓰이는 값(평양 등)이 섞여 있음**
    - **상세지역의 66%가 상위 도시 없는 고아이고, 관광지·동·행정구가 한 바구니에 섞여 있음**
        - 명동·홍대 같은 관광지와 강남구 같은 행정구가 같은 레벨에 있어 분류 상 일관성이 없음
- 이 상태는 두 문제를 야기함
    1. 사용자에게 보이는 지역 표기가 들쭉날쭉하다. (어떤 스팟은 '강릉시', 어떤 스팟은 '서울시 강남구')
    2. 진행 중인 지역(REGION) 페이지 개편이 이 분류 위에 서는데, 토대가 일관적이지 않아 구조를 맞추기 어려움

### 해결 방향

도시·상세지역·동을 정부 법정동 체계의 3레벨(시도 / 시군구 / 읍면동)에 그대로 정렬

- **도시(CITY) = 시도** (경기도, 서울특별시 등)
    - 법정동 최상위에서 생성하고, '한국' 같은 전국값은 자유 입력으로 유지
    - LEGAL_LOCATION 테이블의 level 1에 해당하는 값
- **상세지역(DETAIL_LOCATION) = 시군구** (성남시 분당구·강남구)
    - 법정동에서 선택해 생성, 이름은 다국어 자유 입력, 하위 동은 코드로 자동 연결
    - LEGAL_LOCATION 테이블의 level 2에 해당하는 값

### 어떤 사용자에게 영향이 있을까?

- **지역으로 여행 정보를 탐색하는 유저 (간접·핵심 수혜자)**
    - 지역 도메인 개선 참고
- **모든 스팟을 보는 유저 (직접 영향)** — 스팟 카드의 지역 표기가 바뀜
    - 광역시 스팟(약 5,049개): '서울시' → '서울특별시' 수준으로 사실상 동일
    - 도 소속 스팟(약 1,238개, 전체의 19%): '강릉시' → '강원특별자치도 강릉시'

### 가설적 임팩트?

이 작업은 직접적인 유입·전환 지표를 겨냥한 성장을 위한 작업이 아님. 지역 개편에 대한 토대 정비로, 기대 효과는 다음과 같음

- **일관성 회복** — 전 스팟이 동일한 기준(시도 / 시군구 / 동)의 지역 표기를 갖는다.
- **개편 잠금 해제** — 지역(REGION) 페이지 개편이 신뢰 가능한 분류 위에 설 수 있다.

### 구체적 실행 계획 / 논의할 아젠다

**실행 개요**

- **정비 원칙 = LEGAL 정합·비파괴** (2026-07-06): 링크 있는 카테고리는 삭제하지 않고(레벨 어긋나면 코드 보존 재타입), **LEGAL의 해당 레벨 값이 없을 때만 생성**(있으면 재사용), **완전 무연결 값만 제거**('한국' 유지). CITY = LEGAL L1(시도) 전량 확보(광역시·특별시는 기존 재사용, 없는 시도만 생성), DL = LEGAL L2(시군구) 전량 확보. 기존 시/군 CITY(강릉시 등)는 **DL로 재타입**되고 그 CITY는 소속 시도(강원특별자치도)가 대신한다.
- 관광지·동 상세지역(명동·홍대 등)은 **즉시 삭제하지 않는다.** 정비~대응 REGION 추가 사이 기간에도 관광지명으로 스팟을 찾는 유저가 있어, 미리 지우면 탐색이 끊기기 때문(**유저 무중단**). 순서는 **REGION 생성이 관광지 링크 제거보다 앞선다**: 대응 지역(REGION) 생성(구 연결 + 법정동 선택) → cutover(스팟 링크 소속 구로 정리 + blog·어학당 소속 구 이관) → 삭제(**REGION 이관 트랙, 후속**).
- 스팟은 이미 가진 법정동 코드(legal_location)로 도시·상세지역을 **자동 재태깅**(약 6,287개). 코드 없는 159개는 예외 처리
- 개편 후 스팟의 도시·상세지역은 좌표로 연결된 legal_location에서 **자동 도출·연결**되며, 관리자가 드롭다운으로 직접 수정 가능
- 블로그(약 1만 링크)·어학당(56개)은 법정동 코드가 없지만, 기존 카테고리 코드를 보존(재타입)하므로 링크 재작업이 사실상 없다
- 최초 정비는 스크립트로 일괄 시딩, 이후 신규 지역은 운영자가 화면에서 생성
- 되돌리기 부담이 있는 일괄 변경이므로 **표본 검수·승인 후 실행.** 스크립트 런타임 자체는 분 단위
- LEGAL_LOCATION의 level 1에 해당하지 않는 값 중 CITY에 있는 값들(한국, 타이페이, 평양 등) 처리
    - **평양(북한) 제거 / 나머지 유지** — 한국·타이페이·대만 등은 미운영이나 스팟 연결이 있고 향후 쓰일 수 있어 자유 입력 값으로 유지

### 기획 프레임 자문 (자가 점검용 · 공유 대상 아님)

- **Q1. 이 가치를 이렇게 해야만 구현할 수 있을까?** — *How (수단의 필연성)*
  - 법정동 정렬이 유일하게 지속가능한 경로다. "현행 시/군 도시 유지 + 구 손수 관리"는 레벨 비대칭이 남고 행정 변경마다 다시 썩는다. "상세지역 폐지, 법정동만 사용"은 스팟 라벨·15개 어권 이름을 담을 곳이 없다. 법정동에 정렬하되 상세지역을 라벨·번역 그릇으로 남기는 절충이 손수 매핑을 0으로 만들면서 표기·번역을 지키는 유일한 길이다.
  - 선결 조건 주의: "도시를 시도로 올리는 것"은 개편의 필수 선결조건은 아니다(개편 자체는 현행 레벨로도 가능). 표기에 새어 나오는 결함 정비 차원에서 함께 하는 판단임을 명시.
- **Q2. 이 수단이 닿는 대상이 처음 정의한 타깃과 정확히 같은가?** — *Who (타깃 정합성)*
  - 다르다. 목적의 타깃은 '지역 탐색 유저'지만 수단이 닿는 대상은 전 스팟·블로그 표기로 더 넓다. 성장 레버가 아닌 **결함 정비**라 넓은 대상이 정당하며, 체감 대상(도 소속 스팟 1,238·블로그 650)을 분리해 규모를 드러냈다.
- **Q3. 이 수단이 없어도, 의도한 변화는 지금 얼마나 일어나고 있는가?** — *How much (베이스라인 증분)*
  - 지표: 지역 페이지 유입 비중 · 평균 체류시간
  - 자연 수준(베이스라인): 트래픽 **3.8%** · 체류 **11초** · 전환 5%
  - 이 수단의 증분 가설: **직접 증분 0.** 본 정비는 토대이며 위 지표의 증분은 그 위에 올라가는 지역 개편이 만든다. 실질 증분은 "표기 일관화 + 지역 값 손수 관리 0 + 개편 잠금 해제"라는 정성 효과. (성장 수치를 본 작업에 귀속시키지 않음.)
