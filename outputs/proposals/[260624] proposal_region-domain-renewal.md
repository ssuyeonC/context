# 지역 도메인 리뉴얼 제안

### 왜 이게 문제라고 생각했는가?

- 한국 여행자의 외부 담론을 보면 **'지역'이 가장 큰 관심 축**이다. r/koreatravel 분석에서 목적지(지역) 주제가 전체의 **55.5%**를 차지했고, 지역 글의 89%가 질문형이었다.
    - 그런데 정작 우리 **지역 페이지는 전체 스팟 리스트 트래픽의 3.8%**밖에 받지 못한다.
    - 들어온 유저도 **평균 11초** 만에 이탈한다 (스팟 리스트 49초의 22% 수준). 사실상 랜딩하자마자 떠난다.
    - 즉 **수요는 거대한데(55%) 우리 페이지가 그걸 못 받고 있다(3.8%).** 이 격차 자체가 문제이자 기회의 크기다.
- 페이지가 유저의 질문에 답하지 못한다.
    - 현재 지역 페이지는 같은 스팟 묶음을 **'추천 / 최신 / 인기'처럼 신선도·인기 기준으로만** 반복해서 보여준다.
    - 유저가 실제로 원하는 **'무엇을 볼까(볼거리)·어떻게 갈까(교통)·며칠씩 나눌까(다도시)'** 같은 의도 단위의 묶음이 없다.
- 지역 관련 개념과 데이터가 정리되지 않아 운영이 어렵다. *(유저 페이지 개선과 더불어 이 작업의 또 다른 핵심 목적)*
    - '지역'을 다루는 개념이 **네 가지(도시 CITY · 상세지역 DETAIL_LOCATION · 지역 REGION · 법정지역 LEGAL_LOCATION)**인데, **서로의 관계와 역할이 명확히 정의돼 있지 않다.** (예: '홍대' 지역이 '홍대' 상세지역을 갖는 식으로 단위가 겹친다)
    - 게다가 이 도메인은 **만들어진 뒤 거의 관리되지 않았다** — 지역 데이터 514개 중 **공개는 13개뿐**이고, 대부분 자동 생성된 뒤 방치됐다.
    - → 운영자는 "무엇이 어떤 단위인지" 헷갈리는 **운영 인지부담**을 떠안는다. 이번 작업은 유저 페이지 개선만이 아니라, **이 네 개념의 관계를 정립하고 데이터를 정비**해 운영 혼란을 줄이는 데에도 큰 의의가 있다.
- **'구역·도시·테마' 검색 수요는 큰데 그걸 받을 페이지가 거의 없다 (SEO).**
    - **도시·구역 키워드** — 구글 키워드플래너(전 세계 인바운드 기준) 기준 **things to do in seoul** 월 1만~10만(→ `/지역/서울`), **gangnam·hongdae·myeongdong·itaewon** 각 월 **1만~10만**(→ `/지역/서울/{구역}`)이 대형 수요인데, 지금은 **공개 구역 페이지가 13개뿐**이라 거의 못 받는다.
    - 특히 **구역 키워드가 행정구를 10~100배 압도**한다. (gangnam 1만~10만 vs gangnam-gu 1천~1만 / 홍대 1만~10만 vs mapo-gu 100~1천 — Reddit·내부 SEO 테이블·키워드플래너 3중 교차검증) → 인지 구역을 제대로 된 페이지로 갖추는 직접적 근거.
    - **도시 × 테마 키워드**(seoul restaurants·seoul cafe 각 월 1만~10만, cafe는 +900% 급상승)**도 전용 테마 페이지로 직접 포획한다.** 테마 섹션의 '더보기'를 일반 스팟 리스트가 아니라 **`/지역/서울/restaurants`(도시×테마)·`/지역/서울/강남/restaurants`(구역×테마) 같은 전용 페이지**로 보내고, 그 페이지가 해당 테마 스팟을 카드로 모아 검색 유입을 받는다.
    - 단, **thin·중복 페이지는 오히려 SEO에 독**이므로 — 스팟 수가 임계 미만인 테마 페이지는 만들지 않고, 중복 노출(리스트 필터뷰)은 정본(canonical)으로 정리하는 — **가드레일을 전제로 한다.** ('월 50만을 전부 받는다'가 아니라 가드레일로 거른 만큼.) (내부 SEO 키워드 테이블은 `country=Korea`라 보수적으로 잡힘)

### 어떤 사용자에게 영향이 있을까?

- **'지역'을 탐색의 맥락으로 가진 유저**
    - "서울 어디를 가지", "강남에는 뭐가 있지", "서울이랑 부산을 며칠씩 나눌까"처럼 **지역을 좌표로 두고 명소·이동·일정을 얹어 최적화**하려는 한국 여행 계획자.
- **외부(구글·Reddit 등)에서 지역 키워드로 들어오는 유저**
    - 지역 페이지가 검색 유입의 랜딩이 되는 만큼, 첫인상이 곧 이탈·체류를 가른다.
- **다도시 여행을 계획하는 유저**
    - 외부 담론에서 다도시 비교가 27%를 차지할 만큼, '서울+부산+제주를 어떻게 쪼갤지'를 고민하는 사람.
    - 단, 부산·제주 지역 콘텐츠가 비어 있어 **단기에는 서울 중심 유저에게 먼저 가치가 닿고**, 다도시 타깃 전체로는 콘텐츠 확충 이후 확장된다.
- **지역 데이터를 관리하는 운영자 (내부)**
    - 네 개념(CITY·DETAIL_LOCATION·REGION·LEGAL_LOCATION)의 관계가 불명확하고 데이터가 방치돼 관리가 어려웠는데, 관계 정립·데이터 정비로 **운영 인지부담이 줄어든다.**

### 가설적 임팩트?

- **베이스라인 (현재 자연 수준)**
    - 지역 페이지 트래픽 점유: **약 3.8%** (스팟 리스트 대비)
    - 지역 페이지 평균 참여시간: **약 11초**
    - 지역 페이지 → 스팟 이동률: **약 5%** (들어온 소수는 전환됨)
- **잠재 SEO 수요 (애드레서블 — 키워드 리서치 추정)**
    - 한국 지역/도시/구역 키워드의 월 추정 검색량 합 **약 50만** (서울 ~36만 · 제주 ~6.2만 · 부산 ~4.7만 · 구역(강남·홍대·명동 등) ~3만).
    - 이 구조는 **도시·구역·테마 키워드를 각각 전용 페이지로 직접 받는다**(도시/구역 페이지 + 테마 leaf 페이지). 지금은 공개 구역 페이지가 13개뿐이라 거의 미수취 상태이고, 구조가 생기면 유입으로 전환할 여지가 생긴다. (단 thin·중복 가드레일로 거른 만큼 — 무한정 다 받는 게 아니다.)
    - **구글 키워드플래너로 교차검증**해도 방향이 일치하며(핵심 키워드 월 1만~10만 버킷), **도시 우선순위도 데이터로 드러난다**: things to do in seoul(월 1만~10만) ≫ busan·jeju(1천~1만) ≫ gyeongju·incheon(100~1천). → 콘텐츠 구축은 **서울 우선**.
    - *(주의: 내부 테이블은 SEO 도구의 추정 검색량·시드 기반 부분집합이고, 키워드플래너는 넓은 범위 버킷이다. 두 소스 모두 절대 정밀값이 아니라 자릿수·상대 비교 용도다.)*
- **1차 목표 (두 축)**
    - **유입**: '지역'을 독립 경로로 재구성하고 내부를 지역 탐색 맥락에 맞게 재편해, 지역 탐색 의도 유저를 페이지로 끌어온다 → **지역 도메인 트래픽 점유 3.8% → 상향.**
    - **활성화**: 첫 화면에서 유저 질문(인지 구역·이동·테마)에 답해 **참여시간 11초 이탈을 차단하고 체류를 늘린다.**
    - **가드레일**: 스팟 이동률 **5%는 유지** — 개선이 전환을 해치지 않도록.
- **증분 가설**
    - 현재 3.8%에 들어오는 유저는 이미 지역 의도를 가진 사람들이다. 따라서 **활성화(체류) 개선만으로는 모수가 작아 천장이 낮다.**
    - 의미 있는 규모가 되려면 **유입(메인·스팟 리스트에서 '지역으로 둘러보기' 동선 연결)이 함께 가야** 한다. 활성화 개선을 먼저 검증한 뒤 유입을 연다.
    - 구체 증분 수치는 1차 출시 후 측정으로 확정한다. (TBD)

### 해결 방법 논의 및 실행

1. **'지역'을 독립된 탐색 경로로 재구성한다**
    - 유저는 **도시 → 도시 상세 → 구역 상세**의 3단으로 지역을 탐색한다.
        - 지역 메인에서 한국 지도와 **도시(서울·부산·제주·경주 등)**를 고른다.
        - 도시 상세에서 그 도시의 **구역 목록과 도시 간 이동 정보**를 본다.
        - 구역 상세에서 그 구역의 **스팟·테마·블로그**를 본다.
    - 첫 화면에 유저 질문의 답(인지 구역·이동·테마)을 끌어올려, 11초 이탈을 직접 공략한다.
2. **'지역'을 여행객이 인지하는 '구역'으로 재정의한다**
    - 지역을 행정 폴리곤에 묶지 않고, **여행자가 한 덩어리로 인지하는 구역**으로 다시 정의한다.
        - 예: **'강남'** 구역 = 강남구 + 서초구를 묶은 것. **'홍대'** 구역 = 마포구 + 서대문구.
    - 구역 상세 페이지에는 그 구역에 묶인 지역들에 연결된 스팟이 노출된다.
    - 행정 경계를 넘나드는 '인지 단위'로 묶이므로, 유저의 머릿속 단위와 노출 단위가 일치한다.
3. **도시 간 이동 정보를 제공한다**
    - 도시 카드·도시 상세에서 **"서울에서 가는 방법"**을 보여준다. (예: **서울↔부산 KTX 약 2시간 40분**, **서울↔제주 항공 약 1시간 10분**)
    - 다도시 여행자의 1순위 질문("어떻게·얼마나 걸려 가나")에 먼저 답한다.
4. **콘텐츠를 '테마' 단위로 재편하고, 운영자가 편성한다**
    - 구역 상세에서 스팟을 **신선도·인기 대신 의도(테마) 기준**으로 묶어 보여준다. (예: **볼거리·체험 / 미식 / 쇼핑 / K-뷰티 / 근교**)
    - 운영자는 구역별로 **테마 섹션을 직접 만들고**(섹션 이름 + 묶을 카테고리 + 노출 순서), 도시별 성격에 맞게 편성한다.
    - 각 테마의 **'더보기'**는 **전용 테마 페이지로 연결**한다. 예: **`/지역/서울/강남/restaurants`**(구역×테마)·**`/지역/서울/restaurants`**(도시×테마, 더 큰 키워드). 지역 페이지와 유사한 카드 레이아웃에, 타이틀은 **'seoul gangnam restaurants'** 식으로 잡고 그 테마(카테고리)에 해당하는 스팟을 모두 카드로 노출해 **검색 유입을 받는 랜딩**이 된다.
    - 단, **스팟이 너무 적은 테마 페이지는 만들지 않고(thin 방지), 같은 키워드의 중복 노출은 정본(canonical) 한 곳으로 정리**한다.
5. **도시 페이지는 소속 구역을 모아 보여준다**
    - 도시 페이지는 별도 콘텐츠를 따로 만들지 않고, **소속 구역들의 스팟·블로그를 지역 구분 없이 테마 기준으로 묶어** 보여준다.
    - 운영자는 도시 편집 화면에서 **소속 구역들의 테마를 대표 테마로 묶어** 도시 단위 보기를 구성한다.
6. **운영자가 지역을 관리할 수 있는 도구를 제공한다**
    - 운영자는 지역 관리 화면에서 **도시와 구역을 각각 관리**한다.
    - 도시는 **대표 이미지·태그·설명을 입력하고, 구역을 한 개 이상 연결해야 '활성화'**된다. (필수값이 비면 공개되지 않는다)
    - 구역은 **인지 구역 단위로 지역(상세지역)들을 묶어** 만든다.
7. **선행 데이터 정비와 배포 순서**
    - 인지 구역으로 묶기 전에, **연결이 없는·중복된 지역 데이터를 정리**하고, 관리되지 않은 비공개 지역 데이터를 정돈한다.
    - 스팟이 인지 구역에서 누락되지 않도록, **스팟에 행정구 단위 지역을 함께 태깅**한다. (이는 '스팟에 상세지역 2개까지 연결' 작업이 선행되어야 한다 — 별도 진행 중)
    - **운영자가 어드민에서 데이터를 먼저 채우고, 유저 페이지 공개는 데이터 생성이 끝난 뒤 일정을 잡는다.**

### 기획 프레임 자문 (필수)
> 참고: `.context/templates/planning-frame.md` — How/Who/How much 세 축

- **Q1. 이 가치를 이렇게 해야만 구현할 수 있을까?** — *How* (수단의 필연성 / 대체 수단 탐색)
  - 답: 대안을 따져봤다. ① **기존 행정코드 기반 스팟 수집을 유지한 채 콘텐츠만 보강**하는 길은, 네 개념(CITY·DETAIL_LOCATION·REGION·LEGAL_LOCATION)의 관계 미정립·데이터 방치가 그대로 남고 스팟 적합도(거친 법정코드 기반)도 낮아 근본 문제를 못 푼다. ② **별도 지역 페이지 없이 스팟 리스트에 모두 흡수**하는 길은 지역·구역 단위 SEO 자산과 URL을 잃는다. 그래서 **'인지 구역(REGION)을 운영 분류(상세지역)로 묶어 재정의 + 4개 개념 관계 정립'**하는 것이, 유저 수요와 운영 정합을 동시에 만족시키는 경로다. 더해, **테마 검색 수요(seoul restaurants 등)는 전용 테마 페이지를 신설해 직접 포획**하되, 'thin·중복 페이지가 오히려 SEO를 깎는다'는 선결 함정은 **콘텐츠 임계·canonical 가드레일**로 막는다.
- **Q2. 이 수단이 닿는 대상이 내가 처음 정의한 타깃과 정확히 같은가?** — *Who* (타깃 정합성)
  - 답: 목적의 타깃(= '지역'을 탐색 맥락으로 가진 유저)과 수단이 닿는 대상(= 새 지역 경로·구역 페이지를 보는 유저)은 같다. **다만 부산·제주 구역 콘텐츠 공백 때문에 단기 수단은 서울 중심 유저에게 먼저 닿는다.** 따라서 다도시 타깃 전체를 단기에 다 만족시킨다고 보지 않고, **단기는 서울 인지구역 재구성으로, 중기는 부산·제주 콘텐츠 확충으로** 타깃을 단계적으로 넓힌다.
- **Q3. 이 수단이 없어도, 의도한 변화는 지금 얼마나 일어나고 있는가?** — *How much* (베이스라인 증분)
  - 지표: **유입**(지역 도메인 트래픽 점유) + **활성화**(지역 페이지 참여시간·이탈률). 가드레일 = 스팟 이동률.
  - 자연 수준 (베이스라인): 트래픽 점유 **약 3.8%** / 참여시간 **약 11초** / 스팟 이동률 **약 5%**.
  - 이 수단의 증분 가설: 현재 3.8%로 들어오는 유저는 **이미 지역 의도를 가진 사람들**이라, 활성화(체류) 개선만으로는 모수가 작아 천장이 낮다. 의미 있는 증분은 **유입 동선(메인·리스트 → 지역)이 결합**될 때 생긴다. 활성화 개선을 먼저 검증하고 유입을 여는 순서로 간다. 구체 증분 수치는 1차 출시 후 측정으로 확정한다. (TBD)
