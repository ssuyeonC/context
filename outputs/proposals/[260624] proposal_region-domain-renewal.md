# 지역 도메인 리뉴얼 제안

> ⛔ **SUPERSEDED · 아카이브** — 최신 정본은 마스터 `[260701] region-domain-improvement-master.md`. 이 제안서는 **최초 개념 재정의 기록용**(수정 금지, 역사 참고).

> ⚠️ **개념 구조 갱신됨 (2026-07-06)** — 아래 §"실행 계획 / 논의할 아젠다"의 개념 정의·카디널리티는 초기안이며, 이후 `[260701] region-geo-model-decision.md` §0·§0-3으로 **재정렬**됐다. 최신 확정: **CITY = 시도(L1, 서울특별시·강원특별자치도)** · **DETAIL_LOCATION = 시군구(L2, 강남구·강릉시 — LEGAL 참조)** · **REGION = 큐레이션 인지구역**(CITY 1개 아래 DL 묶음 + 하위 법정동 선택). 따라서 본문의 "CITY=서울시/부산시(시급)"·"REGION이 DL의 상위"·"DETAIL_LOCATION:LEGAL = 1:1" 서술은 최신 문서 기준으로 읽는다(강릉시는 DL, 그 CITY는 강원특별자치도). 정비는 **LEGAL 정합·비파괴**(없는 값만 생성·완전 무연결만 제거·관광지 DL 삭제는 REGION 트랙 후속).

### 왜 이게 문제인가?

- 한국 여행자의 외부 담론을 보면 '지역'이 가장 큰 관심 축 중 하나로 보임
    - 레딧 한국여행 관련 서브레딧(r/koreatravel) 최근 게시물 10,000건 분석에서 목적지(지역) 주제가 전체의 55.5%를 차지했고, 지역 글의 89%가 질문형
        - 그러나 크리에이트립 지역 페이지는 스팟 리스트 트래픽의 3.8%만 꽂히고 있음
        - 들어온 유저도 평균 11초 만에 이탈 (스팟 리스트 49초의 22% 수준으로, 사실상 랜딩하자마자 이탈)
    - 즉 수요는 거대한데(55%) 우리 페이지가 그걸 못 받고 있음(3.8%) ⇒ 이 격차 자체가 문제이자 기회의 크기
- 페이지가 유저의 질문에 답하지 못함
    - 현재 지역 페이지는 같은 스팟 묶음을 '추천 / 최신 / 인기'처럼 신선도·인기 기준으로만 반복해서 보여줌
    - 유저가 실제로 원하는 '무엇을 볼까(볼거리)·어떻게 갈까(교통)·며칠씩 나눌까(다도시)' 같은 의도 단위의 묶음이 없음
- 지역 관련 개념과 데이터가 정리되지 않아 운영이 어려움
    - '지역'을 다루는 개념 네 가지(도시 CITY · 상세지역 DETAIL_LOCATION · 지역 REGION · 법정지역 LEGAL_LOCATION)가 서로의 관계와 역할이 명확히 정의돼 있지 않음
    - 게다가 이 도메인은 만들어진 뒤 거의 관리되지 않음 — 지역 데이터 514개 중 공개는 13개뿐이고, 대부분 자동 생성된 뒤 방치됨
- '구역·도시·테마' 검색 수요는 큰데 그걸 받을 페이지가 거의 없음 (SEO)
    - 구글 키워드플래너(전 세계 인바운드 기준) 기준 '도시 × 테마'(busan tour, seoul restaurants 등)·'도시 × 구역'(seoul gangnam 등)이 월 1만~10만의 대형 키워드이나, 지금 구조로는 이 수요를 받을 수 없음

### 해결 방향

1. **'지역'을 독립 탐색 경로로 재구성**
    - 유저는 도시 → 도시 상세 → 구역 상세 3단으로 탐색
    - 첫 화면에 인지구역·이동·테마를 끌어올려 11초 이탈을 직접 공략
2. **도시 간 이동 정보 제공**
    - 도시 카드·상세에 "서울에서 가는 방법"(서울↔부산 KTX 2시간 40분 / 서울↔제주 항공 1시간 10분 등)
    - 다도시 1순위 질문에 먼저 답
3. **콘텐츠를 '테마' 단위로 재편(운영자 편성)**
    - 신선도·인기 대신 의도(테마) 기준 묶음(볼거리·미식·쇼핑·K-뷰티·근교 등)
    - 운영자가 구역별 섹션을 직접 편성하고, 큰 테마는 전용 테마 페이지로 SEO 유입까지 확보
4. **도시 페이지 = CITY 스팟을 테마로 집계 (B-2)**
    - 그 도시에 연결된 스팟 전체를 테마 기준으로 뿌림 (B-2 — 완전집합이라 부산·제주 콘텐츠 공백도 해소). 블로그는 소속 구역 기준 별도 집계.

### 어떤 사용자에게 영향이 있을까?

- **'지역'을 탐색의 맥락으로 가진 유저**
    - "서울 어디를 가지", "강남에는 뭐가 있지", "서울이랑 부산을 며칠씩 나눌까"처럼 **지역을 좌표로 두고 명소·이동·일정을 얹어 최적화**하려는 한국 여행 계획자.
- **외부(구글·Reddit 등)에서 지역 키워드로 들어오는 유저**
    - 지역 페이지가 검색 유입의 랜딩이 되는 만큼, 첫인상이 곧 이탈·체류를 가른다.
- **다도시 여행을 계획하는 유저**
    - 외부 담론에서 다도시 비교가 27%를 차지할 만큼, '서울+부산+제주를 어떻게 쪼갤지'를 고민하는 사람.
    - 단, 부산·제주 지역 콘텐츠가 비어 있어 **단기에는 서울 중심 유저에게 먼저 가치가 닿고**, 다도시 타깃 전체로는 콘텐츠 확충 이후 확장된다.

### 가설적 임팩트?

- **베이스라인** (현재 자연 수준)
    - 지역 페이지 트래픽 점유: 약 3.8% (스팟 리스트 대비)
    - 지역 페이지 평균 참여시간: 약 11초
    - 지역 페이지 → 스팟 이동률: 약 5% (들어온 소수는 전환됨)
- **잠재 SEO 수요**
    - 한국 지역/도시/구역 키워드의 월 추정 검색량 합 **약 50만** (서울 ~36만 / 제주 ~6.2만 / 부산 ~4.7만 / 구역(강남·홍대·명동 등) ~3만)
    - 이 구조는 도시·구역·테마 키워드를 각각 전용 페이지로 직접 수용(도시/구역 페이지 + 도시/테마 페이지)
        - 지금은 공개 구역 페이지가 13개뿐이라 거의 미수취 상태이고, 구조가 생기면 유입으로 전환할 여지가 생김
- **1차 목표**
    - **유입** — '지역'을 독립 경로로 재구성하고 내부를 지역 탐색 맥락에 맞게 재편해, 지역 탐색 의도 유저를 페이지로 유치 → 지역 도메인 트래픽 점유 3.8% → 상향
    - **활성화** — 첫 화면에서 유저 질문(인지 구역·이동·테마)에 답해 참여시간 11초 이탈을 차단하고 체류를 늘림
- **기타**
    - 현재 3.8%에 들어오는 유저는 이미 지역 의도를 가진 사람이므로, 활성화(체류) 개선만으로는 모수가 작아 임팩트가 제한적
    - 의미 있는 규모가 되려면 유입(메인·스팟 리스트에서 '지역으로 둘러보기' 동선 연결)이 함께 진행 필요

### 구체적 실행 계획 / 논의할 아젠다

1. **선행 — 지역 개념 관계 정립 + 데이터 정비**
    - 인지 구역으로 묶기 전에, 네 개념(CITY·DETAIL_LOCATION·REGION·LEGAL_LOCATION)의 역할을 재정의/분류
        - **CITY** — '지역'의 최상위 개념 (서울시, 부산시, 인천광역시, …)
        - **REGION** — 여행객의 인지 대상이 되는 지역, CITY의 구성요소 (강남, 부산, 경주, 명동, 홍대, 광화문, …)
        - **DETAIL_LOCATION** — 행정구역, REGION의 구성요소 (강남구, 서초구, 해운대구, 마포구, …)
        - 카디널리티: CITY : REGION = 1 : N  /  REGION : DETAIL_LOCATION = 1 : N  /  DETAIL_LOCATION : LEGAL_LOCATION = 1 : 1
    - 네 개념을 **분류 / 콘텐츠 / 기하**로 역할을 갈라 정립
        - **분류 (CITY·DETAIL_LOCATION)** — 스팟이 직접 매달리는 뼈대. "이 스팟은 서울 / 강남구" 같은 꼬리표라, 지역(REGION) 기능과 상관없이 늘 존재한다.
        - **콘텐츠 (REGION)** — 유저에게 보여줄 '인지 구역'. 분류(상세지역) 위에 얹는 큐레이션 단위로, 행정구 상세지역 몇 개를 묶어 만든다 (강남 = 강남구 + 서초구).
        - **기하 (LEGAL_LOCATION)** — 지도에 그릴 경계·좌표. 행정구 상세지역에만 1:1로 붙이고, 구역(REGION)은 자기가 묶은 행정구들의 경계를 합쳐서 자동으로 물려받는다.
        - **지금 문제 → 이렇게 정리** — 현재는 네 개념이 역할 없이 나란히 있어 겹친다 ('홍대' 지역과 '홍대' 상세지역이 같은 이름·단위). 위처럼 분류 / 콘텐츠 / 기하로 역할을 갈라주면 겹침이 사라진다.

    - 불필요하게 만들어진 데이터 정리 (무연결·중복 상세지역, 방치된 비공개 지역 등)
2. **REGION에 '테마' 개념 추가**
    - 정의
        - 유저 의도 단위 묶음(볼거리·미식·쇼핑·K-뷰티 등) — 카테고리를 '테마'라는 대단위로 묶음
        - 운영자가 REGION별로 섹션(이름 + 묶을 카테고리 + 노출 순서)을 직접 편성
    - 근거
        - 지금은 같은 스팟을 '추천·최신·인기'(신선도) 축으로만 반복해, 유저의 '무엇을 볼까·먹을까' 질문에 답 못함
        - 테마(의도) 축을 더해야 질문에 답하고, 이 테마가 곧 **SEO 테마 페이지**(seoul restaurants 등)의 단위가 됨
    - 구조 (참고)

    ```
    /region
    └ /region/{city}                          e.g. /region/seoul
       └ /region/{city}/{region}              e.g. /region/seoul/hongdae
          └ /region/{city}/{region}/{theme}   e.g. /region/seoul/hongdae/tour
       └ /region/{city}/{theme}               e.g. /region/seoul/tour
    ```

### 기획 프레임 자문 (필수)
> 참고: `.context/templates/planning-frame.md` — How/Who/How much 세 축

- **Q1. 이 가치를 이렇게 해야만 구현할 수 있을까?** — *How* (수단의 필연성 / 대체 수단 탐색)
  - 답: 대안을 따져봤다. ① **기존 행정코드 기반 스팟 수집을 유지한 채 콘텐츠만 보강**하는 길은, 네 개념(CITY·DETAIL_LOCATION·REGION·LEGAL_LOCATION)의 관계 미정립·데이터 방치가 그대로 남고 스팟 적합도(거친 법정코드 기반)도 낮아 근본 문제를 못 푼다. ② **별도 지역 페이지 없이 스팟 리스트에 모두 흡수**하는 길은 지역·구역 단위 SEO 자산과 URL을 잃는다. 그래서 **'인지 구역(REGION)을 운영 분류(상세지역)로 묶어 재정의 + 4개 개념 관계 정립'**하는 것이, 유저 수요와 운영 정합을 동시에 만족시키는 경로다. 더해, **테마 검색 수요(seoul restaurants 등)는 전용 테마 페이지를 신설해 직접 포획**하되, 'thin·중복 페이지가 오히려 SEO를 깎는다'는 선결 함정은 **콘텐츠 임계·canonical 가드레일**로 막는다.
- **Q2. 이 수단이 닿는 대상이 내가 처음 정의한 타깃과 정확히 같은가?** — *Who* (타깃 정합성)
  - 답: 목적의 타깃(= '지역'을 탐색 맥락으로 가진 유저)과 수단이 닿는 대상(= 새 지역 경로·구역 페이지를 보는 유저)은 같다. **다만 부산·제주 구역 콘텐츠 공백 때문에 단기 수단은 서울 중심 유저에게 먼저 닿는다.** 따라서 다도시 타깃 전체를 단기에 다 만족시킨다고 보지 않고, **단기는 서울 인지구역 재구성으로, 중기는 부산·제주 콘텐츠 확충으로** 타깃을 단계적으로 넓힌다.
- **Q3. 이 수단이 없어도, 의도한 변화는 지금 얼마나 일어나고 있는가?** — *How much* (베이스라인 증분)
  - 지표: **유입**(지역 도메인 트래픽 점유) + **활성화**(지역 페이지 참여시간·이탈률). 가드레일 = 스팟 이동률.
  - 자연 수준 (베이스라인): 트래픽 점유 **약 3.8%** / 참여시간 **약 11초** / 스팟 이동률 **약 5%**.
  - 이 수단의 증분 가설: 현재 3.8%로 들어오는 유저는 **이미 지역 의도를 가진 사람들**이라, 활성화(체류) 개선만으로는 모수가 작아 천장이 낮다. 의미 있는 증분은 **유입 동선(메인·리스트 → 지역)이 결합**될 때 생긴다. 활성화 개선을 먼저 검증하고 유입을 여는 순서로 간다. 구체 증분 수치는 1차 출시 후 측정으로 확정한다. (TBD)
