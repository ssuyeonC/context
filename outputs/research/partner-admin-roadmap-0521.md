## 0. 프레이밍

### 0.1 목표 재정의
- **목표는 제휴팀 워크로드 감소가 아니라 시간 재배분**: 반응형 트랜잭션 처리 → 관계·전략·영업으로
- 카톡 = **비상연락망**으로 자리잡으면, 카톡에 흐르는 대화는 자연스럽게 사업 성장 관련 대화로 바뀜
- 어드민 = **일상적·주기적 업무의 1순위 채널**

### 0.2 채널 분리 원칙

| 구분 | 채널 | 어떤 작업 |
|------|------|---------|
| **일상·주기** | 어드민 | 예약 확인/확정/취소, 스케줄, 가격·메뉴, 콘텐츠, 고객 메시지, 리뷰 응대, 정산 |
| **비일상·예외** | 카톡 | 신규 상품 등록, 분쟁/이슈, 비즈니스 전략·이벤트 제안, 시스템 장애, 권한·계약 |

→ 모든 P0~P4 항목은 **"일상/주기 작업을 어드민으로 흡수"** 라는 단일 기준으로 평가

### 0.3 2개 워크스트림 동시 진행 (필수)

| 트랙 | 책임 | 목적 |
|------|------|------|
| **A. 어드민 제품 개선** (P0~P4) | 제품·디자인·엔지니어링 | 기능·UX·진행 가시성·모바일 |
| **B. 제휴팀 운영 변화** | 제휴팀·운영 리더십 | 카톡 요청 받았을 때 능동적 리다이렉트, 신규 기능 출시 시 적극 안내(영업) |

→ A만 해서는 트래픽이 옮겨오지 않음. B가 없으면 좋은 어드민도 카톡 우회로 묻힘.

### 0.4 두 종류의 흡수

| 흡수 유형 | 대상 | 예시 |
|---------|------|------|
| **자율 처리 흡수** | 직접 처리 의향 있는 파트너 | 투어스토리 콘텐츠 편집, 모델로 사진 교체, 호수도산 인스타 연동 |
| **요청 채널 흡수** | 직접 처리는 부담스러운 파트너 | 메디큐브 — 어드민으로 요청 → 가시적 진행 상태로 카톡을 대체 |

→ P3 권한 모델은 이 두 갈래를 차등 지원하도록 설계

### 0.5 파트너 본질·페인 매핑 (means-ends chain)

> 종합본 1.5 + 개별 정리본 "파트너가 실제로 겪는 문제" 섹션 cross-reference. 각 P 항목의 출처를 본질 단위로 추적.

| 파트너 | 본질 한 문장 | 가장 강한 P 항목 (개별) | 종합본 인사이트 매핑 |
|--------|------------|----------------|-----------|
| 순시키 | 감당 가능한 인지 부담으로 모든 채널의 예약 직접 통제 | 가용성 통제 / 채널 통합 / 재방문 식별 | 인사이트 5 (CRM) |
| 메디큐브 | 양측 기대가 어긋나지 않도록 정보가 양방향 도달 | 입력 정확성 / 동행 처리 / 다이렉트 메시징 | 인사이트 5 (CRM·메시징) |
| 모델로 | 변화가 잦은 비즈니스가 즉시 반영 + 유연한 구조 | 상품별 스케줄 / 콘텐츠 반영 속도 / 실시간 가시성 | 인사이트 1 (가시성)·6 (자율) |
| 투어스토리 | OTA 표준 자율 권한 + 다스팟·다국어 효율 | 자율 편집 / 검색 / 다국어 / 일괄 처리 | 인사이트 3 (OTA 표준)·6 (자율) |
| 아리한복 | 파워유저 운영 수준에 어드민이 도달, 일상 도구화 우선 | 예약 테이블 UI / 사진 업로드 / 메타 피드백 | 인사이트 7 (파워유저 베이스라인) |
| 호수도산 | 손에서 즉시 통제 + 브랜드 자산 능동 관리 | 모바일 앱 / 다이렉트 메시징+번역 / 리뷰 동선·관리 / SNS 연동 | 인사이트 3 (OTA 격차)·8 (브랜드 자산 운용 도구) |

**해석 가이드**: 단일 P 항목을 출시할 때 어느 파트너의 본질 어디까지를 해소하는지 본질 단위로 역추적 가능. 같은 기능이 여러 본질을 동시에 해결하면 횡단 우선순위가 더 높음 (예: 다이렉트 메시징은 메디큐브·호수도산·순시키 3개 본질에 동시 기여).

## 트랙 B. 제휴팀 운영 변화 (전 기간 병행) ⭐⭐⭐

> 어드민 개선과 **항상 함께** 가야 하는 트랙. 책임은 제휴팀·운영 리더십.

### B-1. 능동적 리다이렉트 운영 (즉시 시작)
- 제휴팀이 카톡 요청을 받았을 때 **"이건 어드민에서 직접 하실 수 있어요"** 안내 → 처리는 일단 도와주되, 다음에는 어드민으로 유도
- 어드민에 같은 기능이 있는데 카톡으로 온 요청 유형을 **태깅·집계** (운영 데이터화)
- 응답 템플릿화 (안내 + 어드민 동선 스크린샷 동봉)

### B-2. 신규 기능 출시 시 적극 안내(영업)
- 어드민에 새 기능이 나오면 **제휴팀이 파트너 1:1로 안내**
- 특히 활용도 높은 파트너(아리한복·순시키)부터 시작 — **얼리어답터 = 디자인 베이스라인 검증자**
  - 아리한복은 본인이 콘텐츠 생산까지 자임하는 파워유저로, 어드민 UI 디테일 페인을 가장 정확히 짚어냄 → 이 파트너에서 통과한 UX는 다른 파트너에게도 매끄럽게 작동할 가능성 ↑ (종합본 인사이트 7)
- 사용 후 후기 받고 가능성 확인되면 다른 파트너에게도 확산

### B-3. 카톡 트래픽 측정·분류 체계
- 일상/주기 vs 비일상/예외로 카톡 요청을 분류 (P0-1 캠페인의 효과 측정 기반)
- 가장 큰 트래픽 유형이 P2~P3 어떤 기능과 연결되는지 매핑 → 기능 우선순위 재조정 인풋

### B-4. 제휴팀 KPI 재정의 (운영 리더십 의사결정)
- 기존: 응대 건수·만족도 등 반응형 지표
- 변경: **카톡 트랜잭션 처리 감소율** + **관계·전략·영업 시간 비중**
- 어드민으로 자율/요청 흡수가 늘면 자연스럽게 KPI 달성되는 구조

## P0 — 즉시 (Q1 ~6주)

### P0-1. 기존 기능 인지·디스커버리 캠페인
**왜**: 알림톡, 리뷰 댓글+자동번역, 직접 취소, 상품별 스케줄, 스팟 정보 수정 요청 — 모두 이미 있는데 모르는 파트너 다수.

**무엇**:
- 어드민 첫 로그인/주기적 인앱 가이드 (사용 안 한 기능 안내)
- "체크리스트" 위젯: 알림톡 ON, 리뷰 댓글 활성화, 직접 취소 권한 확인 등
- 신규 파트너 온보딩 시 카테고리별 권장 기능 세트
- 운영팀이 카톡으로 요청 받았을 때 **"이건 어드민에서 직접 하실 수 있어요" 안내 트리거**

**관련 파트너**: 메디큐브(알림톡·리뷰댓글), 모델로(스케줄·수정요청), 호수도산(직접취소), 순시키(전반)

### P0-2. 버그픽스 (신뢰 회복)
- **모바일 예약 확정 화면 요일 오노출** (메디큐브 — 5/12 토 표시)
- **어드민 사진 수정요청 메뉴의 표시 사진 ≠ 실제 관리 사진** (모델로)
- **예약 캘린더 1년치 오픈 시 기존 차단 타임 초기화** (메디큐브) — 또는 명확한 경고
- **리뷰 작성 알림 누락** (메디큐브)

### P0-3. 알림 누락 점검
- **리뷰 작성 시 파트너 메일 알림 누락 케이스** (메디큐브 인지)
- 알림 발송 신뢰성 점검 + 대시보드로 가시화

## P1 — 단기 (Q1~Q2, 6~12주)

### P1-1. 예약 내역 테이블 리팩토링
**원천**: 아리한복 (구체적 제안)
- 컬럼 단순화: 예약 코드 / 날짜 / 시간 / 이름 / 상태
- **상태 컬러 코딩** + 행별 컬러
- **소팅 기능** 추가
- **상품/이름/날짜 검색** (투어스토리도 강력 요구 — 다스팟에 필수)

### P1-2. 어드민 모바일 사용성 1차 개선 (반응형)
- 모바일 앱(P2)을 만드는 동안 단기 응급조치
- 예약 내역·확정·취소 같은 핵심 액션을 모바일 친화로 재배치
- 순시키/호수도산 요청 1차 대응

### P1-3. 스팟 상세 UI 디테일
**원천**: 아리한복, 메디큐브
- **세로 사진 포맷 지원** + 자동 포맷 조정
- **옵션에 사진 추가**
- **하이라이트 → 리뷰 영역 빠른 이동** 동선
- **상세페이지 강조도 설정** (병원별/파트너별 토글 vs 직노출 선택)

## P2 — 중기 (Q2~Q3, 핵심)

### P2-1. 인앱 다이렉트 메시징 + 자동 번역 ⭐⭐⭐
**원천**: 메디큐브, 호수도산, 순시키 (다수)
**현재 우회**: 왓츠앱, 톡방, CX팀 카톡

**무엇**:
- 어드민에서 고객에게 직접 메시지 발송
- 메시지 입력 시 **파파고/자동 번역** 옵션 (언어 자동 감지)
- 변경/취소 시 사유+메시지 동봉 발송
- 알림톡/메일 동시 전달

**왜 P2 최우선**: 횡단 임팩트 최고. 카톡 우회의 가장 큰 트래픽 흡수.

### P2-2. 모바일 어드민 앱 + 푸시 ⭐⭐⭐
**원천**: 호수도산 (매출 손실 실증), 순시키

**무엇**:
- iOS/Android 네이티브 또는 PWA 수준
- **푸시 알림** — 신규 예약·변경·취소
- 핵심 액션만 (확인/확정/취소/메시지)

**왜 P2**: OTA 표준 격차의 가장 큰 항목. 호수도산은 이미 다른 OTA에 예약을 빼앗기는 중. 다만 비용이 매우 크므로 P2-1과 우선순위 협의 필요.

### P2-3. 수정 요청 진행 가시성
**원천**: 투어스토리 (3개월 대기), 모델로 (1개월 대기)

**무엇**:
- 수정 요청 상태: 받음 → 검토 중 → 반영 완료
- 어드민 화면 + 알림으로 단계별 통보
- 카톡 우회를 어드민으로 끌어오는 핵심 신뢰 회복 장치

### P2-4. 직접 취소 + 메시지 + 번역 (P2-1과 연계)
**원천**: 호수도산 (KKday 표준)
- 취소 사유 선택 + 고객에게 발송할 메시지 (번역 동봉)

### P2-5. 상품/옵션별 스케줄 분리 관리
**원천**: 모델로 (네이버 플레이스 참고)
- 통합 메뉴 → 상품/옵션 단위 ON/OFF
- 상품별/시간대별 실시간 현황 뷰

### P2-6. 리뷰 작성 동선 단순화
**원천**: 호수도산
- 시술 완료 → 푸시 → 즉시 작성
- 파트너 어드민에서 "리뷰 요청" 버튼 → 유저 기기 푸시

## P3 — 중장기 (Q3~Q4, 구조 변경)

### P3-1. 콘텐츠 자율 편집 권한 (파트너 유형별 차등) ⭐
**원천**: 투어스토리(전면 자율 요구), 모델로(사진만), 호수도산(인스타), 메디큐브(부담), 아리한복(의지 X + 본인 생산)

**프레임**: 1차원 스펙트럼이 아니라 **3극 구조** (종합본 2.4)
- **극 1: 부담** — 메디큐브 (자율이 오히려 짐)
- **극 2: 요구** — 투어스토리·모델로·호수도산 (OTA 표준 인용)
- **극 3: 의지 X + 본인이 이미 생산** — 아리한복 (카톡 정착 → 권한 풀어도 즉시 전환 X)

**무엇**:
- **권한 등급제** 도입
  - L1 자율: 가격·일정·콘텐츠 자율 (검수는 가격/썸네일 등 민감 영역만) — 다스팟 검증된 B2B 파트너 (극 2)
  - L2 일부 자율: 사진/SNS만 자율, 텍스트는 검수 — 이미지 중심 카테고리 (극 2)
  - L3 검수 유지: 모두 검수 후 반영 — 의료·언어 민감 (극 1)
- 파트너 신청 + 운영팀 승인 → 등급 이동
- 자율 편집 시 **롤백/이전 버전** 기능 동반 (잘못 수정 부담 완화)

**⚠️ 마이그레이션 동반 필수** (극 3 시사):
- 권한을 풀어도 카톡 우회는 자동 이전되지 않음 (아리한복은 이미 명시적으로 "변화 비용 인식")
- → **B-1 능동적 리다이렉트 + 온보딩 + 1:1 안내**가 권한 부여와 함께 진행되어야 효과 발생
- 검수 분기 모델은 OTA 업계 표준 관행 — 메디큐브·투어스토리 둘 다 정확히 인지하고 있음 → 파트너 커뮤니케이션 시 "민감 영역만 검수 + 나머지 자율" 표현이 신뢰 형성에 유리

### P3-2. CRM·고객 정보 정확성
**원천**: 메디큐브, 순시키
- **여권명 기준 통일** (영문 입력 표준화)
- 전화/이메일 **2회 입력 검증** UX
- SNS ID 공개여부/유효성 입력 단계 안내
- **재방문 고객 자동 표시** (등록번호 기반)
- 신규 정산 시스템 표기와 동일화

### P3-3. 리뷰 시스템 강화
**원천**: 호수도산(적극적 리뷰 관리에 대한 욕구), 메디큐브, 아리한복

**무엇**:
- **비회원 리뷰 작성 허용** (예약 코드 기반)
- **리뷰 작성 알림** 신뢰성
- AI 리뷰 요약 강화 (아리한복 긍정)
- **부정 리뷰 처리·작성자 분쟁 처리** (악플 블러·특정 고객 차단 등)

**⚠️ 정책 텐션 노트** (종합본 2.8):
- 호수도산이 표현한 "적극적 리뷰 관리에 대한 욕구"는 운영자 입장에서 정당한 욕구이나, 부정 리뷰 처리·차단 영역은 **플랫폼 무결성과 텐션**이 있음. 파트너 만족 ↔ 유저 신뢰의 양면.
- 처리 단계 분기:
  - **즉시 추진 가능** (무해): 작성 동선 단순화, 알림 신뢰성, AI 요약, 비회원 작성 허용
  - **정책 프레임 정립 선행 필요**: 악플 처리·작성자 차단 — 정책 가이드라인 수립 후 기능 설계
- KKday의 "리뷰 삭제 가능" 모델을 무비판 답습하지 말고, 크트 자체의 플랫폼 가치관 정립 필요

### P3-4. 동행 예약 처리
**원천**: 메디큐브
- 예약 시 **동행 여부 안내/식별** 정보 추가
- 동일 시간·날짜 다수 예약 = 동행 묶음 표시
- 동행 분산 예약 방지 UX

### P3-5. 다국어 자율 편집 + AI 자동 번역
**원천**: 투어스토리, 모델로
- 자국어 작성 → AI 자동 번역 → 필요 시 수동 보정
- 다국어 일괄 적용

## P4 — 장기 (Q4+, 메타·확장)

> **비전 — 어드민 역할의 확장**: P0~P3이 "운영 효율 도구로서의 어드민"이라면, P4 묶음은 어드민이 **파트너의 마케팅·브랜딩·협업 인프라**로 진화하는 단계 (종합본 인사이트 8, 2.11).
>
> 호수도산이 가장 명확한 신호 — 인스타 연동·이벤트 제안·아카데미 같은 신상품 카테고리를 어드민이 받아내길 기대. 마케팅 욕심 큰 디지털 네이티브 파트너가 늘어날수록 횡단적 욕구가 됨.
>
> P4는 비용 대비 즉시 임팩트는 낮지만, **장기 카테고리 차별화**와 **파트너 락인** 관점에서 로드맵에 명시할 가치가 있음.

### P4-1. 다스팟 운영 도구
**원천**: 투어스토리(50+), 호수도산
- **상품 ID/명 검색** (P1-1과 연계해 즉시 가능)
- **일괄 작업** — 가격 인상·시즌 종료·다건 복사
- 다국어 예약 자동 분류/연동

### P4-2. 인스타그램 직접 연동
**원천**: 호수도산
- 파트너 어드민에서 인스타 계정 연동
- 스팟 상세에 인스타 콘텐츠 노출
- 외부 이탈 방지

### P4-3. 파트너 메모 + 익명 피드백 채널
**원천**: 아리한복 (메타 욕구)
- 어드민 우측 상단 메모 영역
- 익명으로 운영팀에 발송 가능
- 파트너 보이스 수집 채널 자체 강화

### P4-4. 비즈니스 협업 채널
**원천**: 호수도산
- 운영팀이 이벤트 제안 받는/주는 채널
- 신규 상품 카테고리(헤어 아카데미 등) 제안

### P4-5. 타플랫폼 통합 뷰
**원천**: 순시키 (가장 큰 욕구)
- 비용·복잡도 매우 큼 — 자체 통합 도구(네이버 등) 사용 파트너 우선 검증 필요
- 우선순위 낮음 — 다른 P0~P3 처리 후 검토

## 의사결정이 필요한 영역 (제품 리더십)

1. **모바일 앱 P2-2의 투자 규모** — 비용 매우 크지만 매출 손실 실증 있음. PWA vs 네이티브?
2. **자율 편집 권한 등급제 P3-1의 정책 결정** — 운영팀 워크로드/책임 모델 재설계 필요
3. **OTA 표준 격차 대응 속도** — 호수도산이 이미 KKday로 빠지는 중. 카테고리별 잔존율 데이터 확인 필요
4. **운영팀과의 R&R 재설정** — 어드민 자율 권한 확대 = 운영팀 카톡 워크로드 감소. 운영팀 KPI 재정의 동반
5. **다스팟 파트너 비중** — 투어스토리 같은 다스팟 운영자 비중에 따라 P4-1 우선순위 조정

6. **어드민의 장기 진화 방향 결정** — 단순 "운영 효율 도구"에 머물 것인지, P4 묶음(SNS 연동·브랜드 자산·이벤트 제안·익명 피드백 채널)을 통해 "**파트너의 마케팅·브랜딩 인프라**"로 확장할 것인지. 호수도산처럼 마케팅 욕심 큰 디지털 네이티브 파트너 비중·증가 추세를 데이터로 확인 후, 어드민의 정체성 자체에 대한 제품 리더십 의사결정 필요 (인사이트 8).

7. **리뷰 시스템의 플랫폼 가치관 정립** (P3-3 선행 조건) — 부정 리뷰 처리·작성자 차단 영역에서 크트가 어떤 입장을 가질 것인지 정책 프레임 정립. KKday 모델 답습 vs 독자 균형점. 파트너 만족 ↔ 유저 신뢰의 양면 의사결정.
