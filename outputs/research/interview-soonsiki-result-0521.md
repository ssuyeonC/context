## 파트너가 실제로 겪는 문제

> **means-ends chain 매핑**: 어드민이 카톡보다 "명백히 더 나은 경험"이 되려면 아래 문제를 빠르고 가시적으로 해결해야 함.
>
> **본질 한 문장**: *감당 가능한 인지 부담으로, 모든 채널의 예약을 직접 통제하고 싶다.*
>
> 두 축의 페어 — **통제권(Control)** × **인지 비용(Cognitive Load)**. P1~P4는 통제권 차원, P5는 인지 비용 차원. 둘은 함께 작동해야 의미가 있음.

### P1. 가용성 통제 실패 — 스케줄이 페이지에 반영되지 않음 `명시`
- **본질**: 매장에서 미리 올린 스케줄/마감이 크리에이트립 페이지에 반영되지 않아, 받을 수 없는 시간대에 예약·문의가 인입됨
- **현재 처리 방식**: 카톡으로 운영팀에 수정 요청 → CX 응대로 사후 처리
- **비용**: 응대 지연 / 고객 경험 저하 / 1인 운영자의 추가 처리 시간
- **근거**: "스케줄표 미리 올리는데, 크리에이트립 페이지에 반영이 안되어 (...) 예약이 들어오거나 문의하면 답변이 늦거나 하는 경우가 있었음"

### P2. 채널 통합 가시성 결핍 — 다플랫폼 예약을 한 화면에서 볼 수 없음 `명시`
- **본질**: 샤오홍슈·네이버·크리에이트립 등 채널별 예약이 분산되어, 어떤 채널에서 무엇이 들어왔는지 통합 파악이 어려움
- **현재 처리 방식**: 각 플랫폼 별도 확인 (수동 대조)
- **비용**: 인지 부담 폭증 — 특히 샤오홍슈발 인입 급증 시점에 "감당 안 된다" 토로
- **근거**: 핸드SOS를 자발적 레퍼런스로 인용 — "전국 모든 헤어샵이 쓰고 있는 어드민" + "네이버랑 연결되어 있음" + "단순/캘린더 UI"

### P3. 사후 수정 권한 부재 — 예약 변경을 직접 못함 `명시 + 잠재`
- **본질**: 예약 변경/스팟 수정 시 절차가 번거롭고, 직접 처리 흐름이 매끄럽지 않음
- **현재 처리 방식**: 스팟/스케줄 변경은 카톡으로 운영팀에 의뢰
- **비용**: 빠른 CX 대응에 만족하고 있어 본인은 "불편 없다"고 표현하지만, 본질적 통제권은 운영팀에 있는 상태 → 마찰을 의식 못한 채 워크어라운드에 적응
- **근거**: "예약을 변경 요청하는 절차가 편하게 되어있으면 좋을 듯" + "예약 시간 관리 UXUI 개선"

### P4. 고객 컨텍스트 결핍 — 누구의 예약인지 자동으로 인지 안 됨 `명시`
- **본질**: 재방문 고객임을 즉시 알아볼 수 없어, 매번 새 고객처럼 응대해야 함
- **현재 처리 방식**: 수동 기억/대조
- **비용**: 퍼스널 응대 기회 손실 (DM 컨버전은 매뉴얼 응대로는 전환되지 않는 비즈니스 특성) + 인지 부담
- **근거**: "제일 좋은 건 고객님 기록이 남아서 바로바로 뜰 수 있도록 (...) 등록번호 - 재방문 고객"

### P5. 통제 유지의 인지·주의 비용 과다 — 1인 운영자의 한계 `명시 + 잠재`
- **본질**: 모든 예약을 머릿속에 담고 메일에 의존해 즉시 처리해야 함. PC에 못 앉아 있는 시간(이동/매장 업무)에는 통제가 끊김
- **현재 처리 방식**: 메일 알림 즉시 처리 / 카톡 CX 의존 / 모바일에서는 사실상 불가
- **비용**: 매출 폭증 시 처리 한계 도달, 모바일 부재로 즉시성 손실
- **근거**: "메일 오는 거 확인해서 바로 예약 잡는 편" / "모바일로 접근하기 쉽게" / "단순하고 직관적인 UI로" / "감당이 안되는 정도"

### 통합 해석

통제권만 주고 인지 비용이 크면 → 1인 운영자에게는 짐.
인지 비용만 낮추고 통제권이 없으면 → 운영팀 의존 (현재 상태).
→ **"신뢰 가능한 자동화 위에 직접 통제"** 가 본질 해법. 핸드SOS 레퍼런스는 이 조합(캘린더=인지비용↓ + 직접 편집=통제권)을 압축적으로 가리키는 신호.

## 핵심 발견

### 1. 어드민 자체 불편은 낮으나, 채널 통합 니즈가 강함
- 크리에이트립 어드민은 "이미 잘 되어있다" — 큰 불만 없음
- 다만 **여러 플랫폼(샤오홍슈, 네이버 등) 예약을 한 화면에서 통합 관리하고 싶다**는 강한 욕구
- 참고로 언급한 레퍼런스: **핸드SOS** (전국 헤어샵 어드민, 네이버 연동, 단순/직관 UI, 캘린더 중심)

### 2. 스케줄 동기화 마찰
- 매장에서 스케줄표를 미리 올려도 **크리에이트립 페이지에 반영이 안 됨**
- 결과: 휴무/마감 기간에도 예약/문의가 들어옴 → 응대 지연 발생
- 우회 경로: 카톡으로 운영팀에 요청 → 빠른 대응으로 만족도는 높지만 본질 해결은 아님

### 3. 예약 변경 흐름의 마찰
- "예약 변경 요청 절차가 더 편하게 되어있으면 좋을 것"
- 빈도 높은 작업: **예약 닫기 / 변경**
- 메일 알림 확인 후 즉시 예약 처리 (메일 의존도 높음)

### 4. 재방문 고객 식별 니즈
- "**고객님 기록이 남아서 바로바로 뜰 수 있도록**" — 등록번호 기반
- 재방문 고객을 즉시 알아볼 수 있는 기능을 가장 원함
- 예약 검색 기능도 함께 요청

### 5. 기계적 응대 vs 퍼스널 응대
- DM으로 들어오는 예약이 많고 효과도 좋음
- 정해진 매뉴얼대로 응대하면 **전환되지 않음** — 고객이 퍼스널한 경험을 원함
- 상담↔시술 사이 컨버전에 어려움이 가끔 있음

## 정리 차원 매핑

| 차원 | 항목 |
|------|------|
| 행동 | 대표 1인 운영, 메일 알림 확인 → 즉시 예약 처리, 카톡으로 운영팀 요청 |
| 워크어라운드 | 스팟/스케줄 변경 = 카톡, 타플랫폼 통합 = 별도 확인, 재방문 식별 = 수동 |
| 시간/사람 | 1인 운영, 처리량 폭증 중(샤오홍슈발 인입 급증) — 스케일 시점 마찰 명확 |

### 97% 처리율 비결 가설
- 1인 운영 + 메일 알림 즉시 처리 루틴 → **알림 채널이 단일하고 의사결정자가 즉시 처리 가능한 구조**
- 시사점: Type D(저처리율) 파트너에게도 **알림 도달 → 즉시 행동** 사이클을 최소 스텝으로 만드는 게 핵심

### 스팟 수정 마찰 (운영팀 가설 검증)
- ✅ **검증됨** — 본인은 "불편 없다"고 표현하지만, 실제로는 카톡 우회로 처리 중
- 즉, 마찰을 의식하지 못한 채 워크어라운드에 적응한 상태

### 어드민에 없지만 필요한 기능 후보
- 타 플랫폼 예약 통합 뷰 (장기 — 통합 게이트웨이 성격, 우선순위 낮을 수 있음)
- 예약 검색 (단기)
- 재방문 고객 자동 표시 (중기)
- 캘린더 기반 스케줄 직접 관리 (중기)
- 모바일 최적화 (중기 ~ 장기)
