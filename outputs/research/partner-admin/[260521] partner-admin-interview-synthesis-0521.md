## 0. 프레이밍 — 왜 파트너 어드민을 개선하는가

### 0.1 사고 사슬 (means-ends chain)

```
[목표]
회사 제휴팀의 시간을 '반응형 트랜잭션 처리'에서 '관계·전략·영업'으로 재배분
       ↓ (왜?)
제휴팀이 파트너의 일상 요청(예약 처리, 콘텐츠 수정 등)에 시간을 뺏겨 본업을 못 하는 상태
       ↓ (어떻게?)
파트너가 일상·주기적 업무를 어드민에서 스스로 해결하도록 만든다
       ↓ (그러려면?)
어드민이 카톡보다 '명백히 더 나은 경험'이어야 함 — 단순 사용성 개선 ≠ 본질
       ↓ (무엇이 명백히 더 나아야 하나?)
파트너가 실제로 겪는 문제를 빠르고 가시적으로 해결하는 경험
       ↓ (그 문제가 뭔지 알기 위해)
6개 파트너 인터뷰 수행 → 본 문서
```

### 0.2 채널 전략 — 어드민과 카톡의 역할 분리

**원칙**: 카톡은 비상연락망. 평소엔 안 쓰는 게 정상.

| 구분 | 채널 | 특성 | 예시 작업 |
|------|------|------|---------|
| **일상적·주기적** | 어드민 | 빈번, 반복, 트랜잭션 성격, 자율 처리 가능 | 예약 확인/확정/취소, 시간슬롯·스케줄, 가격·메뉴 변경, 콘텐츠 업데이트, 고객 메시지, 리뷰 응대, 정산 확인 |
| **비일상·예외** | 카톡 | 드묾, 예외 처리, 정책/계약 관련, 인간 판단 필요 | 신규 상품 등록·검수, 분쟁/이슈 해결, 비즈니스 전략·이벤트 제안, 시스템 장애 신고, 권한·계약 변경 |

**핵심 인식**:
- 현재는 일상/예외 모두 카톡으로 가고 있음 → 제휴팀 시간이 일상 트랜잭션에 잠식됨
- 카톡 = 비상연락망 정의가 자리잡으면, **카톡 트래픽 자체가 사업 성장과 연관된 대화로 바뀜**
- 어드민 = "이런 일은 여기서 하시면 됩니다"가 자명한 1순위 채널이 되어야 함

### 0.3 핵심 보정 — '신규 사용 유도'가 아니라 '카톡에서 전환'

파트너는 이미 **카톡이라는 작동하는 대안**을 선택해 있음. 이건 게으름이 아니라 합리적 선택의 결과:
- 어드민 요청 = 블랙박스(반영까지 최대 3개월), 카톡 = 사람 응답 + 빠른 피드백
- 아리한복은 명시적으로 "이미 카톡으로 정착되어 바꾸기 어려울 것"이라 인지

→ 따라서 다음 2개 워크스트림이 **항상 함께** 가야 함:
1. **어드민 자체 개선** (제품 트랙) — 기능 + 진행 가시성 + 응답 속도 + 모바일
2. **제휴팀 운영 변화** (영업·운영 트랙) — 카톡 요청 받았을 때 "이건 어드민에서 직접 하실 수 있어요"로 능동적 리다이렉트 + 신규 기능 출시 시 적극 안내

어드민 개선만으로는 트래픽이 자동 이전되지 않음.

### 0.4 모든 파트너가 자율을 원하는 건 아님

메디큐브는 콘텐츠 직접 수정 권한이 **부담**이라고 명시. "직접 하세요" 일색의 기능만 늘리면 이 파트너는 워크로드가 안 줄어듦 — 여전히 제휴팀에 떠넘김.

→ 어드민이 흡수해야 할 두 갈래:
- **자율 처리 흡수**: 파트너가 직접 처리 가능한 작업 (모델로 사진, 투어스토리 콘텐츠, 호수도산 인스타 등)
- **요청 채널 흡수**: 직접 처리는 부담스러워도 **어드민으로 요청 → 가시적 진행 상태 확인** 흐름 자체가 카톡을 대체 (메디큐브 같은 케이스)

### 0.5 측정 지표 (제안)

지표를 미리 정의해두면 우선순위가 선명해짐:
- 요청 유형별 **카톡 → 어드민 전환율**
- 트랜잭션 요청의 제휴팀 처리 건수 감소율
- 제휴팀 시간 배분 변화: 반응형 트랜잭션 vs 관계·전략·영업
- 어드민에서 자율 처리된 작업 비중

→ "어떤 기능부터 만들지"는 *현재 카톡 트래픽이 가장 큰 일상 요청 유형*이 기준이 됨

### 1.5 파트너별 본질 한 문장과 두 축

> 각 개별 정리본의 "파트너가 실제로 겪는 문제" 섹션에서 도출. means-ends chain 매핑 결과.

| 파트너 | 본질 한 문장 | 두 축 |
|--------|------------|------|
| 순시키 | 감당 가능한 인지 부담으로, 모든 채널의 예약을 직접 통제하고 싶다 | 통제권 × 인지 비용 |
| 메디큐브 | 내방 시점에 양측의 기대가 어긋나지 않도록, 예약을 둘러싼 정보가 양방향으로 정확히 도달해야 한다 | 병원→고객 × 고객→병원 (정보 정합성) |

| 투어스토리 | OTA 표준 수준의 자율 편집 권한과 다스팟·다국어 효율 도구가 있어야, 50+ 상품의 시즌·콘텐츠 변화가 비즈니스 속도에 맞춰 반영된다 | 자율 × 효율 (다스팟 × 시즌 × 다국어) |
| 아리한복 | 이미 콘텐츠 생산자·운영자 역할까지 자임하는 파워유저에게는, UI 완성도와 업로드 편의성이 본질이다. 자율 권한 자체보다 우회 비용 없는 일상 도구화가 우선 | UI 완성도 × 생산 워크플로우 |
| 호수도산 | 브랜드 욕심 큰 운영자가 (a) 손에서 즉시 통제하고 (b) 브랜드 자산(리뷰·SNS)을 능동 관리할 때, OTA 카테고리 이탈 압력이 사라진다 | 운영 자율성·즉시성 × 브랜드 자산 능동 관리 |

**관찰**:
- 6개 본질이 **단일 프레임으로 환원되지 않음** → 차등 정책의 강한 근거
- 그러나 모든 본질에 **"통제(Control)"** 가 어떤 형태로든 깔려 있음 — 운영자가 본인의 비즈니스 상태를 직접 손에 쥐고 싶어함
- 차이는 **무엇을 통제할 것인가**: 예약(순시키), 정보 정합성(메디큐브), 변화 속도·구조(모델로), 자율 권한·효율(투어), 일상 도구(아리한복), 브랜드 자산(호수도산)

## 2. 횡단 패턴 (Cross-cutting Themes)

### 2.1 카톡 우회의 보편성과 합리성 ⭐⭐⭐
- 6명 중 **5명이 카톡 우회 사용** (예외: 아리한복도 다른 방식으로 정착)
- 카톡 우회 = **합리적 채널 선택**의 결과 (단순한 게으름이 아님)
  - 어드민 요청 = 블랙박스 (받음 → 검토 → 반영 가시성 X)
  - 카톡 = 사람 응답 + 빠른 피드백 + 다단계 진행 상황 공유
- **반영 지연 사례**: 투어스토리 최대 3개월, 모델로 사진 1개월
- **변화 비용 인식**: 아리한복은 "이미 카톡으로 정착되어 바꾸기 어려울 것" 자체 인지

**시사점**: 어드민에 기능을 추가해도 자동으로 카톡 트래픽이 이전되지 않음. **진행 가시성 + 응답 속도 + 온보딩 캠페인**이 함께 가야 함.

### 2.2 기능 인지 부재 패턴 반복 ⭐⭐⭐
어드민에 **이미 있는** 기능을 모르고 우회하는 사례가 모든 파트너에서 발견:

| 기능 | 인지 부재 파트너 |
|------|--------------|
| 카카오 알림톡 | 메디큐브 (모름), 모델로 (의도적 OFF) |
| 리뷰 댓글 + 자동 번역 | 메디큐브 (현장에서 처음 인지) |
| 직접 취소 + 메시지 | 호수도산 (모름/불편해 안 씀) |
| 상품별 스케줄 관리 | 모델로 (있는데 모르는 듯) |
| 스팟 정보 수정 요청 | 모델로 (알지만 안 씀) |

**시사점**: 신규 기능 개발만큼 **기존 기능 디스커버리/온보딩 개선**이 ROI 높음. 어드민 첫 진입 시 가이드/체크리스트, 인앱 알림, 사용 안 한 기능 안내 등.

### 2.3 OTA 업계 표준과의 격차 ⭐⭐
**KKday를 명시적으로 인용한 비교** — 투어스토리(B2B), 호수도산(헤어) 양 끝의 카테고리에서 동일하게 등장.

| 영역 | KKday 표준 | 크트 현 상태 |
|------|----------|----------|
| 콘텐츠 편집 권한 | 초기 검수 후 자율 (민감 영역만 검수) | 거의 모든 수정 운영팀 의뢰 |
| 진행 가시성 | 단계별 상태 표시 | 블랙박스 |
| 모바일 환경 | 관리자 앱 + 푸시 | PC 중심 |
| 다이렉트 메시징 | 직접 연락 + 언어별 번역 | 부재 (외부 채널 의존) |
| 다건 처리 | 일괄 복사·수정 | 1건씩 |
| 리뷰 통제 | 삭제 가능, 작성 차단 | 제한적 |

**시사점**: 헤어/뷰티/투어 카테고리에서 KKday가 사실상 표준. 격차를 빠르게 메우지 못하면 **카테고리 이탈** 위험 (호수도산은 이미 KKday로 예약이 빠지고 있다고 체감 중).

### 2.4 콘텐츠 직접 편집 권한 — 3극 ⭐
1차원 스펙트럼이 아니라 **3극 구조**로 봐야 정책 분기가 선명해짐:

```
[극 1: 부담]               [극 2: 요구]               [극 3: 의지 X + 본인이 이미 생산]
검수 유지 선호              자율 강력 요구              카톡 정착 + 자체 편집까지 자임
←─────────────────────────────────────────────────────────────────────────→
메디큐브                    투어스토리                   아리한복
(14개언어 오표기 부담)        (OTA 표준 인용, 본인이       (이미지 직접 편집 + 규격 맞춤
                            검수 분기 모델 정확 인지)       전달, 카톡 정착 → 권한 풀어도
                                                          즉시 전환 안 일어남)
                            모델로(사진만)
                            호수도산(인스타·SNS)
                            
                            순시키 — 약함
```

**시사점**:
- 단일한 "모두에게 자율 권한 부여" 정책은 부적합. **카테고리·민감도별 차등 정책**이 필요.
  - 다스팟·B2B: 자율(투어스토리)
  - 헤어/뷰티(이미지 중심): 사진/SNS 자율, 텍스트는 검수(모델로/호수도산)
  - 의료·언어 민감: 검수 유지(메디큐브)
- **극 3(아리한복)의 시사**: 권한 부여만으로는 카톡 우회가 자동 이전되지 않음. **마이그레이션 설계**(어드민 자체 개선 + 제휴팀 능동적 리다이렉트 + 온보딩) 가 함께 가야 함. 종합본 0.3의 원칙을 가장 명확히 보여주는 케이스.
- **메디큐브·투어스토리 공통 관찰**: 둘 다 정반대 극에 있지만 **검수 분기 모델 자체에 대한 정교한 인지**를 공유 — "민감 영역만 검수 + 나머지 자율" 분기가 OTA 업계 표준 관행으로 자리잡음.

### 2.5 모바일 우선 필요성 ⭐⭐
- 호수도산이 가장 강력 — 운전 중 핸드폰 확인, PC 부재로 **다른 OTA 먼저 보고 크트 늦게 봄** (매출 손실)
- 순시키도 명시적 요청 (모바일 접근성)
- 다른 파트너들은 큰 불만은 없지만 **사실상 1인 운영** = 데스크에 못 앉아 있음

**시사점**: 단순 반응형이 아닌 **모바일 앱 + 푸시** 수준의 경험이 카테고리 표준화 중. 호수도산 케이스는 **모바일 부재가 매출에 직접 영향**을 미친다는 첫 증거.

### 2.6 다이렉트 메시징 갈증 ⭐⭐
인앱에서 파트너 ↔ 고객 직접 소통이 부재 → 외부 채널 우회:

| 파트너 | 우회 채널 | 갈증 |
|--------|---------|------|
| 메디큐브 | 왓츠앱 (이메일은 너무 느림) | 인앱 다이렉트 메시징 |
| 호수도산 | 톡방 (밤엔 어려움) | 직접 연락 + 자동 번역 |
| 순시키 | CX팀 카톡 (만족도 높지만 본질 해결 X) | (재방문 식별 우선) |

**시사점**: 변경/취소/안내 같은 1:1 소통은 카테고리 불문 공통 페인. **메시지 입력 + 자동 번역 + 발송** 기능이 가장 횡단적 임팩트.

### 2.7 고객 정보 정확성/CRM ⭐
- **메디큐브**: 가장 강력 — 여권명 통일, 전화/이메일 2회 입력, CRM 분산 문제
- **순시키**: 재방문 식별 (등록번호 기반 자동 표시)
- **호수도산**: 직접 연락 가능해야 의미 있음 (정확한 연락처 전제)

**시사점**: 고객 정보 정확성은 다운스트림(연락 가능 여부, CRM 통합, 정산 표기, 리뷰 작성 가능 여부) 모두에 영향. **입력 단계 검증**이 가장 ROI 높은 개입 지점.

### 2.8 리뷰 페인 — 다차원 ⭐
같은 "리뷰"라도 파트너마다 다른 차원의 페인:

| 파트너 | 리뷰 페인 |
|--------|---------|
| 메디큐브 | 작성 가능 범위(비회원/예약내역), 알림 누락, 댓글 기능 미인지 |
| 호수도산 | 작성 동선 (확정 → 푸시 → 즉시 작성), 악플 통제 |
| 아리한복 | AI 요약 좋음, 하이라이트→리뷰 이동 동선 |
| 모델로/투어스토리 | 특이사항 없음 |
| 순시키 | (언급 없음) |

**시사점**: 리뷰 = 매출 직결 인식이 강함(호수도산은 48시간 내 예약 감소 체감). 작성률 ↑ + 통제 ↑ + 노출 최적화 3축 동시 개선 필요.

**⚠️ 정책 텐션 노트**: 호수도산이 표현한 "적극적 리뷰 관리에 대한 욕구"(악플 블러·특정 고객 차단·삭제 등)는 운영자 입장에서 정당한 욕구이나, **플랫폼 무결성과 텐션**이 있는 영역. 작성률 ↑ 같은 무해한 차원은 즉시 추진 가능하지만, 분쟁 처리·차단 영역은 **정책 프레임 정립이 선행**되어야 함. 파트너 욕구를 인정하되 해법은 정책적 균형 위에 설계.

### 2.9 다스팟·다국적 운영 페인
다스팟 운영 파트너에서만 나오는 차원:
- **투어스토리** (50+ 상품) — 상품 검색, 다국어 자율 편집+AI 번역, 일괄 작업
- **호수도산** — 다건 예약 복사 (KKday는 지원)

**시사점**: 단일 매장 위주의 어드민 설계는 다스팟 운영자에게 정신적·시간적 부담. **검색 + 일괄 처리**가 다스팟의 베이스라인.

### 2.10 UI 디테일 — 깊이 쓰는 사용자에게서만 나옴
- **아리한복**: 예약 테이블 리팩토링(컬럼 단순화, 컬러, 소팅), 세로 사진, 옵션 사진
- **메디큐브**: 상세페이지 강조도(병원별 설정), 토글 vs 직노출
- **모델로**: 실시간 현황 가시성

**시사점**: UI 디테일 페인은 **사용량 많은 파트너에게서만** 노출됨. 어드민 활용도가 낮은 파트너는 UI 페인을 의식하지 못함(애초에 사용 안 함). 어드민 활용도 향상 = UI 디테일 페인 노출 증가 → **지속적 UI 폴리싱 체계** 필요.

### 2.11 신선한 아이디어 (메타·확장)
- **아리한복**: 파트너 메모 영역 + **익명 피드백 채널** (메타 욕구)
- **호수도산**: 이벤트 제안 받기, 신상품 카테고리(헤어 아카데미), 인스타 SNS 어드민 연동
- **순시키**: 타플랫폼 통합 뷰

**시사점**: 단일 기능 개선을 넘어 **파트너 ↔ 크트 협업 채널** 자체에 대한 욕구. 익명 피드백, 이벤트 제안, 비즈니스 확장 제안 등.

**확장 시사 — 어드민의 역할 재정의**: 호수도산 케이스가 특히 시사적. 다른 파트너의 페인이 "운영 효율 도구로서의 어드민"에 머무는 반면, 호수도산은 어드민을 **"브랜드 자산 운용 도구"** 로 기대 — SNS 연동, 리뷰 능동 관리, 이벤트 제안, 비즈니스 확장 제안 모두 한 방향. → 어드민의 장기 진화 방향은 단순 트랜잭션 처리를 넘어 **파트너의 마케팅·브랜딩 인프라**로 확장될 수 있음을 시사. 마케팅 욕심 큰 디지털 네이티브 파트너가 늘어날수록 이 욕구는 횡단적으로 커질 가능성.

## 4. 핵심 인사이트 9개 (한 문장 요약)

0. **목표는 제휴팀 워크로드 '감소'가 아니라 '재배분'** — 트랜잭션 처리 → 관계·전략·영업으로. 카톡 = 비상연락망으로 자리잡으면 카톡 트래픽 자체가 사업 성장 대화로 바뀜.

1. **카톡 우회는 합리적 선택** — 가시성/응답 속도/사람 응답 때문이지 기능 부재만이 아님. 어드민으로 트래픽 이전하려면 **진행 가시성 + 빠른 응답 + 온보딩 + 제휴팀의 능동적 리다이렉트**가 함께 가야 함.

2. **기능 인지 부재가 가장 ROI 높은 개선 영역** — 알림톡·리뷰 댓글·직접 취소 등 이미 있는 기능을 모르는 파트너 다수. 신규 개발보다 디스커버리·온보딩이 우선.

3. **OTA 업계 표준(KKday)과 격차가 카테고리 이탈을 만들고 있음** — 헤어/뷰티에서 실제 매출 손실 증거(호수도산). 모바일 앱+푸시, 다이렉트 메시징, 직접 취소+번역, 다건 처리는 베이스라인.

4. **콘텐츠 자율 편집 권한은 파트너 유형별 차등 정책 필요** — 단일 정책 X. 다스팟·B2B는 자율, 이미지 중심 카테고리는 사진/SNS 자율, 의료·언어 민감은 검수 유지.

5. **고객 정보 정확성과 다이렉트 메시징은 가장 횡단적 임팩트** — 5명 중 4명이 외부 채널로 우회 중. 입력 단계 검증 + 인앱 메시지+번역 발송이 비용 대비 효과 큼.

6. **자율 권한은 3극 구조 + 마이그레이션 설계** — 부담(메디큐브) / 요구(투어·모델로·호수도산) / 의지 X+본인 생산(아리한복) 세 극으로 분기. 권한 부여만으로는 카톡 우회가 자동 이전되지 않음. **차등 정책 + 어드민 자체 개선 + 제휴팀의 능동적 리다이렉트 + 온보딩**을 묶어 설계해야 함.

7. **파워유저는 어드민의 디자인 베이스라인 검증자** — 아리한복은 본인이 콘텐츠 생산자·운영자 역할까지 자임하며 어드민의 수수료 설정으로 노출 순위 조정까지 활용 중인 희귀 케이스. 이 파트너의 UI 디테일 페인을 해결하면 결과물이 다른 파트너에게 트리클다운될 가능성 ↑. **얼리어답터 그룹을 기준 파트너로 설정**한 폴리싱 체계를 권장.

8. **어드민의 역할이 "운영 효율 도구" → "브랜드 자산 운용 도구"로 확장 중** — 호수도산이 가장 명확한 신호 (인스타 연동·적극적 리뷰 관리·이벤트 제안 채널·아카데미 같은 신상품 카테고리). 마케팅 욕심 큰 디지털 네이티브 파트너가 늘어날수록 어드민의 장기 진화 방향이 됨. 단기 페인 해소(P1~P3 류)와 함께 **장기 비전(SNS·브랜드 자산·협업 채널)** 도 로드맵에 명시 필요.
