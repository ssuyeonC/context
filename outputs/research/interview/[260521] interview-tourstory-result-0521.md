## 파트너가 실제로 겪는 문제

> **means-ends chain 매핑**: 어드민이 카톡보다 "명백히 더 나은 경험"이 되려면 아래 문제를 빠르고 가시적으로 해결해야 함.
>
> **본질 한 문장**: *OTA 표준 수준의 자율 편집 권한과 다스팟·다국어 효율 도구가 있어야, 50+ 상품의 시즌·콘텐츠 변화가 비즈니스 속도에 맞춰 반영된다.*
>
> **3가지 운영 컨텍스트 × 2가지 도구**:
>
> ```
> [운영 컨텍스트]                         [필요 도구]
> 다스팟 (50+)            ───┐
> 시즌성 (벚꽃/단풍/스키)  ───┼──→  자율 편집 권한 × 다건·다국어 효율
> 다국어 (영/중 + α)       ───┘
> ```
>
> 이 파트너의 페인은 **"자유도"라는 단일 표현으로 묶이지만 실제로는 4개 하위 차원**: 권한(P1) × 속도(P2) × 다스팟 효율(P3) × 다국어(P4) — 그 위에 OTA 표준 격차(P5)가 메타로 감싼다.

### P1. 콘텐츠 자율 편집 권한 부재 — 마감만 직접 가능, 추가·수정은 요청 필요 `명시` (권한)
- **본질**: 가격·코스·일정표·상품 소개(itinerary)·사진을 직접 수정할 수 없음. 마감/슬롯만 직접 처리 가능
- **현재 처리 방식**: 메일·단톡방으로 요청 → 운영팀 검수 → 반영
- **비용**: 시간슬롯/요일정책 수정은 600+건 vs 가격/코스/사진 수정 2건 — 콘텐츠 수정의 100% 카톡 우회 증거. 시즌 비즈니스에서 매출 직결.
- **근거**: "마감은 직접 가능한데, 추가나 수정은 요청을 드려야 가능한 상황" / "가격, 일정표 변경, 캘린더 상하반기 오픈 반영, 투어지 추가, 옵션 등 / 상품 소개 및 운영"

### P2. 검수 대기에 의한 반영 속도 지연 — 최대 3개월 `명시` (속도)
- **본질**: 직접 수정 후 반영되기까지 검수 대기. 진행 가시성도 부재("블랙박스")
- **현재 처리 방식**: 반영되기까지 기다림 + 반영 전 들어온 예약은 유저와 별도 소통으로 수습
- **비용**: 잘못된 일정/가격으로 들어온 예약 수습 운영 비용 + 고객 신뢰 부담 + 시즌 사이클(벚꽃·단풍·스키) 대응 실패
- **근거**: "직접 수정해서 반영되기까지 기다림. 3개월 동안 안 되기까지" / "반영이 늦어질 경우, 반영되기 전에 들어온 예약건은 유저에게 별도로 소통"

### P3. 다스팟 규모에 맞는 검색·일괄 도구 부재 `명시` (다스팟)
- **본질**: 50+ 활성 상품을 다루는데 검색·일괄 기능 부재 → 개별 요청·개별 수정으로 강제됨
- **현재 처리 방식**: 상품마다 개별 카톡 요청 / 일괄 가격 인상·시즌 종료 시도 어려움
- **비용**: 50+ 상품 운영자의 시간·인지 부담, 시즌 종료 같은 다건 작업이 비현실적
- **근거**: "파트너 어드민 내 검색 기능 — 상품 ID, 상품 명" 직접 명시 / "상품마다 세부적인 내용이 많이 달라질 경우도 있음"

### P4. 다국어 편집·번역 워크플로우 부재 `명시` (다국어)
- **본질**: 특정 외국어를 선택해 직접 편집하거나, 한 언어로 작성 후 다른 언어로 AI 자동번역하는 워크플로우 부재. 영/중 외 언어는 수동 처리.
- **현재 처리 방식**: 메일·단톡 요청 + 내부에서 수동 번역. 예약 알림도 영/중만 자동 연동, 그 외 언어는 수동 내부 정리.
- **비용**: 14개 언어 운영의 인프라 부족 → 다국어 시즌 대응 속도 저하 + 알림 누락 위험
- **근거**: "직접 외국어를 선택해서 편집할 수 있는 기능 / 특정 언어로 편집하고 해당 언어 기반으로 AI 번역될 수 있도록 하는 것" / "영어랑 중국어는 대응이 되는데, 다른 언어는 대응이 되지 않아 이 때는 수동으로 내부 시스템에 정리"

### P5. OTA 업계 표준과의 격차 — 메타 프레임 `명시` (표준)
- **본질**: 다른 OTA에서 이미 작동 중인 "신뢰 기반 자율 권한 + 민감 영역만 재검수" 모델을 정확히 인지하고 크트와 비교 중. 격차 미해소 시 카테고리 이탈 압력.
- **현재 처리 방식**: KKday는 절반 정도 직접 컨트롤, 큰 OTA는 검수 절차 없음 — 본인이 모델 분기를 정확히 인지
- **비용**: 자체 시스템 + 다수 OTA 병행 운영자에게 크트가 "가장 비효율적인 채널"로 자리잡을 위험
- **근거**: "100% 컨트롤할 수 있도록 되어 있음. KKday는 반 정도는 투어스토리에서 컨트롤" / "다른 OTA는 최초 검수가 끝나면 그 뒤로는 자유롭게 진행함 (...) 큰 OTA는 대부분 검수 절차가 없음. 가격, 썸네일 등 중요하고 민감한 부분들은 OTA 업체에서 한번 더 검수하는 절차는 있음"

### 통합 해석

**메타 관찰 1 — 검수 모델의 정교한 인지**: 본인이 "민감 영역만 검수 + 나머지 자율"이라는 OTA 표준 분기 모델을 정확히 알고 있음. 메디큐브가 자율을 부담스러워하는 것과 정반대 스펙트럼이지만, 둘 다 **검수 분기 모델에 대한 정교한 인지**가 있다는 공통점. → 자율 권한 정책은 단일 ON/OFF가 아니라 **카테고리·민감도별 분기 모델**이어야 함 (종합본 2.4 차등 정책 검증).

**메타 관찰 2 — 알림톡 OFF의 본질**: 다스팟이라 알림 폭주 우려로 OFF. 모델로(일상 카톡 정착)와 다른 결의 OFF — **알림 다중화보다 다국어 자동 분류/연동이 본질**.

**메타 관찰 3 — 종합본 2.9 "다스팟·다국적 운영 페인"의 원형 사례**: 다스팟 × 시즌 × 다국어 3개 컨텍스트가 동시에 겹치는 유일한 파트너. 다른 파트너와 단순 비교 어려우며, "단일 매장 위주의 어드민 설계는 다스팟 운영자에게 부담"의 가장 명확한 증거.

## 핵심 발견 (Top 우선순위 → 후순위)

### 1. 콘텐츠 직접 편집 권한 (다른 OTA 대비 격차) ⭐⭐
- 마감/슬롯은 직접 가능하지만 **추가·수정은 크트 운영팀 요청 필수**
- **다른 OTA 운영 비교**:
  - 대다수 OTA: 최초 검수 후 **자유롭게 진행** (큰 OTA는 검수 절차 없음)
  - 가격/썸네일 등 민감 영역만 OTA가 한 번 더 검수
  - **크트 = 100% 컨트롤 가능 어드민이 가장 약한 축**
  - KKday는 절반 정도 직접 컨트롤
- **신뢰 기반 자율 권한**(검수는 민감 영역만)이 OTA 업계 표준에 가까움

### 2. 반영 지연 — 최대 3개월 ⭐⭐
- 직접 수정 후 반영되기까지 **3개월간 안 됐던 케이스** 인용
- 반영 전 들어온 예약은 **유저와 별도 소통**으로 수습
- 카톡 요청 → 진행 가시성 부재 = "블랙박스" 학습
- 카톡이 어드민보다 응답이 빠르고 명확해서 우회 학습 강화

### 3. 검색 기능 부재 (다스팟 핵심 페인) ⭐
- 50+ 활성 상품 운영
- 어드민 내 **상품 ID/상품명 검색** 부재 → 일괄 관리 비효율
- 일괄 가격 인상/시즌 종료 처리 시도하기 어려운 구조

### 4. 다국어 편집 UX ⭐
- 갈증: **특정 외국어를 선택해 직접 편집**, 또는 **한 언어로 작성 → AI 자동 번역**
- 현재 다국어 작업이 수동 + 승인 프로세스로 묶여 있어 시즌 대응 속도 ↓
- 다른 OTA는 AI 자동번역 + 필요 시 수동 보정 흐름이 표준

### 5. 시간슬롯/요일 정책 ON/OFF는 잘 활용 중
- 어드민에서 600건+ 처리 — 가능한 영역은 적극 사용
- 가능 영역 = 즉시 반영 / 불가능 영역 = 카톡 우회의 양극화

### 6. 알림/예약 인입 처리
- 이메일 → **내부 시스템 자동 연동** (영/중 지원)
- 영/중 외 언어는 **수동으로 내부 정리**
- 카카오 알림톡 OFF — 다스팟이라 켜면 알림 폭주 우려
- → **알림 다중화보다 다국어 자동 분류/연동이 본질**

### 7. 어드민 = '확정 도장' 역할에 가까움
- 자체 시스템이 메인, 크트 어드민은 보조
- 단, 일정/마감 같은 즉시성 작업은 어드민이 효율적

## 가설 검증/관찰

### "일정은 셀프, 콘텐츠는 위임" 가설
- ✅ **명확하게 검증됨** — 어드민 권한 경계와 운영 패턴이 1:1로 일치
- 시간슬롯·요일 정책 600건+ vs 콘텐츠 2건

### "승인 채널 가시성 차이"
- ✅ **검증됨** — 어드민 요청 = 블랙박스 + 3개월 지연, 카톡 = 사람 응답 + 빠름
- 카톡 우회는 단순한 게으름이 아니라 **합리적 채널 선택**의 결과

### "다스팟 운영의 검증"
- 검색 부재, 일괄 작업 부재, 다국어 부담 — 다스팟 파트너 공통 마찰 가능성 큼
- KKday/클룩 등 경쟁 OTA가 보유한 기능 = 크트가 따라잡아야 할 베이스라인

### 비즈니스 임팩트
- 잘못된 일정/가격으로 들어온 예약은 별도 소통으로 수습 — **운영 비용·고객 신뢰 부담** 명확
- 시즌 사이클(벚꽃·단풍·스키)에 대응 속도가 매출 직결

| 권한 부담 vs 자율 | 자율 선호 | 부담 (자율 원치 않음) | 사진은 자율, 나머지 부담 | **자율 강력 요구 (업계 표준)** |

→ 투어스토리는 **'직접 권한이 절실한' 유형**의 첫 케이스. 메디큐브(부담)와 정반대 스펙트럼.
