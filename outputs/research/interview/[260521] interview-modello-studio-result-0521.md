## 파트너가 실제로 겪는 문제

> **means-ends chain 매핑**: 어드민이 카톡보다 "명백히 더 나은 경험"이 되려면 아래 문제를 빠르고 가시적으로 해결해야 함.
>
> **본질 한 문장**: *변화가 잦은 비즈니스 운영이 (a) 즉시 반영되고 (b) 충분히 유연한 구조로 표현될 때, 고객·운영·내부 직원 모두에게 같은 상태가 공유된다.*
>
> **두 축의 페어** — **속도(Pace)** × **구조(Structure)**:
>
> ```
> [속도 — 변화의 즉시 반영성]              [구조 — 표현의 유연성]
> 가용성/메뉴/가격/사진/설명이              상품·옵션·스케줄·메뉴를
> 즉시 시스템에 반영되어야                  비즈니스 그대로 표현할 수 있어야
> └ 사후 카톡 조율 회피                     └ 통합 메뉴/취소→재예약 회피
> ```
>
> 모델로의 페인은 단순 "변경 빈도가 높다"가 아니라 **"비즈니스의 동적 상태가 시스템에 못 잡힌다"** — 변경 빈도(속도)와 데이터 모델 한계(구조)가 함께 작동.

### P1. 가용성 통제 결핍 — 모든 시간을 열어두는 운영 방식 `명시 + 잠재` (속도)
- **본질**: 다른 플랫폼/워킹 손님/내부 일정과 충돌 가능성을 알면서도 일단 다 열어둠 → 인입된 예약을 카톡으로 사후 조율
- **현재 처리 방식**: "예약 1건 들어오면 일단 상품 무관하게 닫음" + 카톡/통화로 시간 변경 유도
- **비용**: "열려있어서 예약했는데 안 됨"이라는 고객 불만, 운영자의 사후 조율 부담
- **근거**: "최대한 모든 시간을 열어두고 예약을 받으며, 실제 스케줄 조정은 카카오톡/통화로" / "열려 있어서 예약했는데 실제로는 안 된다는 고객 불만"

### P2. 상품·메뉴 구조 경직성 — 통합 메뉴, 옵션·스케줄 분리 불가 `명시` (구조)
- **본질**: 헤어&메이크업 포함/미포함, 샴푸 포함 등 옵션별로 받고 싶은데 통합 메뉴라 분리가 안 됨
- **현재 처리 방식**: 통합으로 받고 카톡 조율
- **비용**: 옵션별 슬롯·인력 관리 불가 → 실시간 여유 슬롯 응대 비효율
- **근거**: "현재 상품이 통합 메뉴, 옵션 분리하여 예약 받고 싶음" / "네이버 예약처럼 메뉴별로 스케줄 분리" / "헤어/메이크업와 촬영 분리해 관리할 수 있다면 실시간 여유 슬롯 관리·응대가 훨씬 원활"

### P3. 콘텐츠 반영 지연 — 사진·설명·이벤트가 최신 상태와 어긋남 `명시` (속도)
- **본질**: 시즌성·계절성 콘텐츠(이벤트, 신규 사진)가 적시에 반영되지 않아 실제 환경과 페이지가 불일치
- **현재 처리 방식**: 카톡으로 운영팀(창우님) 요청 → 검수·승인 → 반영
- **비용**: 크리스마스 이벤트 약 1개월 / 옛날 사진 그대로 노출 / 사진 수정 어드민 요청 0건 (학습된 카톡 우회)
- **근거**: "크리스마스 이벤트 관련 내용 업데이트 요청 후 반영까지 약 한 달" / "옛날 사진이 그대로 노출" / "AI 번역으로 부담은 줄었지만 승인 구조 때문에 여전히 느림"

### P4. 텍스트 자율 수정 권한 부재 — 부분 자율 욕구 `명시` (속도 + 구조)
- **본질**: 핵심 카피는 검수 OK지만, 메뉴 설명·신규 프로모션은 직접 추가/수정하고 싶음
- **현재 처리 방식**: 카톡 요청 → 검수 흐름
- **비용**: 빠르게 시도해보고 싶은 프로모션·메뉴 변경의 출시 지연
- **근거**: "글은 자주 바꾸진 않지만, 메뉴 설명이나 새로운 프로모션 추가 등 필요 시 파트너가 직접 수정할 수 있으면 좋겠음"

### P5. 실시간 운영 가시성 부족 — 상품/메뉴/시간대별 현황 `명시` (구조)
- **본질**: 어드민이 "예약 수신·확정" 도장 역할에 그침, 비즈니스 현재 상태를 한눈에 볼 수 있는 화면 부재
- **현재 처리 방식**: 메일 수시 확인 + 개별 예약 단위로 관리
- **비용**: 직원 간 공유 어려움(향후 세분화 시 더 큼), 실시간 충돌 사전 인지 불가
- **근거**: "실시간으로 예약 현황(상품별/메뉴별/시간대별)을 직관적으로 볼 수 있는 화면 필요" / "타사(네이버)의 실시간성을 강점으로 언급"

### P6. 가격·메뉴 변경 흐름의 시스템 한계 — 취소→재예약 강제 `명시` (구조)
- **본질**: 같은 가격 내 메뉴명 변경 정도도 시스템 상 취소 후 재예약을 거쳐야 함 → 결제·정산 로직 한계
- **현재 처리 방식**: 취소 → 재예약 우회
- **비용**: 고객·운영 양측에 번거로움, 변경 회피·억제로 이어질 수 있음
- **근거**: "상품 변경 시 사실상 취소 후 재예약 흐름이 필요해 번거롭고, 같은 가격 내에서의 메뉴명 변경 정도는 시스템 상 유연하게 처리되면 좋겠음"

### 통합 해석

P1·P3·P4가 **속도 축**(변화의 즉시 반영), P2·P5·P6이 **구조 축**(표현의 유연성). 두 축은 보완 관계 — 구조가 경직되면 변경할 게 많아져 속도 압박이 커지고, 속도가 느리면 구조 변경 시도 자체를 포기하게 됨.

**메타 관찰 1 — 알림톡 거부**: "채널이 많아지면 헷갈림" → 카톡이 *비상연락망*이 아니라 *일상 채널*로 정착. 종합본 0.2의 "카톡=비상연락망" 원칙이 이 파트너에는 정착이 어려운 케이스. **알림 추가가 솔루션이 아니라, 변경 요청 UX 자체를 개선해야 카톡 트래픽이 줄어듦.**

**메타 관찰 2 — 자율 편집 스펙트럼**: 사진은 어드민 요청 채널 있고(성훈님), 글도 메뉴 설명·프로모션은 자율 희망. 종합본 2.4의 "사진만 자율"보다 한 발 더 — **"사진 + 부분 텍스트(메뉴/프로모션) 자율 / 핵심 카피는 검수"** 가 모델로의 실제 위치.

## 핵심 발견 (Top 우선순위 → 후순위)

### 1. 상품/옵션별 스케줄 분리 관리 ⭐⭐
- 현재는 "통합 메뉴" 구조 → **예약 1건 들어오면 상품 무관하게 일단 닫음**
- 갈증: **상품(헤어메이크업 포함/미포함, 샴푸 포함 등)별로 스케줄 분리**
- 레퍼런스: **네이버 플레이스** — 상품별 현황을 여닫을 수 있음
- 기능이 이미 있어도 모르는 듯한 정황 — **기능 노출/UX 개선 필요**

### 2. 실시간 예약 현황 가시성 ⭐
- "예약이 다 열려있는데 왜 안된다고 하냐"는 고객 불만 발생
- 다른 플랫폼/워킹 손님과 겹치는 시간도 일단 열어둠 → 고객 혼란
- 갈증: **상품별/메뉴별/시간대별 실시간 현황 화면**
- 레퍼런스: 네이버 어드민의 "실시간성"

### 3. 콘텐츠(사진) 직접 수정 권한 ⭐
- **사진 수정 의향 매우 높음** (글은 별로 안 바꿈)
- 현재 카톡 → 운영팀(창우님) 요청 구조
- 사례: 크리스마스 이벤트 사진 수정 **약 1개월 소요**
- 옛날 사진이 그대로 노출되어 실제 환경과 다른 사례 존재
- AI 번역 활용 가능 → 다국어 부담 줄었지만 **승인 구조 때문에 여전히 느림**
- 단, 잘못 수정에 대한 **약간의 부담**은 인정
- 어드민 사진 수정 요청 기능에 **업로드된 사진 ≠ 파트너 어드민 관리 사진** — 데이터 불일치 버그 가능성

### 4. 스팟 정보 수정 메뉴 인지/사용 격차
- "스팟 정보 수정 요청" 메뉴 **알긴 알지만 안 씀**
- 어드민에서 잡힌 수정 요청은 **시간슬롯 ON/OFF가 전부** (가격/패키지/사진 0건)
- → **콘텐츠 수정 = 100% 카톡 우회**의 실증
- 옵션 설명 업데이트에 대한 강한 니즈

### 5. 상품 변경(메뉴명/금액) 시 절차
- 현재는 사실상 **취소 → 재예약 흐름**이 필요해 번거로움
- 같은 가격 내 메뉴명 변경 정도는 **유연하게 처리**되면 좋겠음
- 금액 증감 발생 시 결제·정산 로직 이슈로 조심스러움 인지

### 6. 알림톡 정책 — 의도된 OFF
- 카카오 알림톡 OFF는 **의도된 선택**
- 이유: 예약 변경이 잦은 업무 특성상 카톡 알림보다 **직접 소통이 편함**
- 알림 채널이 많아지면 오히려 헷갈림 우려
- → **알림 다중화보다 변경 요청 UX 개선이 본질**

### 7. 취소/변경 권한
- 취소 권한 전면 위임은 위험성 인지 (악용 우려 — 크트 측 설명 수용)
- 모델로 자체적으로도 **취소보다 시간/메뉴 변경 유도**가 기본 전략
- 예약 확정 전 변경에 대한 시스템 지원 필요

## 가설 검증/관찰

### "63% 미처리의 진짜 사유"
- **인지보다 동기 + 기능 미스매치 문제**
  - 시간슬롯 단위 ON/OFF만 가능 → **상품별 스케줄 관리 불가** = 어드민으로 처리할 수 있는 일이 본질적으로 제한적
  - "예약이 들어오면 (상품 무관하게) 닫는다"는 운영 패턴은 어드민 기능 한계의 직접적 결과
- 즉, 단순히 "안 쓴다"가 아니라 **"써도 운영 니즈를 못 채운다"**

### "콘텐츠 수정 0건의 구조적 이유"
- **자동 승인 범위 인지 부재 + 검수 체감 시간(1개월) + 카톡 응답성(빠름)** 3박자
- 사진 수정 어드민 기능이 있어도 **표시 사진과 실제 관리 사진이 불일치**해서 신뢰 떨어짐
- 카톡 우회가 훨씬 안정적이라는 학습된 행동

### "부분 활용 → 주력 전환 트리거"
- **상품별 스케줄 분리 관리**가 도입되면, 시간 조정 카톡 의존도가 크게 줄 가능성
- **사진 직접 교체 권한**(약한 워크플로우라도)이 생기면 1개월 대기 사라짐
- 이 2개가 부분 활용을 주력으로 끌어올릴 핵심 레버

### "어드민에 없지만 필요한 기능 후보"
- 상품/옵션별 스케줄 ON/OFF (높음)
- 상품별/시간대별 실시간 현황 뷰 (높음)
- 사진 직접 교체 (약한 검토 워크플로우 포함, 높음)
- 같은 가격 내 메뉴명 변경 (중간)
- 어드민↔실제 노출 콘텐츠 동기화 정합성 점검 (버그 가능성)

## 메디큐브/순시키와의 비교 (러프)

| 항목 | 순시키 | 메디큐브 | 모델로 |
|------|--------|---------|--------|
| 어드민 자체 만족도 | 높음 | 보통 | 부분만 만족 |
| 카톡 우회 빈도 | 중간 | 높음 | 매우 높음 |
| 사진/콘텐츠 직접 수정 의향 | 언급 약함 | 부담 (원치 않음) | 사진은 강하게 원함 |
| 알림톡 인지 | 약함 | 인지 없음 (현장 안내됨) | 의도적 OFF |
| 공통 갈증 | 재방문 식별, 채널 통합 | 정보 정확성, 직접 메시징, 동행 | 상품별 스케줄, 사진 |

→ **공통 패턴**: 어드민 기능 인지 부재 + 카톡 우회 학습 + 운영 니즈 미충족
