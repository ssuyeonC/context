## 파트너가 실제로 겪는 문제

> **means-ends chain 매핑**: 어드민이 카톡보다 "명백히 더 나은 경험"이 되려면 아래 문제를 빠르고 가시적으로 해결해야 함.
>
> **본질 한 문장**: *내방 시점에 양측의 기대가 어긋나지 않도록, 예약을 둘러싼 정보가 양방향으로 정확히 도달해야 한다.*
>
> **두 방향의 정보 정합성** — 의료 카테고리 특유의 분쟁 비용 때문에 "트러블 회피·리스크 회피"가 모든 페인의 정서적 기저:
>
> ```
> [병원 → 고객]                       [고객 → 병원]
> 가격·조건·시술 가능 범위가          이름·연락처·SNS·동행 여부가
> 정확히 도달해야                     정확히 도달해야
> └ 내방 시 트러블 회피               └ 연락·CRM·정산 일치
> ```
>
> 주의: 이 파트너의 페인 무게중심은 **어드민이 아니라 유저페이지·운영 정보 흐름**에 있음. 어드민의 역할은 직접 처리보다 **요청 채널 + 진행 가시성** (종합본 0.4의 "요청 채널 흡수" 케이스).

### P1. 가격·조건의 고객 인지 부재 (병원 → 고객) `명시`
- **본질**: 상세페이지에 정보가 있어도 고객이 인지하지 못한 채 내방 → 기대 어긋남으로 트러블 위험
- **현재 처리 방식**: 매번 예약 방법·가격을 병원이 직접 안내 / 부적합 예약은 사후 조정
- **비용**: 반복 안내 시간 + 내방 시점 분쟁 리스크 + 보증금 항의 문의
- **근거**: "보증금만 우선 노출되어 가격을 인지하지 못하는 경우 많음" / "상세페이지 정보를 고객들이 잘 안 봄" / "Select an Option 영역의 거부 안내 잘 못 봄" / "이벤트 토글 안 열어보고 내려감"

### P2. 고객 정보의 병원 도달 실패 (고객 → 병원) `명시`
- **본질**: 고객이 입력한 이름·연락처·SNS가 부정확하거나 도달 불가 → 다운스트림(연락·CRM·정산·리뷰) 전부 깨짐
- **현재 처리 방식**: 왓츠앱 ID 적은 고객만 신속 대응 / 영문명을 수동 통일 / 차트 분산은 사후 정리
- **비용**: 연락 불가로 응대 지연, CRM 한 환자가 여러 차트로 분산, 정산 표기 혼란, 리뷰 작성 불가
- **근거**: "전화·이메일 틀리게 적으면 연락할 수가 없음, 재확인 절차 필요" / "예약자명을 여권 이름으로 통일해달라" / "SNS ID 비공개라 DM 불가" / "정산 시스템 표기가 실장님 영문 표기와 달라 헷갈림"

### P3. 동행 정보 표현 부재 (고객 → 병원) `명시`
- **본질**: 그룹 2~3명이 함께 오는데 따로 시간대로 예약 → 중간 타임이 블록되어 비효율
- **현재 처리 방식**: 동일 시간·날짜 다수 예약 시 동행 여부를 병원이 추측해야 함
- **비용**: 가용 타임 슬롯 손실, 운영 비효율, 분산 예약 정리 부담
- **근거**: "같이 오는데 시간대를 여러개로 설정하는 경우" / "동행 안내가 예약 과정에서 더 잘 보이도록" / "동일 날짜/시간 다수 예약 시 동행 여부 파악할 정보 필요"

### P4. 변경 시 직접 소통 채널 부재 (양방향) `명시 + 잠재`
- **본질**: 예약 변경·조정 시 양방향 즉시 소통이 필요한데 인앱 채널이 없어 외부(왓츠앱)로 우회
- **현재 처리 방식**: 왓츠앱으로 고객과 직접 소통 → 어드민에서 본인이 직접 변경 처리
- **비용**: 외부 채널 의존 / 왓츠앱 미입력 고객은 대응 속도 차이 / "변경 요청 메일"은 응답 지연으로 사실상 사용 안 함
- **근거**: "왓츠앱으로 고객과 소통 후 직접 하는 편" / "고객과 소통 시 이메일밖에 안 되는데 너무 느림" / "앱에서 고객에게 바로 연락할 수 있는 시스템이 마련되면 좋을 듯"

### P5. 기능 인지 부재로 워크어라운드 고착 (어드민 디스커버리) `잠재`
- **본질**: 이미 있는 기능을 모르고 외부 채널이나 수동 작업으로 우회 — 본인은 "불편 없다"고 인식하나 사실상 큰 비용 지불 중
- **현재 처리 방식**: 알림톡 모름 / 리뷰 댓글·자동 번역 모름 (현장에서 처음 인지) / '예약기본정보수정' 메뉴 의미 불명 / 정산 엑셀 일괄 업로드 모름
- **비용**: 카톡·이메일 우회로 제휴팀 시간 잠식 / 리뷰 응대 기회 손실 / 정산 입력 부담
- **근거**: "알림톡 있는지 몰랐음" / "리뷰 관리에서 댓글·자동 번역 가능하다는 기능을 처음 인지" / "예약기본정보수정 → 봐도 너무 어려워서 뭔지 잘 모르겠음"

### P6. 자율 편집 권한이 오히려 부담 (역방향 페인) `명시`
- **본질**: "직접 수정 권한 부여 = 더 좋은 경험"이라는 일반 가정의 반례 — 의료/언어 민감 카테고리는 오표기 리스크가 자율의 효용보다 큼
- **현재 처리 방식**: 가격·콘텐츠 변경은 크리에이트립에 요청 (현재 빈도가 낮아 큰 문제 없음)
- **비용**: (역방향) 자율 권한이 도리어 부담을 키울 수 있음 → 단일 정책으로 모든 파트너에게 자율 부여 시 워크로드 안 줄어듦
- **근거**: "블로그·제목 등 콘텐츠를 직접 수정하는 건 부담을 느낄 것 같음" / "14개 언어 오표기 부담" / "큰 빈도 변경은 아니어서 큰 문제는 없었음"

### 통합 해석

P1·P2·P3는 정보 정합성의 **세 갈래**(병원→고객 / 고객→병원 / 다자 관계), P4는 그 위에 얹히는 **양방향 즉시 소통 채널**, P5는 **이미 있는 채널의 디스커버리 실패**, P6은 **자율 편집의 역방향 페인**.

→ 이 파트너에 대한 해법의 무게중심은 어드민 자체 기능 개발보다 **(a) 유저페이지 정보 가시성 + (b) 입력 단계 검증 + (c) 인앱 메시징 + (d) 기능 온보딩** 쪽. 자율 편집 권한 부여는 이 파트너에겐 솔루션이 아니라 또 다른 부담임을 명심해야 함.

## 인터뷰 컨텍스트

- 실장님이 답변 주도, 인터뷰 시작 전부터 불편 사항을 줄줄이 토로하여 질문지 거의 미사용
- 예약 접수: 네이버 메일 + 별표 관리 (처리 시 별표 해제)
- 예약 변경: 고객 SNS 직접 소통 → 어드민에서 직접 변경
- 알림톡 존재 자체를 모르고 있었음 → 현장에서 추가 안내
- 신규 정산 시스템 만족도 높음 (단, 월 1회 일괄 입력으로 운영 변경됨)
- APR과 광고 협업(촬영·콘텐츠) 구조, 광고비는 APR 부담

## 핵심 발견 (Top 우선순위 → 후순위)

### 1. 예약자 정보 정확성 & CRM 통일 ⭐
- 전화번호·이메일 오입력으로 **병원이 고객에게 연락 불가** 사례 다수
- → **재확인(2회 입력) UX** 필요
- 외국인 고객이 닉네임/별명/철자 다름으로 **CRM 상 동일인이 여러 차트로 분산**
- → **예약자명을 여권 이름(영문) 기준으로 통일** 요청
- 신규 정산 시스템 표기와 실장님이 관리하는 영문 표기가 달라 혼란
- SNS ID 입력 시 **비공개 계정이라 DM 불가** — 입력 단계에서 검증/유도 필요

### 2. 앱 내 직접 연락 채널 ⭐
- 현재 커뮤니케이션 체인: 크리에이트립 → 병원 → 고객 (길고 느림)
- '변경 요청 메일'은 응답 지연/누락으로 **사실상 사용 안 함**
- 실제로는 실장님이 왓츠앱으로 직접 소통 → 어드민에서 변경 처리
- 갈증: **앱/플랫폼 내에서 병원이 고객에게 직접 메시지 보낼 수 있는 기능**

### 3. 동행 예약 처리 ⭐
- 그룹(2~3명)이 **서로 다른 시간대로 따로 예약** → 중간 타임 블록되어 비효율
- 갈증:
  - 예약 과정에서 **동행 안내가 더 잘 보이도록** 노출
  - 동일 날짜/시간 다수 예약 시 **동행 여부를 병원이 식별할 수 있는 정보(질문 항목)**

### 4. 리뷰 작성 가능 범위 확대 ⭐
- 시술 후 **예약 내역이 안 떠서 리뷰 못 쓰는** 케이스 존재
- **비회원 결제 고객**: 자신이 어떤 계정으로 예약했는지 몰라 리뷰 작성 어려움
- 비회원도 리뷰를 남길 수 있도록 하는 방안 요청
- 현재는 경쟁사 악성 리뷰 방지 위해 회원만 허용 중
- 리뷰 작성 시 병원 **메일 알림 누락** 케이스도 인지
- **어드민 리뷰 관리에서 댓글 작성/자동 번역 기능을 처음 인지** — 기능 노출 부족

### 5. 예약 캘린더/타임 관리
- 1년치 예약을 한 번에 열었을 때 **기존 차단 타임이 초기화**되는 문제 경험
- 갈증: "기존 차단 설정 유지하면서 뒤쪽 날짜만 추가 오픈" 로직
- 모바일/PC 모두 사용, 큰 불편 없음 (이 부분만 빼면)
- 주차별 예약 시간 관리: 1건 들어오면 닫는 운영 — 부담 신호

### 6. 보증금 노출 → 가격 인지 마찰
- 노쇼 방지 위해 보증금 운영 중
- 가격이 보증금만 우선 노출되어 **유저가 전체 가격을 인지 못해 문의 다수**

### 7. 상세페이지 정보 가독성
- 상단 공지("화장품 상담/피부측정만 위한 예약 받지 않음")에도 **부적합 예약 인입 지속**
- 이벤트·설명 영역 토글 → **고객이 안 열어보고 내려감**
- 갈증: **이벤트 토글 제거, 가격표/공지를 더 크게/직접 노출**
- (다른 병원은 토글 선호 — **병원별 설정 가능성** 논의)
- 추가 체크박스 늘리는 것보다 **상단 시각적 강조** 선호

### 8. 예약 UX 난이도 (고객 단)
- "예약 절차가 어렵다"는 고객 비중 약 **40%**
- 병원이 매번 예약 방법을 상세 안내해야 하는 부담
- 결제 실패: "휴대폰 껐다 켜기" 워크어라운드 안내 — 해외결제 차단/카드 이슈

### 9. 모바일 예약 확정 화면 요일 버그
- 모바일에서 **예약 확정 시 요일이 잘못 노출** (예: 5/12 토)
- → 단순 버그픽스 필요

### 10. 기타 알림/노출
- 고객 리뷰 작성 시 **알림 받고 싶음**
- '예약기본정보수정' 메뉴 — **봐도 너무 어려워 뭔지 모름** (UI 친화도 ↓)
- 상세페이지 내 '스페셜 이벤트' → 거의 안 보임

## 콘텐츠/언어 관련 입장

- **블로그/제목/콘텐츠 직접 수정 권한은 부담**
  - 14개 언어 중 대부분 영어 표기 — 이 구조 수용 가능
  - 오표기 부담 + 변경 빈도 낮음 → 현재 요청 방식으로 충분

## 타깃/비즈니스 컨텍스트

- 영어·스페인어권(미국/스페인) 집중 — 스페인어 가능 프론트 인력 보유 → 고가 시술 매출 ↑
- 중국·인도·중동·러시아: 언어/장비/사후 민원 이슈로 응대 어려움
- 일본: 단가/업셀링 수용도 낮아 ROI 낮게 인식
- 최근 예약 수요 둔화로 국적 가리지 않고 확정 중 (수요 많을 땐 선별)
- 중동 진출 희망했으나 플랫폼 부재 + 정세로 보류

## 가설 검증/관찰

- **"고객 정보가 부정확하면 모든 다운스트림이 깨진다"** — 메디큐브 케이스가 명확히 보여줌
  - 이름(여권명) → CRM 통합 → 정산 표기 → 리뷰 작성 가능 여부 → 직접 연락 가능 여부
  - 입력 단계 검증이 가장 ROI 높은 개입 지점
- **기능 인지 부재 패턴 반복**: 알림톡, 리뷰 댓글/자동번역 등 어드민 기능을 모르고 우회 중
- **상세페이지 강조도 vs 토글** — 병원별 선호가 다름 → 설정 가능성 필요
