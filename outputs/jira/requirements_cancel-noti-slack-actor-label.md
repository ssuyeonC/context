# 슬랙 예약 취소 알림 — 취소 주체 표기 정확화

## 배경

### 문제 정의

- `#-cs_noti-예약취소내역` 슬랙 채널은 다음 양식의 메시지를 매번 발송한다.
  ```
  *[예약 취소 발생]*
  취소자 : {ID 또는 '비회원'} ({유저 | 어드민})
  예약 번호 : {예약 코드}
  예약처 : {스팟 이름}
  ```
- 그러나 현재 출력 방식에는 두 가지 문제가 있다.
  - **"취소자" 라벨의 ID 자리에는 예약자의 ID가 출력된다.** 어드민이 취소했더라도 어드민의 ID가 아니라 예약을 한 사람의 ID가 박힌다. 즉 "취소자"라는 라벨과 실제 출력값이 어긋난다.
  - **라벨이 (유저) / (어드민) 두 종류뿐이다.** 시스템이 자동으로 취소한 케이스(만석, 결제 만료, 자동 환불 등)도 (유저)로 표시되어, 운영자는 슬랙만 봐서는 "유저 본인 취소"와 "시스템 자동 취소"를 구분할 수 없다.
- 운영팀이 매일 보는 채널이므로, 라벨이 실제 데이터와 어긋나면 취소 원인 추적과 패턴 분석의 신뢰도가 낮아진다.

### 가설적 임팩트

- **운영팀 취소 원인 추적 정확도 향상**: 슬랙 메시지만으로 "누가 또는 무엇이 취소를 트리거했는지"를 즉시 식별할 수 있다.
- **이상 패턴 조기 인지**: 시스템 자동 취소가 급증하는 케이스(특정 시간대 만석 충돌, 결제 시스템 이슈 등)를 운영자가 채널에서 즉시 발견할 수 있다.
- **정량 임팩트**: 운영팀 내부 분석 효율 개선이라 직접 KPI는 없으나, 매일 발송되는 알림의 신뢰도와 해석 가능성이 개선된다.

## 구현

### 유저 플로우

**운영자 (슬랙 메시지 수신자)**

- 운영자는 `#-cs_noti-예약취소내역` 채널에서 예약 취소 알림 메시지를 수신한다.
- 메시지의 '취소자' 라인은 다음 양식으로 노출된다.
  ```
  취소자 : {취소 주체 ID 또는 '-' 또는 '비회원'} ({유저 | 어드민 | 시스템})
  ```
- 운영자는 라벨만 보고 취소 주체를 즉시 식별할 수 있다.
  - **(유저)**: 예약자 본인이 직접 취소했다.
  - **(어드민)**: 운영팀 등 어드민이 취소했다.
  - **(시스템)**: 시스템이 자동으로 취소했다. (만석, 결제 만료, 자동 환불 등)
- 운영자가 (시스템) 케이스에 대해 더 상세한 사유를 확인하고 싶으면, 메시지의 스레드에서 취소 사유 코드를 볼 수 있다.

### 프론트엔드 요구사항

- 별도 변경 없음. 본 변경은 슬랙 메시지를 만드는 백엔드 로직에만 적용된다.

### 백엔드 요구사항

**분기 기준**

- 취소 주체는 예약의 취소 사유 데이터(`reservation_has_cancel_reason.type`)를 기준으로 판별한다.
- 사용 가능한 값은 다음 세 가지이며, 슬랙 라벨에 1:1로 매핑된다.

| 취소 사유 유형 | 슬랙 라벨 |
|---|---|
| `USER` (유저 본인 취소) | (유저) |
| `ADMIN` (어드민 취소) | (어드민) |
| `SYSTEM` (시스템 자동 취소) | (시스템) |

**'취소자' 라인 출력 규칙**

| 취소 사유 유형 | 회원 여부 | 출력 ID | 출력 라벨 |
|---|---|---|---|
| 유저 본인 취소 | 회원 | 예약자의 멤버 코드 | (유저) |
| 유저 본인 취소 | 비회원 | `비회원` | (유저) |
| 어드민 취소 | — | 취소를 실행한 어드민의 멤버 코드 | (어드민) |
| 시스템 자동 취소 | — | `-` (하이픈) | (시스템) |

- 어드민 취소 시 ID 자리에는 **예약을 실제로 취소 처리한 어드민의 멤버 코드**가 출력된다. 어드민 멤버 코드를 확인할 수 없는 비정상 케이스에서는 `-`로 폴백한다.
- 시스템 취소 시 ID 자리에는 별도 식별자 없이 `-`(하이픈)을 출력한다.

**스레드 메시지에 시스템 취소 사유 코드 추가**

- 취소가 시스템에 의해 발생한 경우, 메인 메시지의 스레드에 다음 한 줄을 추가로 노출한다.
  ```
  취소 사유 코드 : {취소 사유 코드}
  ```
  - 예: `취소 사유 코드 : FULLY_BOOKED_TRY_ANOTHER`
- 기존 스레드 메시지의 다른 라인(취소 일시, 예약자 정보, 기존 결제 금액, 총 환불 금액 등)은 그대로 유지하고, 시스템 취소일 때만 위 한 줄을 추가하는 방식이다.
- 유저 본인 취소나 어드민 취소 케이스에는 위 라인을 추가하지 않는다.

**필요 데이터**

- 슬랙 메시지를 생성하는 단계에서 다음 정보를 확보할 수 있어야 한다.
  - 예약의 취소 사유 유형 (`USER` / `ADMIN` / `SYSTEM`)
  - 시스템 취소일 경우 취소 사유 코드 (스레드 표기용)
  - 어드민 취소일 경우 취소를 실행한 어드민의 멤버 코드

**기존 분기 정리**

- 기존에 사용하던 `isAdmin` 단일 분기 플래그는 본 변경 이후 슬랙 메시지 빌더에서 더 이상 사용되지 않는다. 다른 사용처가 없으면 함께 정리한다.

**테스트 케이스**

- 회원이 본인의 예약을 취소한 경우, 메인 메시지에 `취소자 : {member_code} (유저)`가 출력되고 스레드에는 별도의 사유 코드 라인이 추가되지 않는다.
- 비회원이 본인의 예약을 취소한 경우, 메인 메시지에 `취소자 : 비회원 (유저)`가 출력되고 스레드에는 별도의 사유 코드 라인이 추가되지 않는다.
- 어드민이 예약을 취소한 경우, 메인 메시지에 `취소자 : {어드민 멤버 코드} (어드민)`가 출력되고 스레드에는 별도의 사유 코드 라인이 추가되지 않는다.
- 어드민의 멤버 코드를 확인할 수 없는 비정상 케이스의 경우, 메인 메시지에 `취소자 : - (어드민)`가 출력된다.
- 시스템 자동 취소가 발생한 경우, 메인 메시지에 `취소자 : - (시스템)`가 출력되고 스레드에는 `취소 사유 코드 : {취소 사유 코드}` 라인이 추가된다.
- 직전 실제 사례 검증: 만석으로 자동 취소된 예약(예: 예약 코드 `260527cks342`, 취소 사유 `FULLY_BOOKED_TRY_ANOTHER`)의 경우, 변경 전에는 `취소자 : 1382775 (유저)`로 표시되었으나 변경 후에는 메인 메시지에 `취소자 : - (시스템)`, 스레드에 `취소 사유 코드 : FULLY_BOOKED_TRY_ANOTHER`가 노출되어야 한다.

### 결정사항 요약

| 항목 | 결정 |
|---|---|
| 분기 기준 | 예약의 취소 사유 유형 (USER / ADMIN / SYSTEM) |
| (유저) ID 자리 | 예약자의 멤버 코드 (회원) 또는 `비회원` (비회원) |
| (어드민) ID 자리 | 취소를 실행한 어드민의 멤버 코드 |
| (시스템) ID 자리 | `-` (하이픈) |
| 라벨 종류 | (유저), (어드민), (시스템) 세 가지 |
| 시스템 취소의 세부 사유 | 메인 메시지 라벨은 (시스템) 하나로 통일, 스레드 메시지에 취소 사유 코드 추가 |
| 운영팀 사전 공지 | 불필요 (운영자가 자연스럽게 인지 가능) |
| 기존 단일 분기 플래그 | 본 변경 이후 사용처가 없어지면 함께 정리 |
