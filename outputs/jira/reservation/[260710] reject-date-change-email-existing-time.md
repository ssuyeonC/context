# 세부 기획안 요구사항 문서

## 배경

### 문제 정의

예약 날짜 변경이 불가하여 요청이 거절될 때, 고객에게 발송되는 **[Important] [Please Confirm ASAP] Reservation Change Request - Change Not Allowed Notice** 안내 메일이 있다. 이 메일 본문에는 고객의 기존 예약 정보가 **Existing reservation: 2026-06-09** 형태로 안내된다.

- 현재 이 안내에는 기존 예약의 **날짜만 표시되고, 예약 시간은 표시되지 않는다.**
- 같은 날짜에 여러 시간대 예약이 가능한 상품의 경우, 고객은 메일만으로는 어느 시간대의 예약이 대상인지 정확히 확인하기 어렵다.
- 그 결과 고객이 자신의 기존 예약 시간을 오인하거나, 문의(CS)를 통해 재확인해야 하는 혼선이 발생한다.

### 가설적 임팩트

- 기존 예약 시간이 함께 노출되면, 고객이 메일만으로 자신의 예약을 정확히 식별할 수 있어 혼선과 불신을 줄일 수 있다.
- 시간 확인을 위한 불필요한 재문의(CS)가 줄어든다.
- 노출 정보만 보완하는 변경이므로, 예약·매출 등 전환 지표에는 영향이 없다.

## 구현

### 유저 플로우

- 예약 날짜 변경 요청이 거절되어 거절 안내 메일을 받은 고객은, 본문에서 기존 예약의 **날짜와 시간을 모두** 확인할 수 있다.
  - 변경 전(현재): **Existing reservation: 2026-06-09**
  - 변경 후: **Existing reservation: 2026-06-09 14:00**
- 표시되는 시간은 고객이 실제로 예약한 현지 시간 기준이며, 예약 상세·다른 예약 안내에서 노출되는 시간과 동일하게 보인다.
- 예약에 시간 정보가 없는 경우(날짜만 존재하는 예약 등)에는 기존과 동일하게 날짜만 표시하고, 별도의 시간 문구를 덧붙이지 않는다.

### 프론트엔드 요구사항

해당 없음. (고객에게 발송되는 메일 본문만 수정되며, 화면 UI 변경은 없다.)

### 백엔드 요구사항

**예약 날짜 변경 거절 안내 메일의 "기존 예약" 표시에 예약 시간을 함께 포함한다.**

- 메일 본문의 기존 예약 안내 문구(**Existing reservation: DATE TIME**)에 채워지는 값을, 현재의 날짜만(예: `2026-06-09`)에서 **날짜 + 시간**(예: `2026-06-09 14:00`)으로 변경한다.
- 표시 시간은 예약이 보유한 예약 일시를 기준으로 하며, 예약의 시간대(현지 시간) 정보를 반영해 실제 예약 시간으로 노출되도록 한다. 다른 예약 안내에서 예약 일시를 표기하는 방식과 동일한 포맷을 사용한다.
- 이 안내 값은 실제 발송 경로와 메일 미리보기 경로 두 곳에서 각각 생성되므로, **양쪽 모두 동일하게 날짜+시간 포맷으로 맞춘다.** (한쪽만 수정되어 미리보기와 실제 발송 내용이 달라지지 않도록 한다.)
- 예약 일시 정보가 없는 예약의 경우, 시간 없이 기존과 동일하게 날짜만 표시하거나 값이 비지 않도록 안전하게 처리한다.
