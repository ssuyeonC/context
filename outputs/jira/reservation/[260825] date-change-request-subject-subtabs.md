# 세부 기획안 요구사항 문서

## 배경

### 문제 정의

- 어드민 예약내역 **'유저 예약 변경 요청'** 탭에는 두 종류의 건이 함께 노출
  - (A) 사용자가 직접 예약 변경을 요청한 건
  - (B) 관리자·파트너가 예약 변경을 요청 → 사용자가 승낙 → 관리자·파트너의 최종 확인이 필요한 건
- A·B 모두 시스템상 동일한 '사용자 응답 완료, 최종 승인 대기' 상태로 귀결되어 한 탭에 노출 — CX 운영 관점에서 '확인이 필요한 건'을 한곳에서 처리하는 구조라 통합 자체는 자연스러워 **유지 방침**
- 다만 탭 이름이 **'유저'로 한정**되어 있어 B(관리자·파트너 발 요청)까지 포함된다는 사실이 이름만으로 드러나지 않음 → 탭 성격(확인이 필요한 건)과 라벨 불일치
- 목록 단계에서는 각 건의 **최초 요청 주체**(사용자 / 관리자·파트너)를 바로 구분 불가 → 상세 진입·이력 재조회 필요
- 요청 주체별로 처리 우선순위·응대 방식이 달라, 주체 구분 없이 한 목록으로만 보면 운영 효율 저하

### 가설적 임팩트

- 탭 이름이 실제 성격(확인이 필요한 건)과 일치 → 신규 운영자 온보딩 부담·오인 감소
- 요청 주체를 목록 단계에서 즉시 구분 → 상세 진입·요청 이력 재조회 감소
- 라벨 교체·하위탭 추가에 한정되어 예약·매출 등 전환 지표에 영향 없음
- 정량 목표 지표: TBD (운영 효율성 개선 목적)

## 구현

### 유저 플로우

하위탭 구조 (운영자 관점):

- 기존 **'유저 예약 변경 요청'** 탭 라벨을 **'변경 승인 필요'**로 변경
- 해당('변경 승인 필요') 탭 하위에 요청 주체 기준 하위탭 3종 신설 — **전체** / **파트너·관리자 요청** / **유저 요청**
- 하위탭은 탭에 담긴 건들을 **최초 요청 주체**로 필터링해 노출 — 탭에 담기는 건의 범위·조건 자체는 기존과 동일, 주체별 분류만 추가
- 탭 진입 시 기본 선택 하위탭은 **전체**
- **전체** → 요청 주체 무관 전체 노출
- **파트너·관리자 요청** → 관리자 또는 파트너가 최초로 예약 변경을 요청하고 사용자가 승낙해 최종 확인 대기 중인 건 (관리자·파트너 통합)
- **유저 요청** → 사용자가 최초로 예약 변경을 요청한 건
- 각 하위탭 건수 배지 노출 여부 TBD

분류 기준:

- 요청 주체는 예약의 **현재 진행 중인 변경 요청 사이클**의 최초 요청 기록을 기준으로 판정
- **파트너·관리자 요청**은 관리자 발·파트너 발 요청을 하나로 묶어 판정 — 관리자/파트너 세부 구분은 이 하위탭에서 하지 않음
- 한 예약에 과거 종료된 요청 사이클과 현재 진행 중 사이클이 함께 존재할 수 있어, 주체 판정은 반드시 **현재 활성 사이클** 기준으로 스코핑 — 과거 종료 사이클의 요청 이력이 현재 건을 엉뚱한 주체로 오분류하지 않도록 방어

예외·범위:

- 관리자·파트너 발 요청이 **사용자 응답 대기 중**인 별도 탭('관리자 예약 변경 요청' 등)은 이번 범위 밖 — 현행 유지. 하위탭은 **'변경 승인 필요' 탭에만** 적용
- '예약 변경 완료'·'파트너 거절 요청' 등 그 밖의 탭은 변경 없음
- 사용자가 요청 대기 중인 상태에서도 관리자·파트너가 별도로 예약 변경 요청을 추가로 보낼 수 있는 현행 동작은 유지 — 이 경우에도 주체 분류는 활성 사이클의 최초 요청 기준으로 판정
- 관리자·파트너 세부 구분이 필요해지면 향후 하위탭 분리 별도 논의 — 이번엔 통합

### 프론트엔드 요구사항

- 상위 탭 라벨 **'유저 예약 변경 요청'** → **'변경 승인 필요'** 문구 교체
- '변경 승인 필요' 탭 활성 시 하위탭 3종 노출 — **전체** · **파트너·관리자 요청** · **유저 요청**
- 하위탭 선택 시 요청 주체 필터를 목록 조회 조건에 반영
- 탭 진입 시 기본 선택 상태는 **전체**
- 기존 요청 주체(요청자 롤) 필터 UI 패턴을 재사용하여 하위탭 구성

### 백엔드 요구사항

- 목록 조회에 요청 주체(유저 / 관리자·파트너) 필터 확대 — 기존 요청자 롤 기반 필터 인프라 재사용, **신규 컬럼·DB 마이그레이션 불필요** (요청 이력에 요청자 유형·요청자 롤·파트너 요청 식별값이 이미 적재)
- **유저 요청** 판정 → 활성 사이클의 최초 요청 주체가 사용자
- **파트너·관리자 요청** 판정 → 활성 사이클의 최초 요청 주체가 관리자 또는 파트너 (둘을 하나의 필터 값으로 묶음, 롤 세분 불필요)
- 주체 필터는 반드시 예약의 **현재 활성 변경 요청 사이클** 기준으로 스코핑 — 과거 종료된 사이클의 요청 이력이 현재 건에 매칭되지 않도록 서브쿼리 범위 한정
- 사용자 직접 요청 건과 '관리자·파트너 요청 → 사용자 승낙' 건은 모두 동일한 최종 승인 대기 상태로 귀결되므로, 이 탭 노출 대상 자체의 범위는 기존과 동일하게 유지 — 분류만 주체별로 세분
