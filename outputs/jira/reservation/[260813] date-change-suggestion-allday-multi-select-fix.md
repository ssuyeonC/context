# 세부 기획안 요구사항 문서

## 배경

### 문제 정의

- 관리자·파트너가 예약일 변경을 요청할 때, 유저에게 제안할 후보 일자를 여러 개 추가하고 각 일자에 대해 **'모든 시간'**(해당일 종일)을 지정 가능
- 이 '모든 시간' 지정에서 서로 연관된 두 가지 오동작이 발생

- **[증상 ①] 서로 다른 날짜에 '모든 시간' 후보를 여러 개 추가 불가**
  - 한 날짜를 '모든 시간'으로 추가한 뒤 다른 날짜를 '모든 시간'으로 추가하면, 추가되지 않고 **"이미 추가된 날짜입니다."** 노출
  - 결과적으로 한 요청에 '모든 시간' 후보를 하나만 넣을 수 있고, 여러 날짜의 종일 후보를 제안 불가 (특정 시간을 지정한 일반 후보는 여러 개 정상 추가)

- **[증상 ②] 후보 삭제 후 다른 날짜를 '모든 시간'으로 추가하면 엉뚱한 날짜가 입력**
  - 8/13을 '모든 시간'으로 추가 → 그 후보를 삭제 → 8/14를 '모든 시간'으로 선택하면, 실제로는 직전에 다뤘던 8/13이 다시 '모든 시간'으로 입력
  - 사용자가 지정한 날짜가 아니라 이전 날짜가 반영되는 잘못된 입력

- 두 증상 모두 '모든 시간' 선택이 **사용자가 화면에서 지정한 날짜와 어긋난 채 즉시 반영**되는 데서 비롯 — 버튼을 누른 즉시 후보로 확정되며, 이때 기준이 되는 날짜가 현재 선택 날짜가 아니라 직전 값 또는 기본값(오늘)으로 계산됨

### 가설적 임팩트

- 관리자·파트너가 한 번의 요청에서 여러 날짜의 종일 후보를 정확히 제안 가능 → 유저 선택지 확대, 오입력·재요청·CS 문의 감소
- 정량 효과: {미정} — '모든 시간' 후보가 포함된 예약일 변경 요청 건수, 종일 후보 단일 제한·오입력으로 인한 재요청 발생률 측정 필요

## 구현

### 유저 플로우

- 관리자·파트너는 서로 다른 여러 날짜에 대해 각각 '모든 시간' 후보를 추가 가능
- '모든 시간'은 사용자가 선택기에서 실제로 지정한 날짜를 대상으로 추가 (직전 날짜·기본값으로 대체되지 않음)
- 후보를 삭제한 뒤 새 날짜를 '모든 시간'으로 추가하면, 삭제 전 날짜가 아니라 새로 지정한 날짜가 반영
- 같은 날짜에 이미 '모든 시간' 후보가 있으면 중복 추가를 막고 **"이미 추가된 날짜입니다."** 노출 (기존 방어 유지)
- 날짜를 지정하지 않은 상태에서는 '모든 시간' 후보가 임의로 반영되지 않고, 날짜 선택을 먼저 유도

- 한 날짜는 '모든 시간'과 '특정 시간'을 함께 가질 수 없음 (종일은 그 날의 모든 시간을 포함하므로 상충)
  - 이미 '모든 시간' 후보가 있는 날짜에 특정 시간을 추가하려 하면 차단하고 **"해당 날짜는 이미 '모든 시간'으로 추가되어 있어 특정 시간을 추가할 수 없습니다."** 노출
  - 반대로 특정 시간 후보가 있는 날짜에 '모든 시간'을 추가하면, 그 날짜의 기존 특정 시간 후보를 모두 제거하고 '모든 시간'으로 대체(종일 승격) — 차단하지 않음

### 프론트엔드 요구사항

- '모든 시간' 지정 방식을 '저장' 기반으로 통일
  - 현재는 '모든 시간 선택'을 누르는 즉시 후보로 확정되어, 화면에서 지정한 날짜와 어긋나는 문제의 원인
  - `날짜 선택 → (특정 시간 또는 '모든 시간') → 저장` 순서로 통일하여, 저장 시점에 화면에 표시된 날짜를 기준으로 후보를 확정 → 증상 ①·② 동시 해소, 특정 시간·종일 조작 방식 일관
  - 날짜를 지정하지 않은 상태에서는 저장을 비활성 처리하고 날짜 선택을 안내하여, 임의 날짜(오늘)가 반영되지 않도록 처리
- 후보를 삭제하면 관련 편집 상태가 남지 않도록 정리하여, 다음 '모든 시간' 지정이 이전 날짜를 재사용하지 않도록 처리
- 종일과 특정 시간의 상호배제 반영
  - 특정 시간을 추가할 때 같은 날짜에 '모든 시간' 후보가 있으면 차단하고 안내 노출
  - '모든 시간'을 추가할 때 같은 날짜의 특정 시간 후보를 제거하고 종일로 대체
- '모든 시간' 기능은 시간 입력이 필요한 상품에서만 노출되므로, 본 수정도 해당 조건에서만 적용
- 검증 시나리오
  - 서로 다른 두 날짜에 각각 '모든 시간' 지정 → 둘 다 추가
  - 8/13 '모든 시간' 추가 → 삭제 → 8/14 '모든 시간' 지정 → 8/14 추가
  - 같은 날짜에 '모든 시간' 중복 지정 → **"이미 추가된 날짜입니다."** 노출
  - '모든 시간' 후보가 있는 날짜에 특정 시간 추가 → 차단 + 안내
  - 특정 시간 후보가 있는 날짜에 '모든 시간' 추가 → 그 날짜의 특정 시간 후보 제거 후 종일로 대체, 다른 날짜 후보는 유지
  - 날짜 미지정 상태에서 저장 시도 → 임의 추가 없이 날짜 선택 유도

### 백엔드 요구사항

- 없음 — 후보 일자·종일 여부 값은 기존 입출력 구조에 이미 존재하며, 본 건은 관리자 화면에서 후보를 추가하는 동작의 결함. 서버로 전달되는 데이터 형식 변경 없음
