# 세부 기획안 요구사항 문서

## 배경

### 문제 정의

- 어드민 예약 상세의 **최근 수정내역**은 현재 완료된 변경만 기록 — 예약일 변경은 적용이 끝난 시점에만 **예약일 변경** 1건으로 노출
- 예약일 **변경 요청** 단계(요청 생성·거절·철회)는 최근 수정내역에 남지 않고 별도 요청 이력에만 적재되어 예약 상세 화면과 단절
- 운영자가 예약 상세 화면만으로는 "누가 언제 변경을 요청·거절·철회했는지" 확인 불가
- 관리자·파트너가 이미 보낸 변경 요청을 스스로 되돌리는 **철회 수단 자체가 부재** → 잘못 보낸 요청을 상대 응답·거절을 기다리거나 방치
- 관리자·파트너·사용자 어느 주체가 요청을 보내도 그 흔적이 예약 상세에 드러나지 않아, CS·분쟁 대응 시 이력 재조회 필요

### 가설적 임팩트

- 예약 상세 한 화면에서 변경 요청·거절·철회 이력까지 파악 가능 → 별도 이력 조회 단계 제거
- 관리자·파트너가 잘못 보낸 요청을 즉시 철회 가능 → 불필요한 요청 노출·응답 대기·오안내 방지
- 요청 경위 확인을 위한 CS 재조회·재문의 감소 기대
- 기록 항목 추가는 예약·매출 등 전환 지표에 영향 없음

## 구현

### 유저 플로우

기록 관점:

- 관리자가 예약일 변경을 요청 → 최근 수정내역에 **예약일 변경 요청** 기록, 수정자 **관리자**
- 파트너가 예약일 변경을 요청(알림톡·토큰 경유) → **예약일 변경 요청** 기록, 수정자 **파트너**
- 사용자가 예약일 변경을 요청 → **예약일 변경 요청** 기록, 수정자 **사용자**
- 로그인하지 않은 사용자가 예약일 변경을 요청해도 수정자는 **사용자** 태그로 고정 표기
- 관리자·파트너가 사용자의 변경 요청을 거절(고객 통보 거절) → **예약일 변경 요청 거절** 기록
- 무통보 거절은 최근 수정내역에 기록하지 않음
- 관리자가 본인이 보낸 진행 중 변경 요청을 철회 → **예약일 변경 요청 철회** 기록, 수정자 **관리자**
- 파트너가 본인이 보낸 진행 중 변경 요청을 철회 → **예약일 변경 요청 철회** 기록, 수정자 **파트너**
- 변경 요청이 최종 적용 완료 → 기존과 동일하게 **예약일 변경** 기록(변동 없음)
- 세 주체의 '요청'은 하나의 수정 내용(**예약일 변경 요청**)으로 통일, 주체 구분은 수정자 태그(관리자·파트너·사용자)로만 노출

철회 기능 관점:

- 관리자는 관리자 본인이 보낸 진행 중 변경 요청을 철회 가능
- 파트너는 파트너 본인이 보낸 진행 중 변경 요청을 철회 가능
- 철회는 **본인이 보낸 요청**에 한정 — 사용자가 보낸 요청은 철회 대상 아님(해당 건은 기존 '거절'로 처리)
- 철회 시 예약의 변경 요청 **진행 상태만 해제(요청 없던 상태로 복귀)** → 새 변경 요청을 즉시 다시 보낼 수 있음
- 진행 상태를 별도 '철회됨' 상태로 남기지 않음 — 철회는 거절과 달리 쿨다운·거절 흔적 등 후속 로직이 없어 진행 플래그를 비우는 것으로 충분
- 진행 상태값을 남기지 않아도 철회 사실은 최근 수정내역(**예약일 변경 요청 철회**)·요청 이력에 별도로 기록·보존 — '요청 없던 상태로 복귀'는 예약의 진행 상태 플래그에 한정되며 데이터 삭제가 아님
- 철회 시 유저에게 **진행 중이던 예약일 변경 요청이 철회되었음**을 알리는 안내 메일 발송

예외·범위:

- 철회 가능 조건 — 요청이 아직 진행 중(적용·거절·철회 전)인 상태에 한해 철회 허용, 이미 적용·거절·철회된 요청은 철회 불가
- 관리자가 파트너가 보낸 요청을 대신 철회하는 운영 대행은 이번 범위 밖 — 필요 시 별도 논의

### 프론트엔드 요구사항

- '최근 수정내역' 요약 영역과 '전체 수정내역' 모달 양쪽에 신규 수정 내용 문구 노출
  - **예약일 변경 요청**
  - **예약일 변경 요청 거절**
  - **예약일 변경 요청 철회**
- 수정자 컬럼은 기존 태그 재사용 → **관리자**(파랑)·**파트너**(초록)·**사용자**(하늘색)로 주체 구분 노출
- 비로그인 사용자 요청도 수정자 태그는 **사용자**로 노출
- 주체별 문구 분리 없이 단일 '요청' 문구 + 수정자 태그 조합으로 표기
- '최근 수정내역' 요약은 가장 최근 1건만 노출하는 기존 규칙 유지 → 요청·거절·철회도 시점이 가장 최신이면 요약 영역에 노출
- 변경 요청 철회 진입점 신설
  - 관리자: 어드민 예약 상세에서 관리자 본인이 보낸 진행 중 변경 요청을 철회하는 액션 노출
  - 파트너: 파트너 채널에서 파트너 본인이 보낸 진행 중 변경 요청을 철회하는 액션 노출(진입 화면·수단 상세 TBD)
  - 철회 가능한 상태(진행 중)에서만 액션 노출, 진행 중이 아닌 요청에는 미노출

### 백엔드 요구사항

- 수정내역 유형 목록에 **예약일 변경 요청**·**예약일 변경 요청 거절**·**예약일 변경 요청 철회** 항목 추가(기존 유형 목록에 값 추가 방식이라 기존 연동 하위호환 안전)
- 예약일 변경 요청이 생성되는 세 경로(관리자 요청·파트너 토큰 요청·사용자 요청) 각각에서 수정내역 기록 발생, 수정자 유형을 관리자·파트너·사용자로 각각 구분 지정
- 파트너 토큰 요청 경로는 로그인 계정 정보 없이 파트너 식별값만 존재 → 수정자 유형을 파트너로 명시 지정 필요
- 비로그인 사용자 요청 경로는 계정 정보 없이 접수되더라도 수정자 유형을 사용자로 고정 지정
- 예약일 변경 요청 거절 경로는 고객 통보 거절만 수정내역 기록, 무통보 거절은 기록 제외
- 변경 요청 철회 기능 신규 구축
  - 관리자·파트너가 본인이 보낸 진행 중 변경 요청을 철회하는 처리 신설
  - 철회 시 예약의 변경 요청 진행 상태(진행 중 플래그)를 **해제(요청 없던 상태로 복귀)** → 재요청 가능. 별도 '철회됨' 잔존 상태로 남기지 않음(기존 거절과 달리 쿨다운·거절 흔적 불필요). ※ 재요청 가능 여부 자체는 진행 상태값을 참조하지 않으므로 상태 표현과 무관하게 보장됨
  - 철회 사실 기록은 진행 상태값과 별개 — 최근 수정내역은 시점별로 쌓이는 로그이므로, 진행 상태를 비워도 **예약일 변경 요청 철회** 기록은 그대로 남음
  - 해당 요청 이력 record는 철회 종료로 표시(응답 대기 해제)하되 **삭제하지 않음** — 철회 이력은 요청 이력·최근 수정내역으로 보존
  - 본인이 보낸 요청만 철회 가능하도록 권한·소유 검증(다른 주체가 보낸 요청 철회 차단)
  - 철회 처리 시 최근 수정내역 기록 발생, 수정자 유형을 관리자·파트너로 구분 지정
  - 철회 시 유저에게 철회 안내 메일 발송(아래 메일 요구사항)
- 부가 알림: 요청·거절·철회 유형에 대한 Slack 알림은 불필요 — 수정내역 적재 및 철회 안내 메일 발송까지만 수행

철회 안내 메일 요구사항:

- 기존 거절 안내 메일과 동일한 **고정 템플릿 방식** — 요청자가 본문을 작성·선택하지 않음
- 안내 내용: **진행 중이던 예약일 변경 요청이 철회되어 별도 조치가 필요 없음**을 유저에게 통보
- 기존 예약일 변경 요청 메일의 골격(로고·예약처명·예약번호·예약자명·예약상품 블록·하단 소셜/카피라이트)을 따르되, 본문은 철회 통보 문구로 고정
- 발송 대상·수신 주소 처리(예약자 이메일 + 로그인 회원 이메일 병합, 운영 아카이브 BCC)는 기존 예약 관련 메일 발송 방식과 동일
- 언어별 템플릿 신규 작성 필요(기존 요청·거절 메일과 동일하게 예약 언어 기준 발송) — 대상 언어 목록 TBD
