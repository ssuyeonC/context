# 세부 기획안 요구사항 문서

> 🧭 **마스터 [260701] §4·§6의 실행 스포크** — P0 **REGION 트랙(③④⑤⑦)** 정본: REGION 어드민 개선(법정동 picker)·관광지 REGION 생성·REGION 정리(RG-1·RG-3)·관광지 DL cutover 삭제.
>
> **범위 경계**: ①② CITY/DL legal 정합·스팟 1차 재태깅 = `[260701] region-detail-location-cleanup.md` / ⑥ 스팟 지역 표기·검색 = `[260708] region-display-and-search.md`. 본 문서는 그 사이 REGION 데이터·어드민 트랙을 담는다.

## 배경

### 문제 정의

지역(REGION) 도메인 개편으로, 유저가 인지하는 구역(홍대·명동·성수 등)을 담는 **인지구역(REGION)** 을 "구(상세지역) 연결 + 그 구의 법정동 선택"으로 그리기로 확정했다(마스터 §3). 관광지 개념은 상세지역(DETAIL_LOCATION)에서 빼내 REGION으로 이관한다. 그런데 이관을 실제로 하려면 다음이 선행돼야 하는데 아직 없다.

- **REGION 어드민이 '구 연결 + 법정동 선택'을 표현하지 못한다.** 현재 편집 화면에 법정동을 고르는 UI가 없어, 관광지 인지구역(홍대=마포구+{서교동·동교동…})을 만들 수 없다.
- **비공개·방치 REGION이 대량으로 남아 있다.** region 514개 중 공개는 13개뿐이고, 대부분은 2025-02-14 자동 벌크 생성분(id 25~531, 500개)으로 방치돼 있어 새 구조로 가기 전에 정리해야 한다.
- **스팟↔region 직접 연결(`region_spot_area_has_spot`, 6 area·27링크)** 이 남아 있어, 스팟 노출을 legal(법정동) 기반으로 옮기는 새 모델과 어긋난다.
- **관광지 상세지역(홍대·명동 등)이 지금 스팟 카드·검색에 노출 중**이라, 대응 REGION이 표기·검색으로 살아나기 전에 지우면 그 창(window) 동안 관광지명 탐색이 끊긴다. 따라서 **무중단**(REGION이 대체한 뒤 삭제)이 필수다.

### 가설적 임팩트

- 관광지 인지구역이 데이터로 확립돼, 스팟 표기·검색(`[260708]`)과 이후 지역 페이지의 **기반**이 된다.
- 관광지명(홍대·성수·명동) 탐색이 시군구가 아니라 **인지구역 단위로 보존·격상**된다.
- 방치 REGION·직접 연결이 정리돼 운영·데이터 정합이 개선된다.
- 본 작업은 직접적인 유입·전환 지표를 겨냥한 성장 작업이 아니라 **토대 정비**다. 사용자 대상 정량 지표는 도입 후 사후 측정 — `TBD`.

## 구현

> 실행 순서(P0 내): ③ REGION 정리 → ④ 어드민 개선(picker) → ⑤ 관광지 REGION 생성·연결 → **⑥ 표기·검색 cutover(`[260708]`)** → ⑦ 관광지 DL 삭제. **⑦은 ⑥ 완료(REGION이 표기·검색으로 라이브) 이후** — 이것이 무중단 조건이다.

### 유저 플로우

> 주 행위자는 **관리자**. 일반 사용자에게는 관광지명이 인지구역으로 보존되는 결과만 반영된다(표기·검색 동작은 `[260708]`).

- 관리자는 인지구역(REGION) 편집 화면에서 **구(상세지역)를 연결**하고, 그 구에 속한 **법정동 목록에서 인지구역에 포함할 법정동을 체크로 선택**한다.
- 관리자가 법정동을 따로 좁히지 않으면 연결한 구의 **전체 법정동**을 범위로 본다.
- 인지구역의 **상위 도시(시도)는 선택한 구들의 공통 상위로 자동 결정**된다. 서로 다른 시/도의 구를 함께 선택할 수 없다.
- 관리자는 관광지 이름(홍대·명동·성수 등)으로 인지구역을 만들고 위 방식으로 구·법정동을 연결한다.
- 관리자는 한 도시 하위 상세지역을 **전부 선택할 수 없다**(도시 전체와 같은 범위 금지 — `[260708]`).

### 프론트엔드 요구사항

**어드민 — 인지구역(REGION) 편집: 법정동 picker (신규)**

- REGION 편집 화면에 **구(상세지역) 연결** + 그 구의 **법정동 pool 표시 → 체크 선택** UI를 신설한다.
- 법정동 pool은 저장값이 아니라 **구 코드 접두어로 조회 시 자동 도출**(읽기 전용 목록에 체크박스). 예: 성동구 `11200` → 성수동1가 `11200114` …
- **상위 도시(시도)는 선택 구의 공통 상위로 자동 표시**(수동 배선 없음). 다른 시/도의 구가 함께 선택되면 저장을 막고 안내한다.
- 연결한 구의 법정동을 **전부 해제하는 저장은 막는다**(그 구를 빼려면 구 연결을 해제). 인지구역의 유효 법정동 집합은 비어 있을 수 없다.
- 도시 전체 범위 금지·안내 문구는 `[260708]`의 인지구역 생성 제약을 따른다.

### 백엔드 요구사항

**REGION 스키마 — 컬럼 재사용 (신규 테이블 없음)**

- `region_has_detail_location` — REGION ↔ 구(DL) 연결(범위). 기존 브리지 재사용.
- `region.legal_location_legal_codes` — **의미 전환·재사용**: 기존 '프리픽스 LIKE용 코드배열' → REGION이 **선택한 법정동(L3) 코드 집합**.
- 구의 하위 법정동 pool은 **저장·연결하지 않는다** — 구 코드 prefix로 조회 시 자동 도출.

**REGION 스팟 조회**

- REGION 스팟 = **선택 법정동에 `spot.legal_code`가 속하는 스팟**. (지도 폴리곤 = 선택 법정동들의 union.)
- ※ 스팟에 붙는 지역 태그는 **시군구 DL(L2)**, 법정동(L3)은 스팟에 붙지 않고 REGION의 선택 단위다(스팟은 이미 가진 `legal_code`로 필터되므로 재태깅 대상 아님).

**⑤ 관광지 REGION 생성 (일회성 마이그레이션)**

- 현재 **관광지형 DETAIL_LOCATION 이름**(홍대·명동·성수 등) 기준으로 대응 REGION을 생성한다. 이미 공개 REGION이 있는 이름·중복 이름은 제외한다.
- 각 관광지 REGION에 소속 구(DL)를 연결하고 관광지권 법정동을 선택한다(예: 홍대 = 마포구 + {서교동·동교동·상수동…}).
- 기존 **공개 REGION 13개**도 새 구조(구 연결 + 법정동 선택)로 재배선한다.

**③ REGION 정리**

- **RG-1 — 비공개 REGION 삭제**: 2025-02-14 벌크 500개(`id 25~531`) 삭제. **공개(is_publish) REGION·⑤에서 생성한 관광지 REGION은 제외.** (검증: 삭제집합 내 공개 0·하드코딩 id 4·5·15 안전 확인 완료.)
- **RG-3 — 직접 연결 해제**: `region_spot_area_has_spot`(6 area·27링크) 정리 — 스팟↔region 직접 연결을 제거한다(새 모델은 legal 기반).

**⑦ 관광지형 DL 삭제 (표기·검색 cutover 이후)**

- 대응 REGION이 **표기·검색으로 노출된 뒤**(`[260708]` 완료) 수행한다.
- 관광지 DL에 걸린 **스팟**은 소속 시군구 DL로 재태깅(`spot.legal_code` prefix로 소속 구 도출).
- 관광지 DL에 걸린 **블로그·어학당**은 `legal_code`가 없어 자동 도출이 불가하므로 **소속 구로 수동 이관**한다.
- 이관 완료 후 **관광지형 DETAIL_LOCATION을 삭제**한다.
