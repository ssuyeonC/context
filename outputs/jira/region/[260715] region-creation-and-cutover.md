# 세부 기획안 요구사항 문서

> 🧭 **마스터 [260701] §4·§5·§6의 실행 스포크** — P0 **REGION 트랙(③④⑤⑥⑦)** 정본: REGION 어드민 개선(법정동 선택)·관광지 REGION 생성·REGION 정리(RG-1·RG-3)·**스팟 지역 표기·검색**·관광지 DL cutover 삭제
>
> **범위 경계**: ①② CITY/DL legal 정합·스팟 1차 재태깅 = `[260701] region-detail-location-cleanup.md`. 본 문서는 그 위에서 **REGION 생성 → 표기·검색 전환 → DL 삭제**까지 한 흐름을 담는다.

## 배경

### 문제 정의

지역(REGION) 도메인 개편으로, 유저가 인지하는 구역(홍대·강남·성수 등)을 담는 **인지구역(REGION)** 을 "구(상세지역) 연결 + 그 구의 법정동 선택"으로 그리기로 확정(마스터 §3). 관광지 개념은 상세지역(DETAIL_LOCATION)에서 빼내 REGION으로 이관, 스팟의 지역 표기·검색도 시군구가 아니라 인지구역 기준으로 격상. 이관·격상을 실제로 하려면 다음이 선행돼야 하나 아직 없음

- **REGION 어드민이 '구 연결 + 법정동 선택'을 표현하지 못함** — 현재 편집 화면에 법정동을 고르는 UI가 없어 관광지 인지구역(홍대=마포구+{서교동·동교동…})을 만들 수 없음
- **비공개·방치 REGION이 대량 잔존** — region 514개 중 공개는 13개뿐, 대부분은 2025-02-14 자동 벌크 생성분(id 25~531, 500개)으로 방치됨
- **스팟↔region 직접 연결(`region_spot_area_has_spot`, 6 area·27링크) 잔존** — 스팟 노출을 legal(법정동) 기반으로 옮기는 새 모델과 어긋남
- **스팟 지역 표기가 아직 시군구 기준** — 현재 도시(CITY)와 상세지역(DETAIL_LOCATION) 병기(예: '서울시 강남구', '강릉시'). 유저는 시군구보다 인지구역(홍대·성수·신사) 이름으로 위치를 사고하므로 표기·검색을 인지구역으로 격상 필요
- **관광지 상세지역(홍대·명동 등)이 지금 스팟 카드·검색에 노출 중** — 대응 REGION이 표기·검색으로 살아나기 전에 지우면 그 창(window) 동안 관광지명 탐색이 끊김. 따라서 **무중단**(REGION이 대체한 뒤 삭제)이 필수

표기·검색에서 고려할 두 성질

- **인지구역은 큐레이션 자산이라 모든 스팟을 덮지 않음** — 스팟의 인지구역 소속은 저장값이 아니라 스팟의 법정동 코드가 그 인지구역의 선택 법정동 집합에 속하는지로 판정. 어떤 인지구역에도 속하지 않는 스팟은 **{도시} {상세지역}(시군구)** 으로 되돌림(fallback)
- **하나의 스팟이 둘 이상의 인지구역에 걸릴 수 있음**('신사'·'강남'에 함께 속함) — 대표로 표기할 하나를 정하는 규칙 필요. 좁은 구역이 늘 낫진 않아('강남'이 '신사'보다 인지도 높은 경우) 자동 판정만으로는 부족 → **운영자가 인지구역 순서로 대표를 통제**(구현부 §대표 인지구역 선정 규칙). 단 현재 REGION에는 순서 값·변경 기능이 없어 신설 필요

### 가설적 임팩트

- 관광지 인지구역이 데이터로 확립되고, 스팟 표기·검색이 인지구역 기준으로 격상돼 이후 지역 페이지의 **기반**이 됨
- 관광지명(홍대·성수·신사) 탐색이 시군구가 아니라 **인지구역 단위로 보존·격상**되고, 시군구로는 잡히지 않던 검색 커버리지가 넓어짐
- 스팟 위치가 유저 인지 지역명으로 표기돼 위치 파악·신뢰가 높아지고, 스팟 상세의 인지구역 표기가 지역 페이지로 이동하는 **진입점**이 됨
- 방치 REGION·직접 연결 정리로 운영·데이터 정합 개선
- 본 작업은 직접적인 유입·전환 지표를 겨냥한 성장 작업이 아니라 **토대 정비**. 사용자 대상 정량 지표는 도입 후 사후 측정 — `TBD`

## 구현

> **실행 순서(P0 내)**: ③ REGION 정리 → ④ 어드민 개선(법정동 선택) → ⑤ 관광지 REGION 생성·연결 → ⑥ 표기·검색 전환 → ⑦ 관광지 DL 삭제. **⑦은 ⑥ 완료(REGION이 표기·검색으로 라이브) 이후** — 이것이 무중단 조건

### 유저 플로우

**관리자 — 인지구역 생성·편집**
- 인지구역 편집 화면에서 **상세지역(구)을 연결**하면 상위 도시(시도)가 자동으로 정해지고, 그 구의 **법정동(동)이 전체 선택된 상태로** 표시
- 표시된 법정동 중 일부를 해제해 범위를 좁힐 수 있음(예: 성동구를 고른 뒤 성수동1·2가만 남김). 따로 좁히지 않으면 그 구 전체가 범위
- 한 상세지역의 법정동을 전부 해제할 수는 없음(그 구를 빼려면 상세지역 연결을 해제)
- **한 도시의 상세지역을 전부 선택할 수는 없음**(도시 전체와 같은 범위 불가). 전부 선택하면 저장이 막히고 안내 노출
- 하나의 인지구역은 오직 한 도시 아래에만 위치. 서로 다른 도시의 상세지역을 함께 고를 수 없음
- 관광지 이름(홍대·명동·성수 등)으로 인지구역을 만들고 위 방식으로 구·법정동을 연결
- 인지구역 목록에서 **순서를 조정** 가능. 한 스팟이 여러 인지구역에 걸리면 **순서가 앞선 인지구역이 대표로 표기**되고(예: '강남'을 '신사'보다 위에 두면 강남으로 노출), 도시 페이지의 구역 그리드도 이 순서로 노출

**사용자 — 스팟 지역 표기·검색**
- 스팟 상세 페이지에서 **{도시} {인지구역}** 표기 노출(예: Seoul Sinsa). 인지구역에 속하지 않으면 **{도시} {상세지역}**(예: Seoul Gangnam-gu / 강원특별자치도 강릉시)
- 스팟 상세에서는 지역 표기를 눌러 지역 페이지로 이동 가능, 카드·검색 결과에서는 같은 표기를 **링크 없이 텍스트로만** 노출
- 인지구역 이름으로 검색하면(예: 신사) 그 구역 스팟이 노출되고 표기가 검색어에 맞춰 Seoul Sinsa로 노출. 같은 스팟을 다른 인지구역명으로 검색하면(강남) Seoul Gangnam으로 노출(검색어에 따라 다르게 표기 — 의도된 동작)
- 인지구역명이 아닌 검색어(스팟 이름 등)면 상세 페이지와 동일한 대표 인지구역(없으면 상세지역)으로 표기

### 프론트엔드 요구사항

**어드민 — 인지구역 편집: 법정동 선택 (④, 신규)**
- REGION 편집 화면에 **상세지역(구) 연결** + 그 구의 **법정동(동) 목록을 전체 선택 상태로 노출 → 체크 해제로 범위 조정** UI 신설
- 법정동 목록은 **구 코드 접두어로 자동 도출**한 결과를 읽기 전용으로 노출(저장된 매핑 아님, 수동 추가 없음). 예: 성동구 `11200` → 성수동1가 `11200114`
- 상세지역을 고르면 **상위 도시(시도)를 자동으로 채워** 노출. 다른 시/도의 구가 함께 선택되면 저장을 막고 안내
- 한 구의 법정동을 **전부 해제하는 저장은 차단**(그 구를 빼려면 상세지역 연결 해제), 한 도시 상세지역을 **전부 선택하는 것도 차단**(도시 전체 범위 불가). 안내: **"도시 전체 범위의 지역은 만들 수 없어요. 상세지역을 하나 이상 제외해 주세요."**(문구 `TBD`)

**어드민 — 인지구역 순서 (④, 신규)**
- 인지구역 목록(도시 단위)에 **순서 표시 + 재정렬** UI 신설 — 드래그 또는 순서 번호 입력으로 변경(현재 순서 값·기능 없음)
- 이 순서가 **대표 인지구역 선정의 1순위 기준**이자 **도시 페이지 구역 그리드 노출 순서** — 한 값으로 두 용도 공용

**스팟 지역 표기 (상세·카드 공통, ⑥)**
- 지역 표기를 도시+상세지역 병기에서 **{도시} {대표 인지구역}** 으로 변경(대표 인지구역은 백엔드가 내려주는 값 그대로)
- 인지구역에 속하지 않으면 **{도시} {상세지역}(시군구)** fallback. 표기 언어는 유저 현재 로케일

**링크 처리 (⑥)**
- 스팟 상세: 지역 표기(인지구역, fallback 시 상세지역/도시)를 지역 페이지 링크로 처리
- 스팟 카드·검색 결과: 링크 없이 텍스트로만
- 대상 지역 페이지가 아직 없으면 링크 비활성(텍스트만). 링크 개방 시점은 지역 페이지 라이브 이후 — `TBD`

**검색 결과 표기 (⑥)**
- 검색 결과 카드는 검색어에 매칭된 인지구역으로 **{도시} {매칭 인지구역}** 표기
- 어떤 인지구역과도 매칭 안 되면(스팟 이름 검색 등) 상세와 동일한 대표 인지구역(없으면 상세지역)
- 표기에 쓸 인지구역·문자열은 백엔드가 검색 결과와 함께 내려주는 값을 따름

### 백엔드 요구사항

**REGION 스키마 — 컬럼 재사용 (신규 테이블 없음)**
- `region_has_detail_location` — REGION ↔ 구(DL) 연결(범위). 기존 브리지 재사용
- `region.legal_location_legal_codes` — **의미 전환·재사용**: 프리픽스 LIKE용 코드배열 → REGION이 **선택한 법정동(L3) 코드 집합**
- 구의 하위 법정동 pool은 저장하지 않고 구 코드 prefix로 조회 시 자동 도출. 인지구역의 유효 법정동 집합은 비어 있을 수 없음

**REGION 스팟 조회**
- REGION 스팟 = **선택 법정동에 `spot.legal_code`가 속하는 스팟**. 지도 폴리곤 = 선택 법정동들의 union
- ※ 스팟에 붙는 지역 태그는 **시군구 DL(L2)**, 법정동(L3)은 스팟에 붙지 않고 REGION의 선택 단위(스팟은 이미 가진 `legal_code`로 필터 → 재태깅 대상 아님)

**인지구역 생성 제약**
- 한 도시 하위 상세지역을 **전부 선택하는 것을 차단**(최소 하나 제외 — 도시 페이지와 중복 방지)
- 인지구역은 **상위 도시를 하나만** 보유. 상위 도시는 선택 상세지역들의 공통 상위로 자동 결정, 다른 도시의 상세지역 혼합 불가

**인지구역 순서 (신규 컬럼 · ④⑥ 공용)**
- `region`에 **순서(priority) 컬럼 신설**(현재 없음) — 도시 단위 정렬 값. 재정렬 API로 갱신
- 대표 인지구역 선정(⑥)과 도시 페이지 구역 그리드(⑤ 이후) 정렬에 **동일 컬럼 사용** — 값 이원화 없음

**대표 인지구역 선정 규칙 (⑥)**
스팟에 표기할 인지구역 하나를 결정론적으로 확정
1. **후보 집합** — 검색 질의가 있고 스팟이 속한 인지구역 중 질의에 매칭되는 게 있으면 그 매칭 인지구역들을 후보로, 질의가 없거나 매칭이 없으면 스팟이 속한 전체 인지구역을 후보로
2. **후보 중 관리자가 지정한 인지구역 순서(어드민 목록 위치)가 가장 앞선 것을 대표로 선택** — 좁은 범위가 항상 낫진 않아(예: '강남'을 '신사'보다 앞에 두면 강남으로 표기), 어느 인지구역을 대표로 노출할지 운영자가 직접 통제. 좁기(법정동 수)는 판정에 쓰지 않음
3. 순서 값이 같거나 미지정이면 식별자 순
4. 후보가 비면(어떤 인지구역에도 속하지 않음) 도시+상세지역(시군구)으로 표기
- 인지구역 소속은 저장값이 아니라 스팟 법정동 코드가 그 인지구역의 선택 법정동 집합에 속하는지로 판정
- **순서는 도시별로 관리**(대표 후보는 항상 같은 도시), 도시 페이지 구역 그리드 노출 순서와 **동일 값 재사용**. 이 선정은 대표 표기 하나를 정하는 데만 사용, 스팟이 여러 인지구역 리스트에 함께 노출되는 것은 별개(유지)

**검색 인덱싱 (⑥)**
- 스팟 검색 문서에 그 스팟이 속한 **모든 인지구역 이름을 전 언어로** 색인(대표 하나가 아니라 전부). 도시·상세지역(시군구)·법정동 이름도 함께 색인
- 검색 결과 표기 인지구역은 위 '대표 인지구역 선정 규칙'에 검색어를 질의로 넣어 결정. 매칭 판정은 색인과 동일 토크나이저. 색인은 전 언어, 표기 문자열은 현재 로케일로 반환
- 소속이 파생값이라 재색인 반영 — ① 관리자가 인지구역 법정동 선택을 바꾸면 그 법정동 스팟 재색인, ② 스팟 법정동 코드 변경·신규 등록 시 그 스팟 인지구역 재계산·재색인

**⑤ 관광지 REGION 생성 (일회성 마이그레이션)**
- 관광지형 DETAIL_LOCATION 이름(홍대·명동·성수 등) 기준으로 대응 REGION 생성(이미 공개 REGION 있는 이름·중복 제외). 소속 구 연결 + 관광지권 법정동 선택(예: 홍대 = 마포구 + {서교동·동교동·상수동…})
- 기존 **공개 REGION 13개**도 새 구조(구 연결 + 법정동 선택)로 재배선

**③ REGION 정리**
- **RG-1 — 비공개 REGION 삭제** — 벌크 500개(`id 25~531`) 삭제. 공개(is_publish) REGION·⑤ 생성 관광지 REGION 제외. (검증: 삭제집합 내 공개 0·하드코딩 id 4·5·15 안전 확인 완료)
- **RG-3 — 직접 연결 해제** — `region_spot_area_has_spot`(6 area·27링크) 정리

**⑦ 관광지형 DL 삭제 (표기·검색 cutover 이후)**
- 대응 REGION이 **표기·검색으로 노출된 뒤** 수행
- 관광지 DL의 **스팟**은 소속 시군구 DL로 재태깅(`spot.legal_code` prefix로 소속 구 도출)
- 관광지 DL의 **블로그·어학당**은 `legal_code`가 없어 자동 도출 불가 → **소속 구로 수동 이관**
- 이관 완료 후 **관광지형 DETAIL_LOCATION 삭제**
