# P2T4 — /region 유저페이지 프론트엔드 (5개 화면·테마 leaf·이동·301 전환)

**요약** — P2T3에서 제공하는 CITY·REGION 조회 및 라우팅 응답을 사용해 `/region` 인덱스, CITY·REGION 상세, CITY·REGION 테마 leaf를 데스크톱·모바일로 구현하고 기존 숫자형 REGION URL을 신규 경로로 전환한다. **선행: P2T3**

## 배경

- P2T3에서 신규 `/region` 유저페이지에 필요한 공개 판정·라우팅·지도 영역·스팟·테마·이동·콘텐츠 조회 계약을 제공하지만 이를 노출할 유저 화면은 부재
- CITY와 REGION의 탐색 범위 및 페이지 구성은 다르지만 상단 콘텐츠·지도·테마·한국 여행 준비 등 공통 모듈이 많아 경로별로 일관된 화면 구성 필요
- `/region/{city}/{값}`의 세 번째 경로값은 REGION과 테마가 같은 깊이를 사용하므로 서버의 라우트 타입에 따른 화면 분기 필요
- 기존 숫자형 `/spot/region/{id}`와 지역 허브 진입점을 신규 `/region` 경로로 전환해 기존 유저가 끊기지 않도록 연결 필요
- P2T2 어드민에서 등록한 이동수단·소요시간과 P2T3 집계 결과를 그대로 노출해 어드민·백엔드·유저페이지 간 결과 일치 필요

## 구현

### 유저 플로우

- 유저는 `/region`에서 활성화된 CITY 카드를 선택하고 지도·도시 간 이동 정보·주요 REGION을 확인한 뒤 CITY 또는 REGION 상세로 이동
- 유저는 `/region/{city}`에서 도시 소개·REGION 지도와 목록·도시쌍/지역쌍 이동·테마별 스팟·한국 여행 준비·CITY 내 신규 상품·여행 블로그 확인
- 유저는 `/region/{city}/{theme}`에서 CITY 상단 콘텐츠를 유지한 채 선택 테마의 중카테고리별 스팟 확인
- 유저는 `/region/{city}/{regionSlug}`에서 지역 소개·지도 영역·추천 대상·주요 역·테마별 스팟·한국 여행 준비·REGION 내 신규 상품·여행 블로그 확인
- 유저는 `/region/{city}/{regionSlug}/{theme}`에서 REGION 상단 콘텐츠를 유지한 채 선택 테마의 중카테고리별 스팟 확인
- 유저는 기존 `/spot/region/{id}`로 접근해도 매핑된 신규 REGION 상세 경로로 자동 이동

### 프론트엔드 요구사항

**와이어프레임 (참고)**

https://wireframes-lkb.pages.dev/#region-domain-renewal

**공통 라우팅·화면 구성**

- 아래 5개 페이지 유형을 데스크톱·모바일 반응형으로 구현
  - `/region` — CITY 인덱스
  - `/region/{city}` — CITY 상세
  - `/region/{city}/{theme}` — CITY×테마 leaf
  - `/region/{city}/{regionSlug}` — REGION 상세
  - `/region/{city}/{regionSlug}/{theme}` — REGION×테마 leaf
- `/region/{city}/{값}` 진입 시 프론트엔드가 경로값을 추측하지 않고 P2T3 라우팅 결과의 `REGION` 또는 `THEME` 타입에 따라 화면 노출
- 직접 URL 접근·새로고침·화면 내 링크 이동에서 동일한 경로와 화면 상태 유지
- 요청 언어에서 공개되지 않은 CITY·REGION 또는 유효하지 않은 경로는 기존 Not Found 화면 노출
- 상단 breadcrumb에 현재 CITY·REGION·테마 계층을 표시하고 각 상위 단계로 이동 가능
- 스팟 카드는 기존 공통 스팟 카드와 상세 이동 동작을 사용하고, 블로그 카드는 해당 블로그 상세로 이동
- P2T3에서 빈 목록으로 반환한 이동·주요 역·추천 대상·블로그 섹션은 빈 영역을 남기지 않고 미노출
- **{지역명} 내 신규 상품** 섹션은 CITY·REGION 상세와 그 테마 leaf에 이번 티켓에서 구현(CITY 인덱스 제외, 테마 leaf에서는 블로그만 미노출)
- canonical·noindex·구조화 데이터와 GSC 측정은 P2T5 범위로 제외

**`/region` CITY 인덱스**

- 활성화된 CITY 카드에 대표 이미지·CITY 이름·태그·설명을 노출하고 선택 상태 표시
- CITY를 선택하기 전에는 도시 선택 안내를 노출하고, 선택 후 해당 CITY의 지도 영역·도시 간 이동 정보·주요 REGION으로 교체
- 지도에서 선택한 CITY 영역을 강조하고 주요 REGION 진입점을 P2T2 저장 순서로 노출
- CITY 카드 또는 선택 CITY의 상세 진입 동작으로 `/region/{city}` 이동
- 주요 REGION 선택 시 `/region/{city}/{regionSlug}` 이동
- 도시 간 이동은 상대 CITY별 등록 수단과 소요시간을 노출하고, 수단이 여러 개이면 수단 선택에 따라 소요시간 변경
- 등록한 도시쌍이 없으면 이동 섹션 미노출

**`/region/{city}` CITY 상세**

- CITY 대표 이미지·이름·설명·부가설명·태그를 상단 히어로 영역에 노출
- CITY 지도 영역과 공개 가능한 REGION 목록을 함께 노출하고, REGION 선택 시 지도 영역 강조 및 REGION 상세 이동 제공
- 도시쌍과 같은 CITY 안의 지역쌍 이동 정보를 구분해 노출
- 이동쌍에 등록된 이동수단·소요시간을 복수 노출하고 선택한 수단에 맞는 소요시간 표시
- 이동 정보에는 P2T2·P2T3에 정의된 수단과 소요시간만 사용하고 요금·공항 엔드포인트 미노출
- 예약 대카테고리별 스팟 캐러셀에 월간 인기순 최대 9개 노출
- 테마의 전체 스팟이 10개 이상인 경우에만 **더보기**를 노출하고 `/region/{city}/{theme}`로 이동
- **한국 여행 준비** 상품 캐러셀 노출
- **{CITY명} 내 신규 상품** 캐러셀(🆕 헤더·부제 "최근 등록된 투어·티켓·클래스")에 해당 CITY에 최근 등록된 상품을 최신 등록순으로 노출하고, 연결된 신규 상품이 없으면 섹션 미노출
  - 상품 카드에 **NEW** 배지·소속 지역 배지·카테고리 칩·상품명·설명·가격·**보기** 링크를 노출하고, 카드 선택 시 상품 상세로 이동
  - 데스크톱은 이전·다음 탐색 버튼, 모바일은 가로 스크롤로 캐러셀 이동
- CITY 여행 블로그 섹션 노출

**`/region/{city}/{theme}` CITY×테마 leaf**

- 부모 CITY의 히어로·지도·REGION 목록·도시쌍/지역쌍 이동·한국 여행 준비·CITY 내 신규 상품 영역 유지
- 선택한 예약 대카테고리 이름을 제목과 breadcrumb에 노출
- 선택 대카테고리 아래 중카테고리별 스팟 그룹을 P2T3 응답 순서로 노출
- 스팟이 없는 중카테고리는 미노출
- CITY 여행 블로그 섹션 미노출

**`/region/{city}/{regionSlug}` REGION 상세**

- REGION 히어로 이미지·이름·태그·한 줄 소개·대표 키워드·지역 설명과 부모 CITY 정보 노출
- REGION이 선택한 법정동 union 지도 영역을 노출하고 연결 상세지역 정보 표시
- 추천 대상 카드를 저장 순서대로 노출하고 카드별 관련 스팟을 최대 3개까지 연결
- 주요 역에 역명·호선·부가설명을 노출하고 역 선택 시 기존 역 주변 스팟 탐색으로 이동
- 예약 대카테고리별 스팟 캐러셀에 월간 인기순 최대 9개 노출
- 테마의 전체 스팟이 10개 이상인 경우에만 **더보기**를 노출하고 `/region/{city}/{regionSlug}/{theme}`로 이동
- **한국 여행 준비** 상품 캐러셀 노출
- **{REGION명} 내 신규 상품** 캐러셀(🆕 헤더·부제 "최근 등록된 투어·티켓·클래스")에 해당 REGION에 최근 등록된 상품을 최신 등록순으로 노출하고, 연결된 신규 상품이 없으면 섹션 미노출
  - 상품 카드에 **NEW** 배지·소속 지역 배지·카테고리 칩·상품명·설명·가격·**보기** 링크를 노출하고, 카드 선택 시 상품 상세로 이동
  - 데스크톱은 이전·다음 탐색 버튼, 모바일은 가로 스크롤로 캐러셀 이동
- REGION 여행 블로그 섹션 노출

**`/region/{city}/{regionSlug}/{theme}` REGION×테마 leaf**

- 부모 REGION의 히어로·지도·추천 대상·주요 역·한국 여행 준비·REGION 내 신규 상품 영역 유지
- 선택한 예약 대카테고리 이름을 제목과 breadcrumb에 노출
- 선택 대카테고리 아래 중카테고리별 스팟 그룹을 P2T3 응답 순서로 노출
- 스팟이 없는 중카테고리는 미노출
- REGION 여행 블로그 섹션 미노출

**반응형·상호작용**

- 데스크톱은 와이어프레임의 다단 배치와 가로 캐러셀 구조를 적용하고 모바일은 단일 열 중심으로 재배치
- 모바일에서 이동 정보·주요 역 등 접을 수 있는 영역은 제목 선택으로 펼침·접힘 제공
- 스팟·상품·블로그 캐러셀은 터치 스크롤을 지원하고 데스크톱에는 이전·다음 탐색 버튼 제공
- 지도와 REGION 목록의 선택 상태를 동기화하고 선택 가능한 영역과 현재 선택 영역을 구분
- 데이터 조회 중에는 기존 로딩 UI, 조회 실패 시 기존 오류 UI를 사용해 레이아웃 급변 최소화

**기존 경로 전환**

- 기존 `/spot/region/{id}` 접근 시 P2T3 매핑 결과의 `/region/{city}/{regionSlug}`로 301 이동
- 서비스 내부의 기존 REGION 상세 링크를 신규 REGION 경로로 교체
- 기존 지역 허브 `/tips/region-guide`로 연결하던 내부 진입점을 `/region`으로 교체
- 매핑되지 않은 숫자형 REGION ID는 잘못된 신규 경로를 만들지 않고 기존 Not Found 처리

### 백엔드 요구사항

- 화면 데이터와 라우트 타입은 P2T3 조회 계약을 사용하며 이번 티켓에서 별도 스팟 범위·카테고리·콘텐츠 집계 규칙을 추가하지 않음
- **{지역명} 내 신규 상품** 캐러셀은 P2T3의 CITY·REGION별 신규 상품 조회 결과(최신 등록순)를 사용하며, 조회 계약에 해당 항목이 없으면 P2T3에서 CITY·REGION 단위 신규 상품 목록을 제공하도록 선행 반영
- 기존 `/spot/region/{id}` 요청에 대해 P2T3의 신규 경로 매핑을 사용한 영구 리다이렉트 응답 제공
- 301 이동 시 기존 요청의 쿼리 파라미터를 유지하고 매핑이 없거나 대상 REGION이 비공개이면 Not Found 반환

## 수용 조건

- 5개 경로가 CITY 인덱스·CITY 상세·CITY×테마·REGION 상세·REGION×테마 화면으로 각각 노출됨
- 세 번째 경로값이 P2T3 라우트 타입에 따라 REGION 또는 테마로 정확히 분기됨
- `/region`에서 CITY 선택 시 지도·도시 간 이동·주요 REGION이 갱신되고 각 상세 경로로 이동 가능
- CITY 상세에서 REGION 지도·목록, 도시쌍/지역쌍 이동, 테마 캐러셀, 한국 여행 준비, CITY 내 신규 상품, 여행 블로그가 조건에 맞게 노출됨
- REGION 상세에서 메타·법정동 union 지도·추천 대상·주요 역·테마 캐러셀·한국 여행 준비·REGION 내 신규 상품·여행 블로그가 조건에 맞게 노출됨
- CITY·REGION 상세의 **{지역명} 내 신규 상품** 캐러셀이 해당 지역 신규 상품을 최신 등록순으로 노출하고, 카드에 NEW·소속 지역 배지와 상품 상세 이동을 제공하며, 연결 상품이 없으면 섹션 미노출되고, 테마 leaf에서도 부모 상단 콘텐츠로 유지됨(블로그만 미노출)
- 테마 leaf에서 중카테고리별 스팟이 노출되고 부모 상단 콘텐츠는 유지되며 여행 블로그는 미노출됨
- 테마 전체 스팟이 10개 미만이면 **더보기**가 노출되지 않고 leaf로 진입할 수 없음
- 이동 정보는 등록된 수단·소요시간을 복수로 표시하고 요금·공항 엔드포인트를 노출하지 않음
- 빈 이동·주요 역·추천 대상·블로그 데이터는 해당 섹션 미노출로 처리됨
- 데스크톱·모바일에서 지도·카드·캐러셀·접힘 영역이 와이어프레임 구조에 맞게 동작함
- 기존 `/spot/region/{id}`가 매핑된 신규 REGION 경로로 301 이동하고 내부 REGION 링크와 지역 허브 진입점이 신규 경로로 교체됨
- P2T5 SEO 설정이 이번 티켓에 포함되지 않음
