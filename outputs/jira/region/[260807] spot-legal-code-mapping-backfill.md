# 세부 기획안 요구사항 문서

## 배경

### 문제 정의

- 현재 legal_code(법정동 코드)가 비어 있는 스팟이 **179개** 존재
- legal_code는 스팟 좌표를 법정동(level 3) 경계에 매핑한 결과로, 스팟을 지역에 귀속시키는 핵심 키. 지역 페이지·지역 필터·여정 추천 등 지역 기반 조회에서 스팟을 노출시키는 기준으로 사용
- legal_code가 없으면 해당 스팟은 좌표가 서울·부산 도심 한복판이어도 지역 기반 조회 결과에서 누락

- 미보유 179개를 좌표 성격으로 분류
  - **A. 한국 좌표 범위 내 (134개)** — 좌표는 정상권이나 매핑이 한 번도 수행되지 않은 누락분
    - 현행 매핑 로직 기준 지금 바로 매핑 가능 **129개** (경계 내부 매칭 119 + 경계 ±100m 버퍼 매칭 10)
    - 좌표 자체가 이상(바다·해외·오타)해 매핑 불가 **5개** → **본 티켓 범위 제외**
  - **B. 해외·무효 좌표 (45개)** — 좌표가 (0,0)·(1,1) 더미거나 해외(대만·싱가포르 등). 콘서트 셔틀·온라인 상담회·어학당 튜터링 등 **물리적 위치가 없는 상품**이 다수 → legal_code 불필요, 매핑 대상 아님

- 근본 원인은 매핑 트리거 구조
  - legal_code는 **스팟 생성 시점**과 **좌표가 변경되어 저장되는 시점**에만 계산
  - 좌표 변경 판정은 값이 실제로 달라져야 성립. 동일 좌표를 다시 저장하면 매핑 재시도 없음
  - 일괄 매핑 배치가 코드상 존재하나 스케줄러에 연결되어 있지 않아 주기 실행 부재
  - 결과적으로 과거 누적 누락분과, 생성 경로를 우회해 들어온 신규 스팟이 계속 누락되는 구조

### 가설적 임팩트

- 지금 매핑 가능한 129개 중 다수가 서울·부산 도심의 **활성 예약 상품**(한복·스냅·투어·뷰티·어학당 등), 즉 오가닉 지역 유입에서 전환 가능한 인벤토리
- 이 스팟들이 지역 페이지·지역 필터에 노출되지 않아 **지역 유입 → 스팟 전환** 경로에서 노출·전환 기회 손실
- 매핑 트리거가 특정 시점에만 걸리는 구조라, 백필만으로는 재발. 자동화까지 반영해야 향후 누락 방지
- 정량 임팩트(누락 스팟의 지역 페이지 노출·전환 증분)는 배치 반영 후 측정 예정 — TBD

## 구현

### 유저 플로우

- 관리자가 스팟 좌표를 저장하면, 좌표가 유효 범위(한국) 안일 때 법정동·지역이 자동 매핑
- 관리자가 좌표를 바꾸지 않고 저장하더라도, 해당 스팟이 지역 미매핑 상태이면 현재 좌표 기준으로 매핑을 재시도
- 유저가 지역 페이지를 조회하면, 그동안 누락됐던(좌표 정상) 스팟도 지역 결과에 노출
- 좌표가 유효 범위 밖(해외·0,0·1,1)인 스팟은 매핑 대상에서 제외, 지역 귀속 없음 유지

### 프론트엔드 요구사항

- 어드민 스팟 상세·목록에서 현재 매핑된 지역(법정동) 확인 노출
- 매핑되지 않은 스팟은 **지역 미매핑** 상태로 구분 표시, 운영자가 좌표 이상치·누락 스팟을 식별 가능하게 노출
- 세부 화면·배치 위치 TBD (지역 도메인 어드민 화면 확정 후)

### 백엔드 요구사항

- **일회성 백필**
  - legal_code 미보유 + 유효 좌표(한국 범위) 스팟 전체를 현행 매핑 로직으로 재매핑
  - 대상 129개 채움, 경계 밖으로 매핑 실패하는 좌표 이상치 5개는 로그로 분리 남김
- **스케줄러 자동화**
  - 주기적으로 미매핑(유효 좌표) 스팟을 탐지해 매핑, 신규·우회 생성분의 누락 방지
- **좌표 저장 시 매핑 재계산 조건 개선**
  - 기존: 좌표 값이 실제로 변경된 경우에만 매핑 재계산
  - 개선: legal_code가 비어 있고 좌표가 유효하면, 좌표 변경 여부와 무관하게 저장 시 매핑 재시도
- **매핑 실패 집계**
  - 매핑 실패(경계 밖) 건을 로그·집계로 남겨 좌표 이상치 스팟을 운영에서 식별 가능하게 노출
- 매핑 기준(법정동 level 3, 경계 내부 → ±100m 버퍼 순, 좌표 한국 범위 밖 제외)은 현행 로직 유지
