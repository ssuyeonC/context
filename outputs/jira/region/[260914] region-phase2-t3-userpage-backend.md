# P2T3 — /region 유저페이지 백엔드 (조회축·폴리곤·라우팅·테마/콘텐츠 집계)

**요약** — P2T2 어드민에서 저장한 CITY·REGION 콘텐츠를 `/region` 유저페이지 와이어프레임의 5개 경로에서 조회할 수 있도록, 공개 판정·라우팅·지도 영역·스팟 범위·테마·이동·주요 역·추천 대상·블로그·한국 여행 준비 데이터를 제공하는 백엔드를 구현한다. **선행: P2T2(COM-2634)**

## 배경

- P2T2에서 CITY·REGION 메타와 범위·이동·주요 역·추천 대상·카테고리 순서를 입력할 수 있게 되지만, 이를 유저페이지 단위로 조합해 반환하는 조회 계약은 부재
- 기존 REGION 조회는 개편 전 지역 구조를 기준으로 동작해 CITY 전체 스팟과 REGION 선택 법정동 스팟을 서로 다른 범위로 집계하기 어려운 상태
- `/region/{city}/{값}`에서 REGION과 테마가 같은 경로 깊이를 사용하므로 요청값의 타입을 판정하는 라우팅 리졸버 필요
- 도시·지역·테마 페이지가 각자 스팟 범위와 카테고리 순서를 다시 계산하면 페이지별 결과가 달라질 수 있어 서버에서 동일 규칙으로 조합 필요
- P2T2 어드민에서 도시쌍·지역쌍별 이동수단과 소요시간을 복수 등록하므로, 유저페이지 조회도 해당 저장값을 기준으로 구성 필요

## 구현

### 유저 플로우

- 유저는 `/region`에서 활성화된 CITY를 선택하고 도시 메타·지도 영역·도시 간 이동 정보·주요 REGION 확인
- 유저는 CITY를 선택해 `/region/{city}`로 이동하고 도시 소개·이동 정보·REGION 목록·테마별 스팟·한국 여행 준비·여행 블로그 확인
- 유저는 REGION을 선택해 `/region/{city}/{regionSlug}`으로 이동하고 지역 소개·추천 대상·주요 역·지도 영역·테마별 스팟·한국 여행 준비·여행 블로그 확인
- 유저는 CITY 또는 REGION 상세의 테마 **더보기**를 선택해 도시×테마 또는 지역×테마 leaf로 이동하고 중카테고리별 스팟 확인
- 테마 leaf에서도 부모 CITY 또는 REGION의 소개·지도·이동/주요 역·추천 대상·한국 여행 준비를 유지하고 여행 블로그는 미노출
- 요청 언어의 번역이 없거나 비공개인 REGION은 목록·라우팅·상세에서 조회 불가, 다른 언어 콘텐츠로 대체 노출하지 않음

### 프론트엔드 요구사항

**와이어프레임 (참고)**

https://wireframes-lkb.pages.dev/#region-domain-renewal

- 이번 티켓은 유저페이지 UI를 구현하지 않고 P2T4에서 사용할 조회·라우팅 계약 제공
- 아래 5개 페이지 유형을 구분할 수 있는 응답 제공
  - `/region` — CITY 인덱스
  - `/region/{city}` — CITY 상세
  - `/region/{city}/{theme}` — CITY×테마 leaf
  - `/region/{city}/{regionSlug}` — REGION 상세
  - `/region/{city}/{regionSlug}/{theme}` — REGION×테마 leaf
- 프론트엔드는 스팟 범위·공개 판정·카테고리 순서·라우트 타입을 별도로 재계산하지 않고 서버 응답 사용
- 현재 와이어프레임에 없는 별도 **신규 스팟** 섹션은 이번 조회 계약에서 제외
- 기존 `/spot/region/{id}`의 실제 301 응답과 신규 페이지 UI는 P2T4, canonical·noindex·구조화 데이터·GSC 측정은 P2T5 범위

### 백엔드 요구사항

**공통 공개·언어 판정**

- CITY 유저 노출 조건은 자식 REGION 1개 이상 보유와 선택 언어의 대표 이미지·태그·설명 충족으로 적용
- REGION 유저 노출 조건은 부모 CITY 활성화, 선택 언어의 `isPublish=true`, 히어로 이미지·태그·지역 설명 충족으로 적용
- REGION 한 줄 소개와 대표 키워드는 선택 입력으로 처리하고 미입력 상태에서도 공개 허용
- 요청 언어의 REGION 번역이 없거나 비공개이면 다른 언어로 대체하지 않고 미노출·접근 차단
- 스팟은 영업 중이며 요청 언어에서 공개·목록 노출 가능한 항목만 반환

**라우팅 리졸버**

- CITY 경로값으로 CITY를 조회하고 비활성 또는 존재하지 않는 CITY는 `NOT_FOUND` 반환
- `/region/{city}/{값}`의 세 번째 경로값을 해당 CITY의 REGION 또는 예약 대카테고리 테마로 판정해 `REGION` 또는 `THEME` 타입 반환
- `/region/{city}/{regionSlug}/{theme}`는 REGION의 부모 CITY 일치 여부와 예약 대카테고리 테마 유효 여부를 함께 검증
- REGION·테마 경로값이 존재하지 않거나 비공개 범위를 가리키면 `NOT_FOUND` 반환
- 어드민에 별도 slug 입력 필드를 추가하지 않고 P2-T1의 REGION 경로값과 예약 카테고리 경로값을 조회에 사용
- 기존 숫자형 REGION ID를 신규 CITY·REGION 경로로 변환할 수 있는 매핑 제공, 실제 301 응답 처리는 P2T4에서 적용

**`/region` CITY 인덱스 조회**

- 활성화된 CITY 카드 목록에 CITY ID·이름·대표 이미지·태그·설명과 지도 표시 정보 반환
- CITY 선택 시 해당 CITY의 도시쌍 이동 정보와 공개 가능한 자식 REGION 진입점 반환
- 자식 REGION 진입점은 P2T2에서 저장한 REGION 순서를 적용
- 이동 정보가 없는 CITY는 빈 목록을 반환하고 이동 섹션을 구성하지 않도록 상태 제공

**`/region/{city}` CITY 상세 조회**

- 선택 언어의 CITY 이름·대표 이미지·태그·설명·부가설명과 CITY 지도 영역 반환
- 공개 가능한 자식 REGION 목록에 REGION 이름·연결 상세지역·스팟 수·지도 영역·상세 경로 반환
- CITY의 도시쌍과 같은 CITY 안의 지역쌍 이동 정보를 구분해 반환
- CITY 테마 섹션·한국 여행 준비·CITY 여행 블로그 데이터를 한 페이지 응답에서 조회 가능하도록 제공

**`/region/{city}/{regionSlug}` REGION 상세 조회**

- 선택 언어의 REGION 이름·히어로 이미지·태그·한 줄 소개·대표 키워드·지역 설명과 부모 CITY 정보 반환
- P2T2에서 저장한 추천 대상 카드와 관련 스팟 최대 3개를 저장 순서대로 반환
- 주요 역은 호선·역·부가설명 단위로 반환하고 연결된 역이 없으면 빈 목록 제공
- REGION 테마 섹션·한국 여행 준비·REGION 여행 블로그 데이터를 한 페이지 응답에서 조회 가능하도록 제공

**스팟 조회 범위**

- CITY 스팟 범위는 해당 CITY에 연결된 스팟 전체로 구성하고 예약 대카테고리별 교집합으로 테마 섹션 생성
- REGION 스팟 범위는 REGION이 선택한 법정동 코드와 스팟의 법정동 코드가 일치하는 항목으로 구성
- REGION 스팟 조회에 기존 스팟 직접 연결값이나 상세지역 전체 prefix를 사용하지 않음
- CITY×테마 leaf는 CITY 스팟과 선택한 예약 대카테고리의 교집합으로 구성
- REGION×테마 leaf는 REGION 법정동 스팟과 선택한 예약 대카테고리의 교집합으로 구성

**테마·카테고리 조회**

- CITY·REGION 상세는 스팟이 존재하는 예약 대카테고리별 섹션과 월간 인기순 상위 9개 스팟 반환
- CITY×테마·REGION×테마 leaf는 선택한 예약 대카테고리 아래의 중카테고리별 스팟 그룹 반환
- CITY×테마 leaf는 부모 CITY 메타·지도·도시쌍/지역쌍 이동·REGION 목록·한국 여행 준비를 함께 반환
- REGION×테마 leaf는 부모 REGION 메타·지도·추천 대상·주요 역·한국 여행 준비를 함께 반환
- 테마별 전체 스팟 수와 leaf 진입 가능 여부를 함께 반환하고, 전체 스팟이 10개 이상일 때 leaf 진입 가능 처리
- 대카테고리 순서는 페이지별 P2T2 저장값을 우선 적용하고 미설정 시 `home-nav priority` 적용
- leaf의 중카테고리 순서는 해당 페이지·대카테고리의 P2T2 저장값을 우선 적용하고 미설정 시 `category.priority` 적용
- CITY와 REGION의 순서 설정은 서로 상속하지 않고 독립 적용
- 여러 대카테고리를 하나로 묶는 커스텀 그룹·커스텀 테마·커스텀 slug는 생성하지 않음
- 스팟이 없는 카테고리 그룹은 응답에서 제외

**지도 영역**

- CITY 지도 영역은 CITY에 연결된 법정지역 경계로 반환
- REGION 지도 영역은 REGION이 선택한 모든 법정동 폴리곤을 union한 단일 영역으로 반환
- REGION이 여러 구에 걸쳐 있어도 선택 법정동 기준으로 하나의 지도 영역 반환
- 별도 지도 공개 토글을 사용하지 않고 REGION 공개 판정을 지도 노출에도 동일 적용

**이동 정보**

- 도시쌍은 CITY↔CITY, 지역쌍은 같은 CITY 안의 REGION↔REGION 조합만 조회 허용
- 이동쌍은 방향과 무관하게 양쪽 엔드포인트에서 동일하게 조회
- 각 이동쌍에 P2T2 어드민에서 등록한 이동수단과 분 단위 정수 소요시간을 복수로 반환
- 도시쌍 수단은 비행기·기차(KTX/SRT)·고속버스·택시, 지역쌍 수단은 지하철·버스·도보·택시로 제한
- 이동 응답에 요금은 제공하지 않음
- 공항을 이동쌍 엔드포인트로 제공하지 않고 자가용·배 수단도 제공하지 않음
- **한국 여행 준비**에 포함되는 공항 이동 상품은 구매 상품으로 취급하며 이동쌍의 공항 노드와 구분

**한국 여행 준비**

- CITY·REGION 상세와 각 테마 leaf에 지역과 무관한 동일 상품 집합 제공
- 영업 중이며 요청 언어에서 공개·목록 노출 가능한 스팟 중 유심 대카테고리(744) 전체와 교통·여행서비스 대카테고리(743·745) 대상 반환
- 교통·여행서비스 대상 중 지역성 중카테고리 코드 `363·927·3077·3088·3052·876·370·935·3087·933·3078`을 하나라도 가진 스팟 제외
- 대카테고리 중복 태깅 스팟은 한 번만 반환하고 월간 인기순 상위 9개 제공
- 자체 REGION·테마 경로를 만들지 않고 **더보기**에 필요한 기존 스팟 목록 조건 제공

**여행 블로그**

- REGION 여행 블로그는 해당 REGION 참조값을 가진 공개 블로그를 직접 조회
- CITY 여행 블로그는 공개 가능한 자식 REGION을 참조하는 공개 블로그를 CITY 단위로 합쳐 중복 없이 조회
- 테마와 독립된 별도 섹션으로 반환하고 CITY×테마·REGION×테마 leaf 응답에는 포함하지 않음
- 블로그가 없으면 빈 목록을 반환해 섹션 미노출 가능

## 수용 조건

- 5개 유저페이지 경로가 CITY 인덱스·CITY 상세·CITY×테마·REGION 상세·REGION×테마 타입으로 판정됨
- 요청 언어에서 비공개이거나 번역이 없는 REGION이 목록·라우팅·상세에 노출되지 않음
- CITY 스팟은 CITY 연결 기준, REGION 스팟은 선택 법정동 코드 기준으로 서로 다른 범위가 적용됨
- CITY와 REGION의 지도 영역이 각각 CITY 경계와 선택 법정동 union으로 반환됨
- CITY·REGION 상세에 예약 대카테고리별 월간 인기 스팟 9개와 전체 개수·leaf 진입 가능 여부가 반환됨
- CITY×테마·REGION×테마 leaf에 선택 대카테고리 아래의 중카테고리별 스팟이 반환됨
- 각 테마 leaf에 부모 CITY 또는 REGION의 상단 콘텐츠와 **한국 여행 준비** 데이터가 함께 반환되고 여행 블로그는 포함되지 않음
- P2T2에서 저장한 CITY·REGION별 카테고리 순서가 독립 적용되고 미설정 시 기본 순서로 폴백됨
- 도시쌍·지역쌍 이동 정보가 대칭 조회되고 공항 노드·요금·자가용·배가 응답에 포함되지 않음
- 주요 역·추천 대상·이동·블로그 데이터가 없으면 빈 목록으로 반환돼 각 섹션을 미노출할 수 있음
- **한국 여행 준비** 상품이 지역성 중카테고리 제외 규칙과 공개·영업 필터를 적용해 중복 없이 반환됨
- 기존 숫자형 REGION ID의 신규 경로 매핑이 제공되고 실제 301·화면 구현·SEO 설정은 후속 티켓 범위로 유지됨
