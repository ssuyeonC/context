# ▣ EPIC — 지역 도메인 개선 Phase 2 (/region 유저페이지·어드민·테마·SEO)

작성일: 2026-09-10
상태: 초안 — Jira 미생성. Phase 1 에픽(COM-2574)과 **별도 에픽**으로 분리. 양식은 COM-2574에 맞춤. 정본 = `plans/[260831] region-phase2-breakdown.md` · 전역 모듈 = `plans/[260901]` · 어드민 필드 = `plans/[260903]`

- 토대 — 지역 엔티티를 스팟과 동일한 구조(canonical `region` + 언어별 `region_translation`)로 정합. 아래 4개 축이 모두 이 위에 섬
- 축① 어드민 — `/region` CMS(CITY·REGION 콘텐츠 메타 + 이동 편집 + 카테고리 순서)
- 축② 유저페이지 — 4단 라우팅 + CITY·REGION 페이지 + 테마 leaf + 이동 모듈 + 전역 「한국 여행 준비」 모듈 + 신규 스팟 영역
- 축③ 테마·그룹핑 — 예약 카테고리 택소노미 자동 그룹핑 + 페이지별 순서 변경 + 캐러셀/leaf 노출
- 축④ SEO — 콘텐츠 임계·canonical·안정 slug·301 승계·에디토리얼 인트로·측정

## 배경

- Phase 1(COM-2574)이 CITY(시도)·DETAIL_LOCATION(시군구)·REGION(구 묶음+법정동) 재정비와 스팟 필터·표기 전환으로 데이터 토대를 깔지만, 그 데이터를 보여줄 **유저 페이지·어드민 CMS·SEO 구조는 부재**
- 외부 여행 담론(r/koreatravel 10,001건)의 55.5%가 ‘지역’ 관련인데 지역 페이지는 스팟 리스트 트래픽의 3.8%만 수취·평균 체류 11초 — 수요를 못 받는 구조
- ‘도시×테마’(seoul restaurants, 월 1만~10만)·‘도시×구역’(seoul gangnam) 대형 SEO 키워드를 받을 색인 가능한 페이지가 없음
    - 타깃 키워드 합산 추정 검색량 월 ~50만 · Q3 OKR KR1 = 서울 REGION 10개 × 테마 → 색인 테마 leaf 30개

## 개선 방향

- **4단 IA 신설**
    - `/region`(도시 인덱스) → `/region/{city}`(도시 상세) → `/region/{city}/{zone}`(구역 상세) + 테마 leaf(`/{city}/{theme}` · `/{city}/{zone}/{theme}`)
    - 3번째 칸은 zone과 테마가 공유하는 slug 네임스페이스 — 어드민 유니크 가드로 충돌 차단
    - 기존 `/spot/region/{숫자 id}` → 새 slug 301(498 동네 URL SEO 승계)
    - 기존 Region 허브 `/tips/region-guide` 제거, 내부 진입점을 신규 `/region`으로 교체
- **어드민이 콘텐츠 메타를 채우면 유저 페이지가 성립**
    - CITY 카드메타(대표이미지·태그·설명)·REGION 히어로/태그/설명을 운영자가 입력
    - 활성화 게이트 미충족 시 노출 차단 — "REGION만 켜고 도시 메타 누락" 고아 상태 구조적 방지
    - CITY 2단 게이트: ① 어드민 도시 탭 등장 = 자식 REGION ≥1 · ② 유저 그리드 선택 = ① + 카드메타 입력
- **테마 = 예약 카테고리 택소노미 자동 그룹핑**
    - 별도 테마 사전·묶음 CMS 없이 순서 변경만(묶기 제거). CITY = home-nav 대카테고리 개별 캐러셀 / REGION(zone) = 대카 자동, leaf = 중카 자동
    - 지역무관 유틸(교통·유심·여행서비스)은 전역 「한국 여행 준비」 모듈로 자동 노출(카테고리 캐러셀 하단)
- **지역 = 스팟형 구조로 정합** — 현재 Region은 운영상 언어별로 별도 생성·관리되어 동일 정보를 반복 입력해야 하는 구조. `region`에는 slug·legal_code·주변역·카테고리 순서·이동쌍·히어로 등 언어 공통값을 두고, 하나의 Region에 이름·콘텐츠·`is_default`·`is_translated_by_ai`·`is_publish`를 가진 복수의 `region_translation`을 연결. 생성 시 한국어 기준 번역을 만들고 이후 언어별 번역을 추가하며, 공개 상태도 언어별로 독립 관리. **P2 최선행 태스크(P2-T1)**
- **slug 자동생성** — 영문 지역명에서 자동 도출(어드민 입력 필드 없음), 이름 불변 → slug 불변으로 URL·SEO 안정
- **이동 = 도시쌍 + 지역쌍** — 공항을 별도 노드로 두지 않음. 무방향·대칭·큐레이션(풀 매트릭스 금지), 0쌍이면 유저페이지 이동 섹션 미노출
- **SEO 가드레일 필수** — 콘텐츠 임계 10 미만 테마 leaf는 자동 비생성·비색인(thin/중복 역효과 방지). 도시 페이지 스팟은 완전집합이라 항상 충분

## 작업 순서

### Phase 2 - /region 유저페이지·어드민·테마·SEO

지역 구조를 스팟형으로 정합한 뒤, 어드민이 데이터를 채워야 페이지가 성립하므로 스키마 → 어드민 → BE → FE → SEO 순. Phase 1(T1~T8)은 별도 진행 중이며 그 region 재정비 결과 위에 선다.

#### 1) 지역 엔티티 구조 정합 (스팟형 canonical + translation) — P2-T1 (선행: Phase 1 T2·T3)
- 하나의 `region`에 복수의 `region_translation`을 연결하고, 생성 시 한국어 기준 번역을 함께 생성
- `region`은 언어 공통값, `region_translation`은 언어별 이름·콘텐츠·`is_default`·`is_translated_by_ai`·`is_publish`를 보유
- 기존 `is_shown_map`의 값과 탐색 노출 기능을 언어별 `is_publish`로 이관하고, 기존 `is_publish` 값과 `is_shown_map` 필드 제거
- 생성 모달·공개 토글·조회 파라미터 등 구조 전환과 동시에 필요한 어드민·유저 프론트엔드 변경 포함. **P2 최선행 — 어드민·BE·FE가 이 구조 위에 섬**

#### 2) `/region` 어드민 CMS — P2-T2 (선행: P2-T1)
- 지역(REGION) 탭 — 언어 탭·번역 추가/복사/AI 번역·언어별 공개 + 지역 메타정보(히어로 이미지·태그·한 줄 소개·설명)·지역 범위(구+법정동)·이동 정보(주변 역)·추천 대상(persona)·카테고리 순서
- 도시(CITY) 탭 — 도시 카드메타(대표이미지·태그·설명)·이동 편집(도시쌍+지역쌍, 공항 노드 없음)·카테고리 순서
- slug 자동생성(입력 필드 없음) + `(city, slug)` 유니크 가드 · 자동번역 · 지역별 리뷰 토글 제거(테이블 유지)

#### 3) 백엔드 — P2-T3 (선행: P2-T2)
- 조회축 전환(CITY 스팟 집계·REGION 법정동 매칭) · 폴리곤 resolve(선택 법정동 union) · slug 레지스트리·유니크 가드
- 테마 leaf 쿼리 + 캐러셀 쿼리(monthly best 9) + 페이지별 카테고리 순서 override 적용
- 전역 「한국 여행 준비」 모듈 소싱(744 + 743·745 ∖ 지역성 중카 블랙리스트) · 신규 스팟 쿼리(created_at 3개월)

#### 4) 프론트엔드 — P2-T4 (선행: P2-T3)
- 4단 라우팅(3번째 칸 zone|theme 분기) · 301 리다이렉트 · CITY 인덱스(지도 그리드)·CITY/REGION 상세·테마 leaf
- 이동 모듈(도시쌍·지역쌍) · 전역 「한국 여행 준비」 모듈 · 신규 스팟 영역(9개·0건 미노출)

#### 5) SEO — P2-T5 (선행: P2-T4)
- 테마 leaf canonical(`/spot/list?category=` noindex 양보) · 콘텐츠 임계 10 · 에디토리얼 인트로 · 301 승계 · GSC 타깃 키워드셋 측정

## 실행 순서 (하위 태스크)

- P2-T1 지역 구조 정합 → P2-T2 어드민 CMS → P2-T3 BE(조회축·slug·leaf 쿼리·폴리곤·집계) → P2-T4 FE(유저페이지·테마 노출) → P2-T5 SEO 색인·측정
    - **구조 먼저**: 스팟형 canonical+translation 정합이 어드민·BE·FE의 전제(언어 공통값·번역값 책임, 언어별 공개 계약). Phase 1이 진행 중이라 Phase 1에 넣지 않고 P2 최선행으로 분리
    - **어드민 먼저**: 데이터를 채워야 페이지가 성립(생성=어드민, 스크립트 아님)
    - **유저 배포는 Phase 1 완료 후**: "깨진 페이지에 트래픽 먼저 붓지 않음". 어드민·유저페이지는 동시 배포
    - **SEO는 lagging**: 선행지표부터 → Q3말 물꼬·Q4 성숙
- 배포 게이트 = 도시 allowlist 아님, 페이지 단위 조건 충족 시 자동 노출 (Phase 1 종료 시점 REGION ≈45개 전부 유효 대상)
    - ① 어드민·유저페이지·스팟 영역 자동 규칙 구현 완료(개발)
    - ② 해당 도시·지역 카드메타 백필(CITY=대표이미지·태그·설명 / REGION=히어로 이미지·태그·설명 — 초기 백필 AI)
    - ③ CITY 2단 게이트 충족(자식 REGION ≥1 + 카드메타)
    - 서울 한정 아님 — 남은 건 결정이 아니라 메타 백필 처리 순서(수요 큰 순으로 채우면 자연히 그 순서로 노출)
- 운영 불변식: REGION 노출 ⟹ 부모 CITY 활성화. 레이어 분리 — `/region` 어드민은 콘텐츠 메타(노출값)만 편집, 엔티티 생성·다국어 이름은 `/location` 소관
