# 세부 기획안 요구사항 문서

> 🧭 **마스터 [260701] 지역 도메인 개선의 실행 스포크** — 스팟 지역정보 노출(COM-2559)과 대칭으로, **블로그·유저블로그·어학당**의 지역 표기를 region 기준으로 격상. 데이터 근거·이관 규모 = `[260730] tourist-region-drafts-and-link-migration.md`.
>
> **선행 의존**: COM-2557(도시·상세지역 legal 정합) + COM-2559(region 생성·법정동 확정, cutover 링크 재지정). 본 건은 region이 존재한 뒤 동작하는 다운스트림.

## 배경

### 문제 정의

- 지역 도메인 개편으로 **스팟**은 위치 표기를 시군구(상세지역)에서 region 기준 **{도시} {region}** 으로 격상(COM-2559). 반면 **블로그·유저블로그·어학당**의 위치 표기는 여전히 도시·상세지역(구) 기준에 머묾
- 이 세 대상은 스팟과 달리 좌표(`legal_code`)가 없어 region을 자동 판정 불가 — 위치를 사람이 상세지역(구)까지만 지정하는 구조. 어학당 실측상 `legal_code` 컬럼 자체가 없고 도시·상세지역 카테고리로만 위치 지정(블로그와 동일 구조)
- 특히 관광지 상세지역(홍대·명동 등)이 region으로 이관·삭제되면(COM-2559 cutover), 거기 걸려 있던 블로그·유저블로그·어학당은 소속 구(마포구·중구)로만 재지정돼 **'홍대'·'명동' 같은 인지도 높은 지역명 표기를 잃음**
- 현재 관광지형 상세지역에 걸린 연결 규모: 블로그 **1,999건**(게시중 1,079)·유저블로그 **1,613건**(검수완료 249)·어학당 **12건**. 유저블로그는 대부분 홍대·명동·경복궁·성수 등 소수 지역에 집중

### 가설적 임팩트

- 블로그·유저블로그·어학당도 스팟과 동일하게 **{도시} {region}** 으로 위치를 표기해 유저의 위치 인지·신뢰 향상, 지역 페이지로의 진입점 확대
- cutover로 사라질 관광지 지역명(홍대·명동)을 region 표기로 **보존** — 콘텐츠의 지역 인지도 자산 유지
- 지역(REGION) 단위 콘텐츠 노출·검색 커버리지 확대의 기반 마련

## 구현

### 유저 플로우

**관리자 — 블로그·유저블로그·어학당 지역 지정 (병합 셀렉터)**
- 세 대상은 좌표가 없어 위치를 사람이 지정. **현행 어드민 입력(도시 + 상세지역)을 유지**하되, **상세지역 선택 드롭다운에 region을 옵션으로 추가** — 상세지역 자리에서 구 대신 region을 고를 수 있게 함
- 드롭다운 노출 순서: **region 전체가 먼저, 상세지역(구)이 그 뒤**
- region(예: 홍대) 선택 시 그 블로그의 지역 = 홍대 → 표기 {도시}{홍대}. 상세지역(예: 마포구) 선택 시 지금처럼 {도시}{마포구}
- 도시(CITY) 입력은 기존 그대로. 스팟과 달리 **자동 기본값 없음** — 관리자가 고른 값이 곧 표기값
- 드롭다운 **검색 입력 가능**

**사용자 — 블로그·유저블로그·어학당 지역 표기**
- 상세·목록·카드에서 관리자가 region을 지정했으면 **{도시} {region}**(예: Seoul Hongdae), 미지정이면 **{도시} {상세지역}**(예: Seoul Mapo-gu)로 노출
- 표기 언어는 유저의 현재 로케일

### 프론트엔드 요구사항

**어드민 — 상세지역 드롭다운에 region 추가**
- 블로그·유저블로그·어학당 편집면의 **도시 입력은 그대로**, **상세지역 선택 드롭다운의 옵션에 region을 추가**(신규 셀렉터가 아니라 기존 드롭다운 확장)
- 노출 순서: **region 전체가 위, 상세지역(구)이 아래**
- **검색(타이핑 필터) 제공** — region·구 합쳐 목록이 길어짐
- 자동 기본값 없음 — 관리자가 고른 값이 표기값

**블로그·유저블로그·어학당 지역 표기 (상세·카드·목록 공통)**
- 위치 표기를 도시+상세지역에서 **{도시} {region}** 으로 변경, region 미지정이면 **{도시} {상세지역}** fallback
- 링크 처리: 상세는 지역 표기를 지역 페이지 링크로, 카드·목록은 링크 없이 텍스트로만. 대상 지역 페이지가 아직 없으면 링크 비활성(텍스트만) — 링크 개방 시점 `TBD`

### 백엔드 요구사항

**지역 참조 컬럼 (신규)**
- `blog`·`user_blog`·`language_course`에 **region 참조 컬럼**(nullable, 단일) 신설 — 상세지역 자리에서 region을 고르면 그 값을 저장. 값이 있으면 {도시}{region} 표기, 없으면 기존처럼 {도시}{상세지역(구)}
- **도시(CITY)는 현행 입력값 유지**(region에서 도출하지 않음). 자동 계산·기본값 없음 — 관리자가 고른 값 그대로

**드롭다운 옵션·저장**
- 옵션 = **전체 region(상단) + 상세지역 구(하단)**, 검색 필터
- region 선택 시 region 참조값 저장(그 자리를 region이 대신하므로 구 카테고리 연결 없음)
- 상세지역(구) 선택 시 기존처럼 구 카테고리 연결(`blog_has_category`·`user_blog_has_category`·`language_course.detail_location_category_id`)

**지역 페이지 콘텐츠 노출**
- 지역(REGION) 페이지의 블로그·유저블로그·어학당 목록 = 그 region을 값으로 가진 콘텐츠를 **region 참조값으로 직접 조회**(블로그↔region 직접 연결이라 구 경유 불요). 스팟은 법정동 ∩ `legal_code`, 콘텐츠는 region 참조값 — 같은 지역 페이지로 수렴
- 참조값이 단일이라 한 콘텐츠는 **1개 지역 페이지에만** 노출. 복수 지역 페이지 동시 노출이 필요하면 별도 N:N 연결 논의 — 현재 범위 밖 `TBD`

**cutover region 참조값 자동 승계 (일회성)**
- 관광지 상세지역이 region이 되는 경우(재배선 9 + 신규 생성 24, `[260715]` §0.5): 그 상세지역에 걸린 블로그·유저블로그·어학당의 region 참조값을 **대응 region으로 일괄 승계**(기존 관광지 태그 = 관리자가 지정해둔 지역 의도로 간주). 이 경우 구 카테고리 연결은 두지 않음(상세지역 자리를 region이 대신, 도시 입력은 현행 유지)
- region이 되지 않는 관광지 상세지역(~68개)의 연결은 소속 구 카테고리로 재지정, region 참조값은 비움 → {도시}{상세지역} 표기

**검색 색인**
- 블로그·유저블로그 검색 문서에 지정 region 이름을 전 언어로 색인(있을 때). region명으로 검색 시 해당 콘텐츠 노출
- 대표값 변경·cutover 승계 시 해당 문서 재색인
