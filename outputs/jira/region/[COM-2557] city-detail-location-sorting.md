# 지역 도메인 개선 - '도시', '상세지역' 정렬

# 배경

### 문제 정의

지역 도메인의 '도시(CITY)'와 '상세지역(DETAIL_LOCATION)'은 스팟이 실제로 매달리는 분류 단위인데, 지금은 하나의 기준으로 정렬돼 있지 않음

- **레벨이 뒤섞여 있음** — 광역시는 '서울시'가 최상위 도시인데, 일반 도(경기·강원 등)에서는 '강릉시·의왕시' 같은 시가 최상위 도시로 들어가 있음. 같은 '도시' 칸에 시도급과 시/군급이 섞여, "이 스팟이 어디에 있다"를 일관된 기준으로 말할 수 없음
- **안 쓰이는 값이 섞여 있음** — 도시에 '평양'(북한)·'타이페이·대만' 같은 값이 정제 없이 쌓여 있음
- **상세지역은 성격이 다른 값이 한 바구니에 혼재** — 행정구(강남구·종로구)와 관광지·동(명동·홍대·성수동)이 혼재하고, 상세지역 158개 중 105개(66%)가 상위 도시 없는 고아이며, 이름 중복(서면 3개·성수동 2개)과 잔재가 남아 있음
- **재오염 구조** — 상세지역 생성 화면에 상위 도시를 넣는 입력이 없어, 관리자가 만들 때마다 고아가 다시 생겨남
**이 상태가 낳는 두 문제**

1. 사용자에게 보이는 지역 표기가 들쭉날쭉(어떤 스팟은 '강릉시', 어떤 스팟은 '서울시 강남구')
2. 진행 중인 지역(REGION) 페이지 개편이 이 분류 위에 서는데, 토대가 일관적이지 않아 '구역 필터'가 빈 값·엉뚱한 값을 냄. 따라서 지역 기능에 앞서 **도시·상세지역을 법정동 체계에 정합**하는 정비가 선행돼야 함
정비 방향(LEGAL 정합, 기존 값 비파괴)

- **도시, 상세지역 재구성**
  - 도시(CITY) = 시도(서울특별시·강원특별자치도, Legal_Location의 Level 1에 해당)
  - 상세지역(DETAIL_LOCATION) = 시군구(강남구·강릉시, Legal_Location의 Level 2에 해당)
- **비파괴**
  - 링크(스팟·블로그·어학당·지역)가 있는 값은 삭제하지 않음
  - 레벨이 어긋나면 종류만 변경(코드 보존)
    - 예: 현재 도시로 있는 '강릉시'는 지우지 않고 **상세지역으로 재타입**, 그 상위 도시는 '강원특별자치도'로 대체
- **없는 값만 생성**
  - 법정동에는 있는데 우리 데이터에 없는 시도·시군구만 새로 생성(이미 있는 값은 재사용)
- **지역(REGION) 생성·보완 및 연결 (스팟 세팅보다 앞)**
  - 관광지명(홍대·명동) 등은 대응 지역(REGION)을 만들어 구 연결 + 법정동을 선택해 둠
  - 이 작업이 스팟 세팅보다 **앞서야** 스팟을 시군구로 옮겨도 관광지명 탐색이 REGION으로 보존돼 끊기지 않음
  - REGION은 스팟의 좌표(법정동 코드)로 노출되므로 스팟의 상세지역 값과 무관하게 먼저 생성 가능.
    - 관련 티켓: 
- **스팟 일괄 세팅**
  - 스팟의 도시·상세지역은 좌표(법정동 코드)로 도출해 일괄 세팅
  - 관광지가 ‘상세지역'으로 연결된 스팟의 이동은 위 REGION 준비 이후 수행
- **완전 무연결만 제거**
  - 어떤 링크도 없는 값만 제거('한국'은 전국 fallback으로 유지, '평양'은 제거)
- **관광지·동은 상세지역에 새로 만들지 않음**
  - 그 개념은 지역(REGION)에서 다룸
  - 기존 관광지·동 상세지역은 즉시 지우지 않고, 대응 REGION이 생긴 뒤 정리
### 가설적 임팩트

- 전 스팟이 동일한 기준(시도 / 시군구)의 지역 표기를 확보(표기 일관성 회복)
- 이후 지역(REGION)을 "구 연결 + 그 구의 법정동 선택"으로 구성할 수 있는 신뢰 가능한 기반(개편 잠금 해제)
- 스팟은 이미 보유한 법정동 코드(전체 스팟의 97.5%, 위치 정확도 유효 99.7% — prod 실측)로 도시·상세지역·지역 노출이 도출되므로, 관광지 단위 상세지역을 별도로 유지하지 않아도 세부 노출 유지
- 스팟 라벨 체감 변화 — 광역시 스팟(약 5,049개)은 사실상 불변('서울시'→'서울특별시' 수준), 도 소속 스팟(약 1,238개, 전체의 19%)은 '강릉시'→'강원특별자치도 강릉시' 로 변경
## 구현

### 유저 플로우

- 관리자는 도시를 시도 단위로, 상세지역을 시군구 단위로 관리
- 관리자는 지역 관리(/location) 화면의 '도시' 탭에서 '추가' 로 도시를 새로 생성. 이때 법정동(시도)에서 선택, 또는 법정동에 없는 값(한국·해외 등)은 자유 텍스트로 입력
- 관리자는 상세지역(시군구)을 직접 만들지 않음
  - 시군구는 법정동(L2)에서 전량 시딩되고, 상위 도시(시도)·법정동 코드 바인딩도 코드에서 도출되어 편집 대상 아님. 관리자는 시딩된 시군구의 이름(15개 어권 다국어)만 편집
- 관리자는 상세지역 상세 화면에서 그 구에 속한 법정동(동) 목록을 확인 가능하며, 이 목록은 코드 체계로 자동 도출되어 읽기 전용으로 노출, 관리자가 수동으로 연결·편집하지 않음
- 관리자는 상세지역(시군구) 목록에서 15개 어권 이름이 미입력된 시군구를 강조 표기로 즉시 식별 가능 — 어떤 로케일이 비었는지 확인하고 채울 수 있음
- 관리자는 관광지·동을 상세지역으로 새로 만들지 않음
  - 해당 개념은 지역(REGION)에서 다룸
- 관리자는 스팟을 등록·수정할 때 좌표로 연결된 지역에서 도시·상세지역이 자동으로 채워지는 것을 확인, 필요하면 드롭다운으로 직접 수정 가능
  - 스팟의 법정동도 함께 읽기 전용 표시되어, 코드만으로는 알 수 없는 동 단위를 눈으로 확인 가능
- 사용자는 정비 후 스팟에서 {시도} {시군구} 형태의 지역 표기 노출(예: '강원특별자치도 강릉시')
  - 단 해당 로케일의 시군구 이름이 없으면 {시도}만 노출(예: 태국어 미입력 시 '강원특별자치도')
  - 스팟↔시군구 연결 자체는 유지
### 프론트엔드 요구사항

**라벨 표기 — 어드민 필드명 정비 (표시층만 변경)**

- 어드민 UI 라벨 변경
  - '도시' → '시/도'
  - '상세지역' → '시/군/구'
  - 어드민 지역 페이지 내 '법정지역' 탭 → 제거
- ⚠️ **라벨은 표시층만 변경, 내부는 불변**
  - `category.type = CITY`/`DETAIL_LOCATION`, GraphQL 필드(`city`·`detailLocation`), 컬럼, `spot_has_category`·`blog_has_category`·`language_course` 링크 그대로 유지
    - 타입·코드 변경 시 링크 대량 재작업 발생 우려
  - 라벨↔내부명 매핑만 표시층에 둠: '시/도' = `CITY`, '시/군/구' = `DETAIL_LOCATION`
**어드민 — 도시(CITY) 관리 (/location '도시' 탭)**

- '도시' 탭에 '추가' 버튼·생성 모달 추가
- 도시 생성 모달 — 법정동(시도, L1) 선택, 또는 법정동에 없는 값('한국'·해외)은 자유 텍스트 입력으로 생성
- '법정동' 탭(구 '법정지역') 제거
**어드민 — 상세지역 관리(/location)**

- 시군구(상세지역)는 admin 생성·삭제 불가 — 법정동(L2)에서 전량 시딩되는 read-only 구조
  - 상위 도시(시도)·법정동 코드 바인딩도 코드 도출값이라 편집 대상 아님
- admin은 시딩된 시군구의 이름(15개 어권 다국어)만 편집
- 상세지역 상세 모달에 그 구의 법정동(동) 목록을 읽기 전용 노출
- 로케일 미입력 시군구 강조표기
  - 시군구 목록·편집 화면에서 15개 어권 중 이름이 비어 있는 시군구를 시각적으로 강조하고, 어느 로케일이 비었는지 식별 가능하게 노출
    - 스팟 표기가 {시도}로 강등되는 시군구를 운영자가 찾아 채우는 단서
**어드민 — 스팟 지역 태깅**

- 스팟 등록·수정 화면에서 도시·상세지역을 좌표(법정동)로 자동 도출·연결, 드롭다운으로 직접 수정 가능
  - 좌표 기반 자동 연결
- 스팟의 법정동(L3)을 읽기 전용 표시
  - 원천은 `spot.legal_location_legal_code`, `legal_location` 조인으로 이름 노출
  - 별도 저장·태깅 없음(원천은 `legal_code` 하나)
    - 파생 순서: 좌표 → 법정동 → 시군구 → 시도. 미코드(159)·오배정(20) 스팟은 수동 override
**스팟 지역 표기 — 로케일명 누락 fallback (유저 노출)**

- 스팟 표기는 유저 현재 로케일의 이름을 사용
  - 해당 로케일에 시군구 이름이 없으면 {시도}만 노출(빈칸·타언어 노출 금지)
  - 예: 태국어 미입력 시 '강원특별자치도 강릉시' → '강원특별자치도'
- 연결은 항상 유지
  - 시군구↔스팟 연결은 좌표(legal_code) 도출값이라 로케일명 누락과 무관하게 존속(REGION 필터·검색 facet·분류의 기반이므로 표기 누락으로 끊지 않음)
  - 누락은 표기층에서만 강등
### 백엔드 요구사항

**도시 생성 · 시군구 시딩 — 재오염 차단**

- 도시(CITY)만 admin 생성 대상
  - 자유 텍스트 생성은 도시에만 허용(legal 없는 '한국'·해외 그릇)
  - 카테고리 생성은 도시 탭 진입점으로만 허용하고 종류 화이트리스트로 임의 생성 차단
- 시군구(DL)는 admin 생성 진입점 없음
  - 법정동(L2)에서 전량 시딩(스크립트)
    - 상위 도시(parent)는 시군구 코드에서 도출해 저장. admin은 시딩된 시군구의 이름(다국어)만 수정 가능
  - ※ 엔티티 자유생성 ≠ 이름 자유입력 — DL 다국어 이름 편집은 유지(구조·바인딩만 read-only)
  - ※ 해외 DL은 범위 밖 — 필요 시 자유 텍스트 CITY로만 둠
**시군구 ↔ 법정동 연결 (전량 스크립트 시딩)**

- 시군구에 시군구 단위 법정동 코드(1:1, 지도 폴리곤용) 저장 — 법정동(L2)에서 전량 시딩(이름 자동매칭, 모호한 건 수동 지정). admin의 개별 선택·생성 없음.
- 하위 법정동 목록(pool)은 저장·연결 안 함 — 코드 prefix(구 코드)로 조회 시점 자동 도출
- 어드민 상세지역 화면의 '연결된 법정동 목록'도 도출 결과를 읽기 전용 반환
**스팟 도시·상세지역 자동 태깅**

- 스팟의 도시(시도)·상세지역(시군구)을 좌표(법정동)에서 자동 도출·저장. 좌표 없는·오배정 스팟은 수동 지정
**지역 표기 resolution · 로케일 상태 노출**

- 스팟 표기 문자열은 서버가 로케일 fallback을 적용해 내려줌
  - 시군구 로케일명 존재 시 `{시도} {시군구}`, 없으면 `{시도}`
  - 클라가 분기하지 않도록 완성 문자열(또는 표기 단위) 반환
- 어드민 시군구 조회에 로케일별 이름 채움 상태(어느 어권이 비었는지) 반환
**스팟 도시·상세지역 태그 재설정**

- 스팟이 이미 보유한 법정동 코드(`spot.legal_location_legal_code`, 원천)에서 시군구·시도를 파생해 `spot_has_category`의 도시(시도)·상세지역(시군구) 태그를 재설정
- 법정동 값 자체는 이미 있어 신규 저장 아님. 미코드(159)·오배정(20) 스팟만 수동 지정
**데이터 정비 (일회성 마이그레이션) — 실행 순서**

아래 순서로 수행. 비파괴가 기본이며, 링크 재지정 전에 값을 삭제하지 않음

1. **완전 무연결 제거** — 도시·상세지역 중 스팟·블로그·어학당·지역(region) 연결이 모두 없는 것만 제거
  1. '한국'은 유지, '평양'(북한)은 제거. 상세지역 완전 무연결은 현재 청주공항 1건 — 실행 시점 재확인
2. **레벨 재타입 (코드 보존)** — 현재 도시로 있으나 시군구(L2)에 해당하는 값(강릉시·의왕시·춘천시 등)은 삭제하지 않고 상세지역으로 종류만 변경, 상위 도시를 소속 시도로 재지정
  1. 코드를 보존하므로 블로그·어학당 링크가 그대로 살아 재작업 없음.
3. **법정동 기준 생성 (없는 값만)** — 도시 = 법정동 시도(L1), 상세지역 = 법정동 시군구(L2) 확보
  1. 이미 있는 값(광역시·특별시 도시, 행정구·재타입 시군구 상세지역)은 재사용, 없는 값(강원특별자치도 등 시도, 미보유 시군구)만 생성.
4. **지역(REGION) 생성·보완 및 연결 (후속 트랙 · 5의 선행)** — 관광지명 상세지역(홍대·명동)을 대응 지역(REGION)으로 만들어 구 연결 + 법정동을 선택해 둠
  1. 스팟 세팅보다 앞서야 관광지명 탐색이 REGION으로 보존돼 무중단 성립
  2. REGION은 스팟의 좌표(법정동 코드)로 노출되므로 스팟의 상세지역 값과 무관하게 먼저 생성 가능 (선행: REGION 데이터 필드·어드민 개선 — 법정동 선택. 아래 후속 트랙 참조)
5. **스팟 일괄 세팅** — 스팟의 도시·상세지역을 좌표(법정동 코드)의 시도·시군구로 일괄 세팅
  1. 도시(시도)·일반 스팟은 3까지의 정합 위에서 세팅 가능, 관광지 스팟의 이동(홍대→마포구)은 4의 대응 REGION 준비 이후 수행
## 사람이 수행할 작업 (운영·기획 수동)

자동(스크립트) 처리와 별개로, 사람이 판단·검수·승인해야 하는 항목

- **분류 검수** — 이름만으로 오분류되는 2건을 재분류 확정. (**서울대입구** — 접미사 '구'이나 지하철역 상권이므로 관광지형 / **서면** — 접미사 '면'이나 부산 상권이므로 관광지형)
- **동명 시군구 수동 매칭 6건 (일회성)** — 이름 자동매칭이 안 되는 구의 법정동 코드 지정. (중구·동구·서구·남구·북구 — 상위 도시로 판별 / 강서구 — 서울로 판별)
- **재태깅 결과 검수** — 스팟이 엉뚱한 구로 옮겨지지 않았는지 표본 확인. 특히 구 경계에 걸친 스팟(법정동 경계 ±55m 이내)과 위치가 크게 어긋난 소수 스팟(20건)을 우선 확인
- **잡값 처리 확인** — '한국'·해외값(타이페이·대만) 유지, '평양' 제거 확정
- **실행 방식 결정** — 정비를 스크립트로 일괄 처리할지, 어드민에서 수동으로 할지 결정. 시군구(상세지역)는 **전량 스크립트 시딩이 전제**이며, 수동 대상은 도시 생성 채널·시군구 이름(다국어) 편집에 한함
