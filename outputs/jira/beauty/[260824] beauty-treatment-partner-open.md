# 세부 기획안 요구사항 문서

## 배경

### 문제 정의

현재 시술 정보 관리(`/beauty-treatment`) 기능은 크리에이트립 어드민 전용으로, 담당자가 시술과 그 하위 부가정보를 생성하고 스팟에 연결한 뒤 가격까지 직접 관리하는 구조다. 시술 정보는 대분류 피부과(3068)·시력교정(3099) 스팟에만 등록되며, 시술 → 부가정보(옵션) → 스팟 연결(가격) 3단으로 이루어진다.

제휴 피부과 수가 늘고 각 피부과의 시술·가격 정보 변동 빈도가 높아지면서, 담당자 1인이 모든 스팟의 변경을 적시에 확인·반영하기 어려운 운영 병목이 발생하고 있다. 반영이 지연되면 유저 페이지에 옛 시술·가격 정보가 노출되어 정보 최신성과 신뢰도가 떨어진다.

또한 부가정보(옵션)가 시술 하위의 전사 공용 객체로 관리되고 있어, 클리닉마다 상이한 옵션 구성(용량·횟수·패키지 등)을 담기에 구조적으로 맞지 않는다. 이 구조는 담당자가 일괄 큐레이션하던 기존 운영에서는 문제가 없었으나, 파트너가 자기 스팟을 직접 관리하는 방향에서는 어색하다.

이에 각 피부과 파트너가 자기 스팟의 시술 정보를 직접 관리하도록 권한을 이관하되, 시술(상위 분류)은 공용 자산으로 유지하고 부가정보(옵션)는 스팟 단위로 소유를 이전하는 개편이 필요하다.

### 가설적 임팩트

- 파트너가 변경 시점에 직접 반영함으로써 시술·가격 정보의 최신성 향상
- 담당자의 전 스팟 수동 반영 공수 절감, 반영 지연에 따른 오노출 감소
- 스팟 단위 옵션 소유로 클리닉별 실제 시술 라인업을 정확히 반영
- 정량 수치(대상 피부과 수·평균 변경 빈도 기반 절감 공수, 정보 오노출 감소율)는 TBD

## 구현

### 유저 플로우

행위자: 파트너(피부과), 어드민(크리에이트립 담당자), 유저

**파트너**

- 파트너는 파트너 전용 메뉴에서 시술 정보 관리에 진입하며, 자기 소유(파트너십으로 연결된) 스팟만 목록·상세로 조회한다.
- 파트너의 스팟이 대분류 피부과(3068)·시력교정(3099)에 해당하면 시술 정보 관리 대상이 되며, 파트너는 해당 스팟에 제공 시술을 연결한다.
- 파트너는 연결한 시술 아래에 부가정보(옵션)를 직접 추가하고, 옵션별 라벨과 가격을 입력한다.
- 파트너는 옵션의 활성화/비활성화, 스팟 단위 가격 비공개 여부, 시술 전·후 이미지(Before/After 쌍)를 설정한다.
- 파트너의 시술 연결·옵션·가격·비공개 변경은 어드민 승인 없이 즉시 반영된다.
- 파트너는 상위 항목인 '시술' 자체를 생성할 수 없으며, 카탈로그에 없는 시술이 필요하면 어드민에 시술 추가를 요청한다. 어드민 승인 이후 해당 시술을 자기 스팟에 연결할 수 있다.
- 파트너가 입력한 옵션 라벨은 자동번역으로 다국어 번역되며, 번역이 완료된 옵션만 활성화(유저 공개)할 수 있다. 미번역 옵션을 활성화하려 하면 **"번역이 완료되어야 공개할 수 있어요"**(카피 TBD)를 안내하고 활성화를 막는다.

**어드민**

- 어드민은 기존과 동일하게 전 스팟의 시술 정보 관리에 접근하며, 소유권 제한 없이 모든 스팟을 조회·수정한다.
- 어드민은 공용 시술 카탈로그(시술 정의)를 단독으로 관리하며, 파트너는 시술 카탈로그를 편집할 수 없다.
- 어드민은 파트너의 시술 추가 요청을 확인하고 승인 또는 반려한다.
- 어드민은 시술 기준으로 파트너들이 생성한 부가정보를 한눈에 검수하고, 부적절한 라벨은 수정하거나 삭제한다.
- 어드민은 각 부가정보에 연결된 스팟을 읽기 전용으로 확인한다. 연결·해제는 파트너가 자율적으로 수행하므로 어드민 화면에서는 조작하지 않는다.
- 어드민은 각 부가정보의 번역을 현행과 동일하게 편집 관리한다.

**유저**

- 유저는 파트너가 등록·수정한 시술·옵션·가격을 기존과 동일한 노출 경로(스팟 상세 시술 섹션, 검색 결과 카드)에서 확인한다.
- 가격 비공개로 설정된 시술은 상세에서 가격이 노출되지 않는다(기존 정책 유지).
- 번역이 완료되지 않은 옵션은 유저에게 노출되지 않는다.

### 프론트엔드 요구사항

**FR-1. 파트너 시술 정보 관리 진입점·접근 범위**
- 파트너 계정 로그인 시 파트너 전용 메뉴에 시술 정보 관리 진입점 노출
- 파트너에게는 자기 소유 스팟만 목록·상세로 노출, 어드민에게는 전체 스팟 노출
- 파트너의 편집(연결·가격·옵션·비공개)은 승인 절차 없이 즉시 반영

**FR-2. 파트너 관리 대상 스팟 노출 방식** (TBD, BR-7과 연동)
- 1순위: 대분류 피부과(3068)·시력교정(3099)인 파트너 소유 스팟을 별도 등록 절차 없이 자동으로 관리 대상에 노출
- 폴백: 어드민이 파트너에게 열어줄 스팟을 명시 지정, 지정된 스팟만 파트너 화면에 노출(파일럿 클리닉부터 점진 개방)

**FR-3. 스팟 상세 시술 연결 화면 — 부가정보 직접 관리**
- 스팟 상세의 시술 연결 화면에서 부가정보(옵션) **신규 추가**와 **라벨 직접 입력** 지원(기존에는 이미 정의된 옵션의 가격·활성화만 조정 가능)
- 옵션별 가격 입력, 활성화/비활성화 토글, 표시 순서 변경
- 활성화된 옵션에 가격 미입력 시 저장 차단 및 안내 **"활성화된 부가정보에 가격을 입력해주세요."**
- 시술 전·후 이미지는 Before/After 쌍으로만 등록, 한쪽만 등록 시 저장 차단 및 안내 **"이미지는 Before/After 쌍으로 등록해주세요."**
- 스팟 단위 **가격 비공개** 토글을 파트너 화면에도 제공

**FR-4. 옵션 라벨 자동번역·공개 게이트**
- 옵션 라벨 자동번역 실행 진입점 제공, 옵션별 번역 상태(완료/미완료) 노출
- 번역 미완료 옵션은 활성화(공개) 제한, 활성화 시도 시 안내 **"번역이 완료되어야 공개할 수 있어요"**(카피 TBD)

**FR-5. 신규 시술 추가 요청 화면**
- 파트너가 카탈로그에 없는 신규 시술을 요청하는 화면 제공(시술명·카테고리 등 입력)
- 어드민이 요청 목록을 확인하고 승인/반려하는 화면 제공
- 승인 시 해당 시술이 공용 카탈로그에 반영되어 파트너가 자기 스팟에 연결 가능
- 기존 스팟 생성·수정 요청 흐름과 동일한 형태로 구성

**FR-6. 시술 카탈로그 화면 정리**
- 시술 카탈로그(시술 정의) 관리 화면은 어드민 전용으로 유지
- 부가정보 관리 위치를 시술 카탈로그 화면에서 스팟 상세 화면으로 이동(부가정보는 더 이상 시술 하위 공용 목록으로 관리하지 않음)

**FR-7. 어드민 부가정보 검수 화면**
- 시술 기준으로 파트너 생성 부가정보를 검수하는 어드민 전용 화면 제공
- 행 컨트롤이 많아 단일 테이블 대신 **2단 카드 리스트**로 구성
  - 1행(조작): 순서 변경, 라벨 입력, 저장, 번역관리, 삭제
  - 2행(정보): 연결된 스팟을 태그로 노출, 태그는 **#스팟ID 스팟명** 형태, 클릭 시 해당 스팟으로 이동, 다수면 **외 N개**로 접기, 연결이 없으면 **연결된 스팟 없음** 노출
- 라벨 옆에 번역 상태(완료/미완료) 노출, 번역관리는 어드민 편집 가능
- 연결된 스팟 정보는 읽기 전용(연결·해제 조작 없음)

### 백엔드 요구사항

**BR-1. 시술 정보 관리 소유권 스코핑 신설**
- 시술 정보 관리 조회·수정 요청 시 요청자 식별 후 권한 분기
- 파트너 요청은 자기 소유(파트너십으로 연결된) 스팟만 접근 가능하도록 제한
- 어드민 요청은 전체 스팟 접근 유지
- GraphQL 직접 호출 우회를 막기 위해 클라이언트 필터가 아닌 서버 측 불변식으로 강제

**BR-2. 부가정보 소유 구조 스팟 단위 이전**
- 부가정보(옵션) 데이터 소유를 전사 공용 카탈로그에서 스팟 단위 소유로 이전
- 상위 항목인 시술(procedure)은 공용 카탈로그로 유지(검색·필터·카테고리 집계 정합성 유지)
- 스팟-시술 연결 데이터가 참조하는 옵션 대상을 스팟 소유 옵션으로 변경

**BR-3. 데이터 마이그레이션**
- 기존 공용 부가정보 및 이를 참조하는 스팟 연결 데이터를 스팟 소유 옵션으로 이전
- 옵션 라벨·번역·가격 등 기존 값 보존
- 마이그레이션 이후 유저 노출·검색 인덱싱 결과가 기존과 동일하게 유지되는지 검증

**BR-4. 옵션 번역 완료 공개 게이트**
- 옵션 라벨의 다국어 번역 완료 여부를 유저 공개 조건으로 검사
- 번역 미완료 옵션은 활성화 및 유저 노출(상세·검색) 대상에서 제외

**BR-5. 신규 시술 추가 요청 워크플로우**
- 파트너의 시술 추가 요청을 저장하고 어드민 승인/반려로 처리하는 로직 신설
- 승인 시 공용 시술 카탈로그에 반영, 반려 시 사유 저장

**BR-6. 어드민 검수 화면용 조회**
- 시술 기준으로 부가정보 목록과 각 부가정보에 연결된 스팟 목록(스팟 ID·스팟명)을 함께 반환
- FR-7의 2단 카드 노출에 필요한 번역 상태·표시 순서 필드 포함

**BR-7. 파트너 관리 대상 스팟 판별 방식** (TBD, FR-2와 연동)
- 1순위(카테고리 기반 자동 판별): 대분류 피부과(3068)·시력교정(3099) 여부로 관리 대상 판별. 현재 관리 대상 목록·카테고리 집계·가격 비공개 보관이 스팟별 메타 레코드 존재에 의존하므로, 자동 판별 전환 시 해당 로직 개편 필요
- 폴백(어드민 지정): 현 구조를 유지하고 어드민이 지정한 스팟만 대상화, 소유권 스코핑(BR-1)만 추가
- 구현 견적 및 롤아웃 전략에 따라 최종 방식 확정

**BR-8. 계약 호환성**
- 스키마·API 계약 변경 시 소비자 호환성 준수(추가 필드 우선, 타입 변경·필수 필드 추가 등 파괴적 변경은 소비자 동시 대응)
