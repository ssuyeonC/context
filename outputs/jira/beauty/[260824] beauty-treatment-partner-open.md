# 세부 기획안 요구사항 문서

## 배경

### 문제 정의

- 시술 정보 관리(`/beauty-treatment`)가 어드민 전용 — 담당자가 시술·부가정보 생성, 스팟 연결, 가격까지 직접 관리(대분류 피부과 3068·시력교정 3099 스팟 대상, 시술→부가정보(옵션)→스팟 연결(가격) 3단 구조)
- 제휴 피부과 증가·가격 변동 잦아 담당자 1인 반영 병목 → 유저 페이지에 옛 정보 오노출, 최신성·신뢰도 저하
- 부가정보(옵션)가 시술 하위 전사 공용 객체라 클리닉별 상이한 옵션 구성(용량·횟수·패키지)을 담기에 부적합
- 파트너가 자기 스팟 시술 정보를 직접 관리하도록 권한 이관 필요 — 단 시술(상위)은 공용 유지, 부가정보(옵션)는 스팟 단위 소유로 이전

### 가설적 임팩트

- 파트너 직접 반영으로 시술·가격 최신성 향상, 담당자 수동 반영 공수·오노출 감소
- 스팟 단위 옵션 소유로 클리닉별 실제 라인업 정확 반영
- 정량 지표(대상 피부과 수·변경 빈도 기반 절감 공수, 오노출 감소율): TBD

## 구현

### 유저 플로우

행위자: 파트너(피부과) · 어드민(담당 매니저) · 유저

**파트너**
- 파트너 어드민 스팟 수정 요청 화면의 '수가표' 섹션 바로 아래 '시술 정보 관리' 섹션에서 자기 소유 스팟의 시술 정보 관리(전용 메뉴 없음)
- 섹션 노출 = 스팟 대분류 3068·3099 + 파트너 본인 소유(카테고리 게이팅, 어드민 사전 지정 불필요)
- 시술 연결, 부가정보(옵션) 추가·라벨/가격 입력, 옵션 활성/비활성, 스팟 단위 가격 비공개, 시술 전·후 이미지(Before/After 쌍) 설정
- 편집(연결·옵션·가격·비공개·이미지)은 어드민 승인 없이 즉시 반영
- 옵션 라벨은 자동번역, 번역 완료 옵션만 활성(공개) 가능
- 시술(상위) 생성 불가 — 카탈로그에 없는 시술은 어드민에 추가 요청(시술명·설명 원문만 입력), 어드민이 번역·등록하면 자기 스팟에 연결

**어드민**
- 전 스팟의 스팟-시술 관계(연결·해제·부가정보·가격) 직접 편집 — 파트너 개방으로 권한 축소 없음
- 공용 시술 카탈로그(시술 정의) 단독 관리 — 시술 생성·수정·제거(파트너는 카탈로그 편집 불가)
- `/beauty-treatment` 목록에 시술/옵션 데이터가 붙은 스팟 자동 노출 — 어드민 '연결할 스팟 추가하기' 추가분 + 파트너 저장분 함께, 사전 개방 지정 없음
- 파트너 시술 추가 요청을 `/beauty-treatment`에서 확인 → 시술명·설명 검토 + 다국어 번역 작성 후 등록(또는 반려), 요청 접수 시 담당 매니저에게 알림
- 시술 기준 파트너 생성 부가정보 검수 — 부적절 라벨 수정·삭제, 번역 편집

**유저**
- 파트너가 등록·수정한 시술·옵션·가격을 기존 노출 경로(스팟 상세·검색 카드)에서 확인
- 가격 비공개 시술은 상세에서 가격 미노출(검색·리스트 필터로는 활용)
- 번역 미완료 옵션은 미노출

### 프론트엔드 요구사항

**FR-1. 파트너 진입점·섹션 노출**
- 파트너 어드민 스팟 수정 요청 화면 '수가표' 섹션 바로 아래에 '시술 정보 관리' 섹션 배치(전용 메뉴 없음)
- 노출 조건: 스팟 대분류 3068·3099 + 파트너 본인 소유 — 수가표와 동일한 카테고리 게이팅(수가표 3068, 시술 정보 관리 3068·3099)
- 섹션 구성(위→아래): ① 헤더(제목·안내·대분류 노출 노트) → ② **가격 비공개** 스팟 단위 토글 → ③ 연결 시술 카드 리스트(아코디언) → ④ 하단 **+ 시술 연결** · **신규 시술 추가 요청**
- 수가표 섹션의 카드·드래그 순서변경·하단 추가 버튼 패턴 계승(별첨 와이어프레임)

**FR-2. 시술 카드·부가정보 관리 UI**
- 시술 카드 = 연결 시술 1개, **기본 접힘**(아코디언). 헤더에 시술명 + **활성 옵션 수**·**번역 상태(완료/미번역 N)** 배지, 드래그 순서변경, **연결 해제**
- 부가정보(옵션) 행 = 옵션 1개, 2줄 구성 — 1줄: 드래그·**라벨**·**가격**·**활성 토글** / 2줄: **번역 상태 배지**·**번역관리**·**삭제**. **+ 부가정보 추가**로 신설
- 활성 옵션에 가격 미입력 시 저장 차단 — **"활성화된 부가정보에 가격을 입력해주세요."**
- 미번역 옵션 활성화 차단 — **"번역이 완료되어야 공개할 수 있어요"**(카피 TBD)
- 시술 전·후 이미지는 Before/After 쌍만 등록, 한쪽만 등록 시 저장 차단 — **"이미지는 Before/After 쌍으로 등록해주세요."**
- **가격 비공개**는 스팟 단위 토글 1개(섹션 상단) — 켜면 상세 비노출, 검색·리스트 필터는 유지

**FR-3. 신규 시술 추가 요청**
- 파트너: 섹션 하단 **신규 시술 추가 요청**으로 요청 — **시술명·설명(원문)만** 입력(카테고리는 출처 스팟 대분류 자동, 번역 미입력)
- 어드민: `/beauty-treatment`의 '파트너 시술 추가 요청' 인박스에서 시술명·설명 확인 + **다국어 번역 작성** 후 카탈로그 등록(반려 시 사유) — 번역까지 채워야 등록 완료
- 시술 추가만 어드민 처리 필요 — 스팟 소유 편집은 즉시 반영

**FR-4. 어드민 부가정보 검수 화면**
- 시술 기준 파트너 생성 부가정보 검수 화면(어드민 전용), **2단 카드 리스트**
  - 1행(조작): 순서 변경·라벨 입력·저장·번역관리·삭제
  - 2행(정보): 연결 스팟 태그(**#스팟ID 스팟명**, 클릭 시 이동, 다수면 **외 N개**, 없으면 **연결된 스팟 없음**)
- 라벨 옆 번역 상태 노출, 번역관리 어드민 편집 가능
- 검수 화면은 연결 스팟 확인 위주 — 관계 편집은 시술 정보 관리 화면에서 수행

**FR-5. `/beauty-treatment` 화면 정리**
- 시술 카탈로그(시술 정의) 생성·수정·제거는 어드민 전용 유지
- 부가정보 관리 위치를 카탈로그 화면 → 스팟 상세 화면으로 이동(시술 하위 공용 목록 관리 폐지)
- 파트너 시술 추가 요청 인박스 포함(대기 요청·요청자·시술명·카테고리)
- 목록에 시술/옵션 데이터 있는 스팟 자동 노출, 기존 '연결할 스팟 추가하기' 유지

**FR-6. 파트너 편집 변경 내역 노출**
- 파트너 자동 승인 편집(연결·옵션·가격·활성·비공개·이미지)은 승인 큐 미노출, 파트너 수정 요청 화면(`/travel-partner/update-requests`)의 **'수정됨(변경 내역)' 탭**에 이력 노출

### 백엔드 요구사항

**BR-1. 소유권 스코핑**
- 시술 정보 관리 조회·수정 시 요청자 식별 후 분기 — 파트너는 자기 소유 스팟만, 어드민은 전체
- 서버 측 불변식으로 강제(GraphQL 직접 호출 우회 차단)

**BR-2. 부가정보 스팟 단위 소유 이전**
- 부가정보(옵션) 소유를 전사 공용 → 스팟 단위로 이전, 시술(procedure)은 공용 카탈로그 유지
- 스팟-시술 연결이 참조하는 옵션 대상을 스팟 소유 옵션으로 변경

**BR-3. 데이터 마이그레이션**
- 기존 공용 부가정보·스팟 연결 데이터를 스팟 소유 옵션으로 이전(라벨·번역·가격 보존)
- 마이그레이션 후 유저 노출·검색 인덱싱 결과 동일성 검증

**BR-4. 번역 완료 공개 게이트**
- 옵션 라벨 다국어 번역 완료를 유저 공개 조건으로 검사 — 미완료 옵션은 활성화·유저 노출(상세·검색) 제외

**BR-5. 대상 스팟 판별 — 데이터 존재 기반**
- 별도 개방 지정 레코드 없이 `spot_beauty_option`(스팟 시술/옵션 데이터) 존재로 관리 대상 판별(기존 목록 조회 방식 유지 — 옵션 있는 스팟을 카테고리 필터로 distinct 조회)
- 파트너 섹션 노출 = 대분류 3068·3099 + 파트너 소유(BR-1)
- 파트너 저장 시 `spot_beauty_option` 생성 → 어드민 `/beauty-treatment` 목록 자동 노출(어드민 '연결할 스팟 추가하기'의 빈 shell 생성과 동일 경로), 기존 추가·삭제 처리 유지

**BR-6. 신규 시술 추가 요청 · 담당 매니저 알림**
- 파트너 요청 저장 = 시술명·설명(원문)만(카테고리는 출처 스팟에서 파생, 번역 공란)
- 등록 시 공용 카탈로그(`beauty_procedure`)에 시술 생성 — 카테고리 = 출처 스팟 대분류, 언어별 번역(name·description)은 어드민 작성(기존 `categoryCode + translations[]` 등록 구조 재사용), 반려 시 사유 저장
- 처리 화면은 `/beauty-treatment` — 스팟 수정 요청 큐(`/travel-partner/update-requests`)와 분리
- 요청 접수 시 어드민 알림 발송(`admin_notification`·수신자 정책 재사용) — **카테고리→담당 매니저 코드 매핑을 상수(하드코딩)**로 조회, 미매핑은 폴백 수신자로 전달. 매니저 교체 시 상수 수정 필요(빈도 높아지면 운영 테이블 이관 재검토)

**BR-7. 검수 화면 조회**
- 시술 기준 부가정보 목록 + 각 부가정보 연결 스팟(ID·명) 반환, 번역 상태·표시 순서 필드 포함(FR-4)

**BR-8. 파트너 편집 변경 내역 적재**
- 파트너 자동 승인 편집을 승인 대기 없이 즉시 반영 + '수정됨(변경 내역)' 탭 참조 이력에 적재 — 시술 추가 요청(승인 필요)과 적재 경로 구분

**BR-9. 계약 호환성**
- 스키마·API 계약 변경 시 소비자 호환성 준수(추가 필드 우선, 파괴적 변경은 소비자 동시 대응)
