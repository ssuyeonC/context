# 유저 메인 — '오늘의 예약' 플로팅 섹션 (사용자 측 리뷰 작성 동선 단축)

## 배경

### 문제 정의

- 모바일 메인 화면에서 사용자가 당일 예약 정보(시각·장소·바우처·길찾기·리뷰 작성 위치)를 직접 찾아야 한다. 탐색 비용이 크다.
- 특히 시술/체험을 마친 후 리뷰 작성까지 도달하는 동선이 길어, 작성률이 낮다.
- 현장 운영 측에서도 매번 직원이 리뷰 작성 위치를 언어별로 안내해야 하는 부담이 있다. 외국인 고객이 다수인 카테고리에서 더 큼.
- 호수도산 파트너 인터뷰에서 동일 문제 인식이 확인되었다.
  - "고객의 리뷰 작성 경험 개선 — 끝난 후 버튼만 누르면 리뷰 바로 남길 수 있도록"
  - "파트너 어드민에서 특정 버튼 클릭 → 유저 기기에서 바로 리뷰 작성 알림"
- 결과적으로 **사용자 불편 + 현장 운영 부담 + 예약/리뷰 관련 CS 문의**가 함께 발생한다.

### 가설적 임팩트

- **당일 예약 정보 진입률 ↑** — 예약 상세 / 바우처 / 길찾기 액션의 진입이 메인에서 한 번에 가능해진다.
- **리뷰 작성 진입률·완료율 ↑** — 시술 종료 직후 메인 화면에서 [리뷰 쓰기] CTA가 노출되어 작성까지의 동선이 짧아진다.
- **외국인 사용자의 진입 부담 ↓** — i18n 처리된 카드가 자동 노출되어 다국어 안내 부담을 시스템이 흡수한다.
- **현장 안내 부담 ↓** — 직원이 매번 리뷰 위치를 안내하지 않아도, 고객이 앱을 켜면 자연스럽게 작성 동선이 보인다.
- **방문 전 정보 확인 강화** — 바우처·길찾기 즉시 접근으로 지각·노쇼·문의 부담이 줄어들 수 있다.

## 구현

### 유저 플로우

**사용자**

- 로그인 상태에서 모바일 메인 화면에 진입한다.
- 오늘(한국 KST 기준) 날짜에 `COMPLETE` 또는 `USED` 상태의 예약이 있으면 **하단에 '오늘의 예약' 플로팅 섹션**이 자동 노출된다.
- 예약 상태에 따라 카드 모드가 달라진다.
  - 확정됨(`COMPLETE`) → **방문 전 카드** ([예약 상세 보기] / [바우처] / [길찾기])
  - 사용 완료(`USED`) → **방문 후 카드** ([리뷰 쓰기])
- 오늘 예약이 여러 개면 **좌우 스와이프**로 다음/이전 카드로 이동한다. 정렬은 **시간이 임박한 순**.
- 카드는 **닫을 수 없다**. 다만 **아래로 스와이프하면 헤더만 살짝 보이는 미니멀 모드**로 전환되어 메인 콘텐츠 탐색을 방해하지 않는다.
- 각 액션을 클릭하면 해당 페이지로 즉시 이동하거나(예약 상세/리뷰 쓰기) 외부 앱이 열린다(길찾기).

### 프론트엔드 요구사항

**노출 조건 / 범위**

- 모바일 메인 화면에만 노출. PC 웹은 미표시.
- 로그인 사용자에 한해 노출. 비로그인은 노출 X.
- 노출 대상 예약: **한국 KST 기준 오늘 날짜**의 `COMPLETE` 또는 `USED` 상태 예약만.
- 그 외 상태(`CONFIRM_REQUIRED` / `CANCEL` / `REJECT` / `EXPIRED`)는 노출하지 않는다.

**카드 구조**

| 영역 | 공통 | 방문 전 (COMPLETE) | 방문 후 (USED) |
|---|---|---|---|
| 헤더 | 상태 라벨 / 예약 시각 / 스팟명 | "방문 전" 표기 | "방문 완료" 표기 |
| 메인 액션 | — | [예약 상세 보기] / [바우처] / [길찾기] | [리뷰 쓰기] |

**액션 세부 동작**

- **[예약 상세 보기]** → 기존 마이페이지 예약 상세 페이지로 즉시 이동. 별도 인라인 expand 없음.
- **[바우처]** → 카드 내 인라인 영역에 바우처 정보 표시 (예약당 바우처 1개 가정).
  - 표시 항목: `pin`, `link`, `image_pathname` 또는 `text` 중 보유한 것
  - 데이터 소스: 기존 `Voucher` 도메인 (`reservation_code`로 조회)
- **[길찾기]** → Google Maps URL을 새 탭/외부 앱으로 연다. URL에 해당 스팟의 위경도값을 포함한다.
- **[리뷰 쓰기]** → 기존 리뷰 작성 페이지로 즉시 이동, 예약 컨텍스트(스팟·예약 코드)는 자동 채움. 기존 작성 흐름 그대로.

**정렬 / 인터랙션**

- 정렬: 예약 시각이 가까운 순 (시간 임박 순).
- 인터랙션:
  - 좌우 스와이프: 카드 간 이동
  - 아래로 스와이프: 미니멀 모드 (헤더만 살짝 노출) ↔ 위로 스와이프(또는 헤더 탭): 풀 카드 복귀
- 닫기 버튼은 없다.

**다국어 / 지역화**

- 카드 내 모든 텍스트는 i18n 처리한다.
- 시각 표기는 한국 KST 기준이되, 표기 형식은 사용자 로케일을 따른다 (12h/24h, 날짜 포맷).

### 백엔드 요구사항

**신규 query**

- 로그인 사용자의 "오늘(KST) 예약" 목록을 가져오는 query 신설.
  - 조건: `member_code = 본인` + `reservation_date`가 오늘 KST 범위에 해당 + 상태가 `COMPLETE` 또는 `USED`
  - 정렬: `reservation_date` ASC (시간 임박 순)
  - 응답 필드 (카드 렌더링에 필요한 최소 셋):
    - 예약 코드, 예약 시각, 상태
    - 스팟 정보: 이름, 위경도 (`latitude`, `longitude`)
    - 바우처 정보: 첫 1건의 `pin` / `link` / `image_pathname` / `text` (`Voucher` 도메인, `reservation_code`로 조회)
    - 리뷰 작성 가능 여부 (USED + `isReviewed === false`)

**기존 로직 재사용**

- 리뷰 작성 가능 여부 판단: 기존 `verifyReviewable` 도메인 메서드와 동일한 조건 사용.
  - 본인 예약 + 상태 `USED` + `isReviewed === false`
- 바우처 조회: 기존 `voucherRepo.findAllByReservationId` 재사용. 응답에는 첫 1건만 전달.
- 별도 mutation 신설은 불필요. 본 기능은 조회 + 외부 페이지 이동/링크 오픈이 전부.

**오늘 KST 범위 정의**

- 서버는 한국 KST 기준 `00:00:00 ~ 23:59:59`의 `reservation_date` 범위로 필터링한다. 사용자 위치 시간대와 무관하게 한국 시간 기준으로 통일한다.

### 선행 종속성

- **파트너 어드민의 사용 완료 처리 동선 단축** (`requirements_partner-admin-index-set-used-button.md`)
  - 본 기능에서 "방문 후 [리뷰 쓰기]" 카드가 시술 직후에 노출되려면, 파트너가 시술 직후 사용 완료 처리를 빠르게 해서 예약이 `USED`로 전이되어야 한다.
  - 파트너 측 동선이 느리면 본 기능의 임팩트는 반쪽이 된다. 두 작업은 짝으로 묶어 다루는 것이 바람직.

### 후속 검토 대상 (TBD)

- **바우처가 예약당 2개 이상인 경우 처리** — 현재 "1개" 가정으로 인라인 표시. 다수 바우처 케이스가 늘어나면 별도 시트/페이지로 분리 검토.
- **카드 디자인** — 본 PRD는 정보·동작 중심. 시각 디자인은 별도 작업.
- **스와이프 인터랙션 세부** — 제스처 인식 임계값, 미니멀 모드 헤더 노출 높이, 애니메이션 등 디자인·개발 협의 단계에서 결정.
- **마이페이지 예약 영역과의 시각 차별화** — 본 카드는 빠른 진입점이고 마이페이지 예약 영역은 전체 내역이므로 시각 톤·정보 밀도를 다르게 가져갈지 검토.
- **PC 웹 확장 여부** — 현재는 미표시. 추후 사용 패턴 보고 확장 검토.
- **측정 이벤트 정의** — 본 PRD 범위 외. 별도 트랙에서 노출/스와이프/액션 클릭/리뷰 완료 이벤트 정의.
- **'CONFIRM_REQUIRED' 상태 표시 정책** — 현재는 미노출. 추후 사용자에게 "확정 대기 중" 안내가 필요한지 검토.
