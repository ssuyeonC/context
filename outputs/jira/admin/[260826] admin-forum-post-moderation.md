# 세부 기획안 요구사항 문서

## 배경

### 문제 정의

- 커뮤니티(`/board`)에 부적절 게시글이 게시되나, 운영자가 관리자 화면에서 삭제할 수단 부재
- 삭제 능력 자체는 백엔드에 이미 존재 — 게시글 삭제 처리는 관리자(ADMIN·SUPER_ADMIN) 권한이면 작성자가 아니어도 임의 게시글을 삭제 가능하도록 이미 분기됨. 삭제는 소프트 삭제(레코드는 `deleted_at`으로 보존)라 데이터 유지·복구 가능
- 다만 관리자 패널에 개별 게시글을 나열·삭제하는 화면이 없어, 현재 부적절 게시글을 지우려면 개발자가 직접 쿼리·GraphQL을 실행하는 우회뿐
- 관리자 커뮤니티 화면은 포럼(카테고리) 관리(`/forum`)만 제공, 포럼 내부에 쌓인 게시글은 다루지 못함
- 유저 신고(신고) 채널·신고 처리 큐도 부재해, 운영자가 부적절 게시글을 인지·대응하는 정식 경로 없음

### 가설적 임팩트

- 부적절 게시글 대응에 개발자 개입 제거, 운영 리스크·수작업 감소 및 대응 시간 단축
- 정량 임팩트 `TBD` — 신고 채널 부재로 부적절 게시글 총량 미집계, 현재 인지된 문제 게시글은 상한 초과 5건 등 소수 규모

## 구현

### 유저 플로우

- 관리자는 어드민 `/forum`에서 포럼(Talk·Question·My Travel Plan 등) 목록 확인
- 관리자는 특정 포럼에 진입하면 해당 포럼에 속한 게시글 목록 확인
- 관리자는 게시글 행을 클릭하면 해당 게시글 전문 확인, 리스트에서는 본문 일부만 확인
- 관리자는 게시글 목록의 '삭제' 열에서 부적절 게시글을 지정해 삭제
- 삭제는 소프트 삭제 — 커뮤니티 피드·목록 노출에서만 제외, 레코드·작성자 본인 뷰 데이터는 보존
- ADMIN·SUPER_ADMIN 권한 보유자만 게시글 목록 진입·삭제 가능
- 유저는 커뮤니티 글 작성 화면(`/board/write`) 최하단에서 삭제 정책 주의사항 확인

### 프론트엔드 요구사항

- `/forum` 포럼 관리 화면에서 각 포럼 진입 시, 해당 포럼에 속한 게시글 목록 화면 노출
- 포럼별 게시글 목록 화면 신규
  - 목록 컬럼: 게시글 ID, 본문 미리보기(일부), 작성자, 작성일, 삭제
  - 게시글 행 클릭 시 해당 게시글 전문(상세) 노출, 리스트에서는 본문 일부만 노출
  - 정렬 기본값은 최신순, 페이지네이션 적용
  - 목록 내 검색은 미제공
  - '삭제' 열의 버튼 클릭 시 확인 팝업 노출(오조작 방지)
  - 삭제 확인 문구 **"이 게시글을 삭제할까요? 커뮤니티 피드·목록에서 즉시 숨겨집니다."**
  - 삭제 성공 시 목록에서 제거, 완료 안내 노출
- 게시글 목록·삭제 화면 접근 권한은 기존 `/forum`과 동일 레벨(ADMIN·SUPER_ADMIN)로 게이트
- 유저 커뮤니티 글 작성 화면(`/board/write`) 최하단에 삭제 정책 주의사항 문구 상시 노출
  - 안내 문구 **"커뮤니티 성격에 적절하지 않은 글은 통보없이 삭제될 수 있습니다. 건전한 커뮤니티 문화를 위해 노력해주세요."**

### 백엔드 요구사항

- 포럼별 게시글 목록 조회 API 신규 — 지정한 포럼에 속한 게시글을 페이지네이션 단위로 반환, 관리자 전용
  - 이미 삭제된(`deleted_at`) 게시글은 목록에서 제외, 삭제 글 노출·복구 기능은 이번 범위에서 미포함
- 게시글 삭제는 기존 소프트 삭제 로직 재사용 — 관리자 권한 시 임의 게시글 삭제를 허용하는 분기가 이미 존재하므로, 별도 관리자 전용 삭제 엔드포인트는 신설하지 않고 기존 처리 재사용
- 관리자 삭제 시 작성자 알림·삭제 사유 기록은 이번 범위에서 미포함 (유저에게는 작성 화면 주의사항으로 사전 고지)
