# 세부 기획안 요구사항 문서

## 배경

### 문제 정의

- 크리에이트립 환율 페이지(`/exchange`)는 머니박스(e-moneybox) 환율을 노출 중
- 현재 환율 값은 운영자가 어드민 '환율 정보' 화면에서 통화별 **살 때** 값을 손으로 직접 입력·저장하는 방식으로 관리 (**팔 때**는 미사용, 0 고정)
- 머니박스 환율은 영업시간(09~19시) 중 실시간 변동하나, 수동 입력은 반영 시점이 늦고 실제 고시값과 오차 상존
  - 실측 예: USD 어드민 1411 vs 머니박스 실값 1402, EUR 1615 vs 1632, SGD 1090 vs 1103 — 통화별로 편차 방향이 +·−로 섞여 일정한 마진 규칙 없이 어림·반올림된 값으로 추정
- 운영자 반복 공수 발생, 장시간 갱신 누락·오입력 리스크 내포

### 가설적 임팩트

- 운영자 수동 입력 공수 완전 제거
- 페이지 노출 환율의 실시간성·정확도 향상 — 머니박스 고시값과의 오차 해소
- 갱신 누락·오타로 인한 잘못된 환율 노출 리스크 제거

## 구현

### 유저 플로우

- 유저는 환율 페이지(`/exchange`)에서 머니박스 최신 환율이 자동 반영된 상태로 조회
- 운영자는 별도 입력 없이 환율이 자동 갱신됨을 어드민 '환율 정보' 화면에서 확인 (완전 자동, 수동 개입 불요)
- 운영자는 필요 시 특정 통화를 어드민에서 추가·삭제하여 자동 연동 대상 범위를 조정

### 프론트엔드 요구사항

- 어드민 '환율 정보' 화면은 자동 갱신된 **살 때** 값을 그대로 노출 (입력 필드 구조 변경 없음)
- 어드민 화면에 **마지막 자동 갱신 시각** 표기 추가 — 최신성·정상 동작 확인용 (TBD: 노출 위치·형식)
- 환율 페이지(`/exchange`) 노출 로직은 기존 유지 (동일 데이터 소스를 그대로 표출)

### 백엔드 요구사항

- 머니박스 환율 API 연동 배치 신설
  - 소스: `POST https://cems.moneybox.or.kr/api/moneybox.php`, 요청 본문 `cmd=C010` — 인증·세션·토큰 불요 (응답의 `cd` 값은 무시)
  - 폴링 주기: 영업시간 09~19시 **60초 간격** (머니박스 페이지의 자체 폴링 주기와 동일), 영업시간 외에는 직전 값 유지
    - 영업시간 기준은 응답의 `stm`·`etm`(현재 9·19) 참조
  - 통화 필터: 응답 `data[]` 중 **어드민에 등록된 통화만** 반영 (현재 HKD·JPY·SGD·THB·TWD·USD·EUR 7종)
  - 값 매핑: `data[].buy` → 어드민 **살 때**, **소수 둘째 자리 반올림**하여 저장. **팔 때**는 미반영(0 유지)
  - 마진 미적용: API 실값을 반올림만 하여 저장 (별도 스프레드·가감 없음)
  - 단위 처리: `buy` 값은 이미 1통화 기준으로 제공(JPY 실측 8.8182 ↔ 어드민 8.82 일치) → `unit` 필드는 표기용, 별도 환산 불요 (TBD: 저단가 통화 반올림 시 유효자리 확인)
  - 변경 감지: 응답 `history` 값이 직전과 달라진 경우에만 DB 갱신 — 동일 값 중복 쓰기 방지
- 실패·예외 처리
  - API 무응답·오류·포맷 변경 시 직전 정상값 유지, 화면에 0·공백 노출 금지
  - 실패가 일정 횟수 이상 지속되면 운영자 알림 (TBD: 알림 채널·임계치)
- 통화 등록 정합
  - 어드민에 통화 신규 등록 시, API 응답에 존재하면 자동 연동 대상에 포함
  - API 응답에 없는 통화는 자동 갱신 제외, 기존 수동 관리 방식 유지
