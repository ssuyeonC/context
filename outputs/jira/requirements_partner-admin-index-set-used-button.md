# 파트너 어드민 — 인덱스 '오늘 방문 예정' 테이블에 '사용 완료' 버튼 추가

## 배경

### 문제 정의

- 파트너 어드민의 인덱스 화면에는 예약일이 오늘인 예약을 보여주는 '오늘 방문 예정' 테이블이 있다.
- 현재 이 테이블에는 결제 후 확정 대기 상태(CONFIRM_REQUIRED)의 예약에 대한 **'승인' 버튼만** 노출된다. 이미 확정 처리된 예약(COMPLETE)에는 후속 액션 버튼이 없다.
- 그 결과 파트너가 시술/서비스 종료 후 '사용 완료' 처리를 하려면 인덱스를 벗어나 별도 메뉴(스팟 상세의 예약 관리 등)로 이동해야 한다.
- 동선이 길어 시술 직후 즉시 처리되지 못하는 경우가 잦고, 이로 인해 다음 문제가 연쇄적으로 발생한다.
  - 예약 상태가 USED로 전이되는 시점이 늦어진다.
  - USED 상태가 되어야 유저의 리뷰 작성이 가능하므로, **유저의 리뷰 작성 가능 시점도 함께 늦어진다.**
  - 시술 종료 직후 현장에서 리뷰 작성을 유도해도 시스템이 아직 받아주지 못한다.
- 호수도산 파트너 인터뷰에서 동일 인식이 확인되었다.
  - "예약 확정 처리를 빠르게 해야 리뷰 작성으로 이어진다"
- 추가 컨텍스트
  - 장기적으로는 파트너 예약 관리 모바일 앱을 별도 출시할 예정이지만, 그 전까지는 웹 어드민이 메인 운영 환경이다.
  - 인덱스 화면은 파트너가 어드민에 진입하자마자 보이는 화면이라, 일상 액션의 가장 빠른 동선이 될 수 있다.

### 가설적 임팩트

- **사용 완료 처리 속도 향상** — 시술 직후 가장 가까운 화면에서 한 번에 처리 가능. 별도 메뉴 이동 없이 단건 완결.
- **리뷰 작성 가능 시점 단축** — USED 전이가 빨라지면서 유저의 리뷰 작성 가능 시점이 시술 직후로 앞당겨진다. 향후 유저 측 '오늘의 예약' 플로팅 섹션 등 리뷰 작성 유도 기능의 효과 발현 조건이 충족된다.
- **파트너 어드민 사용 빈도 증가** — 인덱스에서 일상 액션(승인 + 사용 완료)이 모두 완결되어 어드민 진입 가치가 커진다.
- **운영팀 트래픽 감소** — 사용 완료 처리를 운영팀에 카톡으로 요청하던 케이스를 흡수한다.

## 구현

### 유저 플로우

**파트너**

- 파트너 어드민에 진입해 인덱스 화면의 '오늘 방문 예정' 테이블을 확인한다.
- 각 예약 행의 상태에 따라 액션 컬럼에 노출되는 버튼이 다르다.
  - 확정 대기(CONFIRM_REQUIRED): **[승인]** 버튼 (현재 동작 그대로)
  - 확정 완료(COMPLETE): **[사용 완료]** 버튼 (신규)
  - 사용 완료(USED): 액션 버튼 없음, 상태 라벨로 "사용 완료" 표시
  - 취소/만료(CANCEL/EXPIRED): 액션 버튼 없음
- 시술/서비스 종료 후 해당 예약 행의 [사용 완료] 버튼을 클릭한다.
- 확인 다이얼로그가 노출되고, 파트너가 확인하면 백엔드에서 사용 완료 처리가 진행된다.
- 처리 완료 후 토스트로 알림이 노출된다. 해당 행은 테이블에서 빠지지 않고 유지되며, 액션 컬럼이 "사용 완료" 상태 라벨로 갱신된다 (그날 처리한 내역을 시각적으로 확인할 수 있도록).

**유저 (간접 효과)**

- 파트너가 사용 완료 처리한 예약은 시스템상 리뷰 작성이 가능한 상태가 된다.
- 별도로 노션에서 논의 중인 '오늘의 예약' 플로팅 섹션 등 유저 측 리뷰 작성 유도 기능과 결합되면, 시술 종료 직후 유저에게 리뷰 쓰기 CTA가 노출될 수 있는 조건이 충족된다.

### 프론트엔드 요구사항

**어드민 인덱스 — '오늘 방문 예정' 테이블**

- 행 단위 액션 컬럼에 예약 상태별 분기 로직을 추가한다.
  - CONFIRM_REQUIRED → [승인] (기존 유지)
  - COMPLETE → [사용 완료] (신규)
  - USED → 회색 라벨 "사용 완료"
  - CANCEL/EXPIRED → 빈 셀 또는 상태 라벨만 표시
- 시각 톤 차등화
  - [승인]은 즉시 액션이 필요한 1차 액션이므로 primary 톤 유지
  - [사용 완료]는 시술 후 후속 액션이므로 secondary 또는 outline 톤 권장
  - 두 액션이 한 테이블에 공존할 때 사용자가 즉시성 차이를 시각적으로 구분할 수 있어야 함
- 시점에 따른 활성화 정책
  - 백엔드 검증상 예약일/예약 시간이 도래하기 전에는 사용 완료 처리가 차단된다.
  - 시간 도래 전: 버튼을 비활성 상태로 노출하고, hover/tap 시 "시술 시간 이후 가능" 안내 툴팁을 노출한다.
  - 시간 도래 후: 버튼 활성화.
- 처리 후 동작
  - 토스트로 "사용 완료 처리되었습니다" 안내.
  - 행은 테이블에서 빠지지 않고 유지, 액션 컬럼만 [사용 완료] 상태 라벨로 갱신.

**모바일 웹 환경**

- 모바일 브라우저에서도 동일하게 동작해야 한다. 인덱스 테이블이 모바일에 적합한 레이아웃으로 표시되는지 확인이 필요하다 (별도 검토).

### 백엔드 요구사항

- 신규 mutation 추가 없이 기존 mutation 그대로 사용한다.
  - `singleUpdateToUsed` (resolver: `reservation.resolver.ts`)
- 권한·상태 검증은 기존 도메인 메서드를 그대로 활용한다.
  - `verifySetAsUsed` — 예약 상태가 COMPLETE인지, 파트너 본인 스팟 예약인지, 예약일이 지났는지 검증.
- 처리 결과 (현재 동작 그대로)
  - 예약 상태가 COMPLETE → USED로 전이된다.
  - 매출일이 정산 정책에 따라 자동 계산된다.
  - 포인트 지급 정책에 따라 적립 처리된다.
  - `RESERVATION_EVENT_TYPE.USED` 이벤트가 발생해 후속 알림·처리 흐름이 트리거된다.

### 결정사항 요약

| 항목 | 결정 |
|---|---|
| 변경 대상 화면 | 파트너 어드민 인덱스의 '오늘 방문 예정' 테이블 |
| 신규 추가 액션 | COMPLETE 상태 예약에 [사용 완료] 버튼 노출 |
| 기존 액션 변경 | 없음 (CONFIRM_REQUIRED에 노출되는 [승인] 버튼은 그대로) |
| USED 상태 표시 | 액션 버튼 대신 상태 라벨 "사용 완료" 노출 |
| 처리 후 행 제거 | 제거하지 않음 (그날 처리 내역 확인용으로 유지) |
| 시점 검증 | 백엔드 `verifyPassedReservationDate`에 의해 차단됨. 어드민에서 시간 도래 전 버튼은 비활성 + 툴팁 안내 |
| 백엔드 mutation 신규 | 없음 (기존 `singleUpdateToUsed` 재사용) |
| 시각 톤 | [승인] primary / [사용 완료] secondary 또는 outline (즉시성 차등화) |

### 후속 검토 대상 (TBD)

- **다건 선택 + 일괄 사용 완료 처리** — 한 타임에 다수를 받는 운영 패턴(예: 아리한복 한 타임 20팀, 헤어샵 연속 시술) 대응. 단건부터 출시 후 사용 패턴 보고 확장 검토.
- **사용 완료 처리 → 유저 리뷰 작성 요청 푸시** — 호수도산 인터뷰의 "파트너가 어드민에서 특정 버튼 클릭 → 유저 기기로 리뷰 작성 알림" 흐름. 본 작업은 그 선행 조건만 푸는 것이며, 알림 발송은 별도 기능으로 후속 진행.
- **모바일 앱 이식** — 장기 모바일 앱 출시 시 동일 흐름을 앱 인덱스에도 이식 (축 3 v1 스코프와 정렬).
- **자동 확정 정책 스팟에서의 흐름** — 자동 확정 스팟은 결제 즉시 COMPLETE로 전이되므로 [승인] 단계 없이 처음부터 [사용 완료] 버튼이 노출된다. UX적으로 자연스러운지 검토.
- **유저 측 '오늘의 예약' 플로팅 섹션 (별도 노션 제안)** — 본 작업이 선행된 이후 유저 측 리뷰 작성 동선과 결합. 짝으로 다뤄야 임팩트가 닫힌다.
