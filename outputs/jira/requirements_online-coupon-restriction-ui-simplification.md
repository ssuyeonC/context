# 스팟 어드민 — 온라인 쿠폰 적용 제한 UI 단순화

## 배경

### 문제 정의

- 어드민의 스팟 결제 정보 페이지에는 '온라인 쿠폰 적용 제한' 토글이 있고, 토글이 ON일 때만 허용 쿠폰을 등록할 수 있는 UI가 함께 노출된다.
- 그러나 토글이 ON이어도 허용 쿠폰이 0개라면, 결제 단계에서 모든 쿠폰이 차단되어 '온라인 쿠폰 적용 제외'를 켠 것과 사실상 동일한 결과가 된다.
- 운영자가 의도치 않게 "토글만 켜고 쿠폰을 등록하지 않은" 상태에 머무를 수 있으며, 어드민 UI상으로는 이 상태가 정상적으로 보인다.
- 토글 + 쿠폰 인풋의 2단계 UI 자체가 운영자에게 불필요한 인지 부담을 준다. 사실상 "허용할 쿠폰이 1개 이상 등록되어 있으면 적용 제한이 작동"하는 단순한 의도를 1단계 UI로 표현할 수 있다.

### 가설적 임팩트

- **운영 휴먼 에러 감소**: 토글만 켜고 쿠폰을 등록하지 않은 상태가 사실상 차단되어, 의도치 않은 모든 쿠폰 차단 케이스 제거.
- **운영자 인지 부담 감소**: 2단계 UI를 1단계로 단순화하여 학습·실행 비용 절감.
- **정량 임팩트**: 호출 빈도가 낮은 운영 액션이라 직접 KPI 영향은 작음. 다만 누적 운영 시간과 휴먼 에러 케이스 감소가 본질.

## 구현

### 유저 플로우

**관리자 (어드민)**

- 관리자는 스팟 결제 정보 페이지에서 '온라인 쿠폰 적용 제한' 항목을 본다.
- 항목에는 허용할 온라인 쿠폰을 검색하여 추가할 수 있는 쿠폰 선택 인풋만 노출된다. 별도의 ON/OFF 토글은 노출되지 않는다.
- 관리자는 검색 결과에서 원하는 쿠폰을 선택해 추가할 수 있다.
- 추가된 쿠폰은 인풋 하단에 태그 형태로 나열된다. 각 태그의 'x' 버튼으로 개별 삭제할 수 있다.
- 관리자가 쿠폰을 1개 이상 추가하면, 해당 스팟은 자동으로 '온라인 쿠폰 적용 제한' 상태가 된다. 즉 이 스팟에는 등록된 쿠폰만 적용 가능하다.
- 관리자가 등록된 쿠폰을 모두 삭제하여 태그가 0개가 되면, 해당 스팟은 자동으로 '온라인 쿠폰 적용 제한' 해제 상태가 된다. 즉 모든 온라인 쿠폰이 적용 가능하다.
- 관리자는 쿠폰이 1개 이상 등록된 상태에서 '온라인 쿠폰 적용 제외'를 켤 수 없다.
  - 시도 시 차단되고 다음 안내 메시지가 노출된다.
  - 문구: **"온라인 쿠폰 적용 제한이 설정된 스팟에는 '온라인 쿠폰 적용 제외'를 함께 켤 수 없습니다."**
- 관리자는 '온라인 쿠폰 적용 제외'가 켜진 상태에서 새 쿠폰을 추가할 수 없다.
  - 시도 시 차단되고 다음 안내 메시지가 노출된다.
  - 문구: **"'온라인 쿠폰 적용 제외'를 먼저 해제한 후 쿠폰을 추가해주세요."**

**유저 (유저페이지)**

- 별도 변경 없음. 본 변경은 어드민 UI와 데이터 동기화 로직에만 적용되며, 유저페이지의 쿠폰 적용 가능성 판단 로직은 기존과 동일하게 동작한다.

### 프론트엔드 요구사항

**어드민**

- 스팟 결제 정보 페이지의 '온라인 쿠폰 적용 제한' 항목에서 ON/OFF 토글을 제거한다.
- 허용 쿠폰을 추가하는 쿠폰 선택 인풋을 항상 노출한다. (현재 토글이 ON일 때만 노출되던 동작 변경)
- 인풋에서 쿠폰을 추가하거나 태그의 'x' 버튼으로 삭제하면, 화면은 변경된 결과 상태(등록된 쿠폰 목록)를 즉시 보여준다.
- 등록된 쿠폰의 개수에 따라 '온라인 쿠폰 적용 제한' 상태가 자동으로 변경되며, 관리자가 별도 액션을 취할 필요는 없다.
- '온라인 쿠폰 적용 제외' 토글은 기존과 동일하게 유지된다.
- '온라인 쿠폰 적용 제외'와 '온라인 쿠폰 적용 제한'은 동시에 활성화될 수 없다. 두 항목이 충돌하는 액션이 발생하면 위 안내 메시지를 노출하여 차단한다.

**유저페이지**

- 별도 변경 없음.

### 백엔드 요구사항

**데이터 모델**

- 스팟의 '온라인 쿠폰 적용 제한' 여부를 나타내는 컬럼은 유지한다. 기존 로직과의 호환을 위해 데이터 모델 변경은 하지 않으며, 어드민 액션에 따라 값이 자동으로 동기화되도록 한다.

**쿠폰 추가 시 동작**

- 관리자가 허용 쿠폰을 추가하면, 해당 스팟의 '온라인 쿠폰 적용 제한' 상태를 자동으로 활성으로 전환한다. (0개에서 1개가 되는 시점 포함, 이미 활성이면 유지)
- 단, 해당 스팟이 '온라인 쿠폰 적용 제외' 상태인 경우 쿠폰 추가를 차단하고 충돌 에러를 반환한다. 자동 전환 시도 자체가 차단된다.

**쿠폰 삭제 시 동작**

- 관리자가 등록된 쿠폰을 삭제했을 때, 삭제 후 남은 쿠폰의 개수가 0개가 되면 해당 스팟의 '온라인 쿠폰 적용 제한' 상태를 자동으로 해제로 전환한다.
- 남은 쿠폰이 1개 이상이면 활성 상태를 그대로 유지한다.

**유저페이지 결제 단계의 쿠폰 적용 가능 여부 판단**

- 별도 변경 없음. 현재 로직(`isOnlineCouponRestricted` 기반)을 그대로 사용한다.

**기존 데이터 처리**

- 본 변경 이전에 '온라인 쿠폰 적용 제한 = ON'이면서 등록된 쿠폰이 0개인 스팟이 존재할 수 있다. 별도 일괄 보정은 수행하지 않는다.
- 운영자가 해당 스팟에 진입하여 쿠폰을 추가하거나 그대로 두는 자연스러운 운영 동선을 통해 정합 상태로 수렴된다.

**기존 토글 전용 API**

- 기존에 어드민 토글이 사용하던 '온라인 쿠폰 적용 제한 직접 변경' API는 본 변경 이후 어드민에서 더 이상 호출되지 않는다. 즉시 제거하지 않고, 외부 호출 가능성을 고려해 일정 기간 유지한 뒤 별도 정리한다.

**테스트 케이스**

- 쿠폰 0개 상태에서 1개를 추가하면 적용 제한 상태가 자동으로 활성으로 바뀐다.
- 쿠폰 1개 상태에서 1개를 더 추가해도 적용 제한 상태는 활성으로 유지된다.
- 쿠폰 2개 상태에서 1개를 삭제해도 적용 제한 상태는 활성으로 유지된다.
- 쿠폰 1개 상태에서 마지막 1개를 삭제하면 적용 제한 상태가 자동으로 해제로 바뀐다.
- '온라인 쿠폰 적용 제외'가 켜진 스팟에 쿠폰 추가를 시도하면 차단되고 안내 메시지가 노출된다.
- '온라인 쿠폰 적용 제한'에 쿠폰이 1개 이상 등록된 스팟에 '온라인 쿠폰 적용 제외' 활성화를 시도하면 차단되고 안내 메시지가 노출된다.
- 본 변경 적용 이전에 '적용 제한 = ON'이면서 쿠폰이 0개였던 스팟에 진입하면, 화면에는 빈 쿠폰 인풋이 정상적으로 노출되며 관리자가 자유롭게 쿠폰을 추가하거나 그대로 두어도 문제가 발생하지 않는다.

### 결정사항 요약

| 항목 | 결정 |
|---|---|
| UI 단순화 방향 | 토글 제거, 쿠폰 선택 인풋만 노출 |
| '온라인 쿠폰 적용 제한' 데이터 컬럼 | 유지 (어드민 액션에 따라 자동 동기화) |
| 자동 전환 트리거 | 쿠폰 추가·삭제 시점 |
| '적용 제외'와의 상호 배타성 | 기존 정책 유지, 충돌 시 안내 메시지 노출 후 차단 |
| 기존 잘못 설정된 스팟 | 별도 일괄 보정 없음, 자연 운영 동선에 위임 |
| 기존 토글 직접 변경 API | 즉시 제거하지 않고 일정 기간 유지 후 별도 정리 |
