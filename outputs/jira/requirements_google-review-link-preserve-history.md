# 스팟 어드민 — 구글 리뷰 연동 동작 개선 (이력 보존 및 최신순 운영)

## 배경

### 문제 정의

- 스팟 어드민의 '리뷰연동' 버튼은 클릭할 때마다 해당 스팟의 기존 구글 리뷰 레코드를 모두 삭제한 뒤 새로 가져온 결과로 덮어쓴다.
- 이로 인해 다음과 같은 운영 문제가 발생한다.
  - 운영자가 단순히 "최신화하려는 의도"로 클릭했는데도 이전에 잘 노출되던 리뷰가 사라진다.
  - 구글에서 가져온 결과가 1개로 줄어드는 케이스가 있고, 운영자는 클릭 시점에 이를 인지할 수 없다.
  - 기존에 가져온 156건 중 1개만 남는 등, 사용자가 구글 맵에서 보는 풍부한 리뷰와 크리에이트립 페이지에 노출되는 리뷰 사이에 큰 괴리가 생긴다.
- 결과가 적어지는 원인은 다음 요소들이 누적된 결과로 분석되었다.
  - **구글 Places API 자체가 한 번 호출에 최대 5건만 반환한다.** 스팟 전체 리뷰가 137건이어도 후보는 5건뿐이다.
  - **New API는 정렬 기준이 `MOST_RELEVANT`(관련성)** 로 동작한다. 작성일 기준 최신 리뷰가 보장되지 않는다.
  - **Legacy API는 `newest` 정렬을 명시하지만, 실패 시 New API로 사일런트 폴백** 되어 운영자가 어느 경로의 결과인지 알 수 없다.
  - **별점 4점 이상만 저장하는 필터**가 추가로 적용되어, API가 반환한 5건 중에서도 일부가 탈락한다.
- 이 모든 단계가 합쳐져 운영자의 의도와 실제 결과가 어긋나며, 한 번의 잘못된 클릭이 이전에 쌓인 데이터를 영구적으로 잃게 만든다.

### 가설적 임팩트

- **데이터 손실 방지**: 클릭으로 인해 기존에 노출되던 리뷰가 사라지는 케이스를 시스템적으로 차단한다.
- **노출 풍부도 개선**: 매 클릭마다 신규 리뷰가 누적되어, 시간이 지날수록 페이지에 노출되는 리뷰가 풍부해진다.
- **운영자 신뢰 회복**: '리뷰연동' 클릭의 결과가 예측 가능해진다. 운영자는 "리뷰가 추가될 수는 있어도 줄어들지는 않는다"는 단순한 멘탈 모델로 기능을 사용할 수 있다.
- **유저 페이지 품질 향상**: 더 다양한 작성일·내용의 리뷰가 노출되어 유저의 의사결정에 도움이 된다.

## 구현

### 유저 플로우

**관리자 (어드민)**

- 관리자는 스팟 어드민의 기본 정보 페이지에서 '리뷰연동' 버튼을 클릭한다.
- 시스템은 구글에서 신규 리뷰를 가져오지만, **해당 스팟에 이미 저장된 기존 구글 리뷰는 삭제하지 않는다.**
- 시스템은 신규로 가져온 리뷰를 기존 리뷰 목록의 가장 앞쪽(첫 번째 인덱스)에 추가한다.
- 시스템은 신규 + 기존을 모두 합친 전체 목록에서 작성일 기준 최신순으로 5개를 추출하여, 이 5개를 유저 페이지에 노출할 대상으로 결정한다.
- 시스템은 5개에 들지 못한 6번째 이후의 리뷰도 데이터로는 유지한다. 다만 유저 페이지에는 노출되지 않는다.
- 시스템은 신규로 추가된 리뷰 중 기존과 동일한 리뷰(작성자 이름과 작성일이 같음)는 중복으로 판단하여 별도로 추가 저장하지 않는다.
- 시스템은 노출 대상 5개 중 이미 다국어 번역본이 있는 리뷰는 기존 번역본을 그대로 사용하고, 번역본이 없는 신규 리뷰에 대해서만 다국어 번역을 새로 생성한다.
- 시스템은 별점이 4점 이상인 리뷰만 저장 대상으로 삼는다. 4점 미만 리뷰는 처음부터 후보에서 제외한다.
- 관리자는 클릭 후 '구글 리뷰 연동 성공' 메시지를 받는다. (현재 동작 유지)

**유저 (유저 페이지)**

- 유저는 스팟 상세 페이지에서 최신 작성일 기준으로 선별된 5개의 구글 리뷰를 본다.
- 유저가 보는 리뷰는 시간이 지날수록 더 풍부해지며, 운영자의 '리뷰연동' 클릭에 의해 줄어들지 않는다.

### 프론트엔드 요구사항

**어드민**

- '리뷰연동' 버튼 자체의 위치·표기·동작 흐름은 변경하지 않는다. 버튼 클릭 시 호출되는 mutation의 동작이 바뀌는 것이라, 어드민 UI 레벨의 변경은 없다.

**유저 페이지**

- 별도 변경 없음. 현재 구글 리뷰를 조회하는 로직(별점 ≥2 이상 + 작성일 정렬 + 최대 5건)을 그대로 사용한다.

### 백엔드 요구사항

**'리뷰연동' 동작 변경**

- '리뷰연동' 처리 흐름에서 다음 동작을 제거한다.
  - 기존 구글 리뷰 레코드를 일괄 삭제하는 동작 (`deleteAllBySpotCode`).
- 대신 다음 동작을 적용한다.
  - 구글에서 받은 신규 리뷰를 기존 리뷰 목록의 첫 번째 인덱스 위치에 추가한다.
  - 신규 + 기존을 합친 전체 목록에서 작성일 기준 내림차순(최신순)으로 정렬한 뒤, 상위 5개를 노출 대상으로 결정한다.

**중복 리뷰 처리**

- 신규로 받은 리뷰가 기존 리뷰와 다음 조건을 모두 만족하면 중복으로 판단하여 신규 저장하지 않는다.
  - 작성자 이름(`authorName`)이 동일하다.
  - 작성일(`writtenAt`)이 동일하다.
- 중복이 아닌 신규 리뷰는 그대로 저장한다.

**번역 재사용**

- 신규로 저장된 리뷰에 대해서만 다국어 번역을 새로 생성한다 (`spot_google_review_content_trans`에 새로 적재).
- 이미 번역본이 존재하는 기존 리뷰는 번역을 다시 생성하지 않는다. 불필요한 GPT 호출과 비용을 방지한다.

**별점 필터 유지**

- 별점 4점 이상 리뷰만 저장 대상으로 한다. (기존 정책 유지)
- 별점 4점 미만 리뷰는 신규로도 추가되지 않고, 기존 데이터에 있던 4점 미만 리뷰는 그대로 둔다(현재 데이터 모델에 4점 미만이 들어 있을 가능성이 낮지만, 일괄 정리는 하지 않는다).

**저장 범위와 노출 범위**

- 저장은 6번째 이후의 리뷰도 그대로 유지한다. 데이터 손실은 발생하지 않는다.
- 유저 페이지 노출은 작성일 기준 최신순 5개로 제한한다. (현재 조회 로직 그대로 사용)

**이력 보존**

- 별도의 클릭 이력 테이블이나 변경 이력은 도입하지 않는다. 기존 데이터가 삭제되지 않으므로 `spot_google_review_content.created_at` 값으로 "언제 추가된 리뷰인지" 추적이 가능하다.

**API 응답 결과 0건 케이스**

- 구글에서 받은 결과가 0건이라도 기존 리뷰는 그대로 유지한다.
- 운영자에게는 별도의 경고 메시지를 노출할지 여부를 후속 정책 결정 대상으로 둔다 (TBD).

**테스트 케이스**

- 기존에 5건이 저장된 스팟에서 '리뷰연동'을 클릭하면, 신규 리뷰가 있는 경우 기존 5건은 보존되고 신규 리뷰가 추가된다.
- 기존에 156건처럼 다수의 리뷰가 저장된 스팟에서 '리뷰연동'을 다시 클릭해도 기존 리뷰는 삭제되지 않는다.
- 구글에서 받은 신규 리뷰 중 1건이 기존 리뷰와 작성자·작성일이 동일하면, 해당 리뷰는 신규 저장되지 않고 기존 리뷰가 그대로 유지된다.
- 노출 대상 5개에 포함된 기존 리뷰는 번역이 새로 생성되지 않는다.
- 노출 대상 5개에 포함된 신규 리뷰는 다국어 번역이 새로 생성된다.
- 작성일 기준으로 6번째 이후의 리뷰는 DB에는 저장되지만, 유저 페이지에는 노출되지 않는다.
- 구글에서 받은 신규 리뷰가 모두 별점 4점 미만이라면, 신규 저장은 0건이고 기존 리뷰는 그대로 유지된다.
- 구글에서 받은 신규 리뷰가 0건(API 실패 또는 빈 응답)이라도 기존 리뷰는 그대로 유지된다.

### 결정사항 요약

| 항목 | 결정 |
|---|---|
| 기존 레코드 삭제 | 제거 |
| 신규 리뷰 위치 | 기존 리스트의 첫 번째 인덱스로 추가 |
| 노출 대상 추출 | 전체 리스트에서 작성일 기준 최신순 5개 |
| 6번째 이후 리뷰 | 데이터는 보존, 노출만 제외 |
| 중복 리뷰 판단 기준 | 작성자 이름 + 작성일 동일 |
| 번역 재사용 | 기존 번역본 보유 시 재사용, 신규 리뷰만 새로 번역 |
| 별점 ≥4 필터 | 유지 |
| 별도 이력 테이블 | 도입하지 않음 (`created_at`으로 충분) |

### 후속 검토 대상 (TBD)

- 구글 Places New API 호출 시 정렬 옵션을 `MOST_RELEVANT`가 아닌 작성일 기준으로 변경 가능한지 추가 조사. New API v1 스펙상 `places.get` 엔드포인트에 정렬 옵션이 없을 가능성이 큼.
- Legacy API 실패 시 New API로 사일런트 폴백되는 흐름을 운영자에게 노출할지 여부. (운영팀이 어느 경로의 결과인지 인지하지 못하는 문제)
- '리뷰연동' 클릭으로 받은 결과가 0건일 경우 운영자에게 별도 경고 메시지를 노출할지 여부.
- 본 변경 적용 후 기존에 저장된 데이터 중 별점 4점 미만이 남아 있는 케이스의 정리 여부.
