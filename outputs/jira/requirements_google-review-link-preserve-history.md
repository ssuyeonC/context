# 스팟 어드민 — 구글 리뷰 연동 동작 개선 (이력 보존 및 최신순 운영)

## 배경

### 문제 정의

- 스팟 어드민의 '리뷰연동' 버튼은 클릭할 때마다 해당 스팟의 기존 구글 리뷰 레코드를 모두 삭제한 뒤 새로 가져온 결과로 덮어쓴다.
- 이로 인해 다음과 같은 운영 문제가 발생한다.
  - 운영자가 단순히 "최신화하려는 의도"로 클릭했는데도 이전에 잘 노출되던 리뷰가 사라진다.
  - 구글에서 가져온 결과가 1개로 줄어드는 케이스가 있고, 운영자는 클릭 시점에 이를 인지할 수 없다.
  - 기존에 가져온 156건 중 1개만 남는 등, 사용자가 구글 맵에서 보는 풍부한 리뷰와 크리에이트립 페이지에 노출되는 리뷰 사이에 큰 괴리가 생긴다.
- 결과가 적어지는 원인은 다음 요소들이 누적된 결과로 분석되었다.
  - **구글 Places API 자체가 한 번 호출에 최대 5건만 반환한다.** 스팟 전체 리뷰가 137건이어도 후보는 5건뿐이다.
  - **New API는 정렬 기준이 `MOST_RELEVANT`(관련성)** 로 동작한다. 작성일 기준 최신 리뷰가 보장되지 않는다.
  - **Legacy API는 `newest` 정렬을 명시하지만, 실패 시 New API로 사일런트 폴백** 되어 운영자가 어느 경로의 결과인지 알 수 없다.
  - **별점 4점 이상만 저장하는 필터**가 추가로 적용되어, API가 반환한 5건 중에서도 일부가 탈락한다.
- 이 모든 단계가 합쳐져 운영자의 의도와 실제 결과가 어긋나며, 한 번의 잘못된 클릭이 이전에 쌓인 데이터를 영구적으로 잃게 만든다.

### 가설적 임팩트

- **의도와 다른 데이터 손실 방지**: 한 번의 클릭으로 이전에 노출되던 리뷰가 사라지는 사고를 시스템적으로 차단한다. (정렬 결과 자연스러운 6위 밖 정리는 의도에 부합하는 갱신이며, 사고로 분류하지 않는다.)
- **노출 풍부도 개선**: 매 클릭마다 신규 리뷰가 누적·정렬되어 가장 최신의 5건이 유지된다. API 경로가 어떤 것이든 후처리 정렬이 안전망으로 작동한다.
- **운영자 신뢰 회복**: '리뷰연동' 클릭의 결과가 예측 가능해진다. 운영자는 "리뷰는 작성일 기준 최신 5건이 자동으로 유지된다"는 단순한 멘탈 모델로 기능을 사용할 수 있다.
- **유저 페이지 품질 향상**: 더 최신의 리뷰가 일관되게 노출되어 유저의 의사결정에 도움이 된다.

## 구현

### 유저 플로우

**관리자 (어드민)**

- 관리자는 스팟 어드민의 기본 정보 페이지에서 '리뷰연동' 버튼을 클릭한다.
- 시스템은 구글에서 신규 리뷰를 가져오지만, **해당 스팟에 이미 저장된 기존 구글 리뷰는 일괄 삭제하지 않는다.**
- 시스템은 신규로 가져온 리뷰를 기존 리뷰 목록에 추가한다.
- 시스템은 신규 + 기존을 모두 합친 전체 목록에서 작성일 기준 최신순으로 정렬한 뒤, **상위 5건만 DB에 유지한다.** 5위 밖 리뷰는 정리된다.
- 시스템은 신규로 추가된 리뷰 중 기존과 동일한 리뷰(작성자 이름과 작성일이 같음)는 중복으로 판단하여 별도로 추가 저장하지 않는다.
- 시스템은 최종 5건 중 이미 다국어 번역본이 있는 리뷰는 기존 번역본을 그대로 사용하고, 번역본이 없는 신규 리뷰에 대해서만 다국어 번역을 새로 생성한다.
- 시스템은 별점이 4점 이상인 리뷰만 저장 대상으로 삼는다. 4점 미만 리뷰는 처음부터 후보에서 제외한다.
- 관리자는 클릭 후 '구글 리뷰 연동 성공' 메시지를 받는다. (현재 동작 유지)

**유저 (유저 페이지)**

- 유저는 스팟 상세 페이지에서 작성일 기준 최신순으로 선별된 5건의 구글 리뷰를 본다.
- DB에 저장된 5건이 곧 노출되는 5건이다. 시간이 지날수록 더 최신의 리뷰가 자동으로 반영된다.

### 프론트엔드 요구사항

**어드민**

- '리뷰연동' 버튼 자체의 위치·표기·동작 흐름은 변경하지 않는다. 버튼 클릭 시 호출되는 mutation의 동작이 바뀌는 것이라, 어드민 UI 레벨의 변경은 없다.

**유저 페이지**

- 별도 변경 없음. 현재 구글 리뷰를 조회하는 로직(별점 ≥2 이상 + 작성일 정렬 + 최대 5건)을 그대로 사용한다. DB에 5건만 유지되므로 결과는 동일하다.

### 백엔드 요구사항

**'리뷰연동' 동작 변경**

- '리뷰연동' 처리 흐름에서 다음 동작을 제거한다.
  - 기존 구글 리뷰 레코드를 일괄 삭제하는 동작 (`deleteAllBySpotCode`).
- 대신 다음 동작을 적용한다.
  - 구글에서 받은 신규 리뷰를 기존 리뷰 목록에 추가한다.
  - 신규 + 기존을 합친 전체 목록에서 작성일 기준 내림차순(최신순)으로 정렬한다.
  - **상위 5건만 DB에 유지하고, 6번째 이후 레코드는 삭제한다.** DB와 유저 페이지 노출이 동일한 5건으로 정합된다.

**API 호출 경로 — Legacy 폴백 정책**

- Legacy API에 `newest` 정렬을 명시한다.
- Legacy API 호출이 실패할 경우 현재처럼 New API로 사일런트 폴백한다.
- 폴백 차단이나 운영자 대상 폴백 알림은 도입하지 않는다.
  - **후처리(append → dedup → 작성일 정렬 → 상위 5건)가 안전망 역할**을 하므로, API가 어느 경로로 어떤 정렬의 결과를 반환해도 최종 DB 상태는 일관되게 "작성일 최신 5건"으로 수렴한다.
  - Legacy 성공 시는 베스트 케이스(진짜 최신 5건이 후보), New 폴백 시는 차선 케이스(MOST_RELEVANT 5건이 후보)이나, 둘 다 최악의 경우 "현 상태 유지"이고 좋은 경우엔 "최신화"라는 결과만 발생한다.
- (선택) Legacy 호출 실패율은 로그로 남겨 두어 추후 모니터링·정책 재검토가 가능하도록 한다.

**중복 리뷰 처리**

- 신규로 받은 리뷰가 기존 리뷰와 다음 조건을 모두 만족하면 중복으로 판단하여 신규 저장하지 않는다.
  - 작성자 이름(`authorName`)이 동일하다.
  - 작성일(`writtenAt`)이 동일하다.
- 중복이 아닌 신규 리뷰는 그대로 저장한다.

**번역 재사용**

- 최종 5건에 포함된 신규 리뷰에 대해서만 다국어 번역을 새로 생성한다 (`spot_google_review_content_trans`에 새로 적재).
- 이미 번역본이 존재하는 기존 리뷰는 번역을 다시 생성하지 않는다. 불필요한 GPT 호출과 비용을 방지한다.
- 5위 밖으로 밀려 삭제되는 리뷰의 번역본도 해당 레코드와 함께 정리한다.

**별점 필터 유지**

- 별점 4점 이상 리뷰만 저장 대상으로 한다. (기존 정책 유지)
- 별점 4점 미만 리뷰는 신규로도 추가되지 않고, 기존 데이터에 있던 4점 미만 리뷰는 그대로 둔다(현재 데이터 모델에 4점 미만이 들어 있을 가능성이 낮지만, 일괄 정리는 하지 않는다).

**저장 범위와 노출 범위**

- 저장과 노출 모두 작성일 기준 최신순 5건으로 정합한다.
- 5건 미만 케이스 (예: API에서 받은 신규 + 기존 합쳐도 5건이 안 됨)에는 있는 만큼만 저장·노출한다.

**이력 보존**

- 별도의 클릭 이력 테이블이나 변경 이력은 도입하지 않는다.
- 5위 밖으로 밀려 삭제된 리뷰는 복원되지 않는다. (트레이드오프 수용: 운영 단순성·DB↔노출 정합성을 우선)
- `spot_google_review_content.created_at` 값으로 "현재 저장된 5건이 언제 추가된 리뷰인지"는 추적 가능하다.

**API 응답 결과 0건 케이스**

- 구글에서 받은 결과가 0건이라도 기존 리뷰는 그대로 유지한다. (사라지는 사고 방지)
- 운영자에게 별도의 경고 메시지를 노출할지 여부는 후속 정책 결정 대상으로 둔다 (TBD).

**테스트 케이스**

- 기존에 5건이 저장된 스팟에서 '리뷰연동'을 클릭하면, 신규 리뷰가 있는 경우 신규 + 기존을 합친 풀에서 작성일 최신 5건이 DB에 유지된다.
- 신규로 받은 리뷰가 모두 기존보다 더 최신이면, DB는 신규 5건으로 갱신되고 기존 5건은 정리된다.
- 신규로 받은 리뷰가 모두 기존보다 더 옛날이면, DB는 기존 5건이 그대로 유지되고 신규는 저장되지 않는다.
- 기존에 5건, 신규에 3건이면 합쳐서 작성일 정렬 후 상위 5건이 DB에 유지된다 (기존 3~5건 + 신규 0~2건 등 작성일에 따라 결정).
- 구글에서 받은 신규 리뷰 중 1건이 기존 리뷰와 작성자·작성일이 동일하면, 해당 리뷰는 신규 저장되지 않고 기존 리뷰가 그대로 유지된다.
- 최종 5건에 포함된 기존 리뷰는 번역이 새로 생성되지 않는다.
- 최종 5건에 포함된 신규 리뷰는 다국어 번역이 새로 생성된다.
- 5위 밖으로 밀려 삭제된 리뷰의 번역본도 함께 정리된다.
- 구글에서 받은 신규 리뷰가 모두 별점 4점 미만이라면, 신규 저장은 0건이고 기존 5건은 그대로 유지된다.
- 구글에서 받은 신규 리뷰가 0건(API 실패 또는 빈 응답)이라도 기존 5건은 그대로 유지된다.
- Legacy API가 실패해 New API로 폴백된 경우에도 후처리 결과 DB는 작성일 최신 5건으로 수렴한다 (현 상태보다 나빠지지 않는다).

### 결정사항 요약

| 항목 | 결정 |
|---|---|
| 기존 레코드 일괄 삭제 | 제거 |
| 신규 리뷰 처리 | 기존 리스트에 추가 후 작성일 정렬 |
| DB 저장 범위 | **작성일 최신순 상위 5건** (6위 밖 삭제) |
| 노출 범위 | DB 저장 범위와 동일 (5건) |
| 중복 리뷰 판단 기준 | 작성자 이름 + 작성일 동일 |
| 번역 재사용 | 최종 5건의 기존 리뷰는 재사용, 신규만 새로 번역 |
| 별점 ≥4 필터 | 유지 |
| Legacy API 정렬 | `newest` 명시 |
| Legacy 실패 시 폴백 | New API로 사일런트 폴백 유지 (차단·알림 도입 X — 후처리가 안전망) |
| 별도 이력 테이블 | 도입하지 않음 |

- 본 변경 적용 후 기존에 저장된 데이터 중 별점 4점 미만이 남아 있는 케이스의 정리 여부.
