# 세부 기획안 요구사항 문서

## 배경
### 문제 정의

링크코리아 이심 상품을 구매하면 고객에게 바우처(PDF)가 발급되고, 그 바우처에는 상품 정보와 함께 **Option** 필드가 노출된다. 현재 이 **Option** 필드에는 관리자가 어드민에서 직접 입력해 둔 옵션명(표시용 이름)이 그대로 표기된다.

문제는 이 표시용 옵션명이 **실제 링크코리아로 주문되는 상품 스펙(사용일수)과 별개로 관리**된다는 점이다. 옵션명은 사람이 입력하는 값이고, 실제 주문에 쓰이는 사용일수는 이와 독립적으로 세팅되므로 둘이 서로 어긋날 수 있다.

실제로 부가상품 이심 옵션을 세팅할 때 사용일수를 잘못 입력해 이슈가 발생했다. 90일 상품인데 발급된 바우처의 **Option**에는 `3일`로 노출되었고, 발급 바우처를 검수하는 과정에서도 표시된 옵션명과 실제 주문 스펙이 다르다는 사실을 놓쳤다.

이처럼 바우처가 실제 발급된 상품과 다른 옵션을 표기하면, 고객이 잘못된 상품 정보를 안내받고 CS 문의·클레임으로 이어질 수 있다. 관리자가 별도로 입력하는 표시명에 의존하는 구조 자체가 오표기의 원인이다.

### 가설적 임팩트

- 바우처 **Option** 표기를 관리자 입력값이 아니라 실제 주문에 사용된 사용일수 기준으로 바꾸면, 표시명과 주문 스펙이 항상 일치하게 되어 오표기로 인한 고객 혼선과 CS 문의를 예방한다.
- 관리자가 옵션명을 별도로 정확히 입력·검수해야 하는 부담이 사라지고, 사용일수라는 단일 값만 올바르면 바우처 표기가 자동으로 맞춰진다.
- 정량적 임팩트(관련 오표기·CS 문의 건수)는 별도 데이터 확인 필요 — TBD.

## 구현
### 유저 플로우

- 유저가 링크코리아 이심 상품을 구매하면 바우처가 발급된다. (부가상품으로 구매한 경우와 예약 스팟 상품으로 구매한 경우 모두 해당)
- 발급된 바우처의 **Option** 필드에는 관리자가 입력한 옵션명이 아니라, 실제 링크코리아에 주문된 **사용일수**를 기준으로 한 값이 노출된다.
- 유저는 바우처에서 옵션을 **`{사용일수} days`** 형식(예: 90일 상품이면 **`90 days`**)으로 확인한다.

### 프론트엔드 요구사항

- 해당 없음. 바우처는 백엔드에서 PDF로 생성되어 고객에게 전달되므로, 별도의 프론트엔드 화면 변경은 없다.

### 백엔드 요구사항

- 바우처 PDF의 **Option** 필드 값을, 관리자가 어드민에 입력한 옵션명 대신 **실제 주문에 사용된 사용일수(useDt) 기준으로 생성**한다.
- 표기 형식은 **영어로 통일**한다: **`{사용일수} days`** (예: 사용일수 90 → **`90 days`**).
  - 바우처의 다른 필드 라벨(Product Name, Validity, SM-DP Address 등)이 모두 영어로 노출되고 있어, 값도 영어 표기로 맞춘다.
  - 기존 표기에 병기되던 시간 단위(예: `(72時間)`)는 제거하고 일수만 표기한다.
  - 단수 표기(예: 1일 → **`1 day`**) 처리 여부는 확정 필요 — TBD.
- 적용 대상은 링크코리아 이심 발급 두 경로 모두다.
  - **부가상품 이심 발급**: 해당 부가상품 발급 설정에 저장된 사용일수 값을 사용한다.
  - **예약 스팟 이심 발급**: 상품(옵션)별로 정의된 사용일수 매핑값을 사용한다.
- 기존에 **Option** 값을 관리자 입력 옵션명에서 가져오던 처리는 제거하고, 위 사용일수 기준 표기로 대체한다. (통신사·망 구분 등 다른 표기 요소는 현행 유지)
