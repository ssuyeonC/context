# 수가표 이미지 기간 기반 노출 제어

## 배경

### 문제 정의

- 현재 어드민에서 수가표 이미지를 업로드하면 관리자가 직접 제거하지 않는 한 유저페이지에 상시 노출된다.
- 시즌·기간 단위로 가격이 변동되는 운영(예: 봄 시즌 가격표, 한정 프로모션, 신학기 가격표 등)에서 운영자가 시즌 전환 시점마다 수동으로 추가·삭제·교체해야 한다.
- 유저는 이미 만료된 가격 정보를 보게 될 가능성이 있고, 운영자는 매 시즌 전환마다 어드민에 접속해야 하는 워크로드를 부담한다.

### 가설적 임팩트

- **운영자 워크로드 감소**: 시즌별 수가표를 미리 등록하고 기간만 설정하면 시점에 맞춰 자동 전환된다. 시즌 시작·종료 시점마다 어드민에 접속할 필요가 없다.
- **유저 신뢰성 향상**: 만료된 가격 정보가 페이지에 잔존하는 상황을 시스템적으로 차단한다.
- **운영 자동화에 따른 휴먼 에러 감소**: 시즌 전환을 잊거나 늦게 반영하는 케이스 제거.
- **정량 임팩트**: 운영 케이스 수·시즌별 수가표 변경 빈도 기반 추정 필요 (TBD)
- **제약**: 운영자 인터뷰 결과 시즌 가격표 입력 빈도는 1~2개월 1회 수준으로, 직접 호출 빈도는 낮음. 다만 누적 운영 시간 절감과 휴먼 에러 감소 가치가 본질.

## 구현

### 유저 플로우

**관리자 (어드민)**

- 관리자는 스팟 기본 정보 페이지의 수가표 섹션에서 각 수가표 카드에 시작일·종료일을 입력할 수 있다.
- 관리자는 시작일과 종료일을 모두 입력하지 않을 수 있으며, 이 경우 해당 수가표는 유저페이지에 상시 노출된다.
- 관리자는 시작일과 종료일을 모두 입력하여 노출 기간을 지정할 수 있으며, 이 경우 해당 수가표는 지정 기간 동안에만 유저페이지에 노출된다.
- 관리자가 시작일·종료일 중 한 쪽만 입력한 채 저장을 시도하면 저장이 차단되고 안내 메시지가 노출된다.
- 관리자는 종료일을 선택할 때 시작일 이전 날짜를 선택할 수 없다.
- 관리자는 시작일을 선택할 때 종료일이 이미 입력되어 있다면 종료일 이후 날짜를 선택할 수 없다.
- 관리자는 시작일과 종료일을 같은 날짜로 지정할 수 있으며, 이 경우 해당 날짜 하루만 노출된다.
- 관리자는 각 수가표 카드의 기간 입력 영역 옆에서 해당 수가표의 현재 노출 상태를 뱃지로 즉시 확인할 수 있다.
  - 시작일 이전이면 '활성 예정' 뱃지가 노출된다.
  - 시작일과 종료일 사이이면 '활성 중' 뱃지가 노출된다.
  - 종료일 이후이면 '만료' 뱃지가 노출된다.
  - 기간이 입력되지 않은 경우 뱃지가 노출되지 않는다.
- 관리자는 기간 입력 영역 옆의 안내 아이콘에 마우스를 호버하여 기간 입력 정책을 확인할 수 있다.
- 관리자는 만료되었거나 활성 예정인 수가표도 어드민에서는 모두 확인·편집할 수 있다.

**유저 (유저페이지)**

- 유저는 스팟 상세 페이지에서 현재 활성 상태인 수가표만 볼 수 있다.
  - 기간이 설정되지 않은 수가표는 상시 노출된다.
  - 기간이 설정된 수가표는 현재 KST 시각이 시작일 0시부터 종료일 23시 59분 59초 사이일 때만 노출된다.
- 해당 스팟에 활성 상태인 수가표가 하나도 없으면 유저는 수가표 섹션 자체를 볼 수 없다.

### 프론트엔드 요구사항

**어드민 (`frontend/apps/admin`)**

- 스팟 기본 정보 페이지 > 수가표 섹션 > 각 수가표 카드 영역에 다음 항목을 추가한다.
  - 시작일 DatePicker
  - 종료일 DatePicker
  - 안내용 툴팁 아이콘 (Info 아이콘)
  - 노출 상태 뱃지 영역
- 두 DatePicker는 기존 제목·설명 입력 영역 아래에 한 줄로 가로 배치한다. 그 우측에 안내 아이콘과 상태 뱃지를 배치한다.
- 안내 아이콘에 마우스를 호버하면 다음 문구의 툴팁이 노출된다.
  - 문구: **"기간 입력 시 해당 기간 동안에만 노출되며, 기간 미입력 시 상시 노출됩니다."**
- DatePicker 상호 제약을 적용한다.
  - 종료일 DatePicker의 `disabledDate` 조건: 시작일이 입력된 경우, 시작일 이전 날짜는 선택 불가.
  - 시작일 DatePicker의 `disabledDate` 조건: 종료일이 입력된 경우, 종료일 이후 날짜는 선택 불가.
- 상태 뱃지는 입력된 기간과 현재 KST 시각을 비교하여 실시간으로 결정한다.
  - 활성 예정: 현재 시각 < 시작일 0시 KST
  - 활성 중: 시작일 0시 KST ≤ 현재 시각 ≤ 종료일 23:59:59 KST
  - 만료: 현재 시각 > 종료일 23:59:59 KST
  - 기간 미입력(둘 다 비어 있음): 뱃지 미노출
- 페이지 하단 '저장' 버튼 클릭 시 다음 클라이언트 측 검증을 수행한다.
  - 수가표 카드 중 시작일·종료일 한 쪽만 입력된 카드가 있으면 저장을 차단하고 다음 메시지를 노출한다.
    - 문구: **"시작일과 종료일을 모두 입력하거나 모두 비워주세요."**
  - 시작일이 종료일보다 늦은 카드가 있으면 저장을 차단하고 다음 메시지를 노출한다.
    - 문구: **"시작일은 종료일보다 이전이어야 합니다."** (DatePicker `disabledDate` 제약으로 1차 차단되지만, 직접 입력·이상 케이스에 대한 방어선)
- `FeeScheduleInput` 타입에 `startDate?: Date | null`, `endDate?: Date | null` 필드를 추가한다.

**유저페이지 (`frontend/apps/web`)**

- 별도 작업 없음 — 백엔드에서 활성 수가표만 필터링하여 응답한다.
- 단, 빈 배열을 받았을 때 수가표 섹션 자체가 숨김 처리되는지 기존 동작을 확인한다.
  - 기존 분기로 자동 숨김 처리되면 별도 작업 없음.
  - 항상 빈 상태 placeholder를 노출하는 분기가 있다면 빈 배열 케이스를 추가하여 섹션을 숨긴다.

### 백엔드 요구사항

**데이터베이스 스키마**

- 수가표 테이블에 컬럼 2개를 추가한다.
  - `start_date DATE NULL`
  - `end_date DATE NULL`
- 기존 데이터는 두 컬럼이 NULL로 자동 설정되어 기존 동작(상시 노출)과 호환된다.

**GraphQL 스키마**

- 수가표 Object Type에 다음 필드를 추가한다.
  - `startDate: Date` (nullable)
  - `endDate: Date` (nullable)
- 수가표 Input Type에 동일하게 두 필드를 추가한다.
- 기존 쿼리·뮤테이션 호환성은 유지된다 (필드 추가만, 제거·변경 없음).

**비즈니스 로직 — 유저페이지 수가표 조회**

- 유저페이지에서 호출되는 수가표 조회 로직에 다음 필터를 적용한다.
  - 시작일·종료일이 모두 NULL이면 노출
  - 또는, 현재 KST 시각이 시작일 0시 KST와 종료일 23:59:59 KST 사이이면 노출
- 시간대 처리: 컬럼은 DATE 타입(시간 미포함). 비교 시 KST 타임존으로 정규화한 뒤 위 조건을 적용한다.

**비즈니스 로직 — 어드민 수가표 조회**

- 어드민에서 호출되는 수가표 조회 로직은 만료·예정 수가표를 모두 포함하여 응답한다.
- 기존 어드민 조회 로직을 그대로 사용하거나, 별도 옵션 인자(`includeExpired: true`)로 분기한다.

**비즈니스 로직 — 수가표 저장 검증 (`upsertSpotBasicInfo` 등)**

- 각 수가표 항목에 대해 다음 검증을 수행한다.
  - 시작일·종료일 중 한 쪽만 입력된 경우 저장을 차단하고 에러를 반환한다.
  - 시작일이 종료일보다 늦은 경우 저장을 차단하고 에러를 반환한다.
  - 시작일·종료일이 모두 NULL인 경우 정상 저장된다.
  - 시작일과 종료일이 같은 날짜인 경우 정상 저장된다.

**테스트 케이스**

- NULL/NULL → 항상 노출
- 시작일 ≤ 현재 ≤ 종료일 → 노출
- 현재 < 시작일 → 비노출 (활성 예정)
- 현재 > 종료일 → 비노출 (만료)
- 시작일 = 종료일이고 해당 날짜가 오늘 → 노출
- 한 쪽만 입력(XOR) → 저장 차단
- 시작일 > 종료일 → 저장 차단
- 어드민 조회 시 만료·예정 수가표 모두 포함되어 응답
- 모든 수가표가 비활성인 스팟 → 유저페이지에서 수가표 섹션 자체 숨김

### 결정사항 요약 (frame 정렬 결과)

| 항목 | 결정 |
|---|---|
| 데이터 모델 변경 범위 | 컬럼 2개 추가 (B-1 안) — 신규 테이블·모달 리팩토링 불필요 |
| 기간 단위 | 이미지(섹션) 단위 |
| 시작일·종료일 nullability | 둘 다 nullable, 단 XOR 입력 금지 |
| 시간대 | KST 기준, `시작일 00:00 ~ 종료일 23:59:59` |
| 시작일 = 종료일 | 허용 (하루만 활성) |
| 시작일 > 종료일 | 차단 (어드민 DatePicker `disabledDate` + 백엔드 검증) |
| 상태 뱃지 | 활성 예정 / 활성 중 / 만료 (기간 미입력 시 미노출) |
| 안내 툴팁 문구 | "기간 입력 시 해당 기간 동안에만 노출되며, 기간 미입력 시 상시 노출됩니다." |
| 모든 수가표 비활성 시 | 수가표 섹션 자체 숨김 |
| 어드민 조회 정책 | 만료·예정 포함 전체 노출 (관리 가능성 보장) |
