# 세부 기획안 요구사항 문서

## 배경

### 문제 정의

- 어드민에서 쿠폰 생성 시 **'쿠폰 중복 발급 허용'**을 설정할 수 있으나, 사용자 화면에서는 중복 발급 허용 여부와 무관하게 쿠폰을 1회 다운로드하면 다운로드 버튼이 즉시 비활성화(회색) 처리
- 중복 발급이 가능한 쿠폰임에도 유저가 추가 쿠폰을 받으려면 **페이지를 새로고침한 뒤 다시 다운로드**해야 하는 불편 발생
- 여러 장을 반복 발급받도록 운영하는 프로모션의 경우, 현재 다운로드 버튼 동작이 어드민의 중복 발급 설정 의도와 불일치
- 현재 비활성화 처리는 발급 성공·실패와 관계없이 다운로드 시도 시점에 일괄 적용되며, 한 화면 세션 안에서만 유지되는 임시 상태 — 새로고침 시 다시 활성화되는 것도 이 때문
- 타사 사례(G마켓)의 경우, 중복 발급이 가능한 쿠폰은 다운로드 이후에도 버튼이 유지되어 **새로고침 없이 동일 쿠폰을 연속 발급**

### 중복 발급 관련 두 가지 설정 (전제)

- 쿠폰은 중복 발급과 관련해 두 값을 함께 가짐 — **중복 발급 허용 여부**, **재발급 대기일**
- **재발급 대기일**은 "이 기간 동안 발급 가능"이 아니라 **"직전 발급 후 이 기간이 지나야 다시 발급 가능"**한 쿨다운 값 — 기본값 15일. 대기일이 지나기 전 재발급 시도는 **재발급 불가 기간 안내**로 거부
- 따라서 **재발급 대기일이 0일 때만 새로고침 없이 즉시 연속 발급이 가능**하고, 0을 초과하면 버튼을 켜둬도 곧바로 다시 누를 때 서버가 발급을 거부
- 프로덕션 현황(2026-08-19 기준): 중복 발급 허용 쿠폰 302개 중 **대기일 0(즉시 연속)은 37개**, 나머지 265개는 대기일 존재(30일 153개, 15일 48개, 25일 42개 등). 이번 개선의 대상은 **즉시 연속 발급용 쿠폰(대기일 0)**

- 즉시 연속 발급 쿠폰의 발급 마찰(새로고침 단계) 제거로, 반복 발급 프로모션의 총 발급 수 및 완주율 증가 기대
- 어드민 설정(중복 발급 허용 + 재발급 대기일 0)과 실제 사용자 경험의 정합성 확보로 운영 혼선 감소

## 구현

### 유저 플로우

- 유저가 **중복 발급 허용 + 재발급 대기일 0** 쿠폰의 다운로드 버튼 클릭 → 발급 완료 안내 노출, 다운로드 버튼은 **비활성화되지 않고 계속 활성화 유지** → 새로고침 없이 버튼을 다시 눌러 동일 쿠폰 연속 추가 발급
- 유저가 **중복 발급 미허용(일반)** 쿠폰의 다운로드 버튼 클릭 → 발급 완료 후 기존과 동일하게 다운로드 버튼 **비활성화**
- 유저가 **중복 발급 허용이지만 재발급 대기일이 있는(0 초과)** 쿠폰의 다운로드 버튼 클릭 → 발급 완료 후 기존과 동일하게 다운로드 버튼 **비활성화** (해당 쿠폰은 지금 즉시 재발급되지 않으므로 기존 동작 유지)

### 프론트엔드 요구사항

- 온라인 쿠폰 카드가 쿠폰의 **중복 발급 허용 여부**와 **재발급 대기일** 두 값을 함께 조회하도록 노출 (두 값 모두 백엔드 스키마에 이미 존재, 쿠폰 카드 조회 항목에 추가 후 코드젠 반영)
- 다운로드 버튼 활성 유지 조건: **중복 발급 허용이면서 재발급 대기일이 0인 경우에만** 발급 성공 이후에도 버튼 **활성화 상태 유지**, 연속 클릭으로 추가 발급 가능
- 위 조건에 해당하지 않는 모든 쿠폰(중복 발급 미허용, 또는 허용이지만 재발급 대기일 0 초과): 발급 이후 다운로드 버튼 **비활성화** (기존 동작 유지)
- 발급 실패 시 버튼 상태도 동일 조건으로 분기 — 활성 유지 대상 쿠폰은 실패 후에도 **활성화 유지**, 그 외는 기존과 동일 처리
- 이미 발급된 상태 또는 재발급 불가 기간에 대한 안내 문구는 기존 발급 실패 안내 처리 흐름을 재사용

### 백엔드 요구사항

- 신규 개발 없음 — 중복 발급 허용 여부·재발급 대기일 필드와 발급 검증 로직은 이미 존재하며, 두 필드 모두 이미 스키마에 노출되어 있어 프론트에서 조회만 추가하면 됨
