# 세부 기획안 요구사항 문서

## 배경

### 문제 정의

파트너는 자신의 스팟 상세에 노출되는 **수가표(시술·가격표 이미지)** 를 파트너 어드민에서 직접 등록·수정할 수 없다.

- 수가표를 새로 올리거나 바꾸려면 파트너가 관리자에게 별도로 요청하고, 관리자가 수동으로 반영해야 한다. (현행 반영 방식·경로: TBD)
- 시술·가격 변동이 잦은 피부시술·뷰티 스팟에서 수가표가 최신 상태로 유지되지 못하고, 그때마다 관리자 처리 부하가 발생한다.

### 가설적 임팩트

- 파트너가 수가표를 스스로 관리하게 되어, 수가표 변경을 위한 관리자 수동 반영 요청이 줄어든다.
- 수가표가 더 자주·빠르게 최신화되어 스팟 상세의 정보 정확도가 올라간다.
- (정량 임팩트: 수가표 관련 관리자 처리 건수 감소 기준으로 산정 필요 — TBD)

## 구현

### 유저 플로우

- 파트너는 '내 스팟 관리(기존 '스팟 수정 요청')'의 **기본 정보 수정** 영역에서 수가표를 관리한다.
- 파트너는 수가표 이미지를 **등록·교체·삭제**할 수 있다.
- 파트너는 수가표가 여러 장일 경우 **드래그로 노출 순서를 변경**할 수 있다.
- 파트너는 각 수가표에 **제목**과 **설명**을 입력할 수 있다.
- 파트너가 등록·변경한 수가표의 반영 방식(즉시 반영 vs. 변경 요청 제출 후 관리자 승인)은 스팟 정보 수정의 기존 정책을 따른다. (수가표에 적용할 반영 방식 확정 필요 — TBD)

### 프론트엔드 요구사항

- 기본 정보 수정 영역 하단에 **'수가표'** 섹션을 노출한다.
- 섹션 상단에 안내 문구 **"시술·가격표 이미지를 등록해 스팟 상세에 노출합니다. (선택 · 드래그로 순서 변경)"** 를 노출한다.
- 각 수가표 항목은 **제목 입력** · **설명 입력** · **이미지 등록**으로 구성한다.
- **'+ 수가표 추가'** 로 항목을 추가하고, 항목별로 **삭제**와 **순서 변경(드래그)** 을 지원한다.
- 수가표는 필수 입력이 아니다. (등록하지 않아도 저장 가능)
- 유저 스팟 상세에서의 수가표 노출 위치·형태는 기존 노출 방식을 그대로 재사용한다.

### 백엔드 요구사항

- 파트너가 등록·수정·삭제한 수가표 이미지와 제목·설명을 저장·조회한다.
- **관리자 어드민에서 입력한 수가표 데이터와 파트너가 파트너 어드민에서 등록하는 수가표 데이터는 동기화된다.** 두 경로가 동일한 수가표 데이터를 공유하므로, 어느 한쪽에서의 등록·수정·삭제가 다른 쪽에도 그대로 반영된다.
- 수가표의 노출 순서를 저장한다.
- 반영 방식(즉시 반영 vs. 관리자 승인)에 따른 저장 흐름을 처리한다. (TBD)
