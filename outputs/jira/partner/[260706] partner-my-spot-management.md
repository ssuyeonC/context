# 세부 기획안 요구사항 문서

## 배경

### 문제 정의

파트너 어드민의 **'스팟 수정 요청'** 페이지는 파트너가 자신의 스팟 정보를 확인·수정 요청하는 공간이지만, 현재 구조가 파트너의 스팟 관리 동선을 충분히 지원하지 못하고 있다.

- **수정과 결과 화면이 분리되어 있다**: 현재는 스팟이 테이블로 나열되고, 특정 스팟 Row를 클릭해야 수정 가능한 정보가 보인다. 파트너는 자신이 입력·수정하는 값이 실제 유저 페이지의 어느 영역에 어떻게 노출되는지 확인할 수 없어, 수정의 결과를 예측하기 어렵다.
- **메뉴 명칭이 역할을 충분히 전달하지 못한다**: **'스팟 수정 요청'** 이라는 명칭은 개별 수정 요청 행위에 초점이 맞춰져 있어, 이 페이지가 파트너가 자신의 스팟을 관리하는 허브라는 점을 드러내지 못한다.
- **'스팟 등록 요청' 진입점이 맥락과 떨어져 있다**: 현재 **'스팟 등록 요청'** 은 좌측 네비게이션에 별도 항목으로 존재한다. 스팟 등록은 '내 스팟'을 다루는 행위인데도 스팟 관리 화면과 분리되어 있어, 파트너가 스팟을 관리하는 흐름 안에서 자연스럽게 등록으로 이어지지 않는다.
- **여러 스팟을 가진 파트너의 전환 동선이 번거롭다**: 스팟이 여러 개인 파트너는 테이블에서 스팟을 찾아 다시 클릭해야 하며, 관리 대상 스팟을 빠르게 전환하기 어렵다.

### 가설적 임팩트

- 파트너가 자신의 수정값이 유저 페이지의 어느 영역에 반영되는지 즉시 인지할 수 있어, 잘못된 값·오배치로 인한 수정 요청과 반려·재요청이 줄어든다.
- 스팟 등록 진입점을 스팟 관리 화면 안으로 옮겨, 스팟을 관리하는 흐름에서 자연스럽게 등록 요청으로 이어진다.
- 스팟이 여러 개인 파트너의 스팟 전환·관리 동선이 단축된다.
- (정량 임팩트: 파트너 수정 요청 건당 반려율·재요청율, 스팟 등록 요청 전환율 기준으로 산정 필요 — TBD)

## 구현

### 유저 플로우

- 파트너는 좌측 네비게이션에서 **'내 스팟 관리'** 로 진입한다. (기존 **'스팟 수정 요청'** 이 이 항목으로 대체된다.)
- 파트너는 화면 최상단의 스팟 선택 영역에서 관리할 스팟을 선택한다.
  - 스팟이 **2개 이상**인 파트너는 상단 드롭다운에서 스팟을 전환할 수 있으며, 진입 시 **가장 최근에 생성된 스팟**이 기본으로 선택되어 있다.
  - 스팟이 **1개**인 파트너는 해당 스팟이 자동으로 로드되며, 드롭다운에는 그 스팟 1개가 노출된다.
  - 스팟이 **0개**인 파트너는 편집·미리보기 영역 대신 안내 메시지를 본다.
- 파트너는 화면을 좌우 2단으로 본다. 좌측에서 자신의 스팟이 유저 페이지에 어떻게 노출되는지 미리보기로 확인하고, 우측에서 스팟 정보를 편집한다.
- 파트너가 우측 편집 영역의 특정 필드에 커서를 올리거나 값을 수정하면, 좌측 미리보기에서 그 값이 노출되는 영역이 강조 표시된다. (편집 값 자체가 미리보기에 실시간 반영되지는 않는다.)
- 파트너는 스팟 선택 영역 우측의 **'스팟 등록 요청'** 버튼을 눌러 스팟 등록 요청 화면으로 진입한다.
- 필드별 편집·저장 방식(즉시 변경 vs. 변경 요청 제출)은 기존 정책을 그대로 유지한다.

#### '옵션 정보 수정' 유저 플로우

파트너가 우측 편집 영역에서 상품/옵션 정보를 수정하는 경우, 아래 흐름을 따른다.

1. 파트너가 **'수정하기'** 버튼을 클릭한다.
2. 기 입력된 정보를 수정하거나, 새로운 상품/옵션을 추가한다.
3. 입력·변경된 내용에 대한 **번역을 진행**한다.
4. 파트너가 **'수정완료'** 버튼을 클릭한다.
5. **관리자가 검토**한다.
6. 관리자가 **최종 승인 혹은 반려**한다.

### 프론트엔드 요구사항

#### 1. 네비게이션 구조 변경

- 좌측 네비게이션의 **'스팟 수정 요청'** 항목 명칭을 **'내 스팟 관리'** 로 변경한다. (진입 경로는 기존 스팟 관리 페이지를 그대로 사용한다.)
- 좌측 네비게이션의 **'스팟 등록 요청'** 항목을 제거한다. 해당 진입점은 아래 3번 스팟 선택 영역 내부로 이동한다.
- **'스팟 리뷰 관리'** 항목은 그대로 유지한다.

#### 2. 페이지 레이아웃 (세로 2단)

- 페이지 본문을 좌우 2단 구조로 구성한다.
  - **좌측 단 = 스팟 미리보기 영역**, **우측 단 = 스팟 편집 영역**
  - 두 단의 가로 폭 비율은 **2 : 1** (좌측이 우측의 2배)로 한다.

#### 3. 상단 스팟 선택 영역

- 페이지 최상단에 **스팟 선택 드롭다운**(좌)과 **'스팟 등록 요청' 버튼**(우)을 한 줄로 배치한다.
- 드롭다운 기본 선택 값은 **가장 최근에 생성된 스팟**이다.
- 스팟 보유 개수에 따라 아래와 같이 분기한다.
  - **2개 이상**: 드롭다운으로 관리 대상 스팟을 전환할 수 있다. 선택을 바꾸면 좌측 미리보기와 우측 편집 영역이 해당 스팟 기준으로 갱신된다.
  - **1개**: 드롭다운에 해당 스팟 1개만 노출되며, 그 스팟이 자동으로 로드된다. **'스팟 등록 요청'** 버튼은 동일하게 노출한다.
  - **0개**: 드롭다운에는 **"등록된 스팟 없음"** 을 노출(선택 불가)하고, 화면 가운데에 안내 메시지 **"등록된 스팟이 없습니다. '스팟 등록 요청' 버튼을 클릭해 스팟을 등록해주세요."** 를 노출한다. 이때 편집·미리보기 영역은 노출하지 않으며, **'스팟 등록 요청'** 버튼은 그대로 노출한다.
- **'스팟 등록 요청'** 버튼을 누르면 기존 스팟 등록 요청 화면으로 진입한다. (등록 요청 기능 자체는 기존 그대로 재사용한다.)

#### 4. 좌측 · 스팟 미리보기 영역

- 현재 선택된 파트너 스팟을 미리보기로 노출한다. 미리보기는 실제 유저 웹 페이지를 그대로 보여주는 방식을 유지한다. (기존 스팟 인라인 미리보기 방식을 재사용한다.)
- **미리보기 상단에 툴바**를 둔다.
  - **디바이스 전환**: `🖥 데스크탑` / `📱 모바일` 토글로 미리보기 뷰포트를 전환한다.
  - **언어 전환**: 미리보기 노출 언어를 전환할 수 있다. **기본값은 한국어**이며, 유저 페이지가 지원하는 언어(한국어·영어·일본어·중국어(간체)·중국어(번체)·태국어·베트남어·인도네시아어·스페인어·프랑스어·러시아어·독일어·이탈리아어·몽골어)로 전환해 각 언어에서의 노출을 확인할 수 있다.

#### 5. 우측 · 스팟 편집 영역

- 현재 스팟 수정 화면에 존재하는 편집 필드를 **모두 그대로** 노출한다. (스팟명·주소·전화·좌표·이미지·타임슬롯·상품/옵션·예약 정책 등)
- 편집 영역 내 필드 구성 방식은 현재와 동일하게 **드롭다운으로 필드 그룹을 선택**해 편집하는 형태를 유지한다. 드롭다운 항목은 다음과 같다.
  - **기본 정보 수정** (스팟명·이미지·주소·전화·위도·경도 등)
  - **옵션 정보 수정** (상품/옵션)
  - **예약 기본 정보 수정**
  - **예약 시간 관리** (타임슬롯)
- 기본 이미지 편집은 **메인 이미지 다중 등록**을 지원하며, **드래그로 순서 변경** 및 **대표 이미지 지정**이 가능하다. (`+ 이미지 업로드`)
- 편집 영역 상단에 **'수정 요청 내역 확인'** 진입점을 둔다. 파트너가 자신이 제출한 수정 요청의 처리 상태(검토 중·승인·반려 등)를 확인할 수 있게 한다. (표시 항목·상세는 기존 수정 요청 이력 기준으로 정리 — TBD)
- 필드별로 정해진 편집·저장 방식(즉시 변경 가능 vs. 변경 요청 제출 필수)은 **기존 정책을 그대로 유지**한다.

#### 6. 편집 필드 ↔ 미리보기 영역 하이라이트 연동

- 파트너가 우측 편집 영역의 특정 필드에 **포커스**(커서 진입)하거나 값을 **수정**하면, 좌측 미리보기에서 그 필드가 노출되는 영역을 강조 표시한다.
- 미리보기는 어드민과 다른 도메인의 실제 유저 페이지를 임베드한 형태이므로, 어드민 화면에서 미리보기 내부 영역을 직접 조작할 수 없다. 따라서 하이라이트는 **어드민 편집 영역 → 미리보기 페이지로 메시지를 전달(postMessage)** 하고, **미리보기(유저 웹) 페이지가 해당 필드 영역을 강조**하는 방식으로 구현한다.
  - 어드민 편집 영역: 필드 포커스/수정 시 대상 필드 식별자를 미리보기로 전달한다.
  - 유저 웹 미리보기 페이지: 전달받은 필드 식별자에 해당하는 영역에 강조 표시를 적용/해제한다.
- **편집 필드 ↔ 미리보기 영역 매핑 정의**가 필요하다. 어떤 필드가 미리보기의 어느 영역에 대응되는지 목록을 확정한다. (매핑 대상 필드 목록: TBD — 위 5번의 전체 편집 필드 기준으로 정리)
- 편집 값 자체를 미리보기에 실시간으로 반영하지는 않는다. (하이라이트만 수행)
- 하이라이트가 대응되지 않는 필드(미리보기에 노출되지 않는 관리용 값 등)는 강조 표시 없이 편집만 지원한다.

#### 7. 수가표(시술·가격표) 관리 — 신규

- 편집 영역에 **'수가표'** 섹션을 추가한다. 파트너가 **시술·가격표 이미지**를 등록해 스팟 상세에 노출할 수 있게 한다. (선택 항목)
- **노출 조건**: **대분류 값이 `3068`인 스팟에만** 수가표 편집 섹션을 노출한다. (그 외 스팟에는 수가표 섹션을 노출하지 않는다.)
- 수가표는 **섹션 단위**로 구성한다. 각 섹션은 아래를 가진다.
  - **수가표 이미지** (등록/`이미지 변경`/`삭제`)
  - **섹션 제목** (선택) — 예: "레이저 시술 수가표", "피부관리 패키지"
  - **설명** (선택)
- **'＋ 수가표 섹션 추가'** 로 섹션을 여러 개 추가할 수 있고, **드래그로 섹션 순서를 변경**할 수 있다.
- 등록된 수가표는 좌측 미리보기(스팟 상세)의 **'수가표'** 영역에 반영되어 노출된다.
- 저장 방식(즉시 변경 vs. 변경 요청 제출)은 다른 필드와 동일한 기존 정책을 따른다. (수가표에 어떤 정책을 적용할지 확정 필요 — TBD)

> 참고: 수가표 노출 기준(대분류 `3068`)과, 위 '추가 요구사항 — 파트너십 정산' 배너의 노출 기준(중분류 `404` '피부시술(사용중)')은 **서로 다른 분류 레벨의 조건**이다. 두 조건의 대상 스팟 범위가 동일한지(피부/뷰티 스팟 집합) 확인이 필요하다 — TBD.

### 백엔드 요구사항

- 스팟 선택 드롭다운은 파트너가 보유한 스팟 목록을 사용한다. 기본 선택을 위해 **가장 최근 생성된 스팟이 먼저 오도록** 정렬 기준(생성일 내림차순)을 제공한다. (기존 파트너 스팟 조회를 재사용하되 정렬·기본값 요건 확인 필요: TBD)
- 기존 편집 필드(스팟명·이미지·주소·좌표·상품/옵션·예약 정책·타임슬롯 등)의 조회·저장(변경 요청 포함)은 기존 기능을 그대로 사용하며, 신규 데이터 모델링·저장 로직 변경은 없다.
- **수가표(신규)**: 시술·가격표 이미지를 섹션 단위(이미지 + 제목 + 설명 + 순서)로 저장·조회할 수 있는 데이터 구조가 필요하다. 스팟 상세(유저 페이지)에서도 동일 데이터를 노출한다. (신규 테이블/필드 설계 여부 — TBD)
- 수가표 편집 섹션의 노출 판별을 위해 **해당 스팟의 대분류 값이 `3068`인지**를 프론트에서 판단할 수 있는 데이터가 필요하다. (기존 스팟 카테고리 조회로 판별 가능한지 확인 필요 — TBD)
- 미리보기 하이라이트 연동은 유저 웹 미리보기 페이지의 처리 사항으로, 별도 백엔드 변경은 없을 것으로 예상한다.

## 추가 요구사항 — 파트너십 정산 페이지: 뷰티 정산 관리 안내

> 위 '내 스팟 관리' 개편과는 대상 페이지가 다른 별건 요구사항이다. (대상: 파트너 어드민 **'파트너십 정산'** 페이지)

### 배경

#### 문제 정의

- 파트너 어드민의 **'파트너십 정산'** 메뉴는 파트너의 모든 예약을 함께 조회한다.
- 그러나 피부과 **무료예약(중분류: 피부시술)** 은 이 페이지에서 정산하는 구조가 아니라, 별도의 **뷰티 정산 관리** 시스템에서 정산이 진행된다.
- 이로 인해 피부시술 무료예약이 파트너십 정산 페이지에 정산가격 `₩0`으로 노출되어, 파트너는 **왜 0원인지**, **어디에서 정산을 확인해야 하는지** 혼란을 겪는다.

#### 가설적 임팩트

- 뷰티 정산이 별도 시스템에서 이뤄진다는 사실과 확인 경로를 페이지 내에서 즉시 안내함으로써, `₩0` 노출로 인한 파트너 문의·혼란이 줄어든다.

### 구현

#### 방향 결정 — 안내 배너 + 새 탭 이동 버튼 (임베드 아님)

파트너십 정산 페이지 상단에 안내 문구와 **'뷰티 정산 관리' 이동 버튼**을 추가하되, 버튼은 뷰티 정산 관리 페이지를 **새 탭으로 여는 방식**으로 구현한다. (어드민 화면 내 iframe 임베드는 하지 않는다.)

- **임베드를 배제한 이유**: 뷰티 정산 관리 링크는 파트너 계정으로 자동 로그인되는 구조인데, 이를 파트너 어드민 도메인 안의 iframe으로 띄우면 (1) 서드파티 쿠키 차단으로 iframe 내부에서 세션이 유지되지 않을 수 있고, (2) 대상 사이트의 `X-Frame-Options`/CSP `frame-ancestors` 설정에 따라 iframe 자체가 차단될 수 있다. 즉 진짜 비용은 iframe 배치가 아니라 iframe 내부의 자동 로그인을 신뢰성 있게 동작시키는 것이며, 뷰티 서비스 측 헤더/인증 변경까지 번질 수 있다. 본 요구사항의 목적(‘₩0 혼란 해소’)은 안내 배너 + 새 탭 버튼만으로 충분히 달성되므로, 리스크 대비 실익이 낮은 임베드는 채택하지 않는다.

#### 프론트엔드 요구사항

- 파트너십 정산 페이지 **상단에 안내 배너**를 추가한다.
  - 안내 문구(예시):
    > 피부과(중분류: 피부시술) 예약은 **뷰티 정산 관리**에서 정산이 진행됩니다.
    > 해당 예약의 정산 내역은 아래 페이지에서 확인해 주세요.
    > 자세한 문의는 크리에이트립 담당 매니저에게 문의 부탁드립니다.
  - 배너 내에 **'뷰티 정산 관리 바로가기'** 버튼을 배치한다.
- **'뷰티 정산 관리 바로가기'** 버튼은 아래 링크를 **새 탭(`target="_blank"`, `rel="noopener"`)** 으로 연다.
  - 링크: `https://beauty-partners.creatrip.team/`
- **노출 조건**: **중분류 카테고리 `404`('피부시술(사용중)')가 연결된 스팟을 하나라도 보유한 파트너**에게만 배너를 노출한다.
  - 피부시술 스팟만 보유한 파트너: 배너를 노출한다.
  - 피부시술 스팟과 그 외 스팟을 **둘 다 보유한 파트너**: 기존 정산 화면은 그대로 노출하고, 그 **화면 상단에 배너를 함께 노출**한다. (정산 리스트 자체는 기존과 동일하게 표시)
  - 피부시술 스팟을 보유하지 않은 파트너: 배너를 노출하지 않는다.

#### 백엔드 요구사항

- 새 탭 이동 방식이므로 정산 관련 백엔드 변경은 없을 것으로 예상한다.
- 단, 배너 노출 판별을 위해 **해당 파트너가 중분류 카테고리 `404`('피부시술(사용중)')가 연결된 스팟을 보유하는지 여부**를 프론트에서 판단할 수 있는 데이터가 필요하다. (기존 파트너 스팟·카테고리 조회로 판별 가능한지 확인 필요 — TBD)
