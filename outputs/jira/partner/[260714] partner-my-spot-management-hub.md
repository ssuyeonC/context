# 세부 기획안 요구사항 문서

## 배경

### 문제 정의

파트너 어드민의 **'스팟 수정 요청'** 페이지는 파트너가 자신의 스팟 정보를 확인·수정 요청하는 공간이지만, 현재 구조가 파트너의 스팟 관리 동선을 충분히 지원하지 못한다.

- **수정과 결과 화면이 분리되어 있다**: 스팟이 테이블로 나열되고, 특정 스팟 Row를 클릭해야 수정 가능한 정보가 보인다. 파트너는 자신이 입력·수정하는 값이 실제 유저 페이지의 어느 영역에 어떻게 노출되는지 확인할 수 없어, 수정의 결과를 예측하기 어렵다.
- **메뉴 명칭이 역할을 충분히 전달하지 못한다**: **'스팟 수정 요청'** 이라는 명칭은 개별 수정 요청 행위에 초점이 맞춰져 있어, 이 페이지가 파트너가 자신의 스팟을 관리하는 허브라는 점을 드러내지 못한다.
- **'스팟 등록 요청' 진입점이 맥락과 떨어져 있다**: **'스팟 등록 요청'** 이 좌측 네비게이션에 별도 항목으로 존재해, 스팟을 관리하는 흐름 안에서 자연스럽게 등록으로 이어지지 않는다.
- **여러 스팟을 가진 파트너의 전환 동선이 번거롭다**: 스팟이 여러 개인 파트너는 테이블에서 스팟을 찾아 다시 클릭해야 하며, 관리 대상 스팟을 빠르게 전환하기 어렵다.

> 본 티켓은 스팟 수정 요청 화면의 **접근성·발견성 개편(허브화)** 을 다룬다. 각 편집 카테고리의 기능 개선은 별도 티켓에서 다룬다 — 옵션 정보 수정 정상화는 `[260714] partner-spot-option-edit-request.md`, 수가표 편집은 `[260714] partner-fee-schedule-edit.md`, 예약 시간 자동승인은 `[260714] partner-reservation-time-auto-approval.md`, 미리보기 하이라이트는 `[260714] partner-spot-edit-preview-highlight.md`.

### 가설적 임팩트

- 파트너가 미리보기와 편집을 나란히 보며 관리해, 자신의 스팟 상태를 더 쉽게 파악하고 수정에 접근할 수 있다.
- 스팟 등록 진입점을 스팟 관리 화면 안으로 옮겨, 스팟을 관리하는 흐름에서 자연스럽게 등록 요청으로 이어진다.
- 스팟이 여러 개인 파트너의 스팟 전환·관리 동선이 단축된다.
- (정량 임팩트: 파트너의 스팟 수정 요청 진입·완료율, 스팟 등록 요청 전환율 기준으로 산정 필요 — TBD)

## 구현

### 유저 플로우

- 파트너는 좌측 네비게이션에서 **'내 스팟 관리'** 로 진입한다. (기존 **'스팟 수정 요청'** 이 이 항목으로 대체된다.)
- 파트너는 화면 최상단의 스팟 선택 영역에서 관리할 스팟을 선택한다.
  - 스팟이 **2개 이상**인 파트너는 상단 드롭다운에서 스팟을 전환할 수 있으며, 진입 시 **가장 최근에 생성된 스팟**이 기본으로 선택되어 있다.
  - 스팟이 **1개**인 파트너는 해당 스팟이 자동으로 로드되며, 드롭다운에는 그 스팟 1개가 노출된다.
  - 스팟이 **0개**인 파트너는 편집·미리보기 영역 대신 안내 메시지를 본다.
- 파트너는 화면을 좌우 2단으로 본다. 좌측에서 자신의 스팟이 유저 페이지에 어떻게 노출되는지 미리보기로 확인하고, 우측에서 스팟 정보를 편집한다.
- 파트너는 스팟 선택 영역 우측의 **'스팟 등록 요청'** 버튼을 눌러 스팟 등록 요청 화면으로 진입한다.
- 파트너는 우측 편집 영역에서 상단 드롭다운으로 편집 카테고리를 전환해 각 정보를 수정한다.

### 프론트엔드 요구사항

**1. 네비게이션 구조 변경**

- 좌측 네비게이션의 **'스팟 수정 요청'** 항목 명칭을 **'내 스팟 관리'** 로 변경한다. (진입 경로는 기존 스팟 관리 페이지를 그대로 사용한다.)
- 좌측 네비게이션의 **'스팟 등록 요청'** 항목을 제거한다. 해당 진입점은 아래 3번 스팟 선택 영역 내부로 이동한다.
- **'스팟 리뷰 관리'** 항목은 그대로 유지한다.

**2. 페이지 레이아웃 (좌우 2단)**

- 페이지 본문을 좌우 2단으로 구성한다. **좌측 단 = 스팟 미리보기 영역**, **우측 단 = 스팟 편집 영역**.
- 두 단의 가로 폭 비율은 **2 : 1**(좌측이 우측의 2배)로 한다.

**3. 상단 스팟 선택 영역**

- 페이지 최상단에 **스팟 선택 드롭다운**(좌)과 **'스팟 등록 요청' 버튼**(우)을 한 줄로 배치한다.
- 드롭다운 기본 선택 값은 **가장 최근에 생성된 스팟**이다.
- 스팟 보유 개수에 따라 아래와 같이 분기한다.
  - **2개 이상**: 드롭다운으로 관리 대상 스팟을 전환한다. 선택을 바꾸면 좌측 미리보기와 우측 편집 영역이 해당 스팟 기준으로 갱신된다.
  - **1개**: 드롭다운에 해당 스팟 1개만 노출되며 자동으로 로드된다. **'스팟 등록 요청'** 버튼은 동일하게 노출한다.
  - **0개**: 드롭다운에 **"등록된 스팟 없음"** 을 노출(선택 불가)하고, 화면 가운데에 안내 메시지 **"등록된 스팟이 없습니다. '스팟 등록 요청' 버튼을 클릭해 스팟을 등록해주세요."** 를 노출한다. 이때 편집·미리보기 영역은 노출하지 않으며, **'스팟 등록 요청'** 버튼은 그대로 노출한다.
- **'스팟 등록 요청'** 버튼을 누르면 기존 스팟 등록 요청 화면으로 진입한다. (등록 요청 기능 자체는 기존 그대로 재사용한다.)

**4. 좌측 · 스팟 미리보기 영역**

- 현재 선택된 파트너 스팟을 미리보기로 노출한다. 진입 시 기본은 파트너 관점의 한국어 기준(`isKorean=true`)으로 노출한다.
- 미리보기는 실제 유저 웹 페이지를 그대로 보여주는 방식을 유지한다. (기존 스팟 인라인 미리보기 방식을 재사용한다.)
- 미리보기 영역 상단에 **언어 탭**을 둔다. 파트너가 특정 언어 탭을 선택하면, 미리보기가 **그 언어로 작성된 스팟 페이지**로 전환된다.
  - **공개 상태인 언어만 선택 가능**하다. **비공개 상태인 언어 탭도 노출하되, 비활성화(선택 불가)** 처리한다. (숨기지 않는다.)
  - 언어 탭 바로 하단에 안내 문구 **"현재 공개 상태인 언어만 선택 가능합니다. 언어 별 공개 여부는 관리자에게 문의해주세요."** 를 노출한다.

**5. 우측 · 스팟 편집 영역**

- 현재 스팟 수정 화면의 편집 기능을 **그대로 임베드**한다. 편집 영역 상단 드롭다운으로 편집 카테고리를 전환하는 형태를 유지하며, 카테고리는 아래 4개로 구성한다.
  - **기본 정보 수정**: 스팟 이름 · 이미지(메인 이미지 대표 지정·순서 변경 포함) · 주소 · 전화번호 · 위도 · 경도 · 수가표
  - **옵션 정보 수정**: 상품/옵션의 명칭 · 판매가 · 정가 · 정산가
  - **예약 기본 정보 수정**: 예약 날짜/시간 입력 필요 여부, 예약 가능 시간(현재 기준 N분 후부터 · 요일별 시간대 · 특별 기간 스케줄), 시간별 예약 제한
  - **예약 시간 관리**: 주차별 예약 시간(지난주/이번주/다음주 전환), 상품별 예약 시간(권한 보유 파트너에게만 노출)
- 각 카테고리의 세부 기능·정책은 기존 편집 화면을 그대로 따른다. (카테고리별 기능 개선은 배경 상단에 명시한 별도 티켓에서 다룬다.)
- 편집·저장 방식(즉시 반영 vs. 변경 요청 제출 후 관리자 승인)은 카테고리별 기존 정책을 유지한다.

### 백엔드 요구사항

- 스팟 선택 드롭다운은 파트너가 보유한 스팟 목록을 사용한다. 기본 선택을 위해 **가장 최근 생성된 스팟이 먼저 오도록** 정렬(생성일 내림차순)을 제공한다. (기존 파트너 스팟 조회 재사용, 정렬·기본값 요건 확인 — TBD)
- 편집 필드의 조회·저장은 기존 기능을 그대로 사용하며, 본 허브 개편으로 인한 신규 데이터 모델링은 없다. (카테고리별 기능 개선에 따른 백엔드 변경은 각 티켓에서 다룬다.)
- 미리보기 언어 탭의 활성/비활성 판별을 위해, 선택된 스팟의 **언어별 공개 여부**를 조회한다. 공개 상태인 언어는 선택 가능, 비공개 상태인 언어는 비활성 처리한다. (기존 스팟 언어별 공개 상태 데이터 재사용 여부 확인 — TBD)
