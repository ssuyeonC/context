# 세부 기획안 요구사항 문서

## 배경

### 문제 정의

파트너가 '내 스팟 관리'에서 스팟 정보를 편집할 때, 자신이 입력·수정하는 값이 실제 유저 페이지의 어느 영역에 어떻게 노출되는지 편집 화면만으로는 파악하기 어렵다.

- 파트너는 편집 중인 필드가 유저 페이지의 어느 위치에 반영되는지 예측하지 못해, 잘못된 값을 넣거나 의도와 다른 위치에 정보를 배치하는 경우가 생긴다.
- 이는 수정의 결과를 눈으로 확인하지 못한 채 요청하게 만들어, 반려·재요청과 관리자-파트너 간 확인 소통을 유발한다.

> 본 티켓은 '내 스팟 관리' 허브의 **좌우 2단(미리보기 : 편집) 레이아웃을 전제**로 한다. 허브 개편은 `[260714] partner-my-spot-management-hub.md`에서 다루며, 본 티켓은 그 위에 편집 필드와 미리보기 영역을 연동하는 하이라이트 기능을 얹는다.

### 가설적 임팩트

- 파트너가 편집 중인 필드가 유저 페이지의 어느 영역에 노출되는지 즉시 인지하게 되어, 잘못된 값·오배치로 인한 수정 요청과 그에 따른 반려·재요청이 줄어든다.
- 수정 결과를 눈으로 확인하며 편집할 수 있어, 관리자-파트너 간 확인 소통 부하가 감소한다.
- (정량 임팩트: 수정 요청 건당 반려율·재요청율 기준으로 산정 필요 — TBD)

## 구현

### 유저 플로우

- 파트너가 우측 편집 영역의 특정 필드에 **커서를 올리거나(포커스)** 값을 **수정**하면, 좌측 미리보기에서 그 값이 노출되는 영역이 강조 표시된다.
- 파트너가 해당 필드에서 벗어나면 강조 표시가 해제된다.
- 편집 값 자체가 미리보기에 실시간으로 반영되지는 않는다. (강조 표시만 이뤄진다.)
- 미리보기에 노출되지 않는 관리용 값 등 대응 영역이 없는 필드는 강조 없이 편집만 지원한다.

### 프론트엔드 요구사항

- 우측 편집 영역의 필드 **포커스(커서 진입) 또는 수정** 시, 좌측 미리보기에서 해당 필드가 노출되는 영역을 강조 표시한다. 포커스 해제 시 강조를 해제한다.
- 미리보기는 어드민과 다른 도메인의 실제 유저 페이지를 임베드한 형태이므로, 어드민 화면에서 미리보기 내부 영역을 직접 조작할 수 없다. 따라서 하이라이트는 **어드민 편집 영역이 미리보기 페이지로 메시지를 전달(postMessage)** 하고, **미리보기(유저 웹) 페이지가 해당 영역을 강조**하는 방식으로 구현한다.
  - 어드민 편집 영역: 필드 포커스/수정 시 대상 필드 식별자를 미리보기로 전달한다.
  - 유저 웹 미리보기 페이지: 전달받은 필드 식별자에 해당하는 영역에 강조 표시를 적용/해제한다.
- **편집 필드 ↔ 미리보기 영역 매핑 정의**가 필요하다. 어떤 편집 필드가 미리보기의 어느 영역에 대응되는지 목록을 확정한다. (매핑 대상 필드 목록 — TBD, 편집 영역 전체 필드 기준으로 정리)
- 편집 값 자체를 미리보기에 실시간 반영하지는 않는다. (하이라이트만 수행)

### 백엔드 요구사항

- 미리보기 하이라이트 연동은 어드민 편집 영역과 유저 웹 미리보기 페이지 간의 처리 사항으로, 별도 백엔드 변경은 없을 것으로 예상한다. (검토 후 확정 — TBD)
