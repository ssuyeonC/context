# 세부 기획안 요구사항 문서

## 배경

### 문제 정의

- 파트너 어드민의 예약 목록(대시보드 '오늘 방문 예약' / '승인 대기 예약' 테이블)과 예약 상세에서 예약 규모를 나타내는 **방문인원** 값이 실제 예약 상품 수와 다르게 노출되어 파트너가 방문 규모를 오해
- (사례) 셔틀버스 왕복 6석(결제 금액 96,000원) 예약이 대시보드·상세 모두 **방문인원 1명**으로 표시되어, 파트너가 실제 규모를 예약 상세의 상품 수량까지 확인해야 파악 가능 — 업체 혼선 발생 (2026-08-24 파트너 문의, 예약 코드 260823z3l8kb)
- 원인은 현행 방문인원이 '인원별 요구정보(개인별 입력값)'의 인원 그룹 수로 계산되며, 인원별 요구정보가 걸리지 않은 스팟의 예약은 무조건 1명으로 계산되는 구조 (기존 개선에서 상품 수량 합계 → 인원 그룹 수 기준으로 변경한 결과, 참고: 관련 PR #3611)
- 인원 그룹 수 기준 계산 자체는 '같은 고객이 여러 상품을 예약했을 때 상품 수량 합계가 인원처럼 부풀려 보이는 문제'를 막기 위한 것이라 유지 필요
- 다만 인원별 요구정보가 없는 예약에서는 실제 예약 규모(상품 수량)가 화면에서 사라지는 부작용

### 가설적 임팩트

- 예약 목록·상세에 실제 예약 상품 수량을 함께 노출하면, 파트너가 예약 상세 진입 없이 예약 규모를 즉시 파악 → 파트너 문의·혼선 감소
- 인원 그룹 수 기준 계산은 그대로 유지하므로, 다상품 단일 인원 예약의 인원 과대표시 방지 효과도 유지

## 구현

### 유저 플로우

- 파트너가 대시보드 '오늘 방문 예약' / '승인 대기 예약' 테이블을 조회하면, 각 예약 행에서 **예약인원**과 **예약 수량**을 각각 확인 가능
- 파트너가 예약 상세에 진입하면 주요 정보 영역에서 **예약인원**과 **예약 수량**을 각각 확인 가능
- 인원별 요구정보가 걸린 스팟의 예약은 **예약인원**에 입력된 인원 그룹 수 노출
- 인원별 요구정보가 걸리지 않은 스팟의 예약은 **예약인원** 1로 노출
- 상품이 여러 개이거나 수량이 여러 개인 예약은 **예약 수량**에 전체 상품 수량 합계 노출

### 프론트엔드 요구사항

**FR-1. 인원 항목 라벨 변경**

- 기존 **방문인원** 라벨을 **예약인원**으로 변경
- 대시보드 '오늘 방문 예약' 테이블, '승인 대기 예약' 테이블, 예약 상세 주요 정보 영역에 동일 적용

**FR-2. '예약 수량' 항목 신규 노출**

- **예약 수량** 항목 신규 추가, 값은 예약에 포함된 전체 상품 수량 합계
- 대시보드 두 테이블 + 예약 상세 모두 노출
- 테이블 헤더에서 **예약인원** / **예약 수량** 이 한눈에 구분되도록 가독성 확인 (두 라벨 모두 '예약'으로 시작하는 점 유의)

**FR-3. 값 표기 규칙**

- **예약인원**: 인원별 요구정보 인원 그룹 수 노출, 인원별 요구정보가 없으면 1로 노출
- **예약 수량**: 예약에 포함된 전체 상품 수량 합계 노출

### 백엔드 요구사항

**BR-1. 예약 수량(전체 상품 수량 합계) 조회 노출**

- 어드민 예약 목록·상세 조회 응답에 예약별 전체 상품 수량 합계 제공
- 예약 도메인에 전체 주문 수량 합계 값이 이미 존재하므로, 어드민 조회 스키마에 노출되어 있는지 확인 후 미노출 시 조회 필드 추가 (TBD: 노출 여부 확인)

**BR-2. 예약인원 계산 로직 유지**

- 인원별 요구정보 인원 그룹 수 기준 계산, 인원별 요구정보가 없으면 1을 반환하는 현행 로직 그대로 유지, 별도 변경 없음

## 비범위(Out of Scope)

- 인원별 요구정보가 없는 예약의 **예약인원**을 상품 수량으로 대체 노출하는 방식은 제외 — 같은 고객이 여러 상품을 예약했을 때 인원이 부풀려 보이는 문제(기존 개선이 해결한 문제)가 재발하므로 미채택
- 인원별 요구정보가 없는 예약의 **예약인원**을 '-' 또는 '미입력'으로 구분 노출하는 방식은 제외 — 현행 계산이 '요구정보 없음'과 '인원 1명'을 모두 1로 반환하여 구분하려면 백엔드 변경이 필요하므로, 이번 범위에서는 1로 통일
- 알림톡·파트너 액션 링크 화면의 인원 표기는 이번 범위 외 (기존 개선과 동일 스코프 유지)

## 검증 포인트

예약 형태별로 **예약인원** / **예약 수량** 이 아래와 같이 노출되는지 대시보드 테이블과 예약 상세 양쪽에서 교차 검증.

| 예약 형태 | 예약인원 | 예약 수량 |
|---|---|---|
| 인원별 요구정보 없음 · 셔틀 6석 (문의 건) | 1 | 6 |
| 인원별 요구정보 없음 · 상품 2개 각 1개씩 | 1 | 2 |
| 요구정보 걸림 · 1명이 상품 2개 예약 (인원 1) | 1 | 2 |
| 요구정보 걸림 · 인원 2 · 수량 2 | 2 | 2 |
| 요구정보 걸림 · 상품 2개 각 1·2개 · 인원 2 | 2 | 3 |

- 대시보드 두 테이블과 예약 상세 모두 동일 규칙으로 노출되는지
- '1명이 상품 2개' 예약이 **예약인원 1** 로 유지되어 인원 과대표시가 없는지
- 인원별 요구정보가 없는 예약이 **예약 수량**으로 실제 규모(예: 6)를 노출하는지
- (TBD) 인원 그룹 수가 전체 상품 수량보다 큰 예약(예: 수량 1 · 인원 2)이 실제 예약 화면에서 생성 가능한지 확인 필요 — 발생 시에도 **예약인원**·**예약 수량**을 각각 그대로 노출
