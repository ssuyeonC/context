# 파트너용 메일 템플릿 다국어 구조 정규화 요구사항

## 배경

### 문제 정의

파트너용 메일 템플릿은 현재 다음과 같은 한계를 가지고 있다.

- 같은 의미의 템플릿이 언어 수만큼 별도 항목으로 중복되어 있다. 예를 들어 한국어 제목이 "조건에 맞지 않는 인원수 (예약 불가)"인 템플릿은 한국어·중국어 번체·일본어·영어 각각 1개씩, 총 4개의 별개 항목으로 존재한다.
- 변경 요청 모달의 템플릿 드롭다운에 동일한 한국어 제목이 여러 번 나타날 수 있어, 파트너가 어떤 항목을 골라야 하는지 구분이 어렵다.
- 한 언어의 본문이 갱신되었을 때 다른 언어가 함께 갱신되었는지 확인할 수 있는 신호가 없어, 다국어 본문이 서로 어긋난 상태로 방치될 수 있다.
- 일부 의미의 템플릿(예: "예약 마감으로 인한 날짜/시간 변경 안내")은 한국어 본문이 비어 있는 채로 외국어 버전만 운영되고 있다.

### 가설적 임팩트

- 같은 의미의 템플릿이 1개 항목으로 통합되어, 파트너가 변경 요청 모달에서 동일 한국어 제목을 여러 번 마주치는 일이 사라진다.
- 파트너가 템플릿을 고르면 해당 예약의 예약자 언어로 작성된 본문이 자동으로 노출되어 파트너의 편의성이 확대된다.
- 다국어 본문이 별도 단위로 정리되어 신규 언어 추가가 단순한 항목 추가로 가능해진다.
- 다국어 갱신 시점이 어긋난 항목을 운영팀이 사전에 발견하여 보강할 수 있다.
- 한국어 본문이 비어 있는 항목이 식별 가능해져, 한국어 누락 항목을 우선 보강할 수 있다.

## 구현

### 유저 플로우

**템플릿 데이터 모델**

- 파트너용 메일 템플릿은 다음 두 단위로 관리된다.
  - 마스터 템플릿: 한 의미를 대표하는 단위. 한국어 제목과 작성 정보(작성자·작성일 등) 같은 기본 정보만 가진다.
  - 언어별 번역: 마스터 템플릿 1개에 대해 모든 언어의 번역이 매달린다. 각 번역은 해당 언어의 제목과 본문을 가진다.
- 각 마스터 템플릿은 지원 언어 전체의 번역이 모두 채워진 상태로 운영된다.

**파트너 어드민 변경 요청 모달에서의 노출**

- 파트너가 변경 요청 모달을 열면, 세부 템플릿 드롭다운에는 마스터 템플릿별로 1개의 옵션이 한국어 제목으로 노출된다.
- 파트너가 옵션 1개를 선택하면, 해당 예약의 예약자 언어로 작성된 번역이 제목·본문 영역에 자동으로 채워진다.

**알림톡 링크 진입 별도 페이지에서의 노출**

- 파트너가 알림톡에서 '예약 변경 요청' 링크를 눌러 진입하는 별도 페이지에서도 동일하게 동작한다.
- 세부 템플릿 드롭다운에는 마스터 템플릿별로 1개의 옵션이 한국어 제목으로 노출된다.
- 파트너가 옵션 1개를 선택하면, 해당 예약의 예약자 언어로 작성된 번역이 제목·본문 영역에 자동으로 채워진다.

**다국어 정합성 점검**

- 운영팀은 다국어 번역이 서로 어긋날 가능성이 있는 마스터 템플릿 목록을 주기적으로 확인할 수 있다.
- 점검 대상으로 식별되는 조건은 다음과 같다.
  - 같은 마스터 템플릿의 번역들 중 가장 최근 갱신과 가장 오래된 갱신 사이의 시간차가 24시간 이상인 경우.
  - 지원 언어 중 1개라도 번역이 비어 있는 경우.
- 점검 대상으로 식별된 목록은 운영팀이 조회할 수 있는 형태로 노출한다. 발견 즉시 운영팀에 자동으로 알리는 동작은 본 티켓 범위 외.

### 프론트엔드 요구사항

**FR-1. 변경 요청 모달 세부 템플릿 드롭다운 — 마스터 단위 노출**

- 드롭다운 옵션은 마스터 템플릿 단위로 구성
- 옵션 라벨은 마스터 템플릿의 한국어 제목을 그대로 사용

**FR-2. 본문 자동 렌더 — 예약자 언어 기준**

- 파트너가 마스터 템플릿을 선택하면, 해당 예약의 예약자 언어에 해당하는 번역이 제목·본문 영역에 자동으로 채움
- 채워진 본문·제목은 그 자리에서 수정 불가

**FR-3. 알림톡 링크 진입 별도 페이지 — 모달과 동일 동작**

- FR-1·FR-2의 동작이 알림톡 링크 진입 별도 페이지에서도 동일하게 적용된다.
- 어드민 모달과 알림톡 링크 진입 별도 페이지는 같은 마스터 템플릿 목록·기본 선택값·언어 매칭 결과를 보인다.

### 백엔드 요구사항

**BR-1. 기존 템플릿 데이터의 마스터 통합**

- 같은 한국어 제목을 가진 파트너용 메일 템플릿 항목들을 1개의 마스터 템플릿으로 통합한다.
- 통합 대상 그룹 내에서는 가장 먼저 만들어진 항목을 마스터로 삼고, 나머지 항목에 연결되어 있던 언어별 번역을 마스터로 옮긴 뒤 잉여 항목을 제거한다.
- 통합 작업은 부분 적용을 방지하기 위해 한 번에 처리한다.
- 본 작업의 대상은 파트너용 메일 템플릿으로 한정한다. 다른 종류의 메일 템플릿은 손대지 않는다.

**BR-2. 마스터 정보의 단순화**

- 통합 이후 마스터 항목은 한국어 제목과 작성 정보만을 가지며, 언어·본문 정보는 가지지 않는다.
- 기존에 마스터 항목이 직접 들고 있던 언어·본문 필드는 더 이상 사용하지 않는다. 이 필드의 물리적 제거는 본 티켓 이후 후속 작업으로 한다.

**BR-3. 파트너 가시 템플릿 조회 응답 정비**

- 파트너 가시 템플릿 조회 흐름이 마스터 단위로 응답을 구성하도록 정비한다. 동일한 한국어 제목이 응답에 여러 번 포함되지 않는다.
- 응답에는 마스터의 한국어 제목과 함께, 클라이언트가 예약자 언어에 맞는 번역을 사용할 수 있도록 지원 언어별 번역(제목·본문)이 포함된다.

**BR-4. 변경 요청 메일 발송 — 마스터와 예약자 언어 기반**

- 변경 요청 메일 발송 흐름은 마스터와 예약자 언어로 번역 본문을 찾아 발송한다.
- 어드민에서 사용하는 발송 인터페이스는 본 티켓에서 변경하지 않는다. 내부 조회 로직만 새 데이터 모델에 맞춰 정비한다.

**BR-5. 다국어 정합성 점검 목록 제공**

- 같은 마스터의 번역들이 다음 중 하나에 해당하면 정합성 점검 필요 목록에 포함한다.
  - 번역들 사이의 갱신 시점 차이가 24시간 이상인 경우.
  - 지원 언어 중 1개라도 번역이 비어 있는 경우.
- 점검 필요 목록은 운영팀이 조회할 수 있는 형태로 제공한다. 능동적 통지(알림·푸시 등)는 본 티켓 범위 외.

**BR-6. 작업 이후 검증**

- 마스터 통합 직후 다음을 확인한다.
  - 파트너용 마스터 항목 수가 한국어 제목 종류 수와 일치하는가.
  - 모든 언어별 번역이 유효한 마스터에 연결되어 있는가.
  - 작업 전후로 변경 요청 발송 본문이 동일하게 생성되는가 (예약자 언어가 비한국어인 케이스를 언어 표본별로 확인).
- 한국어 번역이 비어 있는 마스터 목록을 별도로 출력하여 운영팀이 우선 보강할 수 있도록 한다.
