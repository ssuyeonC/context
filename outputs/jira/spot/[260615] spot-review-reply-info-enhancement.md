# 세부 기획안 요구사항 문서

## 배경

### 문제 정의

리뷰 답글 작성 화면(어드민 스팟 리뷰 상세 모달)에서 답변을 작성할 때, 답변에 필요한 맥락 정보가 충분히 노출되지 않아 담당자가 별도 조회 업무를 반복하고 있다.

- **예약 정보 확인 불가**: 현재 답글 작성 화면에서는 리뷰 ID, 작성자, 작성자 이메일, 스팟명, 번역된 리뷰 내용만 확인할 수 있다. 답변 작성 및 파트너사 문의 대응에 필요한 예약번호·예약자명·예약일/방문일은 화면에서 확인할 수 없다. 그래서 담당자는 작성자 이메일을 복사해 예약관리 페이지에서 다시 검색한 뒤 예약 정보를 대조하고 있다.
  - 참고: 리뷰 데이터에는 이미 연결된 예약 정보가 존재한다. 즉 데이터는 있으나 화면에 노출되지 않는 상태다.
- **원문 언어 확인 불가**: 현재 화면은 번역된 리뷰 위주로 보여주며, 고객이 실제로 어떤 언어로 리뷰를 작성했는지 한눈에 알기 어렵다. 원문 언어를 확인하려면 별도 예약 페이지에서 다시 조회해야 한다.
  - 참고: 리뷰 데이터에는 원문 언어 정보가 이미 저장되어 있다.
- **자동 번역 버튼의 동작 의도 불명확**: 답글 작성 영역 하단에 **"자동 번역"** 버튼이 노출되어 있으나, 담당자 입장에서는 무엇을 번역하는 기능인지 직관적으로 알기 어렵고 "작동하지 않는다"고 인식되고 있다. 사용 의도가 모호한 UI가 노출되어 혼선을 준다.
  - 참고: 현재 이 버튼은 동작이 연결되어 있으며, **담당자가 입력한 답글 텍스트를 리뷰 언어로 번역해 답글 입력란에 채워 넣는** 기능이다. 기능 자체는 살아 있으나, 버튼 명칭·위치·노출 시점이 의도를 충분히 전달하지 못하고 있다.

### 가설적 임팩트

- 리뷰 답변 작성 시 예약 조회를 위한 페이지 이동·재검색이 사라져 답변 1건당 처리 시간이 단축된다.
- 예약 정보 대조를 위한 별도 조회 업무가 감소한다.
- 고객이 작성한 원문 언어를 즉시 확인할 수 있어, 언어에 맞는 답변 작성과 파트너사 문의 대응 효율이 향상된다.
- 사용 의도가 불명확한 UI를 정리해 화면 혼선을 줄인다.
- (정량 임팩트: 구체 수치는 운영팀 평균 답변 처리 건수·소요 시간 기준으로 산정 필요 — TBD)

## 구현

### 유저 플로우

- 담당자는 리뷰 답글 작성 화면을 열면, 해당 리뷰에 연결된 예약번호·예약자명·예약일(또는 방문일)을 별도 조회 없이 화면에서 바로 확인할 수 있다.
- 담당자는 같은 화면에서 고객이 실제로 작성한 **원문 언어**(예: English, Japanese, Traditional Chinese)를 확인할 수 있다.
- 리뷰에 연결된 예약 정보가 없는 경우, 담당자는 예약 정보 영역에서 정보가 없음을 명확히 인지할 수 있다(빈 값이 아닌 안내 표기).
- 담당자는 답글을 작성한 뒤, 자동 번역 기능을 통해 작성한 답글이 고객 언어로 어떻게 번역되는지 확인할 수 있다. (자동 번역 기능의 처리 방향은 아래 '자동 번역 기능 정리'의 결정에 따른다.)

### 프론트엔드 요구사항

#### 1. 예약 정보 노출

- 리뷰 답글 작성 화면(스팟 리뷰 상세 모달) 내에 예약 정보 영역을 추가하고, 아래 항목을 노출한다.
  - **예약번호**
  - **예약자명**
  - **예약일** 또는 **방문일** (둘 중 어느 기준으로 노출할지 운영팀과 확정 — 예약일은 결제·예약 시점, 방문일은 실제 이용일. 우선 노출 기준 결정 필요: TBD)
- 리뷰에 연결된 예약이 없을 경우, 빈 값 대신 **"연결된 예약 정보가 없습니다"** 와 같은 안내 문구를 노출한다. (최종 카피: TBD)
- (선택) 예약번호 클릭 시 예약관리 상세로 이동할 수 있게 할지 여부 검토 — 담당자 동선 단축에 유용하나 범위 확장이므로 별도 결정. (TBD)

#### 2. 원문 언어 노출

- 화면 내에 고객이 실제 작성한 **원문 언어**를 명시적으로 표시한다.
  - 표기 예시: **"원문 언어 : English"**, **"원문 언어 : Japanese"**, **"원문 언어 : Traditional Chinese"**
- 원문 언어는 번역되어 보여지는 내용의 언어와 구분되도록, 라벨을 분리해 노출한다.

#### 3. 자동 번역 기능 정리

- 현재 **"자동 번역"** 버튼은 담당자가 작성한 답글을 리뷰 언어로 번역해 입력란에 채우는 동작을 한다. 이 동작 의도를 운영팀과 확정한 뒤 아래 중 하나로 정리한다.
  - (안 A) **버튼 유지·명확화**: 기능을 유지하되, 버튼 명칭·위치·도움말을 보강해 "작성한 답글을 고객 언어로 번역" 의도가 드러나도록 개선한다. 번역 결과를 입력란에 바로 덮어쓰지 않고, **미리보기로 확인 후 적용**하는 흐름으로 개선하는 것을 권장한다.
  - (안 B) **버튼 삭제**: 운영상 사용되지 않는다고 판단되면 버튼을 제거해 화면 혼선을 줄인다.
- 권장: 답글 작성 후 고객 언어 기준 번역 결과를 미리 확인할 수 있는 **'번역 미리보기'** 형태로 개선(안 A). 최종 방향은 운영팀 결정 사항. (결정: TBD)

### 백엔드 요구사항

- 예약 정보 노출을 위한 데이터는 이미 존재한다(리뷰 ↔ 예약 연결 관계 존재). 추가 데이터 모델링 없이, 리뷰 답글 화면이 사용하는 리뷰 조회에서 연결된 예약의 **예약번호·예약자명·예약일·방문일** 필드를 함께 반환하도록 조회 범위를 확장한다.
- 원문 언어 정보 역시 리뷰 데이터에 이미 저장되어 있다(원문 언어 필드 보유). 리뷰 조회 시 원문 언어 값을 함께 반환하도록 노출한다.
- 연결된 예약이 없는 리뷰의 경우, 예약 정보는 빈 값(없음)으로 정상 반환되어야 하며 오류가 발생하지 않아야 한다.
- 자동 번역 기능을 안 A(미리보기)로 정리할 경우, 기존 번역 처리 로직을 재사용한다(신규 번역 백엔드 작업 불필요로 예상). 안 B(삭제)일 경우 백엔드 변경 없음.
