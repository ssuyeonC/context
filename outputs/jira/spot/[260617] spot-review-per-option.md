# 세부 기획안 요구사항 문서

## 배경

### 문제 정의

현재 예약과 연결된 리뷰는 '예약건' 단위로만 작성할 수 있다. 하나의 예약에 여러 옵션(상품)이 포함되어 있어도, 유저가 남길 수 있는 리뷰는 예약 전체에 대한 한 건뿐이다.

이로 인해 다음 문제가 발생한다.

- 유저가 특정 옵션(상품)에 대해서만 평가를 남기고 싶어도, 예약 전체에 대한 하나의 리뷰로 뭉뚱그려 작성해야 한다.
- 같은 예약에서 옵션마다 만족도가 달랐던 경우, 그 차이를 리뷰에 분리해 담을 수 없다.
- 상품을 탐색하는 다른 유저는 '이 옵션(상품) 자체'에 대한 후기를 따로 확인할 수 없어, 옵션 선택에 참고할 정보가 부족하다.

### 가설적 임팩트

- 옵션(상품) 단위 리뷰가 쌓이면, 상품을 탐색하는 유저에게 더 구체적이고 신뢰도 높은 후기 정보를 제공할 수 있어 상품 전환에 긍정적으로 작용할 것으로 본다.
- 기존 대비 더 많은 리뷰를 확보할 수 있다.
- 리뷰가 옵션 단위로 분리되면, 후기의 정보 밀도가 높아지고 상품별 만족도 파악이 용이해진다.

## 구현

### 유저 플로우

리뷰 작성 '기회'는 예약당 1회로 유지하되, 그 한 번의 작성에서 생성되는 리뷰의 '수'를 1개에서 N개까지 확장한다.

**옵션 선택 영역 노출 조건**

- 유저의 구매건에 2개 이상의 상품 혹은 옵션이 선택되어 있는 경우에만, 리뷰 작성 시 옵션 선택 영역이 노출된다.
- 구매건에 상품/옵션이 1개뿐인 경우에는 옵션 선택 영역을 노출하지 않으며, 기존과 동일하게 단일 리뷰 작성 영역만 제공한다.

**리뷰 작성 기회·보상 (기존 정책 유지)**

- 예약을 사용 완료한 유저는 해당 예약에 대해 리뷰를 1회 작성할 수 있다.
- 한 번의 작성에서 리뷰를 몇 개 생성하든, 그 예약에 대한 작성 기회는 1회로 소진된다.
- 작성을 완료하면 해당 예약은 '리뷰 작성 완료' 상태가 되어, 이후 추가 작성이 불가능하다.
- 리뷰 작성 보상(포인트)은 작성한 리뷰 수와 무관하게 예약당 1회만 지급된다.

**옵션 미선택 — 스팟에 대한 리뷰 (기존과 동일)**

- 리뷰 작성 화면에서 유저는 옵션 선택 영역을 본다. 이 영역은 기본적으로 미선택 상태다.
- 유저가 옵션을 선택하지 않고 작성하면, 스팟(예약한 장소)에 대한 리뷰 1개가 생성된다.
- 이 경우의 동작과 결과는 기존 리뷰 작성과 완전히 동일하다.

**옵션 선택 — 상품(옵션)에 대한 리뷰**

- 유저가 옵션을 1개 이상 선택하면, 선택한 옵션마다 별도의 리뷰 작성 영역이 나타난다.
- 별점은 예약 단위로 1회만 입력한다. 옵션별로 별점을 따로 매기지 않으며, 옵션이 선택되어 작성된 각 리뷰는 예약 단위로 입력된 별점 값을 그대로 승계한다.
  - 옵션마다 별점을 받으면 유저 입력이 번거로워지고, 리뷰를 민감하게 관리하는 파트너 입장에서도 관리 부담이 커지므로 예약 단위 별점을 승계하는 방식을 택한다.
- 유저는 선택한 옵션별로 내용, 사진을 각각 입력한다.
- 선택한 옵션의 내용(본문)은 모두 채워야 제출할 수 있다. 하나라도 본문이 비어 있으면 제출되지 않는다. (사진은 선택 입력)
- 작성을 완료하면, 선택한 옵션 수만큼의 리뷰가 한 번에 생성된다.
- 옵션에 연결된 각 리뷰는 해당 상품(옵션)에 대한 개별 리뷰로 취급되어, 상품 단위로 노출·조회된다.
- 선택할 수 있는 옵션은 해당 예약에 포함된 옵션으로 한정된다.

**상호 배타 규칙**

- 옵션 미선택(스팟에 대한 리뷰)과 옵션 선택(상품에 대한 리뷰)은 상호 배타적이다.
- 한 번의 작성에서 스팟 리뷰와 상품 리뷰를 동시에 생성할 수 없다. 옵션을 하나라도 선택하면 그 작성은 옵션(상품) 리뷰로만 구성된다.

**예외 케이스**

- 같은 옵션을 중복으로 선택해 리뷰를 작성할 수 없다.

### 프론트엔드 요구사항

**와이어프레임**

- 옵션 선택 영역의 위치, 옵션별 작성 영역의 화면 구성은 디자인 확정 필요. (TBD)

- 리뷰 작성 화면에 옵션 선택 영역을 추가하되, 유저의 구매건에 2개 이상의 상품 혹은 옵션이 선택되어 있는 경우에만 노출한다. 진입 시 기본값은 미선택이다.
- 구매건에 상품/옵션이 1개뿐인 경우에는 옵션 선택 영역을 노출하지 않고 기존과 동일한 단일 리뷰 작성 화면을 제공한다.
- 옵션을 선택하지 않은 상태에서는 기존과 동일하게 단일 리뷰 작성 영역(내용·별점·사진)을 제공한다.
- 별점은 옵션별 작성 영역과 분리된 공통 영역에서 예약 단위로 1회만 입력받는다. 옵션을 여러 개 선택해도 별점 입력은 1개다.
- 유저가 옵션을 선택하면, 선택한 옵션 수만큼 리뷰 작성 영역을 노출한다. 각 영역은 해당 옵션이 무엇인지 식별할 수 있도록 옵션명을 함께 보여주며, 내용·사진을 옵션별로 독립 입력받는다. (별점은 옵션별 영역에 포함하지 않는다.)
- 옵션 선택을 해제하면 해당 옵션의 작성 영역도 함께 사라진다.
- 선택한 옵션의 본문이 하나라도 비어 있으면 제출 버튼을 비활성화하거나 제출을 막는다. (사진은 선택 입력)
- 제출 시, 작성된 1~N개의 리뷰를 한 번의 요청으로 함께 저장한다. 일부만 저장되고 일부는 누락되는 상황이 발생하지 않도록 한다.
- 옵션(상품)에 연결된 리뷰는 상품 단위 영역(상품 상세·옵션 후기 등)에서 확인할 수 있도록 노출한다.

**리뷰 노출 규칙 (리뷰에 어떤 옵션을 표시할지)**

- 옵션 미선택 리뷰: 유저가 예약 생성 시 선택했던 모든 옵션을 노출한다.
  - 유저가 예약 생성 시 1개의 옵션만 선택했을 경우는 리뷰 작성 화면에서 옵션 선택 UI가 노출되지 않으므로 '미선택' 케이스로 분류되며, 작성된 리뷰에는 해당 옵션 1개만 노출된다.
- 옵션 선택 리뷰: 유저가 리뷰 작성 시 선택한 옵션을 노출한다.
  - 유저가 리뷰 작성 시 옵션을 n개 선택하여 리뷰를 작성하더라도 각 옵션마다 리뷰가 생성되므로, 리뷰 1건에는 항상 1개의 옵션만 표시된다.
- 옵션명 노출: 스팟 상세 페이지의 리뷰 목록에서는 옵션명이 정상적으로 표기된다. 옵션명 캐시(`totalReservableItem`)가 스팟 상세의 예약 옵션 선택 위젯(`SpotDetailSelectableOptionItems`)에서 채워지는데, 이 위젯은 예약자/탐색 유저 구분 없이 스팟 상세에 진입한 모든 방문자에게 로드되므로 탐색 유저에게도 옵션명이 조회된다. 이번에 옵션 리뷰(`rootSpotItemCode`가 채워진 리뷰)가 생겨도 동일 경로로 옵션명이 노출된다.
- (주의) 단, 위 옵션명은 스팟 상세의 예약 위젯이 로드되어야 채워지는 캐시에 의존한다. 예약 위젯이 없는 다른 노출 위치(예: 별도 리뷰 모달·마이페이지 리뷰 목록 등)에서 옵션 리뷰를 보여줄 경우 옵션명이 빈 값이 될 수 있으므로, 그런 위치가 추가된다면 옵션명 조회 소스를 별도 점검한다.
- (스코프 외) 옵션 선택으로 생성된 리뷰도 일반 리뷰로 취급되어 스팟 평점·리뷰 수 집계에는 반영되지만, 유저 페이지 리뷰 영역에 '옵션별 리뷰 평점'을 별도 UI로 노출할지는 이번 범위에서 다루지 않는다.

### 백엔드 요구사항

- 한 번의 리뷰 작성 요청으로 1개에서 N개의 리뷰를 한 번에 생성할 수 있도록 지원한다. 이 생성은 전체가 함께 성공하거나 함께 실패하도록 처리한다.
- 리뷰 작성 기회 검증(예약당 1회), '리뷰 작성 완료' 처리, 포인트 지급은 한 번의 요청 단위로 1회만 수행한다. 생성되는 리뷰 수가 늘어도 이 정책은 변하지 않는다.
- 리뷰를 특정 옵션(상품)에 연결하는 정보는 기존 리뷰 데이터 구조에 이미 존재하는 항목을 활용한다. `spot_review` 테이블의 `root_option_code` 컬럼(엔티티 필드 `rootSpotItemCode`)이 2025-04-22 마이그레이션으로 이미 추가되어 있으므로, 별도의 데이터베이스 구조 변경(마이그레이션)은 필요하지 않다.
- 백엔드 리뷰 작성 API(`ReservationReviewCreateArgs` → `createSpotReview`)는 `rootSpotItemCode`를 입력으로 받아 저장하도록 이미 구현되어 있다. 다만 현재는 프론트엔드 작성 화면이 이 값을 채워 보내지 않아 기존 리뷰의 `rootSpotItemCode`는 사실상 모두 비어 있으며(null), 그 결과 모든 리뷰가 '옵션 식별자 없음' 상태로 예약에서 선택한 옵션 전체를 표시용으로 노출하고 있다. 이번 작업에서 작성 화면이 선택된 옵션의 `rootSpotItemCode`를 채워 보내고, 한 요청으로 옵션 수만큼 N개 리뷰를 일괄 생성하도록 한다.
- 별점은 요청당 1개(예약 단위)만 전달받으며, 생성되는 모든 리뷰(옵션 수만큼)가 그 별점 값을 승계하여 저장한다. 내용·사진은 옵션별로 다르게 저장한다.

- 데이터 구조는 다음을 따른다.
  - 별점: 예약 단위로 입력된 값이 원천이며, 옵션이 선택되어 생성된 각 리뷰는 이 값을 승계한다.
  - 내용(본문)·사진: 옵션별로 개별 저장한다.
- 옵션 선택 여부는 별도의 플래그(예: `선택했음 true/false`)를 새로 두지 않고, **리뷰에 연결된 옵션 식별자의 유무로 판별**한다.
  - 옵션 식별자 없음(null) → 스팟(예약한 장소)에 대한 리뷰
  - 옵션 식별자 있음 → 해당 상품(옵션)에 대한 리뷰
- 위 판별 방식은 '옵션 연결 정보는 기존 데이터 구조의 기존 항목을 활용'하는 원칙과 일치하며, 옵션 선택 여부 저장을 위한 별도 마이그레이션이 필요하지 않다.
- (참고) 옵션이 있는 예약에서 유저가 옵션 미선택으로 작성한 스팟 리뷰와, 애초에 옵션이 1개뿐이라 선택지가 없던 스팟 리뷰는 둘 다 '옵션 식별자 없음'으로 동일하게 저장된다. 이 둘을 구분할 필요가 생기면 예약 구성(옵션 수)으로 역산한다.
- 다음 조건을 검증한다.
  - 선택한 옵션은 모두 해당 예약에 실제로 포함된 옵션이어야 한다.
  - 한 번의 작성에서 같은 옵션이 중복으로 들어올 수 없다.
  - 옵션이 지정된 리뷰(상품 리뷰)와 옵션이 없는 리뷰(스팟 리뷰)가 한 요청에 섞여 들어올 수 없다.
  - 생성되는 각 리뷰의 내용(본문)은 비어 있을 수 없다. (기존 단건 작성과 동일한 본문 필수 검증을 옵션 수만큼 각 리뷰에 적용)
- 이미지 개수 제한(리뷰당 최대 3장)은 기존과 동일하게 각 리뷰 단위로 적용한다. 옵션을 N개 선택하면 옵션별 리뷰마다 최대 3장씩 첨부할 수 있다.
- 옵션(상품) 단위로 리뷰를 조회·노출할 때, 해당 옵션에 직접 연결된 리뷰를 정확히 반환하도록 한다.
- 여러 리뷰가 한 번에 생성된 경우에도, 스팟의 별점·리뷰 수 집계에 생성된 리뷰가 모두 반영되도록 한다. 옵션별로 생성된 리뷰는 각각 개별 리뷰로 취급되어 집계에 그대로 반영된다. (예: 한 유저가 5점으로 3개 옵션의 본문을 작성하면 5점짜리 리뷰 3건이 추가되며, 스팟 평점·리뷰 수 집계에도 3건으로 반영된다.)
- 파트너의 리뷰 답글은 개별 리뷰 단위로 동작한다. 옵션 선택으로 함께 생성된 리뷰라도, 그 중 한 리뷰에 답글을 달았을 때 같은 작성에서 생성된 다른 리뷰에는 답글이 달리지 않는다.
- 기존에 쌓인 리뷰(현재 모두 옵션 미선택 상태)는 그대로 유지하며, 옵션 연결을 소급 적용(backfill)하지 않는다.
- 유저용 스팟 리뷰 수정 기능은 현재 유저 화면에 존재하지 않으므로(백엔드 `updateSpotReview`/`deleteSpotReview` mutation은 있으나 어드민 패널에서만 사용), 옵션 단위 리뷰의 유저 수정·삭제는 이번 스코프에서 다루지 않는다.
