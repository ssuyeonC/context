# 세부 기획안 요구사항 문서

## 배경

### 문제 정의

현재 어드민에서 스팟에 연결할 수 있는 '상세지역'은 1개로 제한되어 있다. 화면상으로 단일 선택만 허용하고 있어, 관리자는 한 스팟에 2개 이상의 상세지역을 연결할 수 없다.

그러나 실제 운영에서는 한 스팟이 두 개의 상세지역에 동시에 속하는 것으로 인지되는 경우가 있다. 예를 들어 두 지역의 경계에 위치하거나, 사용자에 따라 서로 다른 지역명으로 검색·인지되는 스팟이 이에 해당한다. 이런 스팟은 현재 하나의 상세지역으로만 연결되어 있어, 다른 지역명으로 검색하는 사용자에게는 검색 결과로 노출되지 않는다.

정리하면 다음 두 가지가 충족되지 않고 있다.

- 한 스팟을 2개의 상세지역에 연결할 수 없다. (어드민 입력 제약)
- 스팟이 속한 두 지역 중 어느 쪽으로 검색하든 검색 결과에 노출되도록 만들 수 없다. (검색 노출 한계)

참고로 데이터 구조상으로는 스팟과 상세지역의 연결이 다대다(복수 연결 가능)로 설계되어 있어, 2개 이상의 상세지역을 저장하는 것 자체는 가능하다. 다만 어느 지역을 대표(첫번째)로 볼지에 대한 **순서값이 없고**, 어드민·검색·노출 화면이 모두 단일 상세지역을 전제로 동작하고 있다. 즉 본 기획은 새로운 저장 구조를 만드는 것이 아니라, **순서 개념을 추가하고 복수 상세지역을 입력·노출·검색에 반영**하는 작업이다.

### 가설적 임팩트

- 두 지역 경계에 있는 스팟이 양쪽 지역 검색 결과에 모두 노출되어, 지역 기반 검색에서의 스팟 발견율(검색 노출 수)이 증가한다.
- 사용자가 검색한 지역명과 카드에 표시되는 지역명이 일치하게 되어, 검색 결과의 맥락 일치도가 높아지고 클릭 전환에 기여한다.
- 정량 지표(대상 스팟 수, 복수 지역 연결 시 추가 노출량, 검색 전환율 변화)는 `TBD` — 운영상 복수 지역 연결이 필요한 스팟 규모 집계 후 산정.

## 구현

### 유저 플로우

- 관리자는 스팟의 상세지역을 최대 2개까지 연결할 수 있다.
- 관리자는 상세지역을 1개만 연결할 수도 있다. (기존과 동일하게 동작)
- 관리자는 연결한 상세지역의 순서를 지정할 수 있다. (첫번째 / 두번째)
- 관리자는 이미 2개의 상세지역이 연결된 상태에서 추가로 연결을 시도하면, 더 연결할 수 없다는 안내를 본다.
- 사용자는 스팟 리스트 페이지의 스팟 카드에서 **{도시} {첫번째 상세지역}** 을 본다.
- 사용자는 지역으로 검색하지 않은 채 검색 결과에 노출된 스팟 카드에서 **{도시} {첫번째 상세지역}** 을 본다.
- 사용자는 특정 지역으로 검색하여 노출된 스팟 카드에서 **{도시} {검색한 지역에 해당하는 상세지역}** 을 본다. (첫번째 상세지역이 아니라, 검색 키워드와 일치하는 상세지역을 표시)
- 사용자는 스팟 리스트(행 형태)에서 **{도시명} {첫번째 상세지역} & {두번째 상세지역}** 을 본다.
- 사용자는 스팟 리스트에서 각 상세지역 텍스트를 클릭하여 해당 지역으로 이동할 수 있다. (도시명에는 링크가 걸리지 않는다)

### 프론트엔드 요구사항

**어드민 — 상세지역 입력**

- 스팟 상세지역 입력을 단일 선택에서 복수 선택으로 변경한다. 최대 2개까지 선택할 수 있다.
- 선택한 상세지역의 순서를 지정할 수 있도록 한다. 첫번째로 지정된 지역이 사용자 화면의 기본 노출 지역이 된다.
- 2개가 이미 선택된 상태에서는 추가 선택을 막고, 안내 문구를 노출한다. **"상세지역은 최대 2개까지 연결할 수 있어요."** (문구 확정 `TBD`)
- 1개만 연결한 스팟은 기존과 동일하게 동작한다. (순서 개념이 적용되더라도 단일 지역이 곧 첫번째 지역)

**스팟 카드 — 리스트 페이지**

- 스팟 카드의 위치 텍스트는 **{도시} {첫번째 상세지역}** 으로 표시한다.
- 상세지역이 2개여도 첫번째 상세지역만 노출한다.

**스팟 카드 — 검색 결과 페이지**

- 지역으로 검색되지 않은 상태에서 노출된 스팟 카드는 **{도시} {첫번째 상세지역}** 으로 표시한다.
- 특정 지역으로 검색되어 노출된 스팟 카드는 **{도시} {검색한 지역에 해당하는 상세지역}** 으로 표시한다.
  - 검색한 지역이 스팟의 두번째 상세지역인 경우, 카드에는 두번째 상세지역이 노출되어야 한다.
  - 검색한 지역이 스팟의 상세지역과 일치하지 않는 경우(지역 검색이 아닌 일반 검색으로 노출된 경우)에는 첫번째 상세지역을 노출한다.

**스팟 리스트 — 행(row) 형태**

- 위치 텍스트를 **{도시명} {첫번째 상세지역} & {두번째 상세지역}** 형태로 표시한다. (상세지역이 1개면 첫번째 상세지역만 표시)
- 하이퍼링크는 각 상세지역 텍스트에만 건다. 각 상세지역은 해당 지역 화면으로 이동한다.
- 도시명에는 링크를 걸지 않는다. (현재는 도시명과 상세지역을 묶어 하나의 링크로 처리하고 있으므로, 도시명과 상세지역을 분리하고 각 상세지역만 개별 링크로 변경)

### 백엔드 요구사항

**상세지역 연결 구조 — 순서값 추가**

- 스팟과 상세지역의 연결에 순서(우선순위) 값을 저장할 수 있도록 한다.
- 한 스팟에 연결되는 상세지역은 최대 2개로 제한한다. (3개 이상 연결 시도는 막는다)
- 연결된 상세지역을 조회할 때 순서값 기준으로 정렬하여 반환한다. 첫번째 순서의 상세지역이 기본 노출 지역이 된다.
- 기존에 1개만 연결된 스팟은 별도 마이그레이션 없이 단일 지역이 첫번째 지역으로 동작하도록 한다.

**검색 — 복수 지역 색인 및 매칭 지역 반환**

- 스팟의 상세지역을 검색 색인에 **배열(연결된 모든 상세지역)** 로 반영하여, 두 지역 중 어느 쪽으로 검색해도 동일 스팟이 검색 결과에 노출되도록 한다.
- 지역으로 검색된 경우, 검색에 사용된 지역과 스팟이 가진 상세지역을 대조하여 **검색 키워드에 해당하는 상세지역**을 검색 결과에 식별 가능한 형태로 반환한다. (스팟 카드가 매칭된 지역을 표시할 수 있도록)
  - 현재 검색 결과는 스팟별 대표 상세지역 1개만 반환하고, 어느 지역으로 매칭됐는지 정보를 담고 있지 않다. 따라서 검색 결과 응답에 스팟의 상세지역 정보(또는 매칭된 지역)를 포함하도록 확장이 필요하다.
- 지역으로 검색되지 않은 경우에는 첫번째 상세지역이 대표로 반환되도록 한다.

**노출용 조회 — 순서 보장**

- 스팟 상세·카드·리스트 노출에 사용되는 상세지역 조회 시, 순서값 기준 정렬을 적용하여 첫번째/두번째 상세지역이 일관되게 결정되도록 한다.

**확인 필요 항목 (`TBD`)**

- 검색 색인을 생성·갱신하는 색인 구성에서 스팟의 상세지역을 배열로 담는지, 대표 1개만 담는지 확인 후 배열 색인으로 보정 필요.
- 검색 진입 시 '지역으로 검색됨' 여부와 검색에 사용된 지역 식별자가 검색 맥락에 보존되는지 확인 필요. (스팟 카드가 매칭 지역을 표시하기 위한 전제)
