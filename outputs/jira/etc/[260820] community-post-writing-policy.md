# 세부 기획안 요구사항 문서

## 배경

### 문제 정의

커뮤니티(/board)는 본인의 여행 계획(플랜)을 첨부해 공유·질문하는 단문 중심 게시판으로, 유저가 특정 언어로 원문을 작성하면 전 언어로 자동 번역되어 노출되는 구조

- 최근 일부 유저가 플랜 첨부 기능을 사용하면서 본문에 초장문(한자 980~1,322자)의 시술 후기성 글을 게시 → 피드에서 벽 텍스트로 노출되어 미관·가독성 저해
- 실측상 커뮤니티 원문 본문은 중앙값 30자대·p95 100자 안팎의 단문이 대다수이나, 상한(후술 CJK 500)을 초과하는 초장문 문제글 **5건이 현재 라이브(삭제되지 않음)** — zh-TW 원문 기준 1,313·1,155·1,061·974·524자(1,000자 초과 3건). 이 중 4건은 여행계획 forum의 플랜 첨부 시술 후기로 2026-07-31~08-06에 집중 게시됨
- 자동 번역은 AI가 수행하며 **출력 길이가 결정적(deterministic)이지 않음** → 실측 CJK(한자) 원문 대비 유럽어(en) 번역본 팽창률은 중앙값 x3.49, p90 x4.78, 최대 x9.0로 편차가 큼. 즉 **원문 길이 상한으로는 번역본 길이를 예측·보장할 수 없음**(예: 1,313자 원문 → 번역본 4,774자, 반대로 119자 원문이 번역 폭주로 11,601자까지 튄 사례 존재)
- 현재 글자 수 상한·본문 접힘·문제 게시글 처리에 대한 정책 부재

### 가설적 임팩트

- **작성 상한(원문 대상)** 도입으로, 외부 작성 초장문·광고성 텍스트의 대량 유입을 저장 단계에서 차단하고, 작성 언어 간 표현력(분량) 형평을 확보
- **본문 접힘(폴드)을 표시 로케일별 실제 번역본 길이로 판정** → AI 번역의 길이 편차와 무관하게 각 언어 피드에서 벽 텍스트를 접어 가독성 유지, 커뮤니티의 단문·플랜 공유 성격 보존
- 붙여넣기 차단으로 외부 작성 장문·광고성 텍스트의 대량 유입 억제

## 구현

### 설계 원칙 — 역할 분리

AI 자동 번역의 출력 길이는 사전 예측이 불가능하므로, **번역본 길이를 상한으로 보장하려는 접근은 원천적으로 성립하지 않는다.** 따라서 두 메커니즘의 역할을 분리한다.

| 메커니즘 | 판정 대상 | 판정 기준 | 목적 |
|---------|----------|----------|------|
| **작성 상한** | 원문(작성자가 통제 가능·결정적) | 원문 작성 언어 문자권 | abuse 차단 + 작성 언어 간 표현력 형평 |
| **본문 접힘(더보기)** | 각 로케일에 **실제 표시되는 번역본** | 표시 로케일의 문자권(사후 실측) | 피드·리스트 가독성 |

- **번역본은 상한 대상이 아니다.** 기계 번역 결과물은 작성자가 통제할 수 없으므로 상한으로 거르지 않는다(원문이 상한 이하이면 저장 허용).
- 피드 가독성은 접힘이 전담하되, **원문 길이로 번역본 길이를 추정하지 않고** 번역이 끝난 뒤(렌더/인덱싱 시점) 각 로케일에 표시되는 실제 문자 수를 재서 판정한다. 이것이 번역 길이 비결정성을 우회하는 유일한 신뢰 가능한 지점이다.

### 유저 플로우

- 유저는 커뮤니티 글 작성 시, 원문 작성 언어별 글자 수 상한을 초과하면 저장 불가, 초과 안내 노출
- 유저는 본문 작성 시 외부 텍스트 붙여넣기 불가, 직접 입력만 허용
- 유저는 피드·리스트에서 접힘 기준을 초과한 본문(자신이 보는 로케일의 번역본 기준)을 접힌 상태로 확인, **더보기** 선택 시 상세에서 전문 확인
- 기존 상한 초과 게시글을 작성자가 수정하려는 경우, 상한 이하로 줄여야 저장 가능(소급 일괄 절단은 하지 않음)
- 운영자는 상한 초과·중복 등 문제 게시글에 대해 작성자에게 이메일로 수정 요청, 요청일로부터 1주일 내 미처리 시 운영자가 직접 수정
- 운영자는 동일 작성자가 올린 중복 게시글을 소프트 삭제(피드 노출만 차단, 데이터·작성자 본인 뷰는 보존)

### 프론트엔드 요구사항

**작성 상한 (원문 대상)**

- 글자 수 상한: 한자·일본어(CJK) 원문 **500자**, 라틴·키릴문자 원문 **1,500자**
  - 두 값은 **작성 언어 간 표현력(분량) 형평**을 맞춘 값(번역본 길이 수렴 목적 아님). 동일 내용 기준 실측 등가는 한자 500자 ≈ 영문 약 1,780자(CJK→en 팽창률 중앙값 x3.56)이며, 운영 여유를 두어 라틴군은 1,500자로 채택
  - 일본어(가나+한자)는 문자 밀도가 한자에 가까워 CJK군(500자)으로 분류. 영문·베트남어·프랑스어·독일어·태국어 등 라틴군과 키릴군은 1,500자로 분류
  - 실제 원문 작성 언어 8종(zh-TW·zh-HK·jp·en·vi·fr·de·th) 모두 위 두 군으로 커버. 키릴 원문은 현재 게시 이력 0건이나 향후 유입 대비로 라틴과 동일 상한 적용
  - 입력 중 잔여 글자 수 카운터 노출, 상한 도달 시 추가 입력·저장 차단
  - 초과 시 안내 카피(초안): **"작성 가능한 글자 수를 초과했어요. (한자·일본어 500자 / 라틴·키릴 1,500자)"**
- 본문 입력창 붙여넣기(paste) 차단

**본문 접힘(폴드) — 표시 로케일별 번역본 실측**

- 접힘 기준: **표시되는 로케일의 문자권 기준**으로 판정 — CJK 표시(zh-TW·zh-HK·zh-CN·jp) **200자 이상**, 라틴·키릴 표시(en·vi·fr·de·th 등) **600자 이상**
  - 판정 대상은 원문이 아니라 **해당 로케일에 실제 노출되는 번역본 본문 길이.** 예) CJK 원문 200자가 en로 팽창해 700자로 표시되면 en 피드에서는 600자 기준 초과로 접힘, 원문 로케일(zh)에서는 200자 기준으로 접힘 → 언어와 무관하게 일관되게 접힘
  - 피드·리스트에서 기준 초과 본문은 접힌 상태로 노출, **더보기** 버튼으로 상세에서 전문 노출
  - 접힘은 작성 상한과 별개 정책으로, 상한 이하 원문도 표시 번역본이 기준 초과 시 접힘 적용
- 글자 수 카운트 기준(상한·접힘 공통): 문자(코드 포인트) 단위, 연속 개행은 축약 후 카운트

### 백엔드 요구사항

- 게시글 저장·수정 시 **원문 작성 언어 기준** 글자 수 상한 검증, 초과 시 저장 거부(번역본 길이는 검증 대상 아님)
- 기존 상한 초과 게시글은 소급 절단하지 않고 보존, 작성자 수정 시점에 상한 검증 적용
- 접힘 판정에 필요한 **로케일별 번역본 문자 수는 번역 생성(렌더/인덱싱) 시점에 산출**하여 노출 로직에서 활용(연속 개행 축약·코드포인트 기준 동일). 원문 길이로 대체 추정하지 않음
- **번역 출력 길이 sanity 가드**: 번역본이 원문 대비 비정상 배율(예: 정상 팽창 p90 x4.78을 크게 상회) 또는 절대 길이 임계를 초과하면 번역 폭주(반복 루프)로 간주해 재번역·차단·플래그. 근거: post 110(jp 119자 → vi 11,601자) 등 짧은 원문의 번역 폭주가 실재하며, 이는 작성 상한·접힘만으로 방어 불가
- 기존 라이브 문제글 처리: 상한 초과 원문 5건(post 827·822·823·825·659)은 소급 절단하지 않고 운영자 수정 요청 플로우로 처리, 번역 폭주 번역본(post 110 등)은 재번역 대상으로 별도 처리
- 문제 게시글 처리 이력 관리: 수정 요청 발송일·처리 상태(작성자 처리/운영자 직접 수정), 1주일 경과 판정 기준
- 중복 게시글은 소프트 삭제로 처리(레코드 유지, 커뮤니티 피드·목록 노출에서만 제외)

### 참고 — 데이터 근거

기준: `post`/`post_translation` 테이블, 라이브(deleted_at IS NULL) 690건, 원문 = `original_language` 행, 연속 개행 축약·코드포인트.

- 원문 언어 분포: zh-TW 486·zh-HK 101·jp 56·en 39·vi 4·fr 2·th 1·de 1. 대다수는 단문(CJK p95 100·p99 210)
- **작성 상한(CJK 500) 초과 라이브 5건**: post 827(1,313자)·822(1,155)·823(1,061)·825(974)·659(524) — 모두 zh-TW, 앞 4건은 여행계획 forum 플랜 첨부 시술 후기. 라틴군은 최장 867자로 1,500 상한 미달 0건
- CJK→en 번역 팽창률 실측(643쌍): 중앙값 x3.49 / p90 x4.78 / 최대 x9.0 → 입력 상한으로 번역본 길이 보장 불가. CJK 500 등가 ≈ en 1,744자
- 번역 폭주 사례: post 110(jp 119자 원문 → vi 번역본 11,601자, 동일 문구 반복 루프). 짧은 원문도 특정 로케일에서 수천~1만 자로 팽창 → 원문 기준 접힘·상한으로 방어 불가, 표시 번역본 실측 + 번역 출력 가드 필요
