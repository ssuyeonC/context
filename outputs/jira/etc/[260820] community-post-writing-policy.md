# 세부 기획안 요구사항 문서

## 배경

### 문제 정의

커뮤니티(/board)는 본인의 여행 계획(플랜)을 첨부해 공유·질문하는 단문 중심 게시판으로, 유저가 특정 언어로 원문을 작성하면 전 언어로 자동 번역되어 노출되는 구조

- 최근 일부 유저가 플랜 첨부 기능을 사용하면서 본문에 초장문(한자 980~1,322자)의 시술 후기성 글을 게시 → 피드에서 벽 텍스트로 노출되어 미관·가독성 저해
- 실측상 커뮤니티 게시글 본문 길이는 중앙값 32자, p90 86자, p95 125자, p99 524자로, 문제 글은 전체 상위 이상치에 해당(1,000자 초과 역대 3건)
- 자동 번역 구조 특성상 원문 언어에 따라 번역본 길이가 크게 팽창 → 실측 CJK(한자) 원문 대비 유럽어 번역본은 중앙값 3.5~3.9배, 상위 구간 5배 이상까지 증가. 원문 길이를 제한하지 않으면 번역본이 과도하게 길어짐
- 현재 글자 수 상한·본문 접힘·문제 게시글 처리에 대한 정책 부재

### 가설적 임팩트

- 언어별 글자 수 상한 도입으로, 어떤 언어로 작성·번역되어도 본문 분량이 일정 범위(번역본 기준 약 2,000자) 내로 수렴, 작성 언어 간 분량 형평 확보
- 본문 접힘(폴드) 도입으로 초장문 글도 피드 가독성 유지, 커뮤니티의 단문·플랜 공유 성격 보존
- 붙여넣기 차단으로 외부 작성 장문·광고성 텍스트의 대량 유입 억제

## 구현

### 유저 플로우

- 유저는 커뮤니티 글 작성 시, 작성 언어별 글자 수 상한을 초과하면 저장 불가, 초과 안내 노출
- 유저는 본문 작성 시 외부 텍스트 붙여넣기 불가, 직접 입력만 허용
- 유저는 피드·리스트에서 접힘 기준을 초과한 본문을 접힌 상태로 확인, **더보기** 선택 시 상세에서 전문 확인
- 기존 상한 초과 게시글을 작성자가 수정하려는 경우, 상한 이하로 줄여야 저장 가능(소급 일괄 절단은 하지 않음)
- 운영자는 상한 초과·중복 등 문제 게시글에 대해 작성자에게 이메일로 수정 요청, 요청일로부터 1주일 내 미처리 시 운영자가 직접 수정
- 운영자는 동일 작성자가 올린 중복 게시글을 소프트 삭제(피드 노출만 차단, 데이터·작성자 본인 뷰는 보존)

### 프론트엔드 요구사항

- 글자 수 상한: 한자·일본어(CJK) 원문 **500자**, 라틴·키릴문자 원문 **1,500자**
  - 두 값은 동일 내용 기준 등가(한자 500자 ≈ 영문 약 1,500자)로, 작성 언어 간 분량 형평을 맞춘 값
  - 일본어(가나+한자)는 문자 밀도가 한자에 가까워 CJK군(500자)으로 분류. 영문·베트남어·프랑스어·독일어·태국어 등 라틴군과 키릴군은 1,500자로 분류
  - 실제 원문 작성 언어 8종(zh-TW·zh-HK·jp·en·vi·fr·de·th) 모두 위 두 군으로 커버. 키릴 원문은 현재 게시 이력 0건이나 향후 유입 대비로 라틴과 동일 상한 적용
  - 입력 중 잔여 글자 수 카운터 노출, 상한 도달 시 추가 입력·저장 차단
  - 초과 시 안내 카피(초안): **"작성 가능한 글자 수를 초과했어요. (한자·일본어 500자 / 라틴·키릴 1,500자)"**
- 본문 접힘(폴드) 기준: 한자 **200자 이상**, 영문 **600자 이상**
  - 피드·리스트에서 기준 초과 본문은 접힌 상태로 노출, **더보기** 버튼으로 상세에서 전문 노출
  - 접힘은 글자 수 상한과 별개 정책으로, 상한 이하 글도 기준 초과 시 접힘 적용
- 본문 입력창 붙여넣기(paste) 차단
- 글자 수 카운트 기준: 문자(코드 포인트) 단위, 연속 개행은 축약 후 카운트
- 상한·접힘 판정 기준 언어는 원문 작성 언어 기준(CJK군/라틴·키릴군 2개 문자권으로 분류)

### 백엔드 요구사항

- 게시글 저장·수정 시 원문 언어 기준 글자 수 상한 검증, 초과 시 저장 거부
- 기존 상한 초과 게시글은 소급 절단하지 않고 보존, 작성자 수정 시점에 상한 검증 적용
- 문제 게시글 처리 이력 관리: 수정 요청 발송일·처리 상태(작성자 처리/운영자 직접 수정), 1주일 경과 판정 기준
- 중복 게시글은 소프트 삭제로 처리(레코드 유지, 커뮤니티 피드·목록 노출에서만 제외)
