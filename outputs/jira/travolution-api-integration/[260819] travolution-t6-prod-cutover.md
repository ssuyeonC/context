# 세부 기획안 요구사항 문서 — [T6] 트래볼루션 운영(prod) 전환

> 에픽 `[260819] travolution-api-integration-epic.md` 하위 T6. 선행 T5(dev 통합 테스트 완료).

## 배경

### 문제 정의
- dev 검증 완료 후 실 운영(prod) 환경으로 전환 필요
- 공급사 prod 상품 UID가 dev와 **동일 보장 안 됨**(공급사 2차 문의 확정) → 운영 매핑은 prod 기준으로 재검증해야 함
- prod 인증키·웹훅 URL은 dev와 별도 등록

### 가설적 임팩트
- 실 운영 자동화 개시 — 수동 부킹(연 약 300건 규모) 실제 제거·즉시발권 실시간 바우처 라이브

## 구현

### 유저 플로우
- 해당 없음 — 운영 전환 작업 (전환 후 유저 경험은 T2·T3 정의대로)

### 프론트엔드 요구사항
- 해당 없음

### 백엔드 요구사항 (전환 절차)
- dev 테스트 완료 후 **prod 인증키 요청**(공급사)
- **prod 웹훅 URL 별도 등록**(dev·prod 각각, `dev@bankoftrip.com` 메일 요청, 영업일 1일 이내)
- **prod 상품 UID 재검증** — dev와 동일 보장 안 됨. 매핑 상품은 공급사 어드민(`www.bankoftrip.com/ko/products/b2b`), 미매핑 목록은 운영팀(`op@bankoftrip.com`)
- prod 매핑 등록 → **운영 오픈 상품 범위·순서 확정**
- 환경설정(baseURL·인증키·웹훅 URL)만 prod로 전환(코드 변경 없이)

**완료조건**
- prod 인증키·웹훅 등록 완료
- prod UID 재검증 후 매핑 등록
- 운영 오픈 상품 범위 확정, 실 주문이 API로 정상 처리

---

### [참고] 연동 후 상시 — 신규 상품 연동 가능 판정 절차
운영이 트래볼루션 신규 상품을 스팟으로 만든 뒤 개발팀에 확인 요청 시:
1. 트래볼루션 API에 **연동 가능 상품으로 올라와 있는지 확인** → 없으면 **연동 불가**(수동 유지)
2. 올라와 있으면 **상품 구조가 매핑 가능한지 확인** → 안 되면 **연동 불가**(드묾)
3. 둘 다 OK → **매핑 등록 후 연동**
