# 세부 기획안 요구사항 문서 — [T3] 트래볼루션 예약(BK) 연동

> 에픽 `[260819] travolution-api-integration-epic.md` 하위 T3. 선행 T1. 조회 + 주문 + 승인/거절 상태 반영.

## 배경

### 문제 정의
- 예약(BK) 상품은 스케줄·재고 조회, 필수 추가정보 수집, 공급사 승인/거절 확인을 모두 어드민이 수동 처리 → 오퍼레이션 부담
- API로 **스케줄·재고 조회, 예약 주문 전달, 승인/거절 자동 수신·반영** 필요

### 가설적 임팩트
- **운영 효율**: 예약 상품 재고·마감·승인 확인의 수동 공수 절감
- **에러 감소**: 수동 입력·상태 반영 누락 제거

## 구현

### 유저 플로우
- 유저가 예약 상품 조회 시 **예약 가능 날짜·시간(재고)** 노출
- 유저가 날짜·시간 선택 + **필수 추가정보 입력**(항목별 선택형/입력형) 후 결제
- 결제 완료 시 공급사 예약 주문 생성 → **승인 대기(PD)** 상태
- 공급사 승인/거절 결과를 웹훅으로 수신 → 승인 시 **확정 안내**, 거절 시 환불·CS 연계

### 프론트엔드 요구사항
- **신규 작업 없음** — 기존 크리에이트립 예약 상품 UI 재사용(실측 확인 2026-08-19)
  - 날짜·시간 선택 = 기존 예약 날짜 모달(날짜별 타임슬롯)
  - 추가정보 입력 = 기존 예약 추가정보 폼(입력창 / SELECT) → 트래볼루션 IPU/SEL과 매칭
  - 승인 대기 상태 = 기존 예약 "확정 대기(1영업일 내 확정)" 상태 노출 → BK PD 상태와 매칭
- ※ 트래볼루션 유형(TK/BK)이 크리에이트립 상품 설정과 정합되어야 화면·처리가 일치 (T1 매핑 시 확인)

### 백엔드 요구사항

**스케줄·재고·추가정보 조회**
- 스케줄·재고 조회 — 옵션별 예약 가능 날짜·시간·실시간 재고 조회(날짜 필터), 스케줄 없음(404) 처리
- 필수 추가정보 조회 — 옵션 추가정보 항목 목록 조회 → 항목별 유형(공통 1회 BAC / 여행자별 TRV)·응답유형(선택형 SEL / 입력형 IPU)·선택지 파악

**주문 생성(BK) + 상태 반영**
- 스케줄·추가정보 확인 후 주문 생성(예약일시·추가정보 포함) → **생성 직후 승인 대기(PD)** 로 보류
- 재고 부족·마감 에러 처리(재고부족 / 스케줄 재고부족 / 스케줄 마감) → 유저·어드민 흐름 정의
- 승인 웹훅(BOOKING_ACCEPTED → 확정 AC) / 거절 웹훅(BOOKING_REJECTED → RJ, 환불·CS 연계) 수신·반영
- 기존 **수동 부킹 상태 모델과 정합**(자동·수동 공존 과도기 고려)
- 바우처 자동 발급은 승인(AC) 시점에 T2 발급 로직 재사용

**완료조건**
- dev에서 BK 상품의 슬롯·재고·추가정보 조회 → 주문이 PD로 생성 → 승인/거절 웹훅에 따라 AC/RJ로 전환

> 규모가 크면 하위 서브태스크(①조회 / ②주문+상태반영)로 쪼갤 수 있음
