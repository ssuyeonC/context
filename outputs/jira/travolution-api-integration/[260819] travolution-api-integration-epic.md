## 목적

- 트래볼루션(공급사, API 브랜드 Bank of Trip)이 B2B로 공급하는 티켓·예약 상품의 **주문 전달·확정·상태 동기화를 API로 자동화**
- 현재 어드민이 공급사 콘솔에 수동 부킹 → 반영까지 6시간~+1일 지연 발생, 이를 제거
- 즉시발권(티켓): 주문 즉시 확정 → **실시간 바우처 발급**
- 예약(Booking): 스케줄·재고 조회 및 공급사 승인/거절 자동 수신 → 어드민 수동 부킹 공수 절감

## 범위

- **포함**: 상품 매핑, 주문 생성(TK/BK), 웹훅 수신·주문 상태 동기화, 바우처 자동 발급, 취소 연동, 어드민 자동/수동 구분
- **제외(현행 유지)**: 파트너발 부분취소·부분환불(API 미지원 → 양사 오퍼팀 커뮤니케이션 유지), 운영 오픈 상품 범위·순서 확정(prod 전환 게이트로 이연)

## 진행 단계

### 0단계 — 기반 구축 (A·B 서로 독립, 병렬 진행)

**A. 웹훅 수신 서버**
- 수신 엔드포인트 구현 — `x-nonce` 기반 중복 수신 방지(멱등), 수신 즉시 `GET /orders` 재조회로 상세 대사
- dev 웹훅 URL을 공급사에 메일 등록 (`dev@bankoftrip.com`, 영업일 1일 이내 반영)

**B. 매핑 스키마 + dev 매핑 등록**
- 크리에이트립 ↔ 공급사 UID 매핑 테이블 설계 — 크리에이트립 리프 노드 ↔ 트래볼루션 unit 앵커, product·option·unit 세트 저장
- dev 연동 가능 상품 매핑 등록

> **완료 기준**: dev 웹훅 URL 등록 완료 · 매핑 테이블에 dev 대상 상품 등록 완료

### 1단계 — 핵심 구현

- 주문 생성 `POST /orders` — 티켓(즉시 확정·바우처) / 예약(승인대기 PD)
- 웹훅 이벤트별 주문 상태 반영 — 승인/거절, 사용/복구, 전체/부분 취소
- 바우처 자동 발급 배선 — 주문번호 주입 → 기존 크리에이트립 브랜딩 PDF 자동 렌더
- 어드민 자동/수동 구분 — 예약내역 테이블에 **API 연동 여부** 컬럼 또는 상위 필터 추가
- 폴백 처리 — 연동 실패·거절·타임아웃 건 담당자 확인, **Slack 알림** 발송
- 취소/환불 연동 — `DELETE /orders`(전체 취소 단위)

> **완료 기준**: 티켓·예약 주문이 API로 생성·확정되고, 웹훅으로 상태가 자동 반영되며, 바우처가 자동 발급됨 · 어드민에서 자동/수동 구분 노출

### 2단계 — dev 환경 통합 테스트

- dev 인증키 + dev 웹훅 URL로 전체 흐름 검증 — 주문 → 확정 → 바우처 발급 → 사용(REDEEMED) → 취소 대사

> **완료 기준**: dev에서 주문~사용~취소 전 구간 정상 동작 확인

### 3단계 — 운영(prod) 전환

- prod 인증키 요청 (dev 테스트 완료 후)
- prod 웹훅 URL 별도 등록 (dev·prod 각각)
- prod 상품 UID 재검증 — dev와 동일 보장 안 됨 (매핑 상품은 공급사 어드민, 미매핑 목록은 `op@bankoftrip.com`)
- prod 매핑 등록 → 운영 오픈 상품 범위·순서 확정

> **완료 기준**: prod 인증키·웹훅 등록 완료 · prod UID 재검증 후 매핑 등록 · 운영 오픈 상품 범위 확정

## 신규 상품 연동 가능 판정 절차 (연동 후 상시)

운영이 트래볼루션 신규 상품을 스팟으로 만든 뒤 개발팀에 연동 가능 여부를 확인 요청하면:

1. 트래볼루션 API에 **연동 가능 상품으로 올라와 있는지 확인** → 없으면 **연동 불가 회신**(수동 유지)
2. 올라와 있으면 **상품 구조가 매핑 가능한지 확인** → 안 되면 **연동 불가 회신**(드묾)
3. 연동 가능 + 구조 매칭 → **매핑 등록 후 연동**
