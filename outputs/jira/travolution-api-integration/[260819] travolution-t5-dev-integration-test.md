# 세부 기획안 요구사항 문서 — [T5] 트래볼루션 dev 환경 통합 테스트

> 에픽 `[260819] travolution-api-integration-epic.md` 하위 T5. 선행 1단계 전체(T2~T4).

## 배경

### 문제 정의
- 운영 전환 전, 개발 환경(dev)에서 주문 생성부터 사용·취소까지 전 구간이 API로 정상 동작하는지 검증 필요
- 정상 흐름뿐 아니라 예외(거절·재고부족·취소불가) 케이스까지 확인해야 운영 리스크 최소화

### 가설적 임팩트
- 운영 전환 리스크 사전 제거 — 결함을 dev 단계에서 차단

## 구현

### 유저 플로우
- 해당 없음 — 검증 단계

### 프론트엔드 요구사항
- 해당 없음 (기존 UI 재사용, 별도 화면 없음)

### 백엔드 요구사항 (검증 시나리오)
- dev 인증키 + dev 웹훅 URL로 전체 흐름 E2E 검증 — **주문 → 확정 → 바우처 발급 → 사용(REDEEMED) → 취소 대사(`GET /orders`)**
- 유형별 점검
  - **TK(즉시발권)**: 주문 즉시 확정·바우처 자동 발급
  - **BK(예약)**: 주문 PD 생성 → 승인(AC)/거절(RJ) 웹훅 반영, 승인 시 바우처 발급
- 예외 케이스 점검 — 예약 거절, 재고부족·마감(`LOW_STOCK`/`SCHEDULE_CLOSED`), 취소불가 에러, 웹훅 중복 수신(멱등), Rate limit 429 재시도
- 폴백·Slack 알림 동작 확인

**완료조건**
- dev에서 주문~사용~취소 전 구간이 정상 동작, 예외 케이스가 정의된 흐름대로 처리
