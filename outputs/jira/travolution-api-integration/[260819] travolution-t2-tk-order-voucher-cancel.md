# 세부 기획안 요구사항 문서 — [T2] 트래볼루션 주문 생성(TK) + 바우처 + 취소 연동

> 에픽 `[260819] travolution-api-integration-epic.md` 하위 T2. 선행 T1.

## 배경

### 문제 정의
- 즉시발권(TK) 티켓 상품도 현재 어드민 수동 부킹·수동 바우처 발급 → 실시간 발권 불가, 리드타임 지연
- 주문 취소도 어드민이 공급사 콘솔에서 수동 처리
- API로 **주문 즉시 확정·바우처 자동 발급·취소 자동 연동** 필요

### 가설적 임팩트
- **전환율**: 즉시발권 상품 실시간 바우처 발급 → 구매 전환 개선
- **운영 효율·에러 감소**: 수동 발급·수동 취소 제거로 휴먼 에러·공수 절감

## 구현

### 유저 플로우
- 유저가 TK(즉시발권) 상품 구매·결제 완료
- 결제 완료 시 시스템이 공급사 주문 생성 자동 호출 → **즉시 확정, 실시간 바우처 발급·전달**
- 유저 취소 요청 시 공급사 주문 취소 자동 연동

### 프론트엔드 요구사항
- **신규 작업 없음** — 발급 바우처는 기존 크리에이트립 템플릿·기존 예약 페이지 노출 메커니즘을 그대로 재사용(백엔드 자동 생성만 변경, 유저 화면 동일)

### 백엔드 요구사항

**주문 생성(TK) + 바우처 자동 발급**
- TK 상품 — 가격/단위 확인 후 주문 생성 호출 → **즉시 확정**, 응답 바우처 정보로 발급 트리거
- 주문 생성 시 크리에이트립 주문번호를 참조번호(referenceNumber, 최대 64자)로 전달 → 웹훅·조회 매칭 키
- 바우처 자동 발급 — 주문 응답 `orderNumber`(TV번호) 자동 주입 → **기존 크리에이트립 브랜딩 PDF 템플릿 자동 렌더**(로고·QR 로직 재사용, 신규 디자인 불필요) → 예약 페이지 노출 + 확정 메일
- 발송 정책 — **크리에이트립 자체 발송(`voucherSendType=0`)** (공급사 직발송은 Bank of Trip 브랜딩이라 불가)
- 바우처 구조 분기 — 코드형(주문당 1코드 / unit당 1코드) / 파일·예약번호형. **코드·파일 없는 수동(ONVL)형은 현행 라이브 0건이라 예외 처리 불필요**

**주문 취소 연동 (TK·BK 공통)**
- 크리에이트립발 취소 시 공급사 주문 취소 호출(**주문 전체 단위만** — 부분취소 API 미지원, 공급사 확정)
- 취소 불가 조건 에러 분기 — 주문없음/만료/사용됨/이미취소됨/취소불가/코레일패스오류 → 케이스별 유저·어드민 처리
- **부분환불/부분취소** — API 미지원 → **양사 오퍼레이션팀 커뮤니케이션으로 처리**(현행 유지, 운영팀 확인 완료 2026-08-18). 결과는 `PARTIAL_CANCELED` 웹훅으로 수신(T1 웹훅). 자동화 대상 아님

**완료조건**
- dev에서 TK 주문 생성 시 바우처가 즉시 응답에 포함되어 발급까지 연결
- 전체취소 정상 연동, 취소 불가 케이스가 에러 기준으로 분기 처리

### [참고] 바우처 자동 발송 — 현행 실측 (2026-08-13)
- 현행: 트래볼루션(파트너 code 69) 바우처는 자동 생성 로직 없는 **수동 사전재고 IMAGE(PDF)** 모델. 발급 시 재고 PDF를 예약 폴더에 복사
- 현행 바우처 실물 = **크리에이트립 로고 PDF + QR**, QR 디코딩 결과 = 트래볼루션 주문번호 `TV...` = API `orderNumber`(`voucherCode` 아님). 로고 요구는 이미 충족
- 자동화 = 사람이 손으로 넣던 TV번호를 **API `orderNumber`로 자동 주입** → 기존 브랜딩 PDF 자동 렌더 → `issueExternalVoucher`(IMAGE) 발급. 템플릿 재사용, 신규 디자인 불필요
- 유일한 신규 빌드: "API 데이터 → 브랜딩 PDF 자동 생성" 스텝 배선(docs-gen slug 신설 vs barcode 로고오버레이 중 택1)
- 유형별: TK = 주문 응답 즉시 완전 자동 / BK = 승인 웹훅 후 자동 생성(T3)
- ONVL(수동) = 현행 라이브 0건 → 예외 없음(향후 신규 시 검토)
