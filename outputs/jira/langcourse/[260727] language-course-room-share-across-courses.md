# 세부 기획안 요구사항 문서

## 배경

### 문제 정의

어드민 집값 알아보기 관리 > 장기숙소 데이터는 직방 크롤링으로 매물을 수집하며, 현재 매물 1건은 어학당 1곳에만 연결 가능한 구조

- 이미 어학당 A에 연결하고 세부 정보를 입력·활성화한 매물은, 같은 주소를 어학당 B로 일괄 추가해도 B에 미노출
  - 직방 매물 ID 기준으로 중복 판정 후, 기존 매물의 가격·썸네일만 갱신하고 A 연결은 그대로 유지, B로는 연결·노출되지 않음
- 인접한 여러 어학당(인근 대학)에 동일 매물이 공통으로 유효한 경우가 많으나, 어학당마다 같은 매물을 다시 수집·세팅해야 하는 비효율
- 신규 생성 매물은 비활성 상태로 만들어지므로, 매물을 다른 어학당에서 다시 쓰려면 세부 정보·활성화를 재작업해야 하는 번거로움

### 가설적 임팩트

- 어학당별 매물 재세팅·재활성화 운영 공수 절감
- 인근 매물을 여러 어학당에서 공유 노출하여 어학당별 집값 정보 커버리지 확대

## 구현

### 유저 플로우

- 관리자, 어학당 A로 주소 검색(일괄 추가) 시 직방 매물 노출 → 세부 정보 입력 → **활성화**
- 관리자, 이후 어학당 B로 같은·인근 주소 검색(일괄 추가) 시, 그 주소에 걸리는 기존 매물이 B에도 연결되어 **활성(노출) 상태로** 노출
- 매물의 세부 정보(직방 원본 가격·썸네일 등)는 매물 단위로 공유, 어학당마다 다시 세팅할 필요 없음
- 한 매물은 여러 어학당에 동시 연결 가능(매물 1건 : 어학당 N곳 공유)
- 관리자, 어드민에서 매물을 어학당(연결 과정명) 단위로만 조회, 매물 전역 목록은 없음
- 관리자, 특정 어학당에서 매물을 삭제하면 해당 어학당과의 연결만 해제, 다른 어학당 연결·노출에는 영향 없음

### 프론트엔드 요구사항

- 목록·필터는 어학당(연결 과정명) 기준으로만 조회, 선택한 어학당에 연결된 매물이면 여러 어학당이 공유하는 매물도 함께 노출
- 활성화(노출) 상태는 매물 단위로 관리, 매물이 활성화된 뒤 다른 어학당에 연결되면 별도 조작 없이 활성 상태 그대로 노출
- 활성화 상태는 직방 매물 상태를 기준으로 결정(수동 갱신·자동 배치 갱신), 어드민 UI에 관리자가 매물을 임의로 비활성화하는 수단은 없음
- 비활성화는 직방에서 매물이 내려간 경우 자동 갱신으로만 발생, 매물 단위이므로 연결된 모든 어학당에 공통 적용, 어학당별 개별 비활성화는 대상 아님
- 선택 삭제 버튼은 해당 어학당과의 연결만 해제하는 동작으로 정의(매물 전체 삭제 아님)
- 일괄 추가 결과는 기존 매물 연결/신규 생성 구분 없이 기존과 동일하게 처리, 별도 안내 없음
- 엑셀 다운로드 등 매물-어학당 매핑을 사용하는 화면의 다중 연결 대응 확인

### 백엔드 요구사항

- 매물-어학당 관계를 1:1에서 매물 1건 : 어학당 N곳(다대다)로 확장
  - 직방 원본 데이터(주소·보증금·월세·관리비·썸네일·직방 매물 ID)는 매물 단위로 보관·공유, 매물 1건 = 직방 매물 1건 원칙 보존
  - 어학당별 연결(연결 여부)은 연결 단위로 관리하는 연결 정보 신설(조인 테이블 등), 활성화(노출) 상태는 매물 단위로 보관, 스키마 변경은 마이그레이션으로 반영
- 조회는 항상 어학당 필터 기준으로 연결 정보를 경유, 매물 단위 전역 조회는 제공하지 않음
- 일괄 추가(크롤러) 로직 변경
  - 주소 검색 결과 매물이 이미 존재하면(직방 매물 ID 기준) 신규 생성하지 않고, 요청한 어학당과의 연결만 추가
  - 새로 연결되는 어학당은 매물의 현재 활성화(노출) 상태를 그대로 노출, 별도 초기화 없음
  - 요청한 어학당에 이미 연결돼 있으면 중복 연결 방지
  - 매물의 직방 원본 데이터(가격·썸네일 등) 갱신은 기존과 동일하게 수행, 매물의 활성화 상태는 초기화하지 않음
- 삭제 정책
  - 관리자의 명시적(선택) 삭제: 해당 어학당과의 연결만 해제, 남은 연결이 0개가 되면 매물 데이터 자체 제거
  - 판매 완료 원룸 일괄 삭제: 매물 전체 삭제(모든 어학당 연결 포함)
- 계약(GraphQL) 변경 시 소비자 동시 대응
