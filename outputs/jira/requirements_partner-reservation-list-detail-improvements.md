# 파트너 어드민 예약내역 페이지(리스트·상세) 개선 요구사항

## 배경

### 문제 정의

현재 파트너 어드민의 예약내역 페이지(리스트·상세)는 다음과 같은 한계가 있다.

**리스트 페이지**

- 매일 수십 건의 예약을 다루는 파트너 입장에서 한 화면에 노출되는 컬럼이 과도하게 많고, 특히 스팟 컬럼은 단일 스팟만 운영하는 파트너이거나 이미 특정 스팟을 필터로 좁혀본 상태에서는 매 행마다 같은 값이 반복되어 가독성을 떨어뜨린다.
- 예약 상태(승인 대기·확정 완료·사용 완료·취소 등)가 텍스트로만 구분되어 있어, 처리 필요한 건과 그렇지 않은 건이 한눈에 식별되지 않는다.
- 정렬이 별도의 드롭다운으로 분리되어 있어, 컬럼 헤더에서 직접 정렬을 토글하지 못하고 별도 인터랙션이 필요하다.
- 스팟 selector가 페이지 상단의 다른 필터들과 멀리 떨어져 있어, 다스팟 파트너가 스팟을 자주 전환하며 보는 동선이 불편하다.
- 동일 상태의 예약이 다수 누적되어 있어도 1건씩 반복 처리해야 하며, 다건을 한 번에 처리할 수 있는 도구가 없다.

**상세 페이지**

- 예약 상세에 진입한 시점에서 파트너가 바로 취할 수 있는 액션(승인·취소 요청·변경 요청)이 페이지 내에 분산되어 있거나 인지가 어렵다. 기존 기능이 이미 있음에도 사용하지 않는 파트너가 다수 확인됨.
- 상세 페이지가 정보 표시에 머물고 처리 액션으로 자연스럽게 이어지지 않아, 파트너가 다시 카톡으로 우회하는 흐름이 반복된다.
- 별도 진행 예정인 수정 요청 흐름 개선의 진입점이 상세 페이지 내에 자리잡을 예정이므로, 본 개선에서 정보 구조를 정비할 때 해당 진입점을 함께 정의해 두어야 향후 재작업이 발생하지 않는다.

### 가설적 임팩트

- 컬럼 정비·상태 컬러 코딩·행 시각 구분으로 매일 누적되던 인지 부담이 감소하여, 어드민 활용도가 높은 파트너의 페인이 해소되고 신규 파트너의 학습 비용도 낮아진다.
- 스팟 컬럼 적응형 표시 + 스팟 selector 위치 조정으로 다스팟 운영 파트너(투어스토리·호수도산 등)의 스팟 전환 동선이 짧아진다.
- 헤더 클릭 정렬 통합으로 정렬 인터랙션이 줄어들고, 다건 일괄 승인 도구가 생기면서 동일 상태 다수 처리 시 운영 시간이 줄어든다.
- 상세 페이지에서 액션 진입점이 1뎁스로 통합되면 "있는 기능을 모르고 안 쓰는" 패턴이 줄어들어, 직접 처리 가능한 건이 어드민 내에서 마무리된다 — 운영팀으로 가는 카톡 트래픽 감소.
- 변경 요청 진입점을 사전 정의해 두어, 별도 진행될 수정 요청 흐름 개선 시 상세 페이지를 다시 뒤집지 않아도 된다.

## 구현

### 유저 플로우

**리스트 페이지 진입**

- 파트너가 예약내역 메뉴에 진입하면 정리된 예약 테이블이 노출된다.
- 기본 컬럼은 다음과 같다: **스팟 / 옵션 / 예약일 / 예약 시간 / 예약자 / 인원 / 상태 / 예약 코드**.
- 스팟 컬럼은 스팟 필터 상태에 따라 자동으로 표시/숨김된다 (아래 '스팟 컬럼 적응형 표시' 항목 참조).
- 기존에 노출되던 운영상 불필요한 컬럼은 기본 노출에서 제거된다.

**스팟 컬럼 적응형 표시**

- 스팟 필터가 '전체'인 경우 → 스팟 컬럼 노출 (기본).
- 스팟 필터가 특정 스팟 1개로 좁혀진 경우 → 스팟 컬럼 자동 숨김 (모든 행이 같은 값이므로 중복 제거).
- 스팟 컬럼이 숨겨질 때, 테이블 상단에 현재 보고 있는 스팟을 한 줄로 명시한다: **{스팟명} 스팟의 예약 ({n}건)**.
- 사용자가 어느 스팟의 데이터를 보고 있는지 즉시 인지할 수 있도록 한다.
- 이 적응형 동작은 스팟 컬럼에만 적용한다. 옵션·상태·기간 등 다른 필터에 의해 컬럼이 사라지지는 않는다.

**상태 컬러 코딩 및 행 시각 구분**

- 예약 상태별로 색상이 부여되어 한눈에 식별 가능하다.
  - **승인 대기**: 강조 색(처리 필요 신호)
  - **확정 완료**: 중립 색
  - **사용 완료**: 비활성 톤
  - **취소**: 약화 톤(회색·취소선 등)
- 행 간 시각 구분(zebra striping)으로 행 단위 가독성을 보강한다.

**소팅**

- 다음 컬럼은 헤더 클릭으로 오름차순·내림차순 토글된다: **방문 일시 / 상태**.
- 기존 날짜 기준 소팅 드롭다운은 제거된다.
- 기본 정렬은 방문 일시 오름차순으로 진입한다.

**검색·필터**

- 기존 스팟 선택 필터만 가장 아래로 위치 변경된다 (테이블 헤더 바로 위에 붙어, 스팟 컬럼 적응형 표시의 트리거로 인지되도록).
- 그 외 기존 필터·검색 항목은 변경 없이 유지된다.

**다건 선택 및 일괄 액션**

- 리스트 좌측 끝에 행 선택 체크박스 컬럼이 추가된다. 헤더 체크박스로 현재 페이지 전체 선택이 가능하다.
- 1건 이상 선택되면 리스트 상단에 일괄 액션 바가 노출되고, 선택 카운트가 표시된다.
- 액션 바에 **선택한 예약 승인** 버튼이 노출된다.
  - 클릭 시 확인 모달을 거쳐 일괄 처리되며, 처리 후 성공·실패 카운트를 토스트로 안내한다.
  - 승인 가능하지 않은 상태(이미 확정·취소 등)가 섞여 있으면 가능한 건만 처리되고, 실패 건은 사유와 함께 결과에 반환된다.

**상세 페이지 진입**

- 리스트의 행 또는 예약 코드 클릭으로 예약 상세 페이지에 진입한다.
- 상세 페이지 상단 영역에 핵심 정보가 한 블록으로 묶여 노출된다: 예약 코드, 상태 배지, 방문 일시, 스팟·옵션, 예약자, 인원, 결제 정보.
- 상태 배지는 리스트와 동일한 컬러 코딩을 사용한다.

**상세 페이지 액션 영역**

- 상세 페이지의 상단 액션 영역에 다음 액션이 1뎁스로 노출된다.
  - **승인하기**
  - **예약 취소 요청하기**
  - **예약 변경 요청하기**
- 각 버튼 클릭 시 기존 기능 동작이 수행된다 (별도 흐름 개선은 본 티켓 범위 외 — 수정 요청 흐름 개선 티켓 참조).
- 각 액션 버튼은 현재 상태에 따라 활성/비활성으로 표현된다.

### 프론트엔드 요구사항

**FR-1. 리스트 테이블 컬럼 재구성**

- 기본 컬럼을 다음 8개로 정리한다: 스팟 / 옵션 / 예약일 / 예약 시간 / 예약자 / 인원 / 상태 / 예약 코드.
- 행 마지막에 인라인 액션 컬럼을 둔다 (승인 대기 행에 한해 **승인** 버튼 활성).
- 제거 대상 컬럼: 디자인 단계에서 최종 확정.

**FR-1-1. 스팟 컬럼 적응형 표시**

- 스팟 필터가 '전체'일 때 스팟 컬럼을 표시한다 (기본).
- 스팟 필터가 특정 스팟 1개로 좁혀지면 스팟 컬럼을 자동으로 숨긴다.
- 스팟 컬럼이 숨겨질 때 테이블 상단에 컨텍스트 안내 문구를 노출한다: **{스팟명} 스팟의 예약 ({n}건)**.
- 다른 필터(옵션·기간·상태 등) 변경은 컬럼 표시/숨김에 영향을 주지 않는다.

**FR-2. 상태 컬러 코딩**

- 상태별 색상 토큰을 정의하여 리스트와 상세에서 동일하게 사용한다.
- 색상 토큰 구분: 승인 대기(강조) / 확정 완료(중립) / 사용 완료(비활성) / 취소(약화). 구체 색상 값은 디자인 단계에서 확정.

**FR-3. 행 시각 구분**

- 행 간 시각 구분 처리(zebra striping)를 적용하여 다수 행이 누적되어도 가독성이 유지되도록 한다.

**FR-4. 컬럼 소팅**

- 방문 일시(예약일+예약 시간)·상태 컬럼은 헤더 클릭으로 오름차순·내림차순 토글된다.
- 기본 정렬은 방문 일시 오름차순.
- 기존 날짜 기준 소팅 드롭다운은 제거하고 헤더 클릭 정렬로 통합한다.
- 정렬 상태의 세션 간 유지(persistence)는 1차 범위 외.

**FR-5. 필터 영역 — 스팟 selector 위치 변경**

- 기존 스팟 selector를 리스트 영역 가장 아래(테이블 헤더 바로 위)로 이동한다.
- 그 외 기존 필터·검색 항목은 변경 없이 현재 위치를 유지한다.
- 스팟 selector는 1차 범위에서 단일 선택만 지원한다 (다중 선택은 1차 범위 외).

**FR-6. 다건 선택 및 일괄 액션**

- 행 좌측에 체크박스 컬럼 추가. 헤더 체크박스로 현재 페이지 전체 선택 가능.
- 1건 이상 선택 시 리스트 상단에 일괄 액션 바가 등장하고, 선택 카운트를 표시한다.
- 1차 일괄 액션은 **선택한 예약 승인**. 클릭 시 확인 모달 → 일괄 처리 → 결과 토스트(성공·실패 카운트).
- 부분 성공 안내 시 실패 건의 사유를 함께 노출한다 (예: **이미 확정된 예약은 승인할 수 없습니다**).

**FR-7. 상세 페이지 정보 블록 정비**

- 상세 페이지 상단에 핵심 정보(예약 코드·상태 배지·방문 일시·스팟·옵션·예약자·인원·결제)를 한 블록으로 묶어 노출한다.
- 상태 배지는 리스트와 동일한 컬러 코딩을 사용한다.

**FR-8. 상세 페이지 상단 액션 영역 통합**

- 상세 페이지 상단에 액션 버튼을 1뎁스로 통합한다.
- 액션 3종을 배치한다: 승인하기 / 예약 취소 요청하기 / 예약 변경 요청하기.
- 각 버튼 클릭 시 기존에 동작하던 기능이 그대로 수행된다 (각 흐름의 본질적 개선은 별도 티켓 — 수정 요청 흐름 개선 참조).
- 상태별 활성·비활성 처리와 비활성 사유 안내를 표기한다 (예: **승인 대기 상태일 때만 승인할 수 있습니다**).

### 백엔드 요구사항

**BR-1. 예약 리스트 조회 API 정렬 파라미터 정비**

- 헤더 클릭 정렬을 지원하기 위해 정렬 키 + 정렬 방향 파라미터를 정비한다.
  - 지원 정렬 키: 방문 일시 / 상태.
  - 입력값이 없으면 기본 정렬(방문 일시 오름차순) 적용.
- 기존 필터 항목(스팟 등)은 변경 없이 유지한다.

**BR-2. 일괄 승인 API**

- 예약 코드 다건 입력 → 각 건에 대해 승인 처리 → 건별 성공·실패·사유를 포함한 결과 응답.
- 승인 대기가 아닌 상태의 건은 실패 처리되고 사유 코드와 메시지가 함께 반환된다.
- 트랜잭션은 건별로 독립 처리되어, 일부 실패가 전체 실패로 이어지지 않는다.
- 인가 검증: 요청 파트너가 보유하지 않은 예약은 처리 대상에서 제외된다.

**BR-3. 예약 상세 조회 응답 정비**

- 상세 페이지 상단 액션 영역에서 사용하는 다음 정보가 한 번의 호출로 응답에 포함되도록 정비한다.
  - 현재 상태와 함께, 가능한 액션 목록 (승인 가능 여부·취소 요청 가능 여부·변경 요청 가능 여부 등 상태 머신 기반 플래그).
  - 각 액션이 비활성일 경우의 사유 코드 및 안내 메시지.
- 클라이언트에서 추가 호출 없이 액션 영역의 활성/비활성 상태를 결정할 수 있어야 한다.

## 비범위(Out of Scope)

- 캘린더 뷰 추가 — 별도 작업으로 이미 배포 완료.
- 고객 컨텍스트 표시(재방문·여권명·동행) — 별도 작업으로 이미 배포 완료.
- 이미지 소스 동기화 — 수정 요청 흐름에 포함되며 이미 배포 완료.
- 수정 요청 흐름 자체(예약 변경 요청의 진행 가시성·메시지 동봉·유저페이지 프리뷰 등) — 별도 티켓에서 진행. 본 티켓은 상세 페이지 내 진입점만 정비.
- 정렬 상태·필터 상태의 세션 간 유지(persistence).
- CSV 내보내기, 메모 일괄 입력 등 추가 일괄 액션.
- 상품 단위 일괄 변경(가격 일괄 인상·시즌 마감 일괄 처리 등) — 스팟 관리 영역에 해당.
- 스팟 selector 다중 선택.
- 고객 ↔ 파트너 다이렉트 메시징 기능 — 별도 신규 기능 트랙에서 진행.

## 검증 포인트

- 리스트 진입 시 기본 컬럼이 8개(스팟 / 옵션 / 예약일 / 예약 시간 / 예약자 / 인원 / 상태 / 예약 코드) + 인라인 액션 컬럼으로 표시되는지.
- 스팟 필터가 '전체'일 때 스팟 컬럼이 노출되고, 특정 스팟으로 좁히면 스팟 컬럼이 자동으로 사라지면서 테이블 상단에 컨텍스트 안내 문구(**{스팟명} 스팟의 예약 ({n}건)**)가 노출되는지.
- 옵션·기간·상태 등 다른 필터 변경으로는 컬럼 구성이 바뀌지 않는지.
- 각 상태(승인 대기·확정 완료·사용 완료·취소)가 정의된 컬러 코딩으로 구분되는지.
- 행 간 시각 구분(zebra striping)이 적용되는지.
- 방문 일시·상태 컬럼 헤더 클릭 시 정렬 방향이 토글되는지. 기본 정렬이 방문 일시 오름차순으로 진입하는지.
- 기존 날짜 기준 소팅 드롭다운이 제거되었는지.
- 스팟 selector가 리스트 영역 가장 아래(테이블 헤더 바로 위)로 위치 이동되었는지.
- 다건 선택 후 일괄 승인 시 승인 대기 상태인 건만 처리되고, 그 외 상태는 실패 사유와 함께 결과에 반환되는지.
- 상세 페이지 진입 시 상단 정보 블록과 상단 액션 영역이 각각 1뎁스로 노출되는지.
- 상세 페이지의 액션 3종(승인하기 / 예약 취소 요청하기 / 예약 변경 요청하기)이 노출되고, 클릭 시 기존 기능이 그대로 수행되는지.
- 상세 페이지 액션 버튼이 현재 상태에 따라 정확히 활성/비활성되고, 비활성 시 사유가 안내되는지.
